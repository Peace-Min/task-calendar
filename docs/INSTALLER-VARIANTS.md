# 설치기 두 종류(B안)

상태: 구현 중(2026-10-26)

## 배경과 사용자 결정

WebView2 런타임을 포함하면 설치기가 약 51 MiB에서 255 MiB로 커진다. 이미 앱을 쓰는 PC도 매번 런타임 파일을 내려받게 되는 부담을 줄인다.

사용자 승인(2026-10-26): `feat/db-app`의 기존 런타임 필수 포함 수정 위에 B안을 반영한다. `배포-빌드.cmd`를 실행하면 공유폴더 업데이트용과 처음 설치용 Full을 함께 만든다. 이 정책은 [기존 필수 포함 정책](INSTALLER-WEBVIEW2.md)의 설치기 한 종류 방식을 대체한다.

## 산출물

- `TaskCalendarWidget-Setup-v<버전>.exe`: 공유폴더 업데이트용. WebView2 설치 파일을 포함하지 않는다. 자동 업데이트가 받는 기존 파일명이다.
- `TaskCalendarWidget-Setup-v<버전>-full.exe`: 처음 설치용. WebView2 오프라인 x64 설치 파일을 포함한다. 새 PC에는 이 파일 하나를 전달한다.
- `latest.json`, `release-v<버전>.sql`: 업데이트용 파일명과 SHA256을 사용한다. Full은 자동 업데이트 대상이 아니다.

## 빌드 및 설치 규칙

1. 빌드 PC의 `redist/MicrosoftEdgeWebView2RuntimeInstallerX64.exe`는 계속 필수다. 없으면 publish 전에 전체 빌드를 중단한다.
2. 앱을 한 번 publish하고 동일한 exe와 HTML로 두 설치기를 차례로 컴파일한다. 각 파일 크기와 SHA256을 표시하며 어느 쪽이든 실패하거나 파일이 없으면 실패로 끝낸다.
3. Inno 직접 컴파일은 기본 업데이트용이다. `/DFullInstaller=1`이면 Full을 만들며, 이때 런타임 설치 파일 누락을 거부한다.
4. 업데이트용은 InitializeSetup에서 기존 레지스트리 감지로 런타임 유무를 검사한다. 없으면 처음 설치용(-full.exe)을 안내하고 파일 설치 전에 중단한다. 무인 설치에서도 중단한다.
5. Full은 런타임이 없을 때만 기존 `/silent /install`로 설치하고 종료를 기다린 뒤 앱을 실행한다.
6. AppId와 설치 경로는 같게 유지해 Full 설치 후 업데이트용으로 갱신할 수 있게 한다. 버전은 바꾸지 않는다.
7. 공유폴더에는 업데이트용과 최신 Full을 용도에 맞게 둘 수 있다. 기존 `-CopyTo`는 업데이트용과 `latest.json`만 복사한다. Full은 새 PC용으로 별도 전달한다.

## 하지 않는 것

설치 중 공유폴더에서 별도 런타임을 찾거나 내려받는 방식은 추가하지 않는다. DB 구조와 앱 기능, 버전, 공용 서버와 사용자 데이터는 변경하지 않는다. 바이너리는 기존대로 커밋하지 않고 push는 하지 않는다.

## 검증 순서

관련 시험과 변이 검출, 실제 배포 cmd로 두 설치기 생성, 두 파일 크기와 자동 업데이트 해시 대조, 런타임 누락 시 빌드 실패, 미설치 판정을 주입한 Inno 시험 설치기로 사전 중단 확인, 전체 strict와 Debug 빌드, 위키 및 인계 보고.
