# 보고 창 피드백 묶음(2026-11-16)

상태: 구현(2026-11-16, 다음 판). 사용자 피드백 2026-11-16.

## 1. 보고 창의 [내 과제 열기]
- 일간, 주간 보고 창의 과제 추가 목록 아래 버튼 "+ 캘린더에 새 과제 만들기"는 내 과제 창과 과제 추가 창(일반 과제 탭)을 함께 열었다.
- 바꿈: 버튼 이름을 "내 과제 열기"로 하고, 내 과제 창만 연다. 과제를 더하려면 그 창 아래의 [+ 과제 추가]를 누른다.
- 근태 창에서 누르면 메인 창의 내 과제 창이 열리고, 근태 창에는 고친 뒤 돌아오면 목록에 반영된다는 안내가 나온다.

## 2. 일간 보고 시간 경고
- 보낼 때 근무시간과 과제 시간 합계가 다르면 한 번 묻는다. 보내기를 막지 않는다. 끄는 설정은 없다.
- 근무시간 = 근태 기본값 + 초과시간(없음 = 0). 근태와 초과시간 칸은 서로 독립된 값이고 마지막에 더한다.

| 근태 | 기본값 |
|---|---|
| 정근 | 8 |
| 야근 | 8 |
| 반차 | 4 |
| 그 밖(특근, 외근, 출장, 휴가, 병가, 조퇴, 지각, 지각+야근, 미기록) | 검사 안 함 |

- 외근, 출장, 지각, 특근 등은 그날 일한 시간이 정해져 있지 않아 뺐다(2026-11-16 사용자). 틀린 경고가 잦으면 아무도 읽지 않는다.
- 문구: "근무시간 10시간(근태 야근, 초과 +2)과 과제 시간 합계 8시간이 맞지 않습니다. 그래도 보낼까요?" [보내기] [취소]. [취소]는 아무것도 보내지 않고 편집으로 돌아간다.
- 주간 보고는 대상이 아니다.

## 3. 주간 보고: 더한 과제가 보낸 뒤 다시 열면 빠짐(결함)
- 재현(사용자): 기본 목록에 없는 과제를 [+ 과제 추가]로 넣고 시간을 적어 [보고]로 보낸 뒤, 그 주 편집 화면을 다시 열면 그 과제가 빠져 있다.
- 원인: [보고]가 성공하면 보낸 상태가 처음 상태가 되어 고친 것 없음이 된다. 그 직후 [목록], ‹ ›, 창 닫기가 `awDraftFlushNow` 로 보낸 모양의 임시 저장을 지웠다. DB 기록은 호스트가 회사 되읽기 뒤 따로 저장하고(재시도 10, 30, 60초) 알림(`__reportWeeklySaved`)은 그보다 늦다. 그 사이 다시 열면 임시 저장도 기록도 없어 처음 여는 주처럼 일간 가져오기 기본 목록으로 열렸고, 늦게 온 알림이 그 목록을 기록으로 굳혔다. 이미 보낸 적 있는 주는 옛 기록으로 열렸다.
- 함께 찾음: 알림이 임시 저장을 지우기 전 비교에서 임시 저장의 제목이 비어 있어 늘 어긋났다(닫기 확인이 대신 지워 시험이 통과하고 있었다).
- 고침: 보낸 상태를 `__awSentSig` 에 함께 두고, 지금 화면이 보낸 모양이면 알림까지 임시 저장을 지우지 않는다(`awSentKeep`). 다시 열 때 그 임시 저장을 처음 상태로 삼는다. 성공하면 목록 캐시(AWL)를 비운다. 알림은 제목을 채운 뒤 비교한다.
- 실위젯 확인은 회사 인트라넷으로 보내야 해서 하지 않았다. jsdom 회귀 시험으로 사용자 순서(알림 전 다시 열기, 알림 뒤, 목록 행, ‹ ›, 창 새로 열기)를 확인했다.
- 확인: 보낸 뒤 다시 열기, 근태 창을 닫고 다시 열기 둘 다 보낸 그대로 보인다.

## 4. 일정/할 일 창: 유형을 바꾸면 창이 움직임
- 일정에서 할 일로 바꾸면 일정 전용 칸이 숨어 창이 낮아지고, 화면 가운데에 다시 맞춰지며 위치가 바뀌었다.
- 바꿈: 유형을 바꿔도 창의 크기와 위치가 그대로다(UI 출렁임 금지, docs/UI-FEEDBACK-ATTENDANCE.md).

## 4-2. 일간 [← 불러오기]: 불러온 과제만 바꾼다
- 사용자 피드백(2026-11-16, 다른 사용자 불만 포함): 왼쪽에 A, B, C 블록이 있을 때 A, B 를 불러오면 C 까지 모두 지워지고 A, B 만 남았다(`atLoadClick` 이 블록 배열을 통째로 바꿨다, 2026-10-29 "묻지 않고 바로 바꾼다" 때 굳은 동작).
- 바꿈(묻지 않는 것은 그대로):
  - 불러온 블록과 같은 과제(과제 id `catId`, id 가 없는 옛 블록은 같은 이름)의 블록은 불러온 내용과 시간으로 덮어쓴다. 같은 과제 블록이 왼쪽에 둘 이상이면 첫 블록을 덮고 나머지는 지운다(한 과제 한 블록).
  - 왼쪽에 없던 과제는 새 블록으로 넣고 과제 순서로 자리 잡는다(`atSortBlocks`).
  - 불러오지 않은 과제의 블록과 과제 미정 블록은 그대로 둔다.
  - 자유 메모는 지금처럼 이전 보고의 메모 카드를 체크했을 때만 바꾼다.
  - 남은 블록을 없애려면 사용자가 그 블록을 직접 지운다.
- 주간 [← 이번 주 일간 보고]는 지금처럼 전체를 바꾼다. 그 주 일간 전체를 모아 과제투입시간과 진행사항을 다시 만드는 기능이고, 진행사항은 과제별이 아닌 글 칸 하나라 골라 바꿀 수 없으며, 일부만 바꾸면 합계가 일간과 어긋난다.

## 5. 시험
- 1: 버튼 이름, 내 과제 창만 열림(과제 추가 창 안 열림), 근태 창 경로의 hpost.
- 2: 정근 6시간 경고, 취소면 안 보냄, 야근 +2 에 8시간 경고, 반차 4시간 경고 없음, 정근 8시간 경고 없음, 출장 3시간 경고 없음, 경고 뒤 [보내기]로 보냄.
- 3: 사용자 순서 재현 회귀 시험.
- 4: 유형을 바꿔도 창 높이와 위치 고정.
- 4-2: A, B, C 에 A, B 불러오기면 C 남고 A, B 덮임, 새 과제 D 는 순서 자리에, 과제 미정 블록 남음, 메모는 카드 체크 때만, 같은 과제 두 블록은 하나로, 이전 보고 출처와 캘린더 출처 둘 다.
