# 버그 — 기간 칩을 누르면 달이 바뀐다 (기획서)

> 2026-10-01 · 대상 v0.19.x · 파이프라인 **기획 → 개발 → QA → 위키** 의 1단계 산출물. 개발·QA 의 정본.

## 0. 제보

사용자: "10월 1일(오늘)을 누르면 9월 달력에서는 10월로 바뀌고, 10월 달력에서는 9월로 바뀐다."

## 1. 원인(코드 확인)

- 그리드 클릭 처리(`grid` click)는 **칩을 누르면** `selectDate(chip.dataset.occ || selectedDate)` 를 부른다. 칩이 아닌 칸을 누르면 `selectDate(cell.dataset.date)`.
- 칩의 `data-occ` 는 **그 발생의 시작일**이다.
  - 일정 칩(`chipHtml`): `occDate = item.occ ? item.occ._occStart : e.date` — 기간 일정(9/29~10/2)은 어느 칸에 그려져도 **9/29**.
  - 할 일 칩(`todoChipHtml`): `data-occ = t.due` — 기간 할 일도 **시작일**.
- `selectDate(ds)` 는 `ds` 의 달이 보고 있는 달과 다르면 **그 달로 넘어간다**.
- 그래서 10월 달력의 10/1 칸에 걸친 「9/29~10/2」 막대를 누르면 9/29 가 선택되고 **9월로 넘어간다**. 9월 달력에서 흐린 10/1 칸(빈 곳)을 누르면 정상적으로 10월로 넘어간다. 사용자는 같은 자리를 눌렀는데 달이 번갈아 바뀌는 것으로 보인다.
- 사용자 실데이터에 「프로젝트 포팅 진행 중」(9/29~10/2)이 있어 10/1 칸에 막대가 걸려 있었다.

## 2. 목표 동작

| # | 상황 | 동작 |
|---|---|---|
| B1 | 칩(일정·할 일·기간·반복)을 누름 | **누른 칸의 날짜**를 선택한다(`chip.closest('.cell').dataset.date`). 기간 막대의 어느 칸을 눌러도 그 날짜에 머문다 |
| B2 | 드러내기는 유지 | 일정 칩 → 「일정 상세」 탭 + 그 일정 카드 강조, 할 일 칩 → 「할 일」 탭 + 그 행 강조(지금 규칙 그대로). 선택한 날짜에서 그 카드·행이 실제로 보여야 한다 |
| B3 | 다른 달 칸(흐린 칸)을 누름 | 지금처럼 그 달로 넘어간다(칩을 눌러도 같다 — 누른 칸 기준이므로 일관) |
| B4 | 칸 밖 칩(예: 「+N 더보기」 목록·주간 보기 등 칸 없이 그려진 칩) | 칸을 못 찾으면 지금처럼 `data-occ` 로 대체 |
| B5 | 끌어 옮기기(드래그) | `data-occ` 를 쓰는 드래그 계산은 **건드리지 않는다**(시작일 기준 이동이 맞다) |

## 3. 수용 기준(QA)

| ID | 기준 | 확인 |
|---|---|---|
| K1 | 10월 달력, 9/29~10/2 기간 일정의 10/1 칸 막대 클릭 → 달 그대로(10월) · 선택 10/1 · 상세 탭에 그 카드 강조 | jsdom + 실 위젯 |
| K2 | 같은 막대의 10/2 칸 클릭 → 선택 10/2 | jsdom |
| K3 | 9월 달력, 흐린 10/1 칸의 막대 클릭 → 10월로 넘어가고 선택 10/1(누른 칸 기준) | jsdom + 실 위젯 |
| K4 | 기간 할 일 막대도 K1 과 같다(할 일 탭 + 행 강조) | jsdom |
| K5 | 단일일 일정·반복 일정 칩은 지금과 같은 날짜 선택(누른 칸 = 그 날) | jsdom |
| K6 | 드래그 이동 결과 무변화 | 기존 시험 · 루프 |
| K7 | 기존 스위트·루프 무회귀 | strict · run-loops |
