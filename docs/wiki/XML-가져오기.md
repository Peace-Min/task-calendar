# XML 가져오기

예전 버전(XML 파일에 저장하던 시절)의 기록을 서버로 옮기는 방법입니다. **가져오기는 언제나 교체입니다.** 파일 내용이 지금 캘린더를 통째로 대신합니다.

> 적용 버전: v0.19.1 다음 버전부터. 그 전에는 미리보기 창에 '병합' 버튼이 있었습니다.

## 처음 켤 때 묻는 창

캘린더가 비어 있고, 데이터 폴더(`%APPDATA%\TaskCalendar`)에 예전 기록 파일(`*.xml`, 예: `data.xml`)이 있으면 **"이전 버전 기록을 찾았습니다"** 창이 뜹니다.

- **가져오기**: 그 파일로 캘린더를 채우고 서버에 저장합니다. 캘린더가 비어 있을 때만 뜨는 창이라 지워지는 것이 없습니다.
- **나중에**: 그냥 닫습니다. 다음에 켤 때 다시 묻습니다.
- **다시 묻지 않기**: 그 파일에 대해서는 더 묻지 않습니다. 다른 파일이거나 그 뒤에 고쳐진 파일이면 다시 묻습니다.

창이 떠 있는 사이에 무언가를 적었다면 바로 교체하지 않고 아래 미리보기 창으로 넘어갑니다.

## 직접 고르는 가져오기

⋯ 메뉴의 **XML 가져오기**, 또는 빈 캘린더 안내의 **XML 가져오기…** 를 누릅니다. 파일 고르는 창이 데이터 폴더에서 열립니다.

1. 파일을 고르면 **미리보기** 창이 뜹니다. 파일 안의 과제와 기록 개수, 지금 캘린더의 개수를 나란히 보여 줍니다.
2. 버튼은 **취소**와 **교체** 둘입니다.
3. **교체**를 누르면 "현재 데이터(과제 n개, 기록 n개)가 모두 삭제되고 파일 내용으로 대체됩니다" 확인창이 한 번 더 뜹니다. 여기서 확인해야 실제로 바뀝니다.

## 교체가 바꾸는 것

- 과제, 기록, 할 일, 과제별 시간, 근태, 보고서 서식과 글꼴이 **모두 파일 내용으로** 바뀝니다. 지금 캘린더에만 있던 것은 남지 않습니다.
- 옛 파일의 커밋 기록(커밋에서 만든 작업일지)과 커밋 목록, 과제의 Git/SVN 저장소 경로, 작성자 이름은 읽지 않고 버립니다(2026-10-26 Git, SVN 기능 삭제, [지운 기능](지운-기능)). 나머지 기록은 그대로 들어옵니다.
- 옛 파일의 회의실 목록(`<rooms>`)은 읽지 않습니다(2026-10-21부터). 회의실은 회사 공용 목록이고 관리자가 관리합니다. 기록에 적힌 장소 글자는 그대로 들어옵니다.
- (2026-10-07부터) 과제가 정해지지 않았던 기록과 없는 과제를 가리키던 기록은 **기타**로 들어갑니다. 파일에 '기타'나 '휴가' 과제가 있으면 그 과제가 [기본 과제](기본-과제-휴가와-기타)가 됩니다.
- 서버 저장은 한 번에 처리됩니다. 저장이 실패하면 아무것도 바뀌지 않습니다.
- 성공하면 원본 파일 이름 끝에 `.migrated-<날짜>` 가 붙어 보관됩니다. 파일을 지우지는 않습니다.

## 병합이 없어진 이유 (2026-10-07)

- 병합은 과제와 기록을 **ID 로만** 비교해 합쳤습니다. 이름이 같아도 ID 가 다르면 같은 과제가 두 개 생겼습니다.
- 예전 기록을 옮기는 일은 사람마다 한 번뿐이고, 처음 켤 때 묻는 창은 이미 교체만 했습니다. 가져오기를 교체 하나로 통일했습니다.
- 지금 캘린더에 적은 것을 살리고 싶다면, 가져오기 전에 ⋯ 메뉴의 **XML로 내보내기**로 사본을 남겨 두세요.

## 자주 묻는 것

- **가져오기를 눌러도 안내만 뜨고 진행되지 않아요.** 서버 연결이 끊긴 동안에는 가져올 수 없습니다. [서버 연결이 끊겼을 때](서버-연결이-끊겼을-때)를 보세요. 앱 버전이 서버보다 오래된 경우에도 막힙니다(화면 위 빨간 표시).
- **두 번 가져오면 어떻게 되나요?** 두 번째 파일 내용으로 다시 통째로 바뀝니다. 합쳐지지 않습니다.
