# 지운 기능

쓰는 사람이 거의 없어 앱에서 지운 기능과 그 이유를 남깁니다. 다시 넣자는 이야기가 나오면 먼저 여기와 기획서를 보세요.

## Git, SVN 연동 (2026-10-26)

**무엇이 없어졌나**

- 오른쪽 패널의 '커밋 내역' 탭, 그날 커밋과 여러 날 커밋 불러오기, 커밋 메시지 고치기와 지우기
- 달력의 커밋 기록 칩(렌치 표시)
- '🏷️ 내 과제' 창의 Git 저장소, SVN 작업 복사본 경로, 작성자, 자동 감지 카드
- 보고서의 '커밋 내역' 출처와 커밋 본문 옵션, 월간 보고의 커밋 실적
- [다른 사람 일정 보기](다른-사람-일정-보기)의 커밋 내역 탭
- 커밋 기록만 열던 예전 기록 창, 사용설명서의 Git 장

**이미 있던 커밋 기록은 지웠습니다.** 일반 일정으로 바꾸지 않고 서버에서 모두 지웠습니다. 그 기록에 적어 둔 메모, 장소, 공수도 함께 사라졌습니다. 서버 구조 번호 18 로 올리는 배포 SQL 이 한 번에 지우므로, 그 SQL 을 돌리기 전에 관리자가 DB 를 백업합니다([앱 업데이트와 서버 갱신](앱-업데이트와-서버-갱신)).

**옛 파일과 옛 설정**

- [XML 가져오기](XML-가져오기)로 옛 파일을 넣어도 커밋 기록, 커밋 목록, 저장소 경로, 작성자는 읽지 않습니다. 나머지 기록은 그대로 들어옵니다.
- XML 내보내기도 그 값들을 쓰지 않습니다.
- 각 PC 에 남은 `repo-paths.json`(저장소 경로)은 지우지 않지만 읽는 곳이 없습니다.

**남은 것**: '⋯ → 과제 데이터 내보내기'는 그대로 있습니다. 고른 과제와 기간의 일정과 할 일을 폴더(`과제데이터_<과제>_<시작>_<끝>`) 안의 `calendar/캘린더.md` 로 씁니다(요약 파일 `내보내기_요약.txt` 와 함께). Git, SVN patch 파일은 더 만들지 않습니다.

**왜**: 거의 쓰지 않는 기능인데 앱, 서버 DB, 시험 곳곳에 짐이 컸습니다. 커밋 기록을 일반 기록으로 바꾸는 것보다 지우는 쪽이 가장 깔끔하고 일이 적다고 사용자가 정했습니다.

기획서: [`docs/GIT-SVN-REMOVAL.md`](https://github.com/Peace-Min/task-calendar/blob/feat/db-app/docs/GIT-SVN-REMOVAL.md), 결정 기록: [`docs/DECISIONS.md`](https://github.com/Peace-Min/task-calendar/blob/feat/db-app/docs/DECISIONS.md) 결정 7.

## 선진행 잠금과 '진행중만' 필터 (2026-10-26)

**무엇이 없어졌나**

- 공식 과제의 구분을 '선진행'으로 고르면 계약 시작일, 종료일, 상태를 비우고 잠그던 규칙. 저장할 때 서버가 그 칸들을 말없이 비우던 처리도 함께 없앴습니다.
- 구분을 선진행으로 바꾸면 자동으로 채운 개발 날짜를 비우던 규칙
- 구분의 '선진행', 상태의 '종료' 줄을 숨기거나 지우지 못하게 하던 막기(관리 화면, 휴지통, 서버 구축 스크립트)
- 공식 과제 목록의 '진행중만' 체크(실제로는 상태 '종료' 하나만 빼던 규칙)와 상태 고르기 상자. 상태마다 체크박스로 바뀌었습니다.
- 과제 상세의 '참조 id' 줄, 과제 이름 앞의 구분 색 점

**이미 있던 데이터**: 바꾸지 않았습니다. 예전에 비워진 선진행 과제의 날짜와 상태는 빈 채로 있고, 이제 필요하면 넣을 수 있습니다.

**남은 것**: 새 과제의 개발 날짜 기본값, 상태 색(보이는 색일 뿐), 비슷한 과제 확인창, 날짜 순서와 필수 칸 검사.

**왜**: 한 칸을 바꾸면 다른 칸이 저절로 비거나 잠기는 규칙은 사용자가 모르게 데이터를 바꿉니다. 사업부 장표와 실제 업무가 규칙과 어긋나면 값을 넣을 길도 없었습니다. 그래서 구분, 상태와 날짜를 서로 따로 두기로 했습니다.

자세한 내용: [공식 과제 순서와 거르기](공식-과제-순서와-거르기). 기획서: [`docs/PROJECT-ADMIN-UX.md`](https://github.com/Peace-Min/task-calendar/blob/feat/db-app/docs/PROJECT-ADMIN-UX.md), 결정 기록: [`docs/DECISIONS.md`](https://github.com/Peace-Min/task-calendar/blob/feat/db-app/docs/DECISIONS.md) 결정 8.

## 보고서 버튼과 창 (2026-11-03)

**무엇이 없어졌나**

- 툴바의 **보고서** 버튼과 보고서 창(기간 취합, 월간 보고 두 탭이 남아 있던 창)
- 보고서 창에만 숨어 있던 옛 [일간 작성] [주간 작성] 탭과 전용 기능: 글 편집(카드와 글 편집), 이 보고서에서 빼기, 임시 저장, 보고서 묶음, 회사로 보내는 [일간보고 전송] [주간보고 전송] 단추
- 인트라넷 일간(netcus 일간) 출처. 취합 출처는 캘린더 기록과 인트라넷 주간 둘만 남았습니다.
- 취합의 **포함 항목**(일정, 할 일, 설명, 빈 과제 빼기)과 달력의 일정, 할 일을 하루 단위로 모으던 글(2026-11-03). 캘린더 기록 출처가 이 앱 주간보고 기록을 읽는 것으로 바뀌어 쓸 곳이 없어졌습니다. 취합 미리 보기에서 날짜별 설명을 고치던 연필 단추도 같이 없앴습니다(할 일 편집 창에서 고칩니다).
- 기간 빠른 단추(이번 달, 지난달, 이번 주 등). 기간은 날짜 칸 둘로 직접 고릅니다.

**지금은 어디서 하나**

- 일간, 주간 보고 쓰기와 회사 제출: 근태 탭 [일간], [주간]([근태 보고](근태-보고), [근태 주간 보고](근태-주간-보고)).
- 기간 글 모으기와 월간 보고 Word 문서: 근태 탭 [취합]([근태 보고](근태-보고#월간-예전-이름-취합), [월간 보고](월간-보고)). 취합은 회사로 보내지 않고 복사나 DOCX 저장만 합니다.

**남은 것**: 이 PC 에 쓰다 만 옛 보고서 임시 저장 키는 지우지 않지만 읽는 곳이 없습니다. 서버의 보고 기록(일간, 주간)과 월간 보고 그림은 그대로입니다.

**왜**: 기간 취합과 월간 보고는 같은 글을 두 번 따로 모으는 화면이었고, 일간과 주간은 근태 탭으로 옮긴 뒤 숨겨만 둔 코드가 남아 있었습니다. 보고는 모두 근태 탭 한 곳으로 모으기로 했습니다. 기획서: [`docs/ATTEND-SUMMARY.md`](https://github.com/Peace-Min/task-calendar/blob/feat/attend-summary/docs/ATTEND-SUMMARY.md).

## 작성 중 시간과 서버의 보고 서식 (0.26.0)

**무엇이 없어졌나**

- 과제별 작성 중 시간. 0.24.0 까지 보고서 창 일간 작성의 시간 칸에 적던 값이고, 0.25.0 부터는 적는 화면이 없었습니다. 근태 [가져오기]의 캘린더 출처는 시간 칸을 0 으로 채웁니다.
- 서버에 두던 보고서 서식(머리기호, 들여쓰기)과 보고 글꼴. 근태는 [문단 모양](근태-보고#수준과-문단-모양-0260)을 쓰고, 취합의 글꼴은 이 PC 에 계정별로 기억합니다. 예전 글꼴은 옮기지 않아 처음 한 번은 기본 글꼴입니다.
- 관리자 도구 `xml-to-db`(XML 파일을 서버 DB 로 옮기던 명령줄 도구)와 그 기록 표. 앱 안 [XML 가져오기](XML-가져오기)가 같은 일을 합니다.

**이미 있던 데이터**: 서버 갱신(DB 구조 22) 때 세 표(작성 중 시간, XML 옮기기 기록, 보고서 서식)를 지웁니다. 배포 전 백업에는 남습니다. 근태로 보낸 일간, 주간 보고와 그 공수는 그대로입니다.

**왜**: 지금 근태 화면이 읽지도 쓰지도 않는 표였습니다. 남겨 두면 과제를 지우거나 퇴사자를 정리할 때 함께 챙겨야 할 곳만 늘어납니다. 기획서: [`docs/DB-V22-REPORT-HOURS.md`](https://github.com/Peace-Min/task-calendar/blob/feat/db-app/docs/DB-V22-REPORT-HOURS.md).

## 화면 정리로 빠진 것 (2026-11-03 ~ 11-10)

한 줄씩 남깁니다. 지금 쓰는 길은 괄호 안 페이지에 있습니다.

- 개인 탭 오른쪽 패널의 [일정 상세 | 할 일] 탭, 도구줄의 "＋ 새 기록" 단추(2026-11-03). 패널은 고른 날짜만 보이고 머리의 [+ 추가] 하나입니다([개인 달력 패널](개인-달력-패널)).
- [보기] 팝업의 보기 옵션(완료한 할 일 표시, 중요한 할 일만)과 고른 과제 칩(2026-11-03, [과제 필터와 보기](과제-필터)).
- 패널 안에서 할 일을 바로 고치던 칸(2026-11-05). 할 일 상세의 **수정**이 입력 창을 '할 일 수정'으로 엽니다([일정 입력 창](일정-입력-창)).
- 달력 칸 맨 위의 할 일 구역, 그 아래 점선, '할 일 n' 개수 칩(2026-11-05). 칸은 일정과 할 일을 합쳐 채우고 넘치면 +n개 더보기입니다([개인 달력 패널](개인-달력-패널#달력-칸)).
- 근태 일간 가져오기의 [서식] 줄(머리기호와 들여쓰기, 2026-11-06). 불러온 글은 [문단 모양](근태-보고#수준과-문단-모양-0260)을 따릅니다. 예전에 고른 서식 값은 읽지 않습니다.
- 개인 탭 오른쪽 패널 할 일 줄 끝의 ✕(삭제) 단추와 제목 두 줄 자르기(2026-11-10). 긴 제목이 전부 보이도록 자리를 내주었습니다. 지우기는 제목을 눌러 펼친 상세의 **삭제**입니다([개인 달력 패널](개인-달력-패널)).
