# 지운 기능

쓰는 사람이 거의 없어 앱에서 지운 기능과 그 이유를 남깁니다. 다시 넣자는 이야기가 나오면 먼저 여기와 기획서를 보세요.

## Git, SVN 연동 (2026-10-26)

**무엇이 없어졌나**

- 오른쪽 패널의 '커밋 내역' 탭, 그날 커밋과 여러 날 커밋 불러오기, 커밋 메시지 고치기와 지우기
- 달력의 커밋 기록 칩(렌치 표시)
- '🏷️ 내 과제' 창의 Git 저장소, SVN 작업 복사본 경로, 작성자, 자동 감지 카드
- 보고서의 '커밋 내역' 출처와 커밋 본문 옵션, 월간 보고의 커밋 실적
- [다른 사람 일정 보기](다른-사람-일정-보기)의 커밋 내역 탭
- 커밋 기록만 열던 예전 기록 창, 사용설명서의 Git 장

**이미 있던 커밋 기록은 지웠습니다.** 일반 일정으로 바꾸지 않고 서버에서 모두 지웠습니다. 그 기록에 적어 둔 메모, 장소, 공수도 함께 사라졌습니다. 서버 구조 번호 18 로 올리는 배포 SQL 이 한 번에 지우므로, 그 SQL 을 돌리기 전에 관리자가 DB 를 백업합니다([앱 업데이트와 서버 갱신](앱-업데이트와-서버-갱신)).

**옛 파일과 옛 설정**

- [XML 가져오기](XML-가져오기)로 옛 파일을 넣어도 커밋 기록, 커밋 목록, 저장소 경로, 작성자는 읽지 않습니다. 나머지 기록은 그대로 들어옵니다.
- XML 내보내기도 그 값들을 쓰지 않습니다.
- 각 PC 에 남은 `repo-paths.json`(저장소 경로)은 지우지 않지만 읽는 곳이 없습니다.

**남은 것**: '⋯ → 과제 데이터 내보내기'는 그대로 있습니다. 고른 과제와 기간의 일정과 할 일을 폴더(`과제데이터_<과제>_<시작>_<끝>`) 안의 `calendar/캘린더.md` 로 씁니다(요약 파일 `내보내기_요약.txt` 와 함께). Git, SVN patch 파일은 더 만들지 않습니다.

**왜**: 거의 쓰지 않는 기능인데 앱, 서버 DB, 시험 곳곳에 짐이 컸습니다. 커밋 기록을 일반 기록으로 바꾸는 것보다 지우는 쪽이 가장 깔끔하고 일이 적다고 사용자가 정했습니다.

기획서: [`docs/GIT-SVN-REMOVAL.md`](https://github.com/Peace-Min/task-calendar/blob/feat/db-app/docs/GIT-SVN-REMOVAL.md), 결정 기록: [`docs/DECISIONS.md`](https://github.com/Peace-Min/task-calendar/blob/feat/db-app/docs/DECISIONS.md) 결정 7.

## 선진행 잠금과 '진행중만' 필터 (2026-10-26)

**무엇이 없어졌나**

- 공식 과제의 구분을 '선진행'으로 고르면 계약 시작일, 종료일, 상태를 비우고 잠그던 규칙. 저장할 때 서버가 그 칸들을 말없이 비우던 처리도 함께 없앴습니다.
- 구분을 선진행으로 바꾸면 자동으로 채운 개발 날짜를 비우던 규칙
- 구분의 '선진행', 상태의 '종료' 줄을 숨기거나 지우지 못하게 하던 막기(관리 화면, 휴지통, 서버 구축 스크립트)
- 공식 과제 목록의 '진행중만' 체크(실제로는 상태 '종료' 하나만 빼던 규칙)와 상태 고르기 상자. 상태마다 체크박스로 바뀌었습니다.
- 과제 상세의 '참조 id' 줄, 과제 이름 앞의 구분 색 점

**이미 있던 데이터**: 바꾸지 않았습니다. 예전에 비워진 선진행 과제의 날짜와 상태는 빈 채로 있고, 이제 필요하면 넣을 수 있습니다.

**남은 것**: 새 과제의 개발 날짜 기본값, 상태 색(보이는 색일 뿐), 비슷한 과제 확인창, 날짜 순서와 필수 칸 검사.

**왜**: 한 칸을 바꾸면 다른 칸이 저절로 비거나 잠기는 규칙은 사용자가 모르게 데이터를 바꿉니다. 사업부 장표와 실제 업무가 규칙과 어긋나면 값을 넣을 길도 없었습니다. 그래서 구분, 상태와 날짜를 서로 따로 두기로 했습니다.
