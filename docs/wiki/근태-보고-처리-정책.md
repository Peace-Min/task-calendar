# 근태 보고 처리 정책

정책 확정: 2026-10-26. 이 정책을 반영한 개발 브랜치의 동작을 설명하며, 기존 배포 앱에 이미 적용됐다는 뜻은 아니다.

1. 입력 내용을 확인한 뒤 회사에 보고한다.
2. 회사 성공을 확인하면 캘린더 DB에 보고 기록 전체를 저장한다.
3. 두 단계가 모두 성공하면 완료 안내 후 편집창을 닫고 달력을 갱신한다.

어느 단계든 실패하면 **처리를 완료하지 못했습니다. 다시 시도해 주세요.**를 표시하고 편집창과 입력을 유지한다. 재시도는 회사 보고부터 다시 수행한다. 같은 대상 보고를 덮어쓰는 운용을 전제로 한다.

회사에는 반영됐지만 캘린더 DB 저장만 실패할 수 있다. 이때 회사 내용을 자동으로 되돌리지 않고, 캘린더에는 기존 DB 기록만 표시한다. 실패한 입력은 편집창이 열려 있는 동안만 유지하며 앱을 종료하면 사라질 수 있다. 로컬 복구 큐와 자동 재전송은 제공하지 않는다.

DB 전용 재시도 버튼은 제공하지 않는다. 서버 갱신 중 또는 앱 업데이트가 필요한 경우에는 해당 조건을 해결한 후 다시 시도한다.

회사 시스템과 캘린더 DB 전체를 하나로 묶는 분산 트랜잭션은 아니다. 원자성은 회사 성공 후 수행하는 캘린더 DB 변경 전체에 적용한다.
