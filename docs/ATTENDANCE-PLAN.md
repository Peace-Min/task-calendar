정한 날: 2026-10-29(사용자). 상태: 구현과 QA 완료(2026-10-29, `f368ec8`), 같은 날 사용자 피드백 반영(§8). 아직 배포 안 함. QA 기록은 §7, §8.
시안: `dist/proto/attendance-full.html`(보고 창 내용), `dist/proto/attendance-panel.html`(불러오기 패널). 둘 다 git 밖(dist/)이다.
이전 작업: Codex 브랜치 `codex/attendance-calendar-design`(2026-10-26~27). 운용 결정(회사 먼저, DB 원자 저장)만 가져오고 화면과 C# 코드는 가져오지 않는다. 화면은 사용자가 마음에 들지 않았고, C# 은 화면 문서 구조(AttendanceDocument)에 묶여 있다.

## 1. 결정

### 결정 9. 회사 보고가 성공한 뒤에만 DB 에 원자 저장한다 (2026-10-26, 2026-10-29 보완)
- 순서: 입력 확정, 처리 중 입력과 연속 클릭 잠금, 회사 보고, 성공 확인(되읽기 검증 vr==1), 그 내용 그대로 `cal_report_daily` 1행과 `cal_report_hours` N행을 한 트랜잭션으로 저장, 커밋 확인 뒤에만 완료 안내와 창 닫기.
- 회사 실패, 회사 성공 판정 불가, 회사 성공 뒤 DB 실패는 모두 같은 안내 **"처리를 완료하지 못했습니다. 다시 시도해 주세요."** 를 띄우고 창과 입력을 그대로 둔다. 재시도는 늘 회사 보고부터 다시 한다.
- 하지 않는 것: 회사 요청 전 DB 저장, DB 만 다시 저장하기, 백그라운드 재시도, 부팅 때 자동 재전송, 회사와 DB 자동 대조.
- 회사에만 반영되고 DB 저장이 실패한 상태는 허용한다(사용자가 다시 보내면 둘 다 덮어쓴다).
- **보완(2026-10-29)**: 처음 결정 때는 작성 중 글을 로컬에 저장하지 않기로 했다. 사람에 따라 일간보고가 30~45줄로 길어서, 쓰던 글이 날아가면 쓸 맛이 나지 않는다는 이유로 바꾼다. **작성 중인 글은 이 PC(localStorage)에 자동 임시 저장한다.** 회사 보고와 DB 저장이 둘 다 성공하면 지운다. 임시 저장은 글을 살려 두기만 하고 아무것도 자동으로 보내지 않는다. DB 에는 여전히 회사 성공 뒤에만 쓴다.
- 기존 보고서 모달의 일간 전송도 같은 호스트 경로를 쓰므로 함께 이 순서를 따른다(지금은 회사 성공을 먼저 알리고 DB 는 뒤에서 10, 30, 60초 재시도한다. 이것을 없앤다). 주간은 이번에 바꾸지 않는다.

### 결정 10. 내용은 회사 양식 한 칸, 초안은 과제별 불러오기 (2026-10-29)
- Codex 브랜치의 "과제명 고정, 과제별 칸"(구 결정 10)을 대신한다.
- 내용은 회사 근태관리처럼 한 칸이고 자유롭게 고친다. 과제명도 고칠 수 있다.
- 오른쪽 불러오기 패널에서 과제를 체크하고 **← 불러오기**를 누르면 왼쪽이 그 내용으로 채워진다. 그 뒤로는 왼쪽에서 고친다.
- 가져오기 출처는 둘(2026-10-29 피드백으로 바꿈, §8): **캘린더**(고른 날짜의 일정, 할 일, 공수)와 **근태관리**(고른 날짜에 회사 근태관리에 등록된 일간보고, 읽기만). 날짜는 아무 날이나 고른다(처음 값은 보는 날짜).
- 머리 줄은 기존 보고서와 같은 `[과제명] : 시간`(시간 없으면 `[과제명]`). 줄 서식(머리기호, 들여쓰기, 설명 줄)은 기존 보고서 생성 함수와 설정을 그대로 쓴다.
- 보고 기록용 과제별 시간은 보낼 때 글의 머리 줄에서 읽는다. `[과제명] : 5` 와 `[과제명] 5` 둘 다 받는다. 0 초과 24 이하만 기록한다. `cal_report_hours` 는 과제명을 글자 그대로 저장하므로(cat_no 는 늘 NULL) 내 과제에 없는 이름도 그대로 기록된다.

### 결정 11. 위젯은 따로 뜨는 "근태 창", 브라우저는 화면 전환 (2026-10-29)
- 위젯: 관리 창과 같은 운영체제 창(AppWindow 의 새 종류 Attend). 크기를 끌어 바꾸고 최대화하며 크기와 위치를 기억한다. 종류마다 창은 하나다.
- 갱신(2026-11-02): 근태 창은 닫으면 숨기고 다시 열 때 payload 만 넣는다(`WinKind.ReuseOnClose`, docs/WINDOW-INPAGE.md). 처음 열 때는 호스트가 "불러오는 중"을 보인다.
- 브라우저: 따로 창을 띄울 수 없으므로 근태 탭 안에서 달력이 보고 화면으로 바뀐다(회사 근태관리도 화면 전환이다). 보고 화면 내용은 하나로 만들고 담는 그릇만 다르다.
- 브라우저는 지금 회사 전송을 못 한다(`BrowserPlatform.submitDaily` = 직접 입력 안내). 나중에 API 서버를 두면 그 어댑터만 바꾼다. 임시 저장은 브라우저에서도 같은 localStorage 방식을 그대로 쓴다.

## 2. 화면

### 2.1 상단 탭
- `#pcTabs` 에 세 번째 탭 **근태**(`data-pctab="attend"`)를 더한다. 개인, 과제, 근태.
- `pcSetTab` 은 지금 두 값이다. 세 값으로 넓히고 `body.at-on` 으로 근태 화면을 보이고 개인 캘린더 영역을 숨긴다(`pc-on` 과 같은 방식, DOM 은 붙였다 떼지 않는다). 마지막 탭 기억(`tc_pcal:<loginId>`)도 세 값을 받는다. 열람 창, 관리 창, 근태 창 안에서는 탭 줄이 없다(지금처럼).

### 2.2 근태 달력(탭 화면)
- 개인 캘린더와 같은 달력 격자와 색(주말, 공휴일, 오늘 표시). 월 이동은 개인 캘린더 위쪽 이동과 같은 모양.
- 칸: 근태 표시(회사 달력과 같게 `야근(+2시간)`, `정근`, `반차` 처럼 근태 이름 + 초과가 있으면 `(+n시간)`)와 보고 글. 긴 글은 6줄에서 자르고, 마우스를 올리면 전체가 뜬다.
- 데이터는 DB `cal_report_daily`(이 앱으로 보낸 보고)다. **회사 사이트에서 직접 쓴 보고는 여기 없다.** 그래서 빨간 "미보고" 표시는 하지 않는다(앱을 막 쓰기 시작한 사람에게 거짓 경고가 된다).
- 작성 중 임시 저장이 있는 날은 `✎ 작성 중` 표시.
- 위쪽 요약 줄: 이 달에 앱으로 보고한 날 수, 초과 합계.
- 날짜를 누르면 보고 창(위젯) 또는 보고 화면(브라우저)이 그 날짜로 열린다.

### 2.3 보고 화면(창 안 내용, 브라우저 화면 전환 내용 공통)
- 머리: 제목 "근태 보고"(보기 화면은 "근태 보기"), 날짜와 **‹ ›**(전날, 다음날, 보기 화면에서도 된다), 오른쪽 **가져오기 패널 접기/펼치기**. 브라우저에서는 왼쪽에 **← 근태 달력**.
- 왼쪽: 근태(`ATTEND_STATUS` 그대로, **미기록 없음**. 기본값은 보고한 값, 없으면 그날 개인 캘린더 근태 `getAttendance`, 그것도 없으면 정근), 초과시간(없음, +1~+11시간). 그 아래 내용 칸이 남는 높이를 다 쓴다. "회사 달력 표시" 미리 보기는 없앴다(§8).
- 내용 칸 아래 상태 줄: 줄 수, 과제 수와 합계 시간(머리 줄에서 읽은 값), 임시 저장 시각.
- 오른쪽 가져오기 패널(제목 "가져오기"):
  - 출처 `[캘린더] [근태관리]`와 날짜 칸(아무 날짜, 처음 값은 보는 날짜. 날짜를 넘기면 다시 보는 날짜).
  - 캘린더: 고른 날짜의 개인 캘린더 기록(보는 날짜면 payload 의 것, 다른 날짜면 근태 창은 메인 창에 청한다, §3.2). 옵션: 포함 항목(일정, 할 일), 과제(기록 없는 과제 제외, 기본 켬), 표시(설명 포함). 옵션은 패널 목록만 바로 바꾸고 왼쪽은 불러오기를 눌러야 바뀐다.
  - 근태관리: 고른 날짜에 회사 근태관리에 실제로 등록된 일간보고를 읽기만 한다(`netcusWeekMerge`, 하루짜리 기간). 글은 머리 줄 `[과제명] ...`로 나눠 카드로 보인다(첫 머리 줄 앞의 글은 "머리 줄 없는 글" 하나). 줄 앞 들여쓰기는 그대로 두고 `&nbsp;`, U+00A0 은 공백으로 바꾼다. 읽는 동안은 안내를 보이고 회사에 보고, 출처와 날짜 바꾸기를 잠근다. 실패는 갈래별 안내(로그인 정보 없음, 확인 안 됨, 로그인 실패, 바쁨, 세션 만료, 그 밖)와 [다시 읽기], 글이 없으면 "이날 근태관리에 등록된 보고가 없습니다.". 같은 날짜는 다시 읽지 않는다(실패했거나 그날 보고가 성공하면 다시 읽는다). 브라우저는 "위젯에서만" 안내.
  - 과제 카드: 체크박스, 과제 이름, 건수(캘린더) 또는 시간(근태관리), 줄 미리 보기. 위에 "과제 n / m개 선택", 전체 선택, 전체 해제.
  - **← 불러오기**: 체크한 과제로 왼쪽을 **묻지 않고 바로** 바꾼다(덮어쓰기 확인은 없앴다, §8). 바뀌기 전 글은 임시 저장 흐름 그대로다.
- 아래: 상태 문구, 복사, 닫기, **회사에 보고**.
- 처음 열 때: 임시 저장이 있으면 쓰기 화면으로 그것을 열고 "HH:MM 에 임시 저장된 글을 이어서 엽니다 [버리고 처음 상태로]". 없으면 보고한 날(payload.saved)은 **보기 화면**, 아니면 쓰기 화면에 캘린더 출처 기본 체크로 한 번 불러온 글.
- **보기 화면**(읽기 전용, 회사 근태관리의 하루 보기처럼): 날짜, 근태 표시(`ATTEND_STATUS` 이름, 초과가 있으면 `(+n시간)`), 보낸 시각, 내용(`&nbsp;` 는 공백으로). 아래 **[닫기] [수정]**. [수정]은 보고한 글과 근태, 초과시간을 채운 쓰기 화면으로 바꾸고 가져오기 패널도 쓸 수 있다. 보기 화면은 고친 것이 없는 상태로 본다(닫기, Esc, 탭 이동이 묻지 않는다). 브라우저도 같은 보기 화면을 근태 탭 안에서 쓴다(← 근태 달력).

### 2.4 글 지키기
- **닫을 때 묻지 않는다(2026-10-30 사용자, 일간과 주간 모두).** 닫기, 창의 X, Esc, [목록], 브라우저의 ← 근태 달력과 탭 이동은 임시 저장을 바로 쓰고 그대로 떠난다. 다시 열면 이어서 쓴다. 막는 것은 보내는 중 하나뿐이다(닫으면 보고 결과를 받을 화면이 없다). 예전의 "작성 중인 내용이 있습니다 [계속 쓰기] [닫기]" 창은 없앴다(그 창의 [닫기]도 임시 저장 뒤 닫기라 결과가 같았다).
- 임시 저장: 입력 1초 뒤 저장. 키 `tc_attDraft:<who>:<YYYY-MM-DD>`(who 는 보고서 초안과 같은 규칙), 값 `{v:1, text, status, overtime, savedAt}`. 14일 지난 것은 열 때 지운다. 처음 상태와 같아지면 지운다. 읽기와 쓰기는 함수 몇 개로만 거친다(나중에 서버 저장으로 바꿀 때 그 함수만 고친다).
- 날짜를 넘기거나(‹ ›, 메인 창에서 다른 날짜 클릭) 창을 닫을 때는 먼저 임시 저장을 바로 쓴다.
- 보내기 직전에도 임시 저장을 쓴다. 성공(회사와 DB 모두)하면 지우고, 실패하면 둔다.

### 2.5 보내기
- 내용이 비면 막는다. 처리 중에는 입력과 단추를 잠근다.
- payload 는 기존 보고서와 같은 `Platform.report.submitDaily`. `fields.content` 는 각 줄의 앞 공백을 `&nbsp;` 로 바꾼 글(기존 `buildReportText('&nbsp;')` 과 같은 규칙), `fields.status`(고른 근태 코드. 이 화면에는 미기록이 없어 null 을 보내지 않는다. 보고서 창 레일의 미기록은 그대로다), `fields.overtime`, `hours` 는 머리 줄에서 읽은 `[{name, hours}]`.
- 성공(이 화면이 보낸 것의 `__netcusResult(true)`): 창을 닫지 않고 그날 **보기 화면**으로 바꾼다(보낸 글, 근태, 보낸 시각, 성공 문구). 임시 저장은 지운다. 메인 창의 근태 달력과 개인 캘린더의 그날 근태(`setAttendance`)를 갱신한다.
- 실패: 결정 9 의 공통 안내, 창과 입력 유지.
- 보고한 글을 다시 열 때는 `&nbsp;` 를 공백으로 되돌린다.

## 3. 호스트(C#)와 명령 계약

### 3.1 근태 창 종류 `WinKind.Attend`(widget/AppWindow.cs)
- Url `https://tcapp.local/index.html?win=attend`, 제목 "근태 보고", 최소 720x520, 처음 1200x860, 크기 기억 자리 `WidgetSettings.Attend`, ReqPrefix `"tw:"`, ReadyCmd `attendWinReady`, OpenFn `__attendWinOpen`, ActivatedFn `__attendWinActivated`, GetsCatalog false, AskBeforeClose true.
- 로그아웃이나 계정 전환 때 관리 창과 같이 닫는다.

### 3.2 명령
| 명령 | 보내는 곳 | 하는 일 | 회신 |
|---|---|---|---|
| `attendOpen {payload}` | 메인 창만 | `ShowWin(WinKind.Attend, payload)`. 이미 떠 있으면 `__attendWinOpen(payload)` 후 앞으로 | `{ok}` |
| `attendWinReady` | 근태 창 | 준비 알림(대기 중인 payload 를 넘긴다) | 없음 |
| `attendNav {date, refresh}` | 근태 창 | 메인 창에 `window.__attendNavFromWin(date, refresh)` 를 부른다. 메인이 payload 를 다시 만들어 `attendOpen` 을 보낸다 | 없음 |
| `reportDailyList {from, to}` | 메인, 근태 창 | `ReportDb.ListDailyAsync`: 그 기간 `cal_report_daily` 행 `[{date:'YYYY-MM-DD', status, overtime, content, sentAt}]` | `{ok, rows}` |
| `netcusSubmit` | 메인, 근태 창 | 지금 그대로 + 결정 9 순서 | 결과는 알림 |
| `attendSourceReq {date}` | 근태 창 | 가져오기 캘린더(다른 날짜). 날짜를 `ReportDb.TryParseYmd` 로 확인하고 메인 창 `window.__attendSourceFor(date)` 를 JSON 인자로 부른다 | 없음(아래 push 로 온다) |
| `attendSourcePush {date, source}` | 메인 창만 | 메인 창이 그 날짜로 만든 `source`(payload 의 source 와 같은 모양: rows, hours, fmt). 날짜를 다시 확인하고 source 가 객체일 때만 `{date, source}` 를 JSON 으로 다시 써서 근태 창 `window.__attendSource(...)` 로 넘긴다(근태 창이 없으면 버린다) | 없음 |
| `netcusWeekMerge {reqId, from, to}` | 메인, 근태 창 | 회사 근태관리 일간보고를 **읽기만**(주간보고 병합과 같은 길, 31일 상한). 근태 창은 하루(`from = to`)로 쓴다. 회신은 `tw:` 번호로 근태 창에 간다 | `{ok, error, days:[{date, content, ok}]}` |

- 근태 창 허용 목록(웹 `ATTENDWIN_CMD`, 호스트 `AttendWinCommands`): `attendWinReady`, `attendNav`, `reportDailyList`, `netcusSubmit`, `attendSourceReq`, `netcusWeekMerge`. 양쪽 목록이 같아야 한다(시험). `attendSourcePush` 는 메인 창만 보내므로 목록에 없다.
- 알림: `__netcusProgress`, `__netcusResult` 는 메인 창과 근태 창 모두에 보낸다(각 창은 자기가 보낸 요청일 때만 반응). DB 저장까지 성공하면 호스트가 `__reportDailySaved({date, status, overtime})` 를 두 창 모두에 보낸다.

### 3.3 payload(메인 창이 만든다. 근태 창은 내 달력 데이터를 읽지 않는다)
```
{ v:1, date:'YYYY-MM-DD', me:{userId, loginId, name},
  saved: {status, overtime, content, sentAt} | null,   // 그날 DB 보고(메인 창이 읽어 둔 것). 있으면 보기 화면으로 연다
  attend: '<그날 개인 캘린더 근태 코드>' | '',
  source: { rows:[{key, name, titles:[...], titleMeta:[{kind, details...}]}],  // collectReportData(date,date,{event:true,todo:true,desc:true})
            hours:{ <key>: <number> },                // reportDailyHours
            fmt:{ mkSpec, indent } },                 // reportMarkerSpec(), 일간 서식 설정
  refresh: false }
```
- 근태 창은 받은 rows 를 옵션(일정, 할 일, 설명, 기록 없는 과제 제외)으로 걸러 `reportRowHead` 와 `reportRowBodyText` 로 글을 만든다(같은 HTML 이라 같은 함수).
- `refresh:true`(창이 앞으로 올 때 `__attendWinActivated` 가 `attendNav` 로 요청)면 패널 출처만 바꾸고 왼쪽 글은 건드리지 않는다.
- 가져오기 캘린더의 다른 날짜는 `attendSourceReq` 와 `attendSourcePush` 중계로, 근태관리는 근태 창이 `netcusWeekMerge` 로 직접 읽는다. `reportDailyList` 는 근태 달력(메인 창)과 보고한 날 열기에만 쓴다.

### 3.4 결정 9 순서(widget/NetcusService.cs, MainWindow.xaml.cs, OfflineHost.cs)
- `INetcusHost.SaveDailyReport` 를 `Task<bool>` 로 바꾸고 vr==1 에서 **await** 한 뒤 `NetcusResult(stored, stored ? 성공 문구 : 공통 실패 문구)`.
- 일간의 백그라운드 재시도(`SaveReportRecordWithRetryAsync("daily", …)`)와 그 실패 알림 `__reportRecordFailed`(daily)를 없앤다. 주간은 그대로.
- 기존 보고서 모달은 실패 문구를 받으면 지금처럼 실패로 보인다(초안은 지우지 않는다).

## 11. 가져오기 서식과 날짜 검사 (2026-10-29 사용자)
- **가져오기 서식**: 캘린더 옵션에 서식 줄(머리기호, 들여쓰기 0~6단). 목록은 보고서 창 `#rptMarker` 를 복제한다. 처음 값은 payload `source.fmt`(보고서 창 일간 서식), 고르면 `tc_attFmt:<who>` 에 기억한다. 보고서 창 설정은 바꾸지 않는다. 머리기호 표는 `reportMarkerSpecFor(key, custom)` 로 떼어 냈다(`reportMarkerSpec` 은 그것을 부른다).

## 12. 과제 블록 (결정 12, 2026-10-29 사용자)

### 12.1 화면(근태 창 왼쪽만 바뀐다)
- 한 칸 글(`#atText`) 대신 **과제 블록 목록**. 블록 = 머리(색 점, 과제명 🔒, 시간 숫자 칸, ▲ ▼ ✕) + 내용 칸(자유 글, 쓰는 만큼 늘어난다).
- **과제명**: 글자가 아니라 표시다. 편집 창에서 바꿀 수 없다. 블록은 과제 하나에 하나(같은 과제 두 블록 금지).
- **[+ 과제 추가]**: 내 캘린더 과제 목록에서 검색해 고른다(이미 있는 과제는 흐림). 맨 아래 **[+ 캘린더에 새 과제 만들기]**: 위젯은 메인 창의 과제 창(`openCatModal`)을 연다(근태 창 → 호스트 → 메인 창). 만들고 근태 창으로 돌아오면 새로고침으로 목록이 바뀐다. 브라우저는 같은 화면에서 과제 창을 연다.
- **시간**: 0 이상 24 이하, 0.5 단위 숫자 칸. 새 블록은 0.
- **[글로 보기]**: 회사로 나갈 조립 결과를 읽기 전용 한 칸으로 보인다(복사 가능). 다시 누르면 블록으로.
- 근태, 초과시간, 날짜 이동, 임시 저장, 닫기 질문, 보낸 시각, [인트라넷에서 확인], 상태 줄(과제 수, 합계)은 그대로.
- 보내기 단추 이름은 **보고**(보내는 중 "보고하는 중…"). 2026-10-29 사용자.

### 12.2 보내기 규칙
- 조립: 블록 순서대로 `[과제명] : 시간` + (내용이 있으면) 줄바꿈 + 내용(끝 공백 정리), 블록 사이 빈 줄 하나. 줄 앞 공백은 지금처럼 `&nbsp;`.
- 시간 표기: 정수는 정수(`6`), 소수는 그대로(`2.5`).
- **막는 것**(보내지 않고 그 블록을 빨갛게, 첫 블록으로 이동): 과제가 정해지지 않은 블록, 내용이 있는데 0시간, 시간이 범위 밖, 블록이 하나도 없음.
- 빈 과제(내용 없음, 0시간)는 `[과제명] : 0` 으로 보낸다. 보고 기록 공수(`cal_report_hours`)에는 0 을 남기지 않는다(지금 `HoursInDomain` 그대로).
- hours payload 는 글에서 읽지 않고 블록에서 바로 만든다(0 초과만).
- 합계 검사(정근 8 등)는 하지 않는다.

### 12.3 가져오기
- 출처: **[캘린더] [이전 보고]**. 인트라넷 불러오기(`netcusWeekMerge` 하루 읽기)는 근태 창에서 없앤다. 호스트 명령과 허용 목록의 `netcusWeekMerge` 는 근태 창 목록에서 뺀다(주간보고 병합은 메인 창에서 그대로 쓴다).
- 캘린더: 지금과 같다(포함 항목, 기록 없는 과제 제외, 설명 포함, 서식, 과제별 체크). 불러오기는 체크한 과제를 블록으로 바꾼다. 시간 칸 = 그날 공수표 값(없으면 0), 내용 = 지금 `atCalBlock` 의 본문 부분(서식 적용). 기록 없는 과제 제외를 끄면 빈 과제도 0시간 블록이 된다.
- 이전 보고: 고른 날짜의 이 앱 보고 기록(`reportDailyList` 하루). 글을 블록으로 되살린다: 줄이 정확히 `[이름] : 숫자` 이고 이름이 캘린더 과제명이면 머리, 그 밖은 앞 블록의 내용. 첫 머리 앞의 글이나 캘린더에 없는 이름의 머리는 **과제 미정 블록**(빨강, 과제 고르기 칸)이 되고 원래 머리 줄은 고르면 지운다. 블록 방식 이전에 보낸 자유 형식 글은 대부분 미정 블록 하나가 된다.
- 위젯 전용(브라우저는 안내).

### 12.4 저장과 호환

- 보고한 날을 열면 `p.saved.content` 를 이전 보고와 같은 규칙으로 블록으로 되살린다. 처음 상태(`ATE.base`)와 고침 판단(`atDirty`)은 블록 배열 비교.
- DB 구조, 호스트 저장 경로는 바뀌지 않는다.

## 13. 주간보고 (결정 13, 2026-10-29 사용자)

시안: `dist/proto/attendance-weekly.html`(사용자와 여섯 번 다듬음). 기존 인트라넷 작성 흐름은 사용자 녹화(목록 → [작성] → 기간 고르기 → 제목 자동 → 진행사항, 과제투입시간, 차주계획 쓰기 → [임시저장]/제출)에서 확인했다.

### 13.1 화면
- **근태 탭 머리에 [일간][주간]**. 일간 = 지금 근태 달력. 주간 = 목록. 마지막으로 고른 쪽을 기억한다.
- **주간 목록**(첫 화면): 번호, 제목, 기간(10/26 ~ 11/1), 상태(**작성 중** = 이 PC 임시 저장이 있음, **완료** = 이 앱으로 보고한 기록이 DB 에 있음), 날짜(보고한 날, 없으면 임시 저장 날). 최근이 위. 오른쪽 위 **[작성]** = 이번 주(이미 있으면 그 주를 연다). 목록은 이 앱으로 쓴 주만 보인다(인트라넷에 직접 쓴 주는 [인트라넷에서 확인]으로 본다).
- **주간 편집**(위젯은 근태 창의 주간 모드, 브라우저는 화면 전환): 머리 [← 주간 목록](잘 보이는 단추) ‹ 제목 (기간) › [전체 초기화]. 그 아래 한 줄: 기간 단추(주 고르기 달력), 제목 칸.
- 표 네 줄(왼쪽 항목명): **진행사항**(과제 블록: 과제명 글자, 내용 자유, ✕, [+ 과제 추가], 캘린더 과제 순서 자동 정렬), **과제투입시간**(진행사항 블록의 과제마다 숫자 칸 0~168, 0.5, 2열, 아래 합계), **차주계획**(과제 블록), **회의내용**(자유 글).
- 오른쪽 패널 [미리보기][가져오기]. 미리보기는 **인트라넷 주간보고 폼 모양 그대로**(테마와 상관없이 흰 바탕, 회색 항목칸, 파란 테두리 칸, 굴림체; 기간, 제목, 진행사항, 과제투입시간, 미처리사항(빈칸), 차주계획, 문제점 및 건의사항(빈칸), 회의내용). 가져오기는 두 단추: **← 이번 주 일간 보고**(진행사항, 과제투입시간), **← 지난주 차주계획**(차주계획). 문구는 짧게.
- 하단: 상태 줄, [닫기], [보고]. 복사 단추는 없다.
- [← 주간 목록] 같은 아이콘, 문구 다듬기는 구현 중 UI 검토로 보완한다(사용자 요청).

### 13.2 규칙
- 한 주: 2026-11-02 갱신(공용 달력, docs/CALENDAR-COMMON.md). 달력 한 주 = 일~토, 회사 보고 기간 = 그 줄의 월~토(period_start 는 월요일, period_end 는 토요일). 기간 단추의 달력은 일요일 시작이고 보고 있는 달의 월~토 날짜를 누르면 그 줄을 고른다(일요일 칸, 앞뒤 달 날짜는 막힘).
- 제목: 달력에서 고르면 **그 달 달력의 몇째 줄**(`n월 m째주`). 고르지 않고 열면(목록, [작성], ‹ ›) 월요일이 든 달에서 그달 1일이 든 주를 첫째주로(`calWeekTitle`). 제목 칸은 읽기 전용이라 손으로 고치지 않는다(2026-11-02).
- 과제투입시간 목록 = 진행사항 블록의 과제(빼면 같이 빠지고, 더하면 그 주 일간 합계로 칸이 생긴다). 회사로는 `[과제] : 시간` 줄들 + `-----` + `합계 : n`.
- 진행사항, 차주계획 조립: 블록마다 `[과제명]` 줄 + 내용(비면 `-`), 블록 사이 빈 줄 하나. 과제명은 캘린더 과제에서만(일간 결정 12 와 같은 원칙).
- 가져오기 일간: 그 주(월~토) 이 앱 일간 보고에서 과제별 내용 줄을 모으고(같은 줄은 한 번), 시간만 있는 과제(휴가 등)도 블록으로 넣고, 과제투입시간을 과제별 합계로 채운다. 일간 글은 블록 규칙(`atParseReport`)으로 읽는다.
- 가져오기 지난주 차주계획: 지난주(월요일 -7) 이 앱 주간 기록의 차주계획을 `[과제명]` 머리로 나눠 차주계획 블록으로(캘린더에 없는 이름은 과제 미정 블록).
- [작성]으로 처음 여는 주는 두 가져오기를 한 번 해 둔다. 완료한 주는 DB 기록으로 연다. 임시 저장이 있으면 그것으로 연다(안내 없이, 일간과 같다).
- 막는 것(보내지 않고 빨간 블록): 과제 미정 블록, 진행사항 블록이 하나도 없음. 시간 합계 검사는 하지 않는다.

### 13.3 보내기와 저장

- 채운 뒤 기록: `cal_report_weekly`(`SaveWeeklyAsync`)에 회의내용을 더해 저장(지금처럼 재시도). 성공하면 그 주 임시 저장을 지우고 목록 상태가 완료.

## 14. 주간 자유 글과 MM 원천 (결정 14, 2026-10-30 사용자)

시안: `dist/proto/attendance-weekly.html`(2026-10-30 판).

### 14.1 화면 (13.1 을 바꾼다)
- **진행사항**, **차주계획**: 과제 블록 대신 **자유 글 한 칸**(쓰는 만큼 늘어난다, 최소 높이를 넉넉히). 과제명 규칙이 없다(PM 처럼 담당자 배치표, `[과제](~'28/12)` 같은 표기도 그대로).
- **과제투입시간**: 진행사항과 **따로 움직이는 목록**. 줄 = 색 점, 과제명(글자, 고칠 수 없음), 시간 숫자 칸(0~168, 0.5), ✕(빼기). 아래 [+ 과제 추가](캘린더 과제 검색 목록에서만, 이미 있는 과제는 흐림)와 합계. 캘린더 과제 순서로 정렬. 새로 더한 과제의 시간은 그 주 일간 합계(없으면 0).
- 회의내용, 목록, 머리, 기간과 제목 규칙, 미리보기(인트라넷 폼 모양), 임시 저장, [전체 초기화]는 그대로.

### 14.2 가져오기
- **← 이번 주 일간 보고**: 과제투입시간 목록과 시간을 그 주 일간 합계로 **바꾸고**, 진행사항 칸에 일간 내용을 `[과제명]` 머리로 정리한 **초안 글을 넣는다**(덮어쓴다, 묻지 않는다. 불러오기 원칙과 같다).
- **← 지난주 차주계획**: 지난주 주간 기록의 차주계획 **글 그대로** 차주계획 칸에 넣는다(덮어쓴다).

### 14.3 보내기와 저장
- 조립: 진행사항(`endwork`)과 차주계획(`planwork`)은 칸의 글 그대로(줄 앞 공백 처리는 지금과 같다). 과제투입시간(`content`)은 `[과제명] : 시간` 줄들 + `-----` + `합계 : n`(지금과 같다).
- 막는 것: 과제투입시간이 하나도 없음(과제 0개). 진행사항이 비어도 막지 않는다(사용자 판단). 과제 미정 개념은 없어진다(과제명을 고르기만 하므로).
- 저장: `cal_report_weekly` 한 행(지금과 같음, 회의내용 포함) + **`cal_report_weekly_hours` 과제별 줄**을 **한 트랜잭션**으로. 다시 보내면 그 주의 줄을 지우고 새로 넣는다(일간 `SaveDailyAsync` 와 같은 방식). 0 시간 줄은 남기지 않는다.
- 웹이 hours 를 구조로 넘긴다(`[{name, projectUid, hours}]`, 글을 파싱하지 않는다). `projectUid` 는 공식 과제(`db-<uid>`)면 uid, 개인 과제는 빈 값.

### 14.4 DB (구조 20 에 합친다)
- 새 표 `cal_report_weekly_hours`:
  - `user_id SMALLINT UNSIGNED`, `period_start DATE`, `line_no SMALLINT UNSIGNED`, `task_name VARCHAR(200)`, `project_uid CHAR(36) NULL`(공식 과제 id, 개인 과제 NULL), `hours DECIMAL(5,2)`(0 초과 168 이하 CHECK).
  - PK `(user_id, period_start, line_no)`, FK `(user_id, period_start)` → `cal_report_weekly` ON DELETE CASCADE ON UPDATE CASCADE(일간 `fk_crh_daily` 와 같은 결), 집계용 인덱스 `(project_uid, period_start)` 와 `(user_id, period_start)`.
- v20 조각(`v20-weekly-meeting.sql`)에 이 표 만들기를 더한다(표가 없을 때만). 구조 번호는 20 그대로.
- **이 PC 개발 DB 는 이미 20** 이라 v20 이 건너뛴다. 늘어난 표만 만드는 일회용 SQL(`dist/rehearsal/apply-v20b-dev`)을 사용자가 직접 실행한다(어제와 같은 방식, 사본 리허설 뒤).
- **보고서 창의 [일간 작성] [주간 작성]은 입구만 숨긴다(2026-10-30 사용자 결정).** 보고서 창은 기간 취합으로 열린다. 그 코드와 시험은 기간 취합, 월간까지 근태 탭으로 옮겨 보고서 창을 없앨 때 한 번에 걷는다(기간 취합이 주간과 그리기 코드를 함께 써서 지금 걷으면 깨질 수 있다).
- **옛 주간 기록은 v20 이 모두 지운다(2026-10-30 사용자 결정).** 19 까지 보고서 창이 쓴 `cal_report_weekly` 행은 시간 줄이 없고, 근태 탭 전이라 사용자가 본 적도 없다. 원본은 인트라넷에 남는다. 19 에서 올릴 때 한 번만 지우고(20 이상은 건너뜀), 일간 기록은 건드리지 않는다(일간과 주간 사이 FK 없음). 되돌릴 수 없어 배포 전 백업(DB-RELEASE-OPS)이 전제다.
- 일간 표는 바꾸지 않는다. 앱 계정 권한(GRANT)과 스키마 보고서, 데모 DB, 스키마 시험을 함께 맞춘다.
