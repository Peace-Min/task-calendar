# 근태 탭과 근태 보고 창 기획

정한 날: 2026-10-29(사용자). 상태: 기획 확정, 구현 전.
시안: `dist/proto/attendance-full.html`(보고 창 내용), `dist/proto/attendance-panel.html`(불러오기 패널). 둘 다 git 밖(dist/)이다.
이전 작업: Codex 브랜치 `codex/attendance-calendar-design`(2026-10-26~27). 운용 결정(회사 먼저, DB 원자 저장)만 가져오고 화면과 C# 코드는 가져오지 않는다. 화면은 사용자가 마음에 들지 않았고, C# 은 화면 문서 구조(AttendanceDocument)에 묶여 있다.

## 1. 결정

### 결정 9. 회사 보고가 성공한 뒤에만 DB 에 원자 저장한다 (2026-10-26, 2026-10-29 보완)
- 순서: 입력 확정, 처리 중 입력과 연속 클릭 잠금, 회사 보고, 성공 확인(되읽기 검증 vr==1), 그 내용 그대로 `cal_report_daily` 1행과 `cal_report_hours` N행을 한 트랜잭션으로 저장, 커밋 확인 뒤에만 완료 안내와 창 닫기.
- 회사 실패, 회사 성공 판정 불가, 회사 성공 뒤 DB 실패는 모두 같은 안내 **"처리를 완료하지 못했습니다. 다시 시도해 주세요."** 를 띄우고 창과 입력을 그대로 둔다. 재시도는 늘 회사 보고부터 다시 한다.
- 하지 않는 것: 회사 요청 전 DB 저장, DB 만 다시 저장하기, 백그라운드 재시도, 부팅 때 자동 재전송, 회사와 DB 자동 대조.
- 회사에만 반영되고 DB 저장이 실패한 상태는 허용한다(사용자가 다시 보내면 둘 다 덮어쓴다).
- **보완(2026-10-29)**: 처음 결정 때는 작성 중 글을 로컬에 저장하지 않기로 했다. 사람에 따라 일간보고가 30~45줄로 길어서, 쓰던 글이 날아가면 쓸 맛이 나지 않는다는 이유로 바꾼다. **작성 중인 글은 이 PC(localStorage)에 자동 임시 저장한다.** 회사 보고와 DB 저장이 둘 다 성공하면 지운다. 임시 저장은 글을 살려 두기만 하고 아무것도 자동으로 보내지 않는다. DB 에는 여전히 회사 성공 뒤에만 쓴다.
- 기존 보고서 모달의 일간 전송도 같은 호스트 경로를 쓰므로 함께 이 순서를 따른다(지금은 회사 성공을 먼저 알리고 DB 는 뒤에서 10, 30, 60초 재시도한다. 이것을 없앤다). 주간은 이번에 바꾸지 않는다.

### 결정 10. 내용은 회사 양식 한 칸, 초안은 과제별 불러오기 (2026-10-29)
- Codex 브랜치의 "과제명 고정, 과제별 칸"(구 결정 10)을 대신한다.
- 내용은 회사 근태관리처럼 한 칸이고 자유롭게 고친다. 과제명도 고칠 수 있다.
- 오른쪽 불러오기 패널에서 과제를 체크하고 **← 불러오기**를 누르면 왼쪽이 그 내용으로 채워진다. 그 뒤로는 왼쪽에서 고친다.
- 불러오기 출처는 둘: **캘린더**(그날 일정, 할 일, 공수)와 **보고한 날짜**(앞서 보고한 날 하나를 골라 그 글).
- 머리 줄은 기존 보고서와 같은 `[과제명] : 시간`(시간 없으면 `[과제명]`). 줄 서식(머리기호, 들여쓰기, 설명 줄)은 기존 보고서 생성 함수와 설정을 그대로 쓴다.
- 보고 기록용 과제별 시간은 보낼 때 글의 머리 줄에서 읽는다. `[과제명] : 5` 와 `[과제명] 5` 둘 다 받는다. 0 초과 24 이하만 기록한다. `cal_report_hours` 는 과제명을 글자 그대로 저장하므로(cat_no 는 늘 NULL) 내 과제에 없는 이름도 그대로 기록된다.

### 결정 11. 위젯은 따로 뜨는 "근태 창", 브라우저는 화면 전환 (2026-10-29)
- 위젯: 관리 창과 같은 운영체제 창(AppWindow 의 새 종류 Attend). 크기를 끌어 바꾸고 최대화하며 크기와 위치를 기억한다. 종류마다 창은 하나다.
- 브라우저: 따로 창을 띄울 수 없으므로 근태 탭 안에서 달력이 보고 화면으로 바뀐다(회사 근태관리도 화면 전환이다). 보고 화면 내용은 하나로 만들고 담는 그릇만 다르다.
- 브라우저는 지금 회사 전송을 못 한다(`BrowserPlatform.submitDaily` = 직접 입력 안내). 나중에 API 서버를 두면 그 어댑터만 바꾼다. 임시 저장은 브라우저에서도 같은 localStorage 방식을 그대로 쓴다.

## 2. 화면

### 2.1 상단 탭
- `#pcTabs` 에 세 번째 탭 **근태**(`data-pctab="attend"`)를 더한다. 개인, 과제, 근태.
- `pcSetTab` 은 지금 두 값이다. 세 값으로 넓히고 `body.at-on` 으로 근태 화면을 보이고 개인 캘린더 영역을 숨긴다(`pc-on` 과 같은 방식, DOM 은 붙였다 떼지 않는다). 마지막 탭 기억(`tc_pcal:<loginId>`)도 세 값을 받는다. 열람 창, 관리 창, 근태 창 안에서는 탭 줄이 없다(지금처럼).

### 2.2 근태 달력(탭 화면)
- 개인 캘린더와 같은 달력 격자와 색(주말, 공휴일, 오늘 표시). 월 이동은 개인 캘린더 위쪽 이동과 같은 모양.
- 칸: 근태 표시(회사 달력과 같게 `야근(+2시간)`, `정근`, `반차` 처럼 근태 이름 + 초과가 있으면 `(+n시간)`)와 보고 글. 긴 글은 6줄에서 자르고, 마우스를 올리면 전체가 뜬다.
- 데이터는 DB `cal_report_daily`(이 앱으로 보낸 보고)다. **회사 사이트에서 직접 쓴 보고는 여기 없다.** 그래서 빨간 "미보고" 표시는 하지 않는다(앱을 막 쓰기 시작한 사람에게 거짓 경고가 된다).
- 작성 중 임시 저장이 있는 날은 `✎ 작성 중` 표시.
- 위쪽 요약 줄: 이 달에 앱으로 보고한 날 수, 초과 합계.
- 날짜를 누르면 보고 창(위젯) 또는 보고 화면(브라우저)이 그 날짜로 열린다.

### 2.3 보고 화면(창 안 내용, 브라우저 화면 전환 내용 공통)
- 머리: 제목 "근태 보고", 날짜와 **‹ ›**(전날, 다음날), 오른쪽 **불러오기 패널 접기/펼치기**. 브라우저에서는 왼쪽에 **← 근태 달력**.
- 왼쪽: 근태(`ATTEND_STATUS` 그대로, 기본값은 보고한 값, 없으면 그날 개인 캘린더 근태 `getAttendance`, 그것도 없으면 정근), 초과시간(없음, +1~+11시간), 옆에 "회사 달력 표시: 야근(+2시간)" 미리 보기. 그 아래 내용 칸이 남는 높이를 다 쓴다.
- 내용 칸 아래 상태 줄: 줄 수, 과제 수와 합계 시간(머리 줄에서 읽은 값), 임시 저장 시각.
- 오른쪽 불러오기 패널:
  - 출처 `[캘린더] [보고한 날짜]`. 보고한 날짜는 고르는 목록(최근 60일 안에 보고한 날, 기본은 가장 최근).
  - 캘린더일 때 옵션: 포함 항목(일정, 할 일), 과제(기록 없는 과제 제외, 기본 켬), 표시(설명 포함). 옵션은 패널 목록만 바로 바꾸고 왼쪽은 불러오기를 눌러야 바뀐다.
  - 과제 카드: 체크박스, 과제 이름, 건수(캘린더) 또는 시간(보고한 날짜), 줄 미리 보기. 위에 "과제 n / m개 선택", 전체 선택, 전체 해제.
  - **← 불러오기**: 체크한 과제를 왼쪽에 채운다. 왼쪽을 고친 뒤면 "왼쪽에서 고친 내용이 지워집니다 [덮어쓰기] [그만두기]".
- 아래: 상태 문구, 복사, 닫기, **회사에 보고**.
- 처음 열 때: 임시 저장이 있으면 그것을 열고 "HH:MM 에 임시 저장된 글을 이어서 엽니다 [버리고 처음 상태로]". 없으면 보고한 날은 보고한 글, 아니면 캘린더 출처 기본 체크로 한 번 불러온 글.

### 2.4 글 지키기
- 고친 내용이 있으면(처음 상태와 다르면) 바깥 클릭과 Esc 로 닫히지 않는다. 닫기, ×, 창 닫기 단추, 브라우저의 ← 근태 달력과 탭 이동은 "작성 중인 내용이 있습니다. 닫아도 이 PC 에 임시 저장되어 있어 다시 열면 이어서 쓸 수 있습니다 [계속 쓰기] [닫기]" 를 묻는다. 위젯 창은 AskBeforeClose 로 같은 질문을 한다.
- 임시 저장: 입력 1초 뒤 저장. 키 `tc_attDraft:<who>:<YYYY-MM-DD>`(who 는 보고서 초안과 같은 규칙), 값 `{v:1, text, status, overtime, savedAt}`. 14일 지난 것은 열 때 지운다. 처음 상태와 같아지면 지운다. 읽기와 쓰기는 함수 몇 개로만 거친다(나중에 서버 저장으로 바꿀 때 그 함수만 고친다).
- 날짜를 넘기거나(‹ ›, 메인 창에서 다른 날짜 클릭) 창을 닫을 때는 먼저 임시 저장을 바로 쓴다.
- 보내기 직전에도 임시 저장을 쓴다. 성공(회사와 DB 모두)하면 지우고, 실패하면 둔다.

### 2.5 보내기
- 내용이 비면 막는다. 처리 중에는 입력과 단추를 잠근다.
- payload 는 기존 보고서와 같은 `Platform.report.submitDaily`. `fields.content` 는 각 줄의 앞 공백을 `&nbsp;` 로 바꾼 글(기존 `buildReportText('&nbsp;')` 과 같은 규칙), `fields.status`(빈 값이면 null), `fields.overtime`, `hours` 는 머리 줄에서 읽은 `[{name, hours}]`.
- 성공: 위젯은 창을 닫고, 브라우저는 근태 달력으로 돌아간다. 메인 창의 근태 달력과 개인 캘린더의 그날 근태(`setAttendance`)를 갱신한다.
- 실패: 결정 9 의 공통 안내, 창과 입력 유지.
- 보고한 글을 다시 열 때는 `&nbsp;` 를 공백으로 되돌린다.

## 3. 호스트(C#)와 명령 계약

### 3.1 근태 창 종류 `WinKind.Attend`(widget/AppWindow.cs)
- Url `https://tcapp.local/index.html?win=attend`, 제목 "근태 보고", 최소 720x520, 처음 1200x860, 크기 기억 자리 `WidgetSettings.Attend`, ReqPrefix `"tw:"`, ReadyCmd `attendWinReady`, OpenFn `__attendWinOpen`, ActivatedFn `__attendWinActivated`, GetsCatalog false, AskBeforeClose true.
- 로그아웃이나 계정 전환 때 관리 창과 같이 닫는다.

### 3.2 명령
| 명령 | 보내는 곳 | 하는 일 | 회신 |
|---|---|---|---|
| `attendOpen {payload}` | 메인 창만 | `ShowWin(WinKind.Attend, payload)`. 이미 떠 있으면 `__attendWinOpen(payload)` 후 앞으로 | `{ok}` |
| `attendWinReady` | 근태 창 | 준비 알림(대기 중인 payload 를 넘긴다) | 없음 |
| `attendNav {date, refresh}` | 근태 창 | 메인 창에 `window.__attendNavFromWin(date, refresh)` 를 부른다. 메인이 payload 를 다시 만들어 `attendOpen` 을 보낸다 | 없음 |
| `reportDailyList {from, to}` | 메인, 근태 창 | `ReportDb.ListDailyAsync`: 그 기간 `cal_report_daily` 행 `[{date:'YYYY-MM-DD', status, overtime, content, sentAt}]` | `{ok, rows}` |
| `netcusSubmit` | 메인, 근태 창 | 지금 그대로 + 결정 9 순서 | 결과는 알림 |

- 근태 창 허용 목록(웹 `ATTENDWIN_CMD`, 호스트 `AttendWinCommands`): `attendWinReady`, `attendNav`, `reportDailyList`, `netcusSubmit`. 양쪽 목록이 같아야 한다(시험).
- 알림: `__netcusProgress`, `__netcusResult` 는 메인 창과 근태 창 모두에 보낸다(각 창은 자기가 보낸 요청일 때만 반응). DB 저장까지 성공하면 호스트가 `__reportDailySaved({date, status, overtime})` 를 두 창 모두에 보낸다.

### 3.3 payload(메인 창이 만든다. 근태 창은 내 달력 데이터를 읽지 않는다)
```
{ v:1, date:'YYYY-MM-DD', me:{userId, loginId, name},
  saved: {status, overtime, content} | null,           // 그날 DB 보고(메인 창이 읽어 둔 것)
  attend: '<그날 개인 캘린더 근태 코드>' | '',
  source: { rows:[{key, name, titles:[...], titleMeta:[{kind, details...}]}],  // collectReportData(date,date,{event:true,todo:true,desc:true})
            hours:{ <key>: <number> },                // reportDailyHours
            fmt:{ mkSpec, indent } },                 // reportMarkerSpec(), 일간 서식 설정
  refresh: false }
```
- 근태 창은 받은 rows 를 옵션(일정, 할 일, 설명, 기록 없는 과제 제외)으로 걸러 `reportRowHead` 와 `reportRowBodyText` 로 글을 만든다(같은 HTML 이라 같은 함수).
- `refresh:true`(창이 앞으로 올 때 `__attendWinActivated` 가 `attendNav` 로 요청)면 패널 출처만 바꾸고 왼쪽 글은 건드리지 않는다.
- 보고한 날짜 출처는 근태 창이 `reportDailyList` 로 직접 읽는다.

### 3.4 결정 9 순서(widget/NetcusService.cs, MainWindow.xaml.cs, OfflineHost.cs)
- `INetcusHost.SaveDailyReport` 를 `Task<bool>` 로 바꾸고 vr==1 에서 **await** 한 뒤 `NetcusResult(stored, stored ? 성공 문구 : 공통 실패 문구)`.
- 일간의 백그라운드 재시도(`SaveReportRecordWithRetryAsync("daily", …)`)와 그 실패 알림 `__reportRecordFailed`(daily)를 없앤다. 주간은 그대로.
- 기존 보고서 모달은 실패 문구를 받으면 지금처럼 실패로 보인다(초안은 지우지 않는다).

## 4. 범위 밖
- 회사 사이트에서 직접 쓴 보고 읽어 오기, 주간보고, DB 구조 변경(구조 19 그대로), 보고서 모달 일간 전송 없애기(그대로 둔다. 두 입구가 같은 회사 보고를 덮어쓴다), 다른 기기 사이 임시 저장 이어 쓰기.

## 5. 시험
- 웹(jsdom): 탭 세 값과 기억, 근태 달력 그리기(목록 회신 흉내), 근태 표시 문구, payload 로 초안 만들기(옵션 네 개), 머리 줄 시간 읽기(두 형식, 범위), 보고한 날짜 출처, 덮어쓰기 확인, 임시 저장(쓰기, 되살리기, 버리기, 14일 정리, 성공 시 지우기, 실패 시 남기기), 닫기 지키기(바깥, Esc, 닫기, 창 닫기 질문 `__winCloseRequest`), 보내기 payload(`&nbsp;`, hours, status null), 처리 중 잠금과 연속 클릭, 근태 창 모드 부팅(내 달력 부팅 안 함), 브라우저 화면 전환과 떠날 때 확인, 허용 목록.
- 호스트(정적 + 빌드): WinKind.Attend 값, 허용 목록 양쪽 일치, `attendOpen` 은 메인 창만, 결정 9(await 뒤 결과, daily 재시도 없음), 알림이 두 창에 감, `ListDailyAsync` SELECT(사용자와 기간으로 거름, 파라미터 바인딩).
- DB: `ListDailyAsync` 를 `zz_` 시험 DB 에서 실제로 읽기.
- 실제 위젯(QA): 근태 창 열기, 크기 기억, 날짜 이동, 닫기 질문, 임시 저장 되살리기, 보내기는 `Platform.report.submitDaily` 를 가로채 결과를 흉내 낸다. **회사 사이트에 실제로 보내지 않는다.**

## 6. 위키
- 새 페이지 "근태 보고": 근태 탭, 보고 창, 불러오기, 임시 저장, 회사 먼저 보내고 기록, 브라우저에서는 직접 입력.
- "보고서 회사 전송" 페이지: 일간 전송은 DB 저장까지 성공해야 성공으로 보인다는 한 줄.
