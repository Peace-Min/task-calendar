# 날짜 넘김: 오늘 표시 맞추기 (Fable 설계, 전면 재작성)

2026-11-13. 구현 전 설계다. 코드, 호스트, 시험은 아직 고치지 않았다.
줄 번호는 feat/db-app 083bab6 의 task-calendar-prototype.html 기준이다.

이 문서가 구현 기준이다(2026-11-13 확정). 같은 날 세 번 방향을 바꾼 끝의 최종안이다. 앞의 두 안(상태 따라가기와 입력 미룸을 갖춘 큰 안, 다시 그리기만 하는 단순판)은 버렸고 까닭은 "지나온 길"에 적었다. 최종안은 docs/CALENDAR-TODAY-HIGHLIGHT.md(코덱스)와 같은 방식이며, 이 문서는 거기에 대상 칸, 코드 모양, 시험 기준을 코드와 대조해 구체로 적은 것이다.

## 요약

**문제.** 달력은 그릴 때마다 PC 날짜를 읽어 오늘 칸에 표시를 붙인다. 앱을 켜 둔 채 자정을 넘기면 다시 그릴 계기가 없어 어제 칸에 표시가 남는다.

**범위.** 달력의 오늘 표시만 PC 날짜에 맞춘다. 고른 날, 보던 달과 주, 키보드 초점, 열린 창과 편집 값은 건드리지 않는다. 서버 조회, 알림, 호스트(C#), DB 는 범위 밖이다.

**방법.** 칸을 다시 그리지 않는다. 이미 그려진 칸에서 `today` 클래스와 읽어 주는 이름의 "오늘"만 옮긴다.

**계기는 둘이다.**

1. 다음 자정에 맞춘 타이머 하나.
2. 창이 다시 보이거나 포커스를 받을 때.

**크기.** 앱 코드 30줄 안팎, 기억할 상태는 타이머 손잡이 하나, 시험 파일 하나. 주기 확인은 없다.

**왜 이 방법인가.** 칸이 그대로 남으므로 클릭, 더블클릭, 끌기, 포커스, 열린 팝업과 부딪힐 일이 구조상 없다. 앞의 두 안이 복잡해진 원인(칸을 갈아 끼우는 순간의 클릭 보호)이 통째로 사라진다. 잘못돼도 최악은 표시가 안 옮겨지는 것이고, 그건 지금과 같은 상태다.

## 오늘에 기대는 곳

조사한 곳 전체다. 분류는 넷이다.

- A: 날이 바뀌면 낡는다. 이번에 고친다.
- A-: 날이 바뀌면 낡는다. 이번 범위 밖이다.
- B: 부를 때마다 새로 구한다. 이미 괜찮다.
- D: 사용자가 고른 값이거나 편집 중인 상태다. 바꾸면 안 된다.

### 오늘 표시(A, 이번에 고친다)

오늘 표시는 CSS 규칙 하나로 칠한다(341 `.cal-c.today .num`). 클래스는 `calCellCls`(5333)가 `o.today` 를 받았을 때만 붙인다.

| 화면 | 칸 | 날짜 속성 | 읽어 주는 이름 | 줄 |
|---|---|---|---|---|
| 개인 월간, 열람 월간, 나란히 보기 오른쪽 | `.cell` | `data-date` | 날짜 부분 뒤에 ", 기록 n건" 등이 붙는다 | 12081, 11916 |
| 개인 주간, 열람 주간의 머리 | `.cell.wr-hd` | `data-date` | 날짜 부분만 | 12147, 12149 |
| 과제 월간 | `.pc-day` | `data-date` | 날짜 부분 뒤에 ", 일정 n건" | 25033, 25036 |
| 과제 주간의 머리 | `.pc-whday` | `data-hdate` | 없음 | 25059 |
| 근태 일간 달력 | `.at-day` | `data-date` | 날짜 부분 뒤에 ", 보고함" 등 | 21445, 21449 |

**대상이 아닌 칸.** `.cal-c` 와 날짜 속성을 가졌지만 원래 오늘 표시가 붙지 않는 칸이다. 여기에 붙이면 새로 그린 화면과 달라진다.

탭 전환은 지금 코드로 이미 오늘 표시를 고친다. 다만 두 가지가 남는다.

- 켜져 있는 탭을 다시 누르면 개인 탭과 근태 탭은 아무것도 그리지 않는다. 과제 탭만 다시 그린다(24733 `pcRender()`).

## 감지

### 계기

| 계기 | 하는 일 |
|---|---|
| 자정 타이머 | 다음 자정을 먼저 예약하고, 표시를 맞춘다 |
| `visibilitychange`(보임), 창 `focus`, `pageshow` | 다음 자정을 다시 예약하고, 표시를 맞춘다 |
| `pagehide` | 예약을 지운다 |

누르기와 키 입력은 감시하지 않는다. 칸을 갈아 끼우지 않으므로 지킬 것이 없다.

### 비교할 상태가 없다

"마지막으로 본 오늘"을 기억하지 않는다. 표시 맞추기는 몇 번을 불러도 결과가 같다(오늘이 아닌 칸에서 떼고 오늘 칸에 붙인다). 그래서 계기가 올 때마다 그냥 부른다. 날짜가 앞으로 가든 뒤로 가든(시계를 되돌림) 같은 길이다.

비용은 그려진 달력 칸 수십 개를 한 번 훑는 것이다. 창 복귀마다 불러도 된다.

### 타이머

- 손잡이는 하나다. 걸기 전에 늘 지운다.
- 다음 자정은 `new Date(y, m, d + 1)` 로 구한다. 24시간을 더하지 않는다.
- 기다릴 시간은 "다음 자정까지 + 1초", 하한 1초다. 타이머가 벽시계보다 몇 밀리초 일찍 뜨면 아직 같은 날인데, 여유가 없으면 몇 밀리초짜리 예약을 되풀이한다.
- 창 복귀 때는 날짜가 같아도 다시 예약한다. 같은 날 안에서 PC 시각을 고쳤을 수 있고, 타이머는 벽시계가 아니라 흐른 시간만 세기 때문이다.
- 창마다 다른 여유(흩뜨리기)는 두지 않는다. 서버를 읽지 않으니 흩뜨릴 것이 없다.

### 덮지 못하는 틈

| 경우 | 결과 |
|---|---|
| 창이 숨어 있다(트레이) | 크로미움이 숨은 문서의 타이머를 늦춘다(길어야 1분). 숨어 있어 보이지 않고, 다시 보일 때 한 번 더 맞춘다 |
| 시계를 손으로 바꿈 | 다음 창 복귀나 타이머에서 맞는다 |
| 창이 계속 보인 채 절전으로 자정을 넘김 | 깨어난 뒤 타이머가 뜰 때 맞는다. 바로 뜨는지, 잠든 시간만큼 늦는지는 재지 않았다(열린 질문 5) |

호스트의 절전 복귀 이벤트를 쓰면 마지막 틈이 바로 닫히지만, 웹만으로 간다는 결정을 따른다.

## 반영

### 코드 모양

`todayYmd`(5283) 가까이에 둔다. 이름은 구현 때 정한다.

```js
//  오늘 표시 맞추기(docs/DAY-ROLLOVER-FABLE.md). 칸을 다시 그리지 않고 표시만 옮긴다.
//  대상은 원래 오늘 표시가 붙는 칸뿐이다. 주간 몸통 칸(wr-c, pc-wday)은 머리에만 표시가 있어 뺀다.
const DAY_CELLS = '.cal-c.cell:not(.wr-c)[data-date], .cal-c.pc-day[data-date], .cal-c.pc-whday[data-hdate], .cal-c.at-day[data-date]';
function dayMark(){
  const t = todayYmd();
  document.querySelectorAll(DAY_CELLS).forEach(el => {
    const ds = el.dataset.date || el.dataset.hdate, on = ds === t;
    if(el.classList.contains('today') === on) return;             // 이미 맞다
    //  이름에 쓸 글을 클래스보다 먼저 구한다. 여기서 던지면 클래스도 그대로라 다음 번에 이 칸을 다시 맞춘다
    //  (클래스를 먼저 바꾸면 다음 번은 "이미 맞다" 로 건너뛰어 색과 이름이 어긋난 채 남는다)
    const a = el.getAttribute('aria-label');
    const from = a ? calAria(ds, on ? '' : ds) : '', to = a ? calAria(ds, on ? ds : '') : '';
    el.classList.toggle('today', on);
    //  읽어 주는 이름은 날짜 부분만 바꿔 끼운다. 뒤에 붙은 글(기록 n건, 보고함)은 그대로
    if(a && a.startsWith(from)) el.setAttribute('aria-label', to + a.slice(from.length));
  });
}
let dayTimer = 0;
function dayArm(){
  clearTimeout(dayTimer);
  const n = new Date(), next = new Date(n.getFullYear(), n.getMonth(), n.getDate() + 1);
  dayTimer = setTimeout(dayTick, Math.max(1000, next - n + 1000));
}
function daySync(){ try{ dayMark(); }catch(e){ try{ console.warn('[day]', e); }catch(_){} } }
function dayTick(){ dayArm(); daySync(); }                        // 예약이 먼저다. 표시가 실패해도 다음 자정은 산다
function dayInstall(){
  if(SUBWIN) return;                                              // 메인 창, 브라우저, 열람 프레임만
  const back = () => { if(document.visibilityState !== 'hidden'){ dayArm(); daySync(); } };
  document.addEventListener('visibilitychange', back);
  window.addEventListener('focus', back);
  window.addEventListener('pageshow', back);
  window.addEventListener('pagehide', () => { clearTimeout(dayTimer); dayTimer = 0; });
  dayArm();
}
```

부팅 끝(`renderAll()` 뒤)에서 `dayInstall()` 을 한 번 부른다.

### 읽어 주는 이름

"오늘"은 이름 끝이 아니라 가운데에 들어간다. 예: "11월 13일 금요일, 오늘, 일정 3건". 그래서 이름 전체를 다시 쓰지 않고 날짜 부분만 바꿔 끼운다.

- 개인 달력은 `calAria`(5339)로 날짜 부분을 만든다.
- 과제 월간(25036)과 근태(21449)는 같은 모양을 직접 이어 붙인다. 순서가 같다(날짜, 요일, 공휴일, 오늘).
- 그래서 `calAria(ds, '')`(오늘 없음)와 `calAria(ds, ds)`(오늘 있음)를 앞부분으로 견줘 바꾸면 세 화면에 다 맞는다.
- 앞부분이 예상과 다르면 건드리지 않는다. 클래스만 옮겨진다.

구현 때 과제와 근태의 이름 조립을 `calAria` 로 바꿔 한 곳으로 모으면 어긋날 여지가 없어진다. 필수는 아니다.

### 하지 않는 것

- `renderGrid`, `renderPanel`, `pcRender`, `atRenderMonth`, `selectDate` 를 부르지 않는다.
- `tabindex`, `aria-selected`, `.sel` 을 건드리지 않는다.
- `hostRequest`, `hpost` 를 부르지 않는다.
- 이미 있는 창 복귀 처리(과제 범위 다시 읽기 26334, 근태 달력 다시 그리기 22499)는 그대로 둔다. 순서에 기대는 것이 없어 묶을 필요가 없다.

근태 달력은 지금도 창 포커스 때 다시 그린다(22499). 그 화면에서는 표시 맞추기가 할 일이 없을 뿐이고 서로 해가 없다.

## 지킬 것

칸을 갈아 끼우지 않으므로 아래는 따로 지킬 장치 없이 그대로 남는다.

| 무엇 | 까닭 |
|---|---|
| 고른 날, 보는 달과 주, 기준일 | 읽지도 쓰지도 않는다 |
| 누르는 중인 클릭, 더블클릭, 끌기 | 칸 요소가 같은 것이다 |
| 키보드 초점 | 초점을 가진 요소가 남는다 |
| 열린 모달, 그날 목록, 편집 화면 | 건드리는 곳이 달력 칸의 클래스와 이름뿐이다 |
| 스크롤 자리, 칩 맞춤 | 다시 그리지 않는다 |

**알고 받아들이는 동작.** 11월 30일 밤에 11월을 보다가 12월 1일이 되면 11월을 계속 본다. 12월 1일 칸이 그 화면에 있으면(달력의 이웃 달 칸) 거기에 표시가 붙고, 없으면 표시가 사라진다. 고른 날은 어제에 남고 패널은 어제 내용이다. 오늘로 가려면 [오늘] 을 누른다.

## 오류와 복구

1. **표시가 실패해도 다음 자정은 산다.** 타이머가 뜨면 다음 예약을 먼저 잡는다. 예약은 뺄셈과 `setTimeout` 뿐이라 던질 것이 없다.
2. **표시 맞추기는 `try/catch` 하나로 감싼다.** 잡은 오류는 `console.warn` 으로 남긴다. 창 복귀 때의 다른 처리(과제 범위 다시 읽기)는 따로 등록된 듣기라 영향이 없다.
3. **실패의 최악은 지금과 같다.** 표시가 안 옮겨질 뿐이다. 다음에 달력이 다시 그려지면 원래 코드가 맞는 표시를 만든다. 새 코드는 기존 그리기를 대신하지 않고 사이를 메운다.
4. **타이머가 쌓이지 않는다.** 손잡이 하나, 걸기 전에 지운다.
5. **몇 번 불러도 같다.** 보임과 포커스가 연달아 와도 해가 없다.

## 시험

tests/today-mark.test.mjs 하나를 새로 만든다. 개발 중에는 이 파일만 돌리고 전체 strict 는 끝에 한 번 돌린다.

시간은 jsdom 창의 `Date` 를 바꿔 끼워 옮긴다(이 저장소의 다른 시험과 같은 방식). 타이머는 부팅 전에 창의 `setTimeout`, `clearTimeout` 을 가로채 건 함수와 길이를 적어 두고 시험이 직접 부른다. 앱에 시계 주입 장치를 넣지 않는다.

### 기준 하나

**표시만 옮긴 화면이, 같은 날짜로 새로 그린 화면과 같다.** 날짜를 옮기고 표시를 맞춘 뒤 칸마다 클래스와 읽어 주는 이름을 적어 둔다. 그 자리에서 그리기 함수를 직접 불러 다시 적어 견준다. 대상 칸을 잘못 고르거나 이름을 깨뜨리면 여기서 걸린다.

### 목록

1. **새로 그린 것과 같다**: 개인 월간, 개인 주간, 나란히 보기(양쪽), 과제 월간, 과제 주간, 근태 일간. 11/12 에서 11/13.
2. **주간 몸통 칸**: `wr-c`, `pc-wday` 에는 `today` 가 붙지 않는다.
3. **읽어 주는 이름**: 옛 칸에서 ", 오늘" 이 빠지고 새 칸에 들어간다. 뒤의 ", 기록 3건", ", 일정 2건", ", 보고함" 과 공휴일 이름은 그대로.
4. **새 오늘 칸이 화면에 없다**: 11월을 보다 12/7 이 되면(화면 밖) 옛 표시만 지워진다. 3월을 보는 중이면 변화가 없다.
5. **월말과 연말**: 11/30 에서 12/1 은 11월 달력의 이웃 달 칸에 붙는다. 12/31 에서 1/1 도 같다. 보는 달은 그대로.
6. **시계 되돌림**: 11/13 에서 11/12. 표시가 12일로 돌아간다.
7. **칸이 같은 요소다**: 맞추기 전후로 칸 노드가 같고(`===`), 초점을 가진 요소가 같고, 고른 날, 보는 달, 과제 기준일, 근태 기준일이 같다. 모달과 과제 그날 목록을 연 채로도 같다.
8. **밖으로 나가는 것이 없다**: 맞추는 동안 `hostRequest`, `hpost` 호출 0번. `renderGrid`, `renderPanel`, `pcRender`, `atRenderMonth` 호출 0번.
9. **타이머 하나**: 설치 뒤 살아 있는 예약 1개. 보임과 포커스를 50번씩 보낸 뒤에도 1개. `pagehide` 뒤 0개, `pageshow` 뒤 1개.
10. **예약 길이**: 23:59:30 에 걸면 31초쯤. 23:59:59.995 에 타이머가 떠도 다음 예약이 1000ms 이상.
11. **실패해도 다음 자정**: `calAria` 를 던지게 바꾸고 타이머를 부른다. 예약 1개가 남고 `console.warn` 이 찍힌다. 던진 칸은 클래스도 이름도 옛 그대로다(색과 이름이 어긋나지 않는다). 되돌리고 다시 부르면 클래스와 이름이 함께 맞는다.
12. **설치하지 않는 창**: 근태 창, 관리 창, 열람 창 껍데기로 부팅하면 예약 0개.
13. **숨은 문서**: 타이머가 뜨면 표시는 맞춘다(숨어 있어도 클래스 바꾸기는 해가 없다). 숨은 채 `focus` 가 와도 예약을 건드리지 않는다.

## 범위 밖 결함: 알림이 끊긴다

이번에 고치지 않지만 조사에서 나온 실제 결함이라 적어 둔다. 화면과 무관하고 사용자가 눈으로 알 수 없다.

- 일정 시작 전 알림 창은 호스트가 띄운다. 호스트는 일정을 모르고, 웹이 `reminderSync` 로 보내 준 목록만 20초마다 본다(widget/Reminders.cs 123).
- 웹은 "오늘부터 모레까지"의 발생만 보낸다(26472 `addDays(today, 2)`).
- 보내는 때는 부팅, 저장, 서버 재연결, 테마 변경뿐이다(6101, 6502, 6753, 19432).
- 그래서 월요일에 켜고 아무것도 고치지 않으면 호스트의 목록은 수요일까지다. 목요일 일정은 달력에는 있어도 알림이 뜨지 않는다. 탭 전환으로도 고쳐지지 않는다.

고치는 방법은 작다. 날짜가 바뀐 것을 알았을 때 메인 창이 `pushReminders()` 를 한 번 부른다. 이 설계의 타이머와 창 복귀 자리에 "마지막으로 보낸 날짜와 다르면 보낸다" 한 줄을 얹으면 된다. 호스트는 같은 일정의 단계와 창을 지키므로(Reminders.cs 87~97) 다시 보내도 알림이 겹치지 않는다.

기간을 +7일로 넓히는 것은 따로 정한다. 절전으로 자정 타이머가 며칠 못 도는 경우(주말 최대 절전 뒤 월요일 아침)의 여유분이고, 절전 실측 결과를 보고 정하면 된다.

## 지나온 길

같은 날 설계가 세 번 바뀌었다. 다음에 같은 길을 다시 걷지 않으려고 적는다.

**첫째 안: 날짜 넘김 전체(docs/DAY-ROLLOVER.md).** 날이 바뀌면 고른 날과 보는 달을 오늘로 따라가게 하고, 달력을 다시 그리고, 범위가 바뀌면 서버를 다시 읽고, 알림을 다시 보낸다. 누르기와 키 입력에서도 날짜를 확인했다.

커진 원인은 하나였다. 누르는 순간 칸을 갈아 끼우면 그 클릭이 사라진다. 이를 막으려고 칠하기 미룸이 붙었고, 미룸을 지키려고 마감 고정, 끌기 깃발, 연장 상한, 상태와 칠하기 분리, 창 복귀 조회 미루기가 붙었다. 검토를 돌 때마다 미룸에서 새 문제가 나왔다(첫 클릭이 덮어써짐, 더블클릭 간격, 월 경계에서 클릭이 칸을 교체, 진행 중이던 조회가 미룸 중에 다시 그림). 장치를 지키는 장치가 쌓이는 모양이었다.

**둘째 안: 단순판.** 입력 확인과 미룸을 빼고 타이머와 창 복귀에서 다시 그리기만 한다. 그런데 "창을 누르면 포커스가 클릭보다 먼저 온다"는 재지 않은 가정에 기댔고, 타이머가 뜨는 순간의 클릭은 여전히 사라질 수 있었다.

**셋째 안(이 문서): 표시만 옮긴다.** 문제의 뿌리가 "칸을 갈아 끼운다"였으니 갈아 끼우지 않으면 된다. 코덱스가 낸 방식이고, 사용자가 범위를 "오늘 표시만"으로 좁히면서 가능해졌다.

배운 것:

- 요구가 "오늘 표시가 안 바뀐다"였는데 "오늘에 기대는 모든 것을 따라가게 한다"로 넓혀 읽었다. 범위를 먼저 물었어야 했다.
- 보호 장치가 보호 장치를 부르기 시작하면, 장치를 다듬지 말고 보호가 필요해진 원인(여기서는 다시 그리기)을 없앨 수 있는지 먼저 본다.
- 탭 전환이 이미 고쳐 준다는 사실, 같은 달 안의 클릭은 고쳐 주지 않는다는 사실은 처음 조사에서 확인했어야 했다. 문제의 실제 크기가 거기서 정해진다.

첫째 안에서 건진 것은 이 문서에 다 옮겼다: 오늘에 기대는 곳 조사, 다음 자정 계산과 하한, 예약을 먼저 잡는 순서, 알림 결함 분석.

## 코덱스 문서와의 관계

docs/CALENDAR-TODAY-HIGHLIGHT.md 와 방식, 범위, 계기가 같다. 이 문서가 더한 것은 넷이다.

1. **대상 칸을 이름으로 못 박았다.** 코덱스 문서의 "날짜가 있는 `.cal-c` 칸"은 주간 몸통 칸(`wr-c`, `pc-wday`)까지 잡는다.
2. **시험 기준과 시험 파일.** "새로 그린 것과 같다" 하나로 대상과 이름을 함께 잡는다. 코덱스 문서의 "확인할 것"은 사람이 볼 목록이다.
3. **예약에 1초 여유와 하한.** 타이머가 일찍 뜨는 경우.
4. **기억할 상태가 없다는 점.** 옛 오늘을 저장하지 않고 매번 맞춘다.

다른 결론은 없다.
