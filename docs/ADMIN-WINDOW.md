# 관리 화면 별도 창 (ADMIN-WINDOW)

- 상태: 기획 확정(2026-10-22). 2절 "정할 것" 네 가지는 기본안대로 확정(사용자 승인).
- 목표: 메인 창 안의 ⚙ 관리 허브(`#adminHub`)를 **별도 OS 창**으로 연다. 창 크기 조절과 최대화가 되고, 캘린더를 보면서 관리할 수 있다.
- 범위: 관리 허브와 그 안에 붙는 화면 전부(공식 과제 편집, 발주처, 구분, 상태, 회의실, 구성원 편집, 직원 등록과 수정, 직급과 소속, 휴지통). 보고서와 사용설명서는 이번 범위가 아니다(사용자 결정 2026-10-22, 따로 개선 방향이 있다).
- 근거: 팝업 전수 검수(2026-10-22). 관리 화면들은 메인 캘린더 데이터(`state`)를 거의 쓰지 않고 DB 왕복과 목록 갱신 알림만 써서, 분리 비용이 가장 낮은 단위다.
- 선례: 다른 사람 일정 보기 별도 창([WINDOW-UI.md](WINDOW-UI.md), `widget/PeerWindow.cs`, `?peerwin=1`).

## 1. 사용자 동작

- 메인 ⋯ 메뉴의 **⚙ 관리**(관리자로 확인될 때만 보임)를 누르면 관리 창이 열린다. 이미 열려 있으면 앞으로 가져온다. 창은 하나만 열린다.
- 내 과제 창의 "⚙ 공식 과제 편집은 관리에서 ›" 링크도 관리 창을 열고 **공식 과제** 항목을 고른다.
- 관리 창은 일반 창이다: 제목줄, 최소화, 최대화, 닫기, 크기 조절, 작업 표시줄에 따로 뜸. 메인 창은 관리 창이 열려 있어도 그대로 쓸 수 있다.
- 창 안의 모양은 지금 허브와 같다(왼쪽 묶음과 항목, 오른쪽 화면). 창이 커지면 목록과 표가 함께 넓어진다.
- 관리 창에서 바꾼 것(과제, 발주처, 구분, 상태, 회의실)은 메인 창 목록에도 바로 반영된다.
- 로그아웃, 계정 바뀜, 앱 종료 때 관리 창도 닫힌다. 메인 창을 트레이로 숨기는 것과는 무관하다.
- 메인 창의 "맨 앞에 띄우기" 를 켜면 관리 창도 같이 맨 앞에 둔다(열람 창과 같은 규칙).
- 창 크기와 위치, 최대화 여부를 기억한다. 처음에는 메인 창이 있는 모니터 가운데에 연다.
- 버전 관문 차단 화면은 관리 창에도 뜬다(열람 창과 같은 작은 카드, "메인 창에서 업데이트해 주세요").

## 2. 확정한 동작 (2026-10-22)

1. **기본 크기:** 처음 열 때 1200×800(작업 영역의 90% 이하로 줄임), 최소 720×520.
2. **저장 안 한 입력이 있을 때 창 닫기:** 직원 등록과 수정 폼처럼 지금 "저장 안 한 입력" 확인이 있는 폼이 열려 있으면, 창을 닫기 전에 같은 확인을 묻는다.
3. **관리 창이 열려 있을 때 메인의 ⚙ 관리:** 관리 창을 앞으로 가져오기만 한다(새로 열지 않는다).
4. **창 제목:** "수행과제 캘린더 관리".

## 3. 설계 요약

- **창 종류 일반화:** 지금 `PeerWindow` 하나에 고정된 별도 창 구조를 창 종류별(열람, 관리)로 넓힌다. 종류마다 URL(`?win=admin`), 최소 크기, 하나만 열기, 크기 기억 키, 명령 허용 목록, 회신 번호 접두사를 둔다. 열람 창 동작은 바꾸지 않는다.
- **명령 허용 목록:** 관리 창은 관리 화면이 쓰는 명령만 허용한다(약 30개: 과제 저장과 숨김, 엑셀 내보내기, 발주처, 코드, 회의실, 구성원, 직원 저장, 직급, 소속, 휴지통, 관리자 확인, 목록 읽기, 버전 관문 재확인). 웹과 호스트 양쪽에서 거른다. 관리자 판정은 지금처럼 호스트의 관리자 관문(`OpenAdminAsync`)이 쓰기마다 한다.
- **회신 길:** 요청 번호 접두사로 보낸 창을 찾아 그 창에만 회신한다(열람 창의 `pw:` 방식과 같음).
- **목록 갱신 알림을 두 창으로:** `__applyProjects`, `__applyCodes`, `__applyCustomers`, `__projectSaved` 등은 메인 창과 관리 창 모두에 보낸다.
- **관리 창 부팅:** 내 캘린더는 부팅하지 않고, 로그인 사용자, 연결 상태, 과제, 코드, 발주처 목록만 받아 온다.
- **허브 붙이기와 떼기:** 관리 창에서는 허브가 문서 전체라 항목을 고를 때 화면을 붙이는 방식은 그대로 쓰되, 허브 닫기는 창 닫기가 된다. 편집 폼, 확인 창, 이름 입력 확인 창은 관리 창 안에서 그 위에 뜬다.
- **메인 창에서 없애는 것:** 메인 창의 허브는 더 열지 않는다. 내 과제의 "공식 과제 찾아보기"(전원용 읽기 전용)는 메인 창 모달로 그대로 둔다.
- **파일 대화상자:** 엑셀 내보내기 같은 대화상자의 소유자를 요청한 창으로 한다(관리 창 위에 뜸).

## 4. 시험과 QA

- 정적 시험: 창 종류 등록, 관리 창 허용 목록(목록 밖 명령 거절, 열람 창 목록은 그대로), 회신 접두사 라우팅, 목록 갱신 알림이 두 창으로 감, 메인 창에서 허브가 열리지 않음, 관리 창 문서에서 허브가 전체를 차지함, 관리자 관문 유지.
- 바뀌는 시험: 관리 허브와 그 안 화면 id 를 잡는 시험들(관리 허브, 공식 과제, 구성원 편집, 확인 창 등).
- 실동작(QA): 디버그 위젯에서 관리 창 열기와 앞으로 가져오기, 각 관리 화면 쓰기, 메인 창 반영, 엑셀 내보내기 대화상자 위치, 크기 기억, 로그아웃 때 닫힘, 버전 관문 카드. 실동작 시험(loop-admin-hub, loop-user-admin, loop-trash, loop-org-title 등)이 두 번째 창을 다루도록 고친다.
