# 다른 사람 일정으로 바로 가는 입구 기획서(사람 고르기, 최근, 즐겨찾기, 창 안에서 바꾸기)

> 2026-10-02, 대상 v0.19.x. 파이프라인(기획, 개발, QA, 위키)의 1단계 산출물로, 개발과 QA 의 정본이다.
> 관련: [`PEER-VIEW-FULL.md`](PEER-VIEW-FULL.md), [`PEER-OVERLAY-REDESIGN.md`](PEER-OVERLAY-REDESIGN.md), [`PEER-SIDE-BY-SIDE.md`](PEER-SIDE-BY-SIDE.md)

## 0. 요구

사용자: 남의 일정을 보려면 '구성원'으로 가야 한다. 일반 사용자에게는 **순서가 어색하고 숨은 기능**처럼 느껴진다.
결정(2026-10-02): ① **상단 툴바 입구와 사람 고르기 창(검색, 최근, 즐겨찾기)**, ② **열람 창 안에서 사람 바꾸기**. 즐겨찾기도 넣는다.

## 1. 지금

상단 사용자 아이콘, '사용자 정보', '구성원 보기', 조직도에서 사람 찾기, 클릭을 거쳐야 열람 창이 열린다. **4단계**이고 입구 이름에 '일정'이 없다. 다른 사람으로 바꾸려면 창을 닫고 처음부터 다시 해야 한다.

## 2. 상용 참고

| 제품 | 입구 | 다시 보기 |
|---|---|---|
| Google | 메인 사이드바에 늘 있는 **'사용자 검색'** 칸 | 한 번 본 사람은 '다른 캘린더' 목록에 남는다 |
| Outlook | 캘린더 목록의 **'캘린더 추가 → 디렉터리에서'** | '사용자 캘린더' 묶음에 남는다 |
| Apple | 사이드바 공유 캘린더 목록 | 목록에 남는다 |

공통점: 입구는 **메인 화면에서 보이는 자리**에 있고, **본 사람은 다시 찾지 않는다.** 조직도는 찾는 수단이지 입구가 아니다.

## 3. 목표 동작

| # | 항목 | 동작 |
|---|---|---|
| K1 | 툴바 입구 | 상단 툴바('🔍 검색', '📄 보고서' 줄)에 **'👥 다른 사람 일정'** 버튼을 둔다. 좁은 폭에서는 다른 보조 버튼과 같은 규칙으로 아이콘만 남기거나 ⋯ 메뉴로 접힌다(라벨은 aria-label 로 보존). 열람 창 안(`PEER`)에는 없다 |
| K2 | 사람 고르기 창 | 버튼 아래 **작은 팝오버**(모달 아님, Esc 나 바깥 클릭으로 닫힘). 위에서부터 **이름 검색 칸**(열리면 포커스), **★ 즐겨찾기**, **최근 본 사람**, (검색어가 있으면) **검색 결과** |
| K3 | 검색 | '구성원 보기'와 같은 명부(`membersGet`)에서 **이름, 직급, 조직** 부분 일치(대소문자와 공백 무시). 결과는 최대 20행이고 넘치면 "N명 더 있습니다. 이름을 더 입력하세요". 명부는 팝오버를 열 때마다 새로 읽는다(구성원 보기와 같은 규칙: 캐시 안 함). 읽는 중에는 '불러오는 중', 실패하면 "명부를 불러오지 못했습니다"와 '다시 시도'를 보인다. 그때도 즐겨찾기와 최근은 저장된 이름으로 보이고 누를 수 있다(열기는 지금처럼 권한을 다시 따진다) |
| K4 | 행 모양 | 이름, 직급, 조직 한 줄과 오른쪽 **☆/★ 즐겨찾기 버튼**(`aria-pressed`). **나 자신**은 목록에 없다. **열람 범위 밖**(canViewSchedule=false)은 회색이고 누를 수 없으며 툴팁은 "일정 열람 범위 밖입니다". 명부에서 사라진 사람(퇴사 등)이 즐겨찾기나 최근에 남아 있으면 회색 '명부에 없음'과 지우기(✕)를 보인다 |
| K5 | 열기 | 행을 누르거나 Enter 를 치면 팝오버가 닫히고 **지금의 열람 창**이 열린다(`openPeerSchedule` 그대로. 권한 판정, 읽기 전용, 봉인 불변) |
| K6 | 최근 본 사람 | 열람 창이 **성공적으로 열린** 사람을 맨 앞에 넣는다(중복은 앞으로 당긴다). **최대 5명**. 실패나 권한 없음은 넣지 않는다. '구성원 보기'에서 연 것도 똑같이 기록한다(입구가 어디든). (2026-10-29 갱신: 최근 본 사람 행마다 ☆ 옆에 ✕ 지우기 단추를 두고, 머리말 오른쪽에 '전체 지우기' 단추를 둔다, [`PEER-ORG-RECENT.md`](PEER-ORG-RECENT.md)) |
| K7 | 즐겨찾기 | ☆ 를 누르면 ★(추가), 다시 누르면 해제. 추가한 순서대로 두고 **최대 20명**(넘으면 "즐겨찾기는 20명까지입니다"). 즐겨찾기에 있는 사람은 최근 목록에서 빼고 보여 준다(같은 사람 두 줄 금지) |
| K8 | 저장 | 이 PC 의 개인 설정(`localStorage`)에 **내 계정별 키**로 둔다: `tc_peerFav:<내 login_id>`, `tc_peerRecent:<내 login_id>`. 값은 `[{loginId, name}]`(표시용 이름 캐시). DB 나 서버는 바꾸지 않는다. 깨진 값이나 형식 이상은 빈 목록으로 읽는다. 다른 계정으로 로그인하면 그 계정 목록이 따로 있다 |
| K9 | 열람 창에서 바꾸기 | 열람 창 제목 '○○ 님의 일정' 옆에 **▾ 사람 바꾸기** 버튼을 둔다. 누르면 **같은 사람 고르기 창**(K2~K7 동일)이 제목 아래에 뜬다. 고르면 창을 닫지 않고 **그 자리에서 다른 사람으로** 바뀐다(지금 보던 달, 보기 방식, 밀도는 그대로 이어진다). 지금 보는 사람은 목록에서 '(보는 중)'으로 표시하고 누를 수 없다 |
| K10 | 열람 창 즐겨찾기 | 열람 창 제목 옆에 **☆/★**. 지금 보는 사람을 즐겨찾기에 넣고 뺀다(K7 과 같은 저장) |
| K11 | 키보드와 접근성 | 검색 칸에서 ↓/↑ 로 행 이동, Enter 로 열기, Esc 로 닫고 입구 버튼으로 포커스 복귀. 팝오버는 `role="dialog"` 와 `aria-label`, 목록은 `role="listbox"`/`option` 또는 버튼 목록, 회색 행은 `aria-disabled` |
| K12 | 지키는 것 | '구성원 보기' 동작은 그대로(조직도에서 사람 클릭으로 열람). 권한 판정은 호스트(`peerSchedule`)가 한다(목록의 회색은 안내일 뿐). 열람 창 읽기 전용과 hpost 봉인 불변. 새 hostRequest 명령 없음(`membersGet`, `peerSchedule` 재사용). 남의 이름 등 DB 문자열은 모두 이스케이프하거나 textContent 로 넣는다. 테마 토큰만 사용(5종 대비 AA) |

## 4. 수용 기준(QA)

| ID | 기준 | 확인 |
|---|---|---|
| R1 | 툴바 버튼이 내 창에 있고 열람 창 안에는 없다. 좁은 폭에서 접힌다 | jsdom + 실 위젯 |
| R2 | 팝오버: 열기/Esc/바깥 클릭, 검색 포커스, 검색 결과(이름, 직급, 조직), 20행 제한 문구, 나 자신 없음, 범위 밖은 회색이고 클릭해도 반응 없음 | jsdom |
| R3 | 명부 실패 때 안내가 나오고 즐겨찾기와 최근은 보이며 열린다 | jsdom |
| R4 | 최근: 성공 때만, 맨 앞, 중복 당김, 5명, 구성원 보기에서 연 것도 기록, 즐겨찾기와 중복 표시 안 함 | jsdom |
| R5 | 즐겨찾기: 토글, 순서, 20명 제한, 계정별 키, 깨진 값은 빈 목록 | jsdom |
| R6 | 명부에 없는 사람: 회색 '명부에 없음'과 ✕ 로 지우기 | jsdom |
| R7 | 열람 창 ▾ 바꾸기: 창을 닫지 않고 다른 사람으로 바뀐다. 보던 달, 보기 방식, 밀도 유지, '보는 중' 표시 | jsdom + 실 위젯 |
| R8 | 열람 창 ☆/★ 가 저장과 일치(팝오버와 양방향) | jsdom |
| R9 | 키보드: ↓/↑/Enter/Esc, 포커스 복귀 | jsdom |
| R10 | 실 DB: 툴바, 검색, 열람, 최근에 남음, 즐겨찾기, 열람 창 ▾ 로 바꾸기 순서로 진행한다. 아무것도 나가지 않고(봉인) DB 는 그대로이며, 끝나면 저장 키를 원복한다 | loop-peer-frame 확장 |
| R11 | 테마 5종 대비, 기존 스위트와 루프 무회귀 | strict, run-loops, 실 위젯 |
