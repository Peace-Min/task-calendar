# 날짜 패널 할 일 제목: 자르지 않고 전부 보이기 (D 안)

2026-11-10 결정, 같은 날 구현(브랜치 `feat/day-panel-todo-title`). 아래 1~7절은 구현 전에 쓴 기획이고 줄 번호도 그때 기준이다. 실제로 한 것과 달라진 점은 9절에 있다.

## 1. 무엇이 문제였나

개인 탭 오른쪽 날짜 패널의 할 일 제목이 두 줄에서 `...` 으로 잘린다. 제목을 눌러 상세를 펼쳐도 제목은 잘린 채라, 전체 글을 읽을 방법이 마우스를 올려야 뜨는 툴팁(title)뿐이다.

원인은 두 가지다.

- `task-calendar-prototype.html` 의 `.dp-todos .todo-text` 규칙(523줄 근처)이 `-webkit-line-clamp:2` 로 자른다.
- 줄 끝의 색 점, 별, ✕ 가 줄마다 80px 넘게 차지한다. 패널이 가장 좁을 때(240px) 제목이 쓸 수 있는 폭이 96px 뿐이다. 그래서 자르기만 풀면 긴 제목이 7줄로 늘어진다.

같은 패널의 일정 카드는 제목과 메모를 자르지 않는다(docs/DAY-PANEL-CARDS.md 결정 3). 할 일만 잘랐다.

## 2. 결정 (D 안)

날짜 패널의 할 일 줄을 아래처럼 바꾼다.

| 항목 | 지금 | 바꾼 뒤 |
|---|---|---|
| 제목 | 두 줄까지, 넘치면 `...` | 전부 보인다(줄 수 제한 없음) |
| 제목의 title 툴팁 | 전체 글 | 없앤다(전부 보이니 필요 없다) |
| 줄 끝 ✕ (삭제) | 늘 보인다 | 없앤다. 지우기는 제목을 눌러 펼친 상세의 [삭제] |
| 별 (중요) | 늘 보이고 누른다 | 그대로 |
| 과제 색 점 | 늘 보인다 | 그대로 |
| 체크 | 늘 보이고 누른다 | 그대로 |
| 줄 안 세로 맞춤 | 가운데 | 첫 줄에 맞춤(체크, 색 점, 별이 제목 첫 줄 높이에 온다) |
| 마우스를 올렸을 때 | 변화 없음 | 변화 없음(올렸을 때 나오는 단추를 만들지 않는다) |
| 제목을 눌렀을 때 | 상세 펼침, 다시 누르면 접힘 | 그대로 |

글자 칸은 ✕ 가 차지하던 자리(단추와 간격을 합쳐 약 30px)만큼 넓어진다. 시안의 240px 패널에서 잰 제목 폭은 96px 에서 124px 가 됐고, 긴 제목(50자쯤)이 5줄, 300px 패널에서는 4줄이다. 시안은 스크롤 막대를 늘 그리므로 실제 앱은 조금 더 넓을 수 있다.

고르지 않은 안과 이유.

- A(자르기만 풀기): 240px 에서 긴 제목이 7줄. 글자 칸이 그대로 좁다.
- B, C(✕ 나 별을 마우스를 올렸을 때만 보이기): 상세에 [삭제]가 이미 있으니 올림 단추가 필요 없다. 터치 화면에서는 올릴 수도 없다.
- E(별도 켜진 것만 보이고 켜고 끄기는 수정 창에서): 중요 표시는 훑으면서 자주 켜고 끄는 동작이라 매번 수정 창을 여는 것이 번거롭다.

## 3. 범위

바꾸는 곳은 **날짜 패널(`#dpBody`)의 할 일 줄뿐**이다.

- 밀린 할 일 팝업(`#todoAllModal`)은 그대로 둔다. 이 팝업도 `<div class="dp-todos">` 를 쓰므로(`todoRowHtml(t, { all: true, noDot: true })`, 18664줄 근처) 지금의 `.dp-todos .todo-text` 자르기가 팝업에도 걸려 있다. 팝업은 폭이 넓고 ✕ 가 원래 없다. 이번에는 팝업의 두 줄 자르기를 유지한다.
- 열람 창(다른 사람 일정, `PEER`)의 날짜 패널은 같은 줄을 읽기 전용으로 그린다. 제목 전부 보이기와 첫 줄 맞춤은 열람 창에도 똑같이 적용된다. ✕ 는 원래 없다.
- DB, 호스트(C#), 버전 번호, 패치노트는 건드리지 않는다. 버전 갱신은 사용자가 따로 지시할 때 한다.

## 4. 고칠 곳

줄 번호는 2026-11-10 `feat/db-app` (커밋 fcf53d3) 기준이다. 어긋나면 이름으로 찾는다.

### 4.1 CSS (`task-calendar-prototype.html`)

523줄 근처의 규칙을 날짜 패널과 팝업으로 나눈다.

지금:

```css
.dp-todos .todo-text{display:-webkit-box;-webkit-box-orient:vertical;-webkit-line-clamp:2;overflow:hidden;overflow-wrap:anywhere}
```

바꾼 뒤(뜻만 맞으면 되고 선택자 모양은 구현자가 정한다):

```css
/* 밀린 할 일 팝업: 두 줄까지(그대로) */
#todoAllModal .dp-todos .todo-text{display:-webkit-box;-webkit-box-orient:vertical;-webkit-line-clamp:2;overflow:hidden;overflow-wrap:anywhere}
/* 날짜 패널: 제목 전부. 체크, 색 점, 별은 제목 첫 줄에 맞춘다(docs/DAY-PANEL-TODO-TITLE.md) */
#dpBody .dp-todos .todo-row{align-items:flex-start}
#dpBody .dp-todos .todo-check{margin-top:...}
#dpBody .dp-todos .todo-dot{margin-top:...}
#dpBody .dp-todos .todo-star-btn{margin-top:...}
```

- `margin-top` 값은 제목 첫 줄(13px 글자)의 가운데에 각 요소가 오도록 실제 화면에서 맞춘다. 시안에서는 체크 3px, 색 점 6px, 별 2px 이었지만 시안의 체크는 앱과 모양이 달라(앱은 16px 글리프 단추) 그대로 옮기면 안 맞을 수 있다.
- 기간 할 일은 제목 아래에 기간 글자 줄(`.todo-dueline`)이 붙는다. 첫 줄 맞춤 뒤에도 어색하지 않은지 본다.
- 펼친 줄의 옅은 바탕(`.dp-todos .todo-row.open`, 508줄)은 그대로다.
- 좁은 폭 터치 규칙(1663줄, `@media (max-width:440px)` 에서 별과 ✕ 를 32px 로 키움)은 그대로 둔다. 별이 32px 높이가 되어도 첫 줄 맞춤이 어긋나지 않는지 확인한다.
- 새 CSS 에 hex 색을 쓰지 않는다(`tests/day-panel-fold.test.mjs` 123줄이 막는다).

### 4.2 줄 그리기 (`todoRowHtml`, 18592줄 근처)

- `textAttr` (18605줄): `opts.panel` 일 때 붙이던 `title="${esc(t.text)}"` 를 뺀다. `data-dp="td" role="button" tabindex="0" aria-expanded` 는 그대로.
- `del` (18612줄): 지금 `(ro || opts.all) ? '' : ...` 이다. `opts.panel` 일 때도 그리지 않게 한다. 지금 `todoRowHtml` 을 부르는 곳은 날짜 패널(12777줄)과 밀린 할 일 팝업(18664줄) 둘뿐이라, 바꾸고 나면 ✕ 를 그리는 경로가 남지 않는다. 그 경우 `.todo-del` CSS(1652, 1653, 1663줄)와 `#dpBody` 클릭 처리의 줄 끝 `del` 갈래(19806줄)가 죽은 코드가 되는지 확인하고, 다른 데서 안 쓰면 같이 걷는다. 상세의 [삭제](19797줄)는 그대로 둔다.
- 함수 위 주석(18588~18591줄)과 18604줄 주석("제목은 두 줄까지, 전체는 title")을 새 동작에 맞게 고친다.

### 4.3 그대로 두는 동작

- 제목 누름과 Enter, Space 로 상세 펼치기와 접기(12736줄, 19810줄).
- 상세 내용(`dpTdDetHtml`, 12620줄): 기한, 과제, 메모, [수정] [삭제]. [삭제]는 토스트의 "실행 취소"가 있다.
- 체크와 별의 동작(19805, 19807줄).

## 5. 시험

개발 중에는 관련 시험만 돌리고, 전체 strict 는 끝에 한 번 돌린다.

고쳐야 하는 기존 시험.

- `tests/day-panel-fold.test.mjs` 124줄: `.dp-todos .todo-text` 에 `-webkit-line-clamp:2` 가 있다고 단언한다. 날짜 패널은 자르지 않고, 밀린 할 일 팝업은 두 줄 자르기가 남아 있다는 단언으로 바꾼다. 121줄의 CSS 줄 고르기 정규식(`\.dp-todos \.todo-text`)과 122줄의 개수 하한(14)도 선택자를 바꾸면 영향을 받는다.
- 같은 파일 399~415줄 `todos`: 406줄은 제목 전체가 title 에 있다고, 407줄은 줄에 `[data-act="del"]` 이 있다고 단언한다. title 이 없고, 줄에 ✕ 가 없고, 펼친 상세에 `[data-act="del"]` 이 있다는 단언으로 바꾼다. 399줄 주석도 고친다.
- `tests/personal-panel.test.mjs` 454줄: `.todo-del` 을 언급하지만 `|| true` 라 늘 통과한다. 뜻 있는 단언으로 고치거나 지운다.
- `tests/peer-view-full.test.mjs` 174, 398줄과 `tests/personal-panel.test.mjs` 638줄은 열람 창에 `.todo-del` 이 없다는 단언이라 그대로 통과한다.

새로 넣을 시험.

- 날짜 패널 할 일 줄에 `.todo-del` 이 없다. 제목에 title 속성이 없다.
- 제목을 펼친 상세의 [삭제]로 지워지고, "실행 취소"로 돌아온다(이미 있으면 재사용).
- 실제 Chromium(`tests/loop-ui-visual.mjs` 방식)에서 240px 패널에 긴 제목(40자 이상)을 넣고: 제목 높이가 두 줄보다 크다(잘리지 않음), 체크와 별의 세로 가운데가 제목 첫 줄 가운데와 2px 안쪽으로 맞는다, 패널 가로 넘침이 없다. 밝은 테마와 어두운 테마 둘 다.
- 변이 시험: 날짜 패널 선택자에 자르기를 되돌리면 잡힌다. `del` 조건에서 `opts.panel` 을 빼면 잡힌다.

시험 자료의 제목에는 실제 과제명이나 발주처를 쓰지 않는다(가짜 이름만).

- `docs/DAY-PANEL-CARDS.md` 에 할 일 줄 이야기가 있으면 같이 맞춘다.

## 7. 다 됐다는 기준

- 240px 와 300px 패널에서 긴 할 일 제목이 끝까지 보인다.
- 줄에 ✕ 가 없고, 마우스를 올려도 아무것도 나타나지 않는다.
- 펼친 상세의 [삭제]와 실행 취소가 동작한다.
- 밀린 할 일 팝업의 모양은 바뀌지 않았다.
- 관련 시험 통과, 끝에 `TC_TEST_STRICT=1 node tests/run-tests.mjs` exit 0.

## 8. 참고

## 9. 구현 결과 (2026-11-10)

기획과 달라진 점.

- 제목에 `display:block` 을 넣었다. inline 으로 두면 부모 글자 크기(14px) 때문에 첫 줄 가운데가 1px 내려가서, 13px 글자 기준 줄 높이 17px 로 고정하려는 것이다.
- 체크와 별에는 `margin-top` 을 넣지 않았다. 둘 다 아이콘이 17px 라 위에 붙이면 첫 줄 가운데(8.5px)와 맞는다. 체크에 값을 넣으면 440px 이하의 터치 영역 규칙(`.todo-check{padding:8px;margin:-8px}`)을 덮어 어긋난다. 색 점만 4.5px 내렸다.
- 440px 이하에서는 별이 32px 단추가 되므로 날짜 패널에서만 `margin-top:-7.5px` 로 끌어올렸다.
- `.todo-del` CSS, `todoRowHtml` 의 `del`, `#dpBody` 클릭 처리의 줄 끝 `del` 갈래를 걷었다. `body[data-peer] .todo-del` 감춤 규칙 한 줄은 `tests/peer-view-full.test.mjs` 가 그 규칙이 있다고 단언해서 남겼다(해는 없다).

실제 화면에서 잰 것(브라우저 단독 실행, 표본 할 일 5개, 50자쯤 되는 제목 포함).
