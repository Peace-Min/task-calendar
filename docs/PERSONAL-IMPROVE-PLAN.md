# 개인 탭 개선 기획 (기간 막대, 한 화면 입력 폼)

작성 2026-10-23. 상태: 기획 확정, 개발 전. 브랜치 `feat/personal-improve`. 시안: [prototypes/personal-improve.html](prototypes/personal-improve.html).

## 1. 목표

과제 탭에서 정한 화면 규칙 두 가지를 개인 탭에도 들여온다.

- 월간 달력의 기간 일정을 칸마다 조각으로 그리지 않고, 여러 날을 가로지르는 막대 하나로 그린다.
- 일정과 할 일 입력을 한 화면 폼으로 바꾼다. "옵션 더보기"로 칸을 숨기지 않는다.

하지 않는 일: DB 변경(구조 번호 그대로), 저장 방식 변경, "다른 사람 일정" 창의 겹쳐 보기 변경, 오른쪽 패널 구조 변경.

## 2. 결정 (2026-10-23 사용자)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 기간 일정 모양 | 과제 탭식 연속 막대. 주 경계에서 나누고, 잘린 쪽은 ◂ ▸, 사흘 이상이면 오른쪽에 기간 글자(10/5 ~ 10/13). 위젯 기본 폭에서는 기간 글자와 화살표를 숨긴다(과제 탭 규칙) |
| 2 | 누르기 | 지금과 같다. 누른 자리의 날짜를 고르고 오른쪽 패널이 바뀐다. 목록 창(팝오버)은 없다 |
| 3 | 끌어 옮기기 | 잡은 자리 기준. 막대의 어느 날을 잡았는지 기억하고, 놓은 칸과의 날짜 차만큼 시작일과 종료일을 함께 옮긴다(길이 유지). 반복 일정은 지금처럼 끌 수 없다 |
| 4 | 기간 할 일 | 점선 띠 모양을 막대에서도 유지한다 |
| 5 | 메모 첫 줄 표시 | 개인 탭에는 넣지 않는다 |
| 6 | 입력 폼 | 한 화면. 유형(일정, 할 일), 제목, 시작일과 종료일, 과제, 종일 또는 시작과 종료 시각, 미리알림, 반복, 장소, 메모, 취소와 저장. "옵션 더보기" 없음 |
| 7 | 시각 입력 | 한 칸에서 시와 분을 같이 고르는 시각 칸. 분은 **5분 단위**로 고른다. **개인 폼과 과제 폼 공통**. 이미 저장된 5분 단위가 아닌 값(11:38 등)은 그대로 보이고 저장된다 |
| 8 | 반복 | "안 함, 매주, 매월"만 고른다. 반복 간격, 끝(날짜, 횟수) 같은 세부 칸은 폼에서 뺀다. 예전에 세부 값을 넣은 일정은 값을 지우지 않고 보존하며, 수정 폼에 한 줄 요약(예: 2주마다, 10회)만 보인다 |
| 9 | 좁은 창(위젯 기본 400px) | 폼이 창보다 길면 아래에서 올라오는 시트 안에서 스크롤하고 저장 단추는 아래에 고정. 앱의 다른 창과 같은 규칙(사용자 판단 불필요, PM 결정) |
| 10 | "자세히 편집" 창 | 한 화면 폼이 모든 칸을 가지므로 일정과 할 일 편집에서는 쓰지 않는다. 작업일지 기록 편집처럼 그 창에만 있는 기능은 그대로 둔다(개발 때 실제 쓰임을 확인해 기록) |

## 3. 그대로 두는 것

- 오른쪽 패널(일정 상세, 할 일, 작업일지), 과제 필터, 키보드 이동, 휴일과 +N, 반복 일정 펼침, 커밋 표시 위치(작업일지 탭).
- 저장 경로(`saveState`, `CalendarWriteDb` 차이 계산)와 저장 형식. 반복 세부 값 칸(`recur_interval`, `recur_until`, `recur_count`)도 그대로 저장된다.
- "다른 사람 일정" 열람 창(PEER)의 칩. 막대로 바꾸지 않는다(칸별 칩 순서에 기대는 겹쳐 보기가 있어 따로 설계가 필요).

## 4. 위험과 확인할 것

- 월간 그리기는 앱의 중심 화면이라 화면 배치 시험(layout-stability, loop-ui-visual 등)이 촘촘히 걸려 있다. 바뀌는 시험은 의도를 적고 고친다.
- 끌어 옮기기: 막대가 여러 칸을 덮으므로 놓을 칸은 손가락 아래 칸으로 정한다(막대 아래 칸을 찾는다).
- 할 일 막대와 일정 막대가 같은 차선 계산을 쓴다. 완료 할 일, 중요 별, 반복 표시가 막대 안에 그대로 보여야 한다.
- 5분 단위 시각 칸이 위젯(WebView2)의 시각 선택 목록에서 실제로 5분 간격으로 나오는지 실제 앱에서 확인한다. 안 나오면 시와 분 고르기를 직접 만들어 대신한다(결정 7의 뜻은 같음).

## 5. 단계

1. 기획(이 문서).
2. 개발: 월간 막대, 끌기, 한 화면 폼(일정, 할 일), 시각 5분 단위(개인과 과제), 반복 단순화와 세부 값 보존, 좁은 창 시트.
3. QA: strict 게이트, 실제 앱 루프(기존 개인 루프 + 새 루프), 넓은 창과 400px 캡처를 시안과 나란히 비교.
4. 위키: 개인 탭 사용법 갱신.
