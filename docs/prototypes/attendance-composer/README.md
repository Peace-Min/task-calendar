# 캘린더를 활용한 근태 보고 작성 시안

2026-10-27. A/B/C 비교용이며 제품에 적용할 작성 흐름은 아직 확정하지 않았다.

## 회사 PC에서 열기

`index.html`을 Chrome 또는 Edge로 직접 연다. 같은 폴더의 `style.css`, `app.js`를 함께 유지한다. 외부 라이브러리, 인터넷, 로그인, DB가 필요하지 않다.

로컬 웹 주소로 확인하려면 저장소 루트에서 실행한다. Node.js 외의 패키지 설치는 필요 없다.

```powershell
node docs/prototypes/attendance-composer/server.mjs
```

브라우저에서 `http://127.0.0.1:4319/?case=B`를 연다. 포트가 이미 사용 중이면 `$env:PORT='4320'`으로 바꾼다. 실행 중인 터미널에서 Ctrl+C로 종료한다.

## 세 가지 접근

| 시안 | 시작 방식 | 유리한 상황 | 검토할 부담 |
|---|---|---|---|
| A. 선별 조립 | 빈 보고 옆의 캘린더에서 항목 선택, 복수 추가 또는 드래그 | 실제 업무 중 보고할 일부만 고르는 경우 | 과제가 많고 본문이 길면 보고 영역을 많이 스크롤함 |
| B. 과제 집중 | 고정된 과제 목록, 현재 과제의 편집창, 해당 과제의 원본 후보 | 여러 과제의 긴 내용을 오가며 작성하는 경우 | 원본과 편집을 위해 가로 공간이 필요함 |
| C. 초안 검토 | 캘린더의 과제별 내용과 시간을 채운 표, 필요한 행만 펼침 | 대부분의 캘린더 내용을 보고하는 경우 | 자동 포함된 내용을 실제로 검토하고 불필요한 항목을 제외해야 함 |

제안은 B의 과제별 작업 공간과 C의 초안 채우기를 결합하는 것이다. 사용자 확정은 아니다. 자동으로 모두 넣을지, 버튼으로 선택해서 넣을지는 다음 검토 사항이다.

## 눌러볼 것

1. 상단에서 과제 수를 3개, 8개, 15개로 바꾼다.
2. A에서 여러 원본 항목을 선택해 추가한다. 과제별로 나뉘는지 확인한다. 캘린더에 없는 내용은 직접 작성할 과제를 선택한다.
3. B에서 원본을 추가하고 문구를 수정한 뒤 다른 과제로 갔다가 돌아온다. 입력은 유지된다.
4. C에서 행을 펼쳐 문구를 고치거나 블록의 포함 체크를 끈다. 제출 내용 확인에서 제외 결과를 본다.
5. 기존 보고 편집을 선택한다. 저장된 문구를 우선하며 자동으로 캘린더 내용으로 교체하지 않는다. C의 다시 채우기는 별도 확인 후 교체한다.
6. 편집창을 닫고 배경 날짜를 누른다. 상세 화면을 거치지 않고 편집창이 열린다.
7. 일간보고를 주간보고로 바꿔 기간 후보와 차주 계획 입력을 확인한다.

상단 비교 방식, 과제 수, 시작 상태 및 날짜를 바꾸면 이 시안의 입력은 초기화된다. 실제 앱의 저장 및 날짜 전환 정책을 구현한 것이 아니다.

## 데이터와 제출 형태

- 가상 데이터만 사용하며 실제 캘린더 및 회사 시스템을 읽거나 쓰지 않는다.
- 일정 제목과 메모를 보고용 블록으로 복사한다. 블록 편집, 제외와 순서 변경은 원본에 반영하지 않는다.
- 같은 원본은 중복 추가하지 않는다. 보고에서 삭제하면 원본 후보에서 다시 추가할 수 있다.
- 시간은 날짜별 과제 시간의 예시 값이다. 캘린더 항목을 두 개 추가해도 같은 과제 시간을 두 번 합산하지 않는다.
- 제출 미리보기에서는 블록을 과제별 텍스트로 합친다. 새 블록 DB 스키마를 제안하거나 확정한 것이 아니다.
- 실제 제출 버튼 및 영구 저장은 없다. 회사 성공 후 DB 저장하는 기존 정책은 별도 [정본](../../ATTENDANCE-REPORT-POLICY.md)을 따른다.
