## 한 줄 요약

사용자가 지정한 로컬 개발/QA DB와 기존 실행 중인 구성원 편집 위젯으로 실제 저장 왕복 루프를 검증했다.

## 바뀐 것 (파일과 이유)

앱과 기존 시험 스크립트는 변경하지 않았다. 실제 루프 결과와 확인 범위를 이 보고서에 기록한다.

## 결정

- 사용자가 정한 것: 이 PC의 `localhost:3306/taskcalendar`는 개발/QA 전용이며, 해당 DB에서 기존 zz 시험과 정리를 실행해도 된다. 복제 DB와 별도 위젯은 필요하지 않다. 현재 위젯은 구성원 편집 브랜치로 빌드한 것이다. 구성원 관리 루프를 다른 시드로 두 번, UI 무결성 루프를 한 번 실행한다.
- 내가 정한 것(검토 필요): DB 읽기로 실제 구조 번호를 먼저 확인했다. 전달받은 정보의 17과 달리 실제는 19이며 앱과 일치했다. `db_updating=0`, MySQL 8.4.9를 확인했다. 이 시험을 위해 스키마 이관은 실행하지 않았다.
- CDP 9222에서 로그인된 실제 위젯과 `#uaTree` 존재를 읽기 전용으로 확인했다.
- 자격증명은 자식 프로세스 환경 변수로만 전달했다. 기존 루프의 mysql.exe 호출에 있던 비밀번호 인자는 메모리 래퍼에서 제거하고 `MYSQL_PWD`로 전달했다. 기존 SQL, UI 조작과 판정은 변경하거나 모의 처리하지 않았다. 비밀번호를 파일, 로그 또는 OS 명령줄 인자에 넣지 않았다.
