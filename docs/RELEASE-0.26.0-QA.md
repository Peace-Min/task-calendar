# 0.26.0 배포 전 점검(시니어 QA, 배포 담당 관점)

상태: 기획(2026-11-06 저녁, 사용자 지시 "이전 배포에 비해 작업이 너무 많아 불안하다. 배포 전 기획, QA, 위키"). 버전 갱신은 하지 않는다(지시 때). 결과는 이 문서 끝 "결과" 절과 `dist/qa-morning/release-0.26.0/`.

## 범위
- 기준: 마지막 배포 0.25.1(`8b273b5`, DB 구조 20). 지금 `feat/db-app` 은 커밋 50개, 파일 208개.
- DB: 구조 21(`cal_project_watch`, 관심 과제), 구조 22(일간보고 과제별 줄, 표 셋 삭제). 폐쇄망은 20 에서 22 로 한 번에 오른다(release SQL 이 v21, v22 조각을 차례로).
- 기능 묶음:
  1. 근태 탭: 취합(기간 취합, 월간 보고를 근태 [일간 | 주간 | 취합]으로), 월간 설정 띠, 취합 출처(이 앱 주간보고 DB).
  2. 근태 본문 수준과 문단 모양(이슈 #19), 작성 보조 B안, 가져오기 서식을 문단 모양으로.
  3. 주간보고: 임시저장까지 앱이 누르고 되읽기, 기존 글 수정은 진짜 글 번호, 일간 불러오기.
  4. 일간보고: 0시간 블록, 메모와 과제별 줄 저장, 이전 보고.
  5. 개인 달력: 오른쪽 날짜 패널(카드, 늘 보이는 머리), 보기 팝업과 밀린 할 일, 칸 일정과 할 일 합쳐 채우기, 선택 칸 테두리, 과제 옆 숫자 두 칸.
  6. 과제 탭: 다른 과제 읽기 전용 보기, 관심 과제.
  7. 스크롤 튐 근본 결함, 한글 조합 중 휠 스크롤.
  8. 공식 과제 연결: 공수 이관과 옛 과제 삭제.

## 위험(배포 담당 관점, 높은 순)
1. **DB 업그레이드 20 → 22**: 데이터를 지우는 단계(옛 일간 줄 DELETE, 표 셋 DROP)가 있고 연 뒤에는 되돌릴 수 없다. 20 상태에서 시작하는 실제 리허설이 아직 없다(지금까지는 21 에서 시작).
2. **Setup 과 SQL 사이 창**: Setup 을 먼저 올리면 새 앱이 구조 20 DB 를 보는 동안 막힘 문구가 맞게 나와야 한다. 0.25.1 앱은 구조 22 를 열지 않아야 한다.
3. **회사 사이트 자동화**(주간 임시저장, 글 번호): 이 PC 에서는 회사 사이트에 보낼 수 없어 폐쇄망 확인 목록으로만 남는다.
4. **바뀐 화면이 많다**: 근태 탭 구조, 날짜 패널, 보기 팝업. 회귀와 출렁임.
5. **문서와 실제의 어긋남**: 위키, 배포 절차, 사전 조회.
