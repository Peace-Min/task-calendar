# 과제 필터 다중 선택과 팝업형 필터 줄

상태: 구현 완료(2026-10-30, 브랜치 `feat/filter-multi`). 시안 `docs/prototypes/filterbar-proto-v3.html` 의 V2 카드(세션 "과제필터 UI 프로토타입" 에서 확정).

## 1. 배경

- 개인 탭 상단 필터 줄은 과제마다 칩을 늘어놓는다. 과제가 많으면 두 줄로 넘치고 스크롤이 생긴다. 단일 선택이라 두 과제를 함께 볼 수 없다.
- 오른쪽 할 일 탭에 두 번째 필터(`noteFilterCat`)가 따로 있고, 상단 필터와 서로 모른다. 상단에서 A 를 골라도 할 일 목록은 모든 과제다.
- 주간 과제별 줄(docs/PERSONAL-PEER-WEEK-VIEW.md)이 생기면서 "몇 개 과제만 골라 보기"의 쓸모가 커졌다.

## 2. 결정 (2026-10-30 사용자)

1. **팝업형 필터 줄(V2).** 줄은 한 줄(42px) 고정. 왼쪽에 폭 고정 "과제" 버튼(208px, 600px 미만 156px), 오른쪽에 고른 과제 칩(x 로 하나씩 빼기, 넘치면 `+N`). 줄바꿈, 높이 캡, 가로 스크롤, 오른쪽 페이드(`syncOverflowFade`)는 없앤다.
2. **다중 선택.** 팝업에서 여러 과제를 켜고 끈다. 버튼 글자: `전체`(모두) / `과제명`(하나) / `과제명 외 N`(여럿) / `선택 없음`(하나도 없음).
3. **팝업.** 맨 위 검색칸, 그 아래 [전체 선택] [전체 해제]. 목록은 기록 많은 순, 같으면 가나다순. 이번 달 기록 0건 과제는 구분선 뒤에 흐리게. 항목은 체크, 색점, 이름, 기록 수. 줄 폭이 480px 미만이면 줄 아래 꽉 찬 시트로 연다.
4. **할 일 탭의 과제 필터를 없앤다.** 할 일 목록은 상단 필터를 따른다(필터는 화면 전체에 하나). 드래그 손잡이(`.nd-filter-rs`)와 저장 키 `tc_filterMax` 도 없앤다.
5. **다른 사람 일정 창도 같다.** 같은 필터 줄이 그 사람의 과제로 그려진다. 내 일정 겹은 지금처럼 필터를 타지 않는다.

## 3. 동작 규칙

- **상태**: `filterCats` = 고른 과제 id 묶음(Set). `null` 이면 전체(필터 없음). 빈 묶음이면 선택 없음(아무 기록도 안 보인다). 저장하지 않는다(지금처럼 창을 다시 열면 전체).
- **통과 판정**: `passFilter` 와 할 일 거르기는 `filterCats === null || filterCats.has(categoryId)`. 분류 없는 기록(categoryId 없음)은 전체일 때만 보인다.
- **주간 과제별 줄**: 필터가 있으면 고른 과제의 줄만(빈 과제 줄 포함), "분류 없음" 줄은 전체일 때만. 열람 창 아래쪽 내 과제 줄은 필터와 무관하게 그대로.
- **할 일 탭**: 상단 필터로 거른다. 비었을 때 안내 "이 과제에 할 일이 없습니다" 는 필터가 있을 때 "고른 과제에 할 일이 없습니다".
- **상세 패널**: 기록 수 옆 "(필터 적용 중)" 은 전체가 아닐 때.
- **새 기록의 기본 과제**: 필터가 있으면 고른 과제 중 과제 목록 순서로 첫 번째, 아니면 지금처럼.
- **과제를 지우면** 그 id 를 묶음에서 뺀다. 묶음이 비면 전체로 돌린다(지운 과제 하나만 골라 두었던 경우).
- **사람을 바꾸거나 데이터를 새로 받으면**(지금 `filterCatId = null` 하는 자리) 전체로.
- **칩**: 전체일 때는 칩이 없다. 고른 과제마다 칩(색점, 이름, x). 줄에 다 안 들어가면 남는 개수만큼 `+N` 칩, 누르면 팝업을 연다.
- **키보드와 aria**: 버튼은 Enter, Space, ↓ 로 열고 검색칸에 포커스. 검색칸에서 ↓ 로 목록(listbox, aria-multiselectable, aria-activedescendant). 목록 ↑ ↓ Home End PageUp PageDown, Space/Enter 로 켜고 끄기. Esc, 바깥 클릭, Tab 으로 닫고 포커스는 버튼으로. 한글 조합 중 입력은 건너뛴다. 칩 줄은 toolbar(좌우 화살표).
- **문구 규칙**: 엠 대시, 띄어 쓴 가운데 점, 낫표 없음. 설명 문구를 넣지 않는다(docs/UI-FEEDBACK-ATTENDANCE.md).

## 3-1. 구현에서 정한 것

- 하나씩 다 켜서 모든 과제가 켜지면 전체(필터 없음)로 바꾼다.
- 마지막 칩을 x 로 빼면 선택 없음이 아니라 전체로 돌아간다. 선택 없음은 [전체 해제]로만.
- 칩 순서와 단추 글자의 첫 과제는 과제 목록 순서. 팝업 목록만 기록 많은 순.
- 팝업 목록 높이는 내용만큼, 상한(300px, 시트 360px)까지. 연 뒤에는 검색해도 높이를 바꾸지 않는다.
- 나란히 보기 주간의 같은 DB 과제 줄도 필터로 고른 과제만.
- 팝업 목록 클래스는 `.fb-opts`(`.fb-list` 는 문의 창 목록 이름).
- 저장 키 `tc_filterMax` 는 지우지 않는다(읽는 곳이 없어 무해).

## 4. 하지 않는 것

- DB, 호스트(C#), 버전은 바꾸지 않는다.
- 과제 탭(`#pcView`)의 과제 체크 목록과 근태 탭은 그대로다.
- 필터를 저장해 두지 않는다.
