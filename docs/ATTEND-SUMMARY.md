# 근태 탭 취합 (기간 취합과 월간 보고를 하나로) + 주간보고 목록 찾기 (0.26.0)

상태: 구현 완료(2026-11-03). 기획 확정은 같은 날 사용자(시안 dist/proto/merge-report.html). 관련 이슈 #17.

**2026-11-03 사용자 결정(뒤집힘): 캘린더 기록은 앱 주간보고 DB.** 아래 2번과 6번에서 "캘린더 기록"은 달력의 일정과 할 일이 아니라 **이 앱의 주간보고 DB(`cal_report_weekly`, 근태 [주간]에서 쓰고 보낸 주)** 를 읽어 과제별로 모은 것이다. 달력의 일정과 할 일을 하루 단위로 모으는 출처는 취합에서 없앴다(셋째 출처로도 남기지 않음). 그래서 **포함 항목 칸(일정, 할 일, 설명, 빈 과제 빼기)도 없앴다**(어느 출처에서도 쓰이지 않는다). 아래 본문 중 이와 어긋나는 줄은 이 결정이 이긴다. 구현은 본문 끝 "7. 출처 정의(2026-11-03)".

## 1. 배경

- 보고서 창에는 기간 취합과 월간 보고 두 탭이 남아 있다(일간, 주간 작성은 2026-10-30 근태 탭으로 옮김).
- 두 탭은 겹친다. 월간 보고의 수행 실적은 기간 취합 탭의 설정(출처, 포함 항목)으로 만든 그 글이다. 기간 고르기와 읽어 오기를 두 번 따로 한다.
- 보고는 모두 근태 탭으로 모은다는 방향(메모리: Reports into attendance tab)과 #17 의 "근태 영역에서 작성, 조회까지"에 맞춘다.

## 2. 결정

- 근태 탭 머리의 [일간 | 주간] 에 **취합**을 더해 [일간 | 주간 | 취합] 으로 한다. 툴바의 **보고서 버튼과 보고서 창을 없앤다.**
- 취합 화면은 왼쪽 설정, 오른쪽 미리 보기(가운데 끌개, 근태 화면의 끌개와 같은 공용 방식).
- 왼쪽(위에서부터):
  - **기간**: 날짜 칸 두 개만. 빠른 단추(이번 달, 지난달 등)는 두지 않는다. 처음 값은 지난달 1일~말일.
  - **내용 출처**: [캘린더 기록 | 인트라넷 주간] 둘. 인트라넷 일간은 뺀다. 캘린더 기록은 이 앱 주간보고 DB, 인트라넷 주간은 회사 사이트(2026-11-03 사용자).
  - ~~포함 항목: 일정, 할 일, 설명, 빈 과제 빼기~~ (2026-11-03 없앴다. 출처를 바꿀 때 칸이 생기거나 사라지지 않게 아예 없앤다).
  - **읽어 오기**.
  - **월간 보고 문서 설정**(오른쪽 결과 형태가 문서일 때만 맨 아래에 펼침): 계획 기간, 작성일, 이름(읽기), 과제(내 과제 순서, 그림 넣기), 기타 표 고르기. 지금 월간 보고 탭의 규칙 그대로.
- 오른쪽 위: **결과 형태 탭 [과제별 글 | 월간 보고 문서]** 와 같은 줄 끝의 내보내기 단추([복사] / [DOCX 저장], 저장 뒤 [폴더 열기]). 탭은 바꾸는 대상(미리 보기) 바로 위에 둔다(UX 검토).
- 기본 결과 형태는 과제별 글.
- 인트라넷 주간 읽기 상한 400일은 그대로.

## 3. 주간보고 목록 찾기 (#17 남은 것)

- 근태 [주간] 목록에 기간 고르기와 찾기를 더한다.
  - 기간: 최근 3개월, 올해, 전체, 직접 지정. 처음은 최근 3개월. 판정은 보고 대상 기간(period_start~period_end)이 고른 기간과 겹치는지(작성일로 주를 추정하지 않는다).
  - 찾기: 제목과 본문(진행사항, 차주계획, 회의내용, 과제투입시간 과제명) 글자 포함.
  - 결과 수 표시, 페이지 이동(한 쪽 20건).
  - 조회 가능한 최초 기록까지 간다(이 앱 DB 기록 기준. 회사 사이트에서 직접 쓴 글은 없다).
- 목록 읽기는 지금 `reportWeeklyList`(기간) 를 그대로 쓰고 범위만 넓힌다. 호스트 상한(ReportDb.ListMaxDays)이 모자라면 나눠 읽는다.

## 4. 구현 원칙 (새로 만들지 않는다)

- **기간 취합과 월간 보고의 기존 함수와 화면 조각을 옮겨 쓴다.** 글 만들기(`buildReport`, `collectReportData` 등), 월간 보고(rptm* 함수, DOCX, 그림)를 다시 짜지 않는다. 담는 그릇(보고서 창 → 근태 탭 영역)과 탭 배치만 바꾼다.
- 공용 달력(CALENDAR-COMMON), 공용 끌개, 공용 토큰을 쓴다. 새 hex 색 금지.
- 보고서 창에만 있던 옛 일간, 주간 작성 탭(숨김)과 그 전용 코드는 이번에 같이 걷는다(위키 "지운 기능"에 기록). 걷기 전에 근태 화면이 그 함수를 쓰는지 확인한다.

## 5. 하지 않는 것

- 인트라넷 일간 출처, 기간 빠른 단추.
- 월간 보고 문서 양식 변경.
- DB 구조 변경.

## 7. 출처 정의(2026-11-03 사용자)

- **캘린더 기록 = 이 앱의 주간보고 DB.** `reportWeeklyList`(근태 주간 목록과 같은 호스트 읽기)로 기간과 겹치는 주(`periodStart`~`periodEnd` 가 [시작, 끝] 과 겹침)를 읽어 과제별로 모은다. 달력의 일정과 할 일을 하루 단위로 모으지 않는다. 회사 사이트로 가는 요청은 없다. 위젯에서만 된다(브라우저는 위젯 안내).
- **인트라넷 주간 = 회사 사이트 주간보고**(`netcusWeeklyRangeRead`). 지금 그대로다. 호스트도 기간 겹침(`ps <= to && pe >= from`)으로 주를 고르므로 두 출처의 주 고르기 규칙이 같다.
- 읽은 행은 `parseNetcusWeekly` 가 받는 모양으로 바꾼다: `endwork` 그대로, `content` 는 hours 표가 있으면 `[과제] : 시간` 줄(없으면 글 그대로), `title`=제목, `period`=`시작 ~ 끝`, `regdate`=작성 시각. 그 뒤는 인트라넷 주간과 같은 코드(과제별 글 미리 보기, 복사, 월간 보고 문서의 과제와 기타 표, 미식별 항목)다. 결과는 같은 그릇(`netcusWeeklyMerge`)에 두고 열쇠에 출처가 들어가 두 출처가 섞이지 않는다.
- 읽기는 둘 다 [읽어 오기]를 눌렀을 때만이다. 기간을 바꾸면 읽어 둔 글은 버려지고, 출처만 바꾸면 그 출처로 읽은 글이 없을 때 미리 보기는 읽어 오기를 기다린다.
- 읽은 주가 없으면 `이 기간에 이 앱으로 쓴 주간보고가 없습니다.` 한 줄.
- 호스트 상한(`ReportDb.ListMaxDays` 400일)을 넘는 기간은 나눠 읽는다(근태 주간 목록과 같은 함수 `awRowsFetch`, 시작 쪽을 한 주 더 읽어 겹치는 주를 놓치지 않는다).
- **걷은 것**: 포함 항목 칸(`#asInc`, `#rptSrcEvent`, `#rptSrcTodo`, `#rptWithDesc`, `#rptSkipEmpty`)과 저장 함수(`rptSources`, `normRptSrc`, `loadRptSourcePrefs`, `applyRptSourcePrefs`, `saveRptSourcePrefs`), `atSumIncSync`, `rptMBuildCal`, 취합 전용 일정 글(`buildReport` 의 캘린더 경로), 날짜별 설명 고치기(`commitDayNoteEdit`, `reportDayLinesHtml`, `reportDetailsHtml`, 편집 키).
- **남긴 것**: `collectReportData`, `reportRowBodyText`, `reportMarkerSpec` 은 근태 일간 가져오기(캘린더)가 쓴다. 서식 중 글꼴은 과제별 글 복사에 쓰인다. 머리기호와 들여쓰기는 이제 취합 글에 쓰이지 않아 화면에서 숨기고(요소는 근태 가져오기 서식 목록이 선택지를 복제해 가므로 남김), 뒤 작업에서 목록 정의를 옮기면 지운다. 월간 문서의 기타 표 규칙은 인트라넷 주간과 같다(공식 과제가 아닌 내 카테고리, 이름이 같은 머리만, 나머지는 미식별).
