# 월간보고 HW 양식 추출과 SW 양식 대조

작성 2026-11-10. 상태: 분석과 기본 템플릿 추출까지. 구현(양식 고르기 SW/HW)은 다음 단계.

## 0. 한 줄 요약

HW 양식은 SW 양식과 **표 뼈대(격자 7열, 세 본문 칸)는 같고**, 머리 줄, 개발 일정, 변경이력, 기타 표, 제목, 글머리가 다르다.
그래서 `DocxWriter` 에 양식 하나를 더 그리는 함수(HW)를 두고, 웹 payload 는 거의 그대로 쓰는 방향이 맞다.

## 1. 입력

- HW팀 한 사람이 쓴 월간보고 PDF 3건(파일 이름 표기 05월, 08월, 09월, 2026년). 저장소에 두지 않는다(실제 과제명, 동료 이름 포함).
- 세 PDF 모두 문서 메타데이터 제목이 `Microsoft Word - ...doc(x)`, 만든 곳 `Hancom PDF`. 즉 **원본은 Word 문서**를 한컴 PDF 로 인쇄한 것이다(SW 양식과 같은 사정).
- 측정은 `pdfplumber` 로 표 선 좌표, 칸 배경색, 글꼴 이름과 크기를 읽었다. 세 보고서의 열 폭은 0.1pt 안에서 같다(05월만 표 전체가 왼쪽으로 5.7pt 옮겨져 있다).
- 아래 예시 값은 모두 지어낸 `(예시)` 값이다.

## 2. 한눈에 보는 차이

| 항목 | SW (지금 앱) | HW (추출) |
|---|---|---|
| 제목 | `월간보고 (이름) [구분] 2026년 09월 08일`, 굵게 12pt, 밑줄 | `월간보고 [구분] H/W팀 (이름) [구분] 2026년 9월 8일`, 굵게 **14pt**, 밑줄. 월, 일 **앞 0 없음** |
| 제목 아래 기간 줄 | 없음 | `[ 2026. 8. 17 ~ 2026. 10. 2 ]` 맑은 고딕 11pt 가운데. **실적 기간** |
| 계획 기간 | 표 머리 `월간 계획: MM월 DD일 ~ MM월 DD일` | **어디에도 없음** |
| 표 맨 윗줄(연파랑 #DBE5F1) | 과제명 / 월간 실적: 기간 / 월간 계획: 기간 | **없음**(파랑 배경 자체가 없다) |
| 과제 수행 기간 값 | `YYYY/MM ~ YYYY/MM` | `YYYY년 M월 ~ YYYY년 M월`, 끝이 없으면 `YYYY년 M월 ~` |
| 개발 일정 | 그림 칸(사람마다 과제당 5장) | **작은 표**: 머리 `개발 항목 / 시작 / 종료 / 상세 내용` + 빈 줄 1개. 세 보고서 모두 비어 있음. 그림 없음 |
| 일정 변경이력 | 머리 + 이력 줄(없으면 빈 줄 1개) | **없음** |
| 본문 칸 이름 줄 | 회색 #F2F2F2, 굵게 | **흰 바탕**, 굵게 |
| 세 본문 칸 폭(pt) | 175.5 / 275.5 / 182.1 | 198.3 / 233.7 / 233.5 (실적과 오른쪽 계획이 같은 폭) |
| 왼쪽 수행 계획 | 실제 보고서는 비어 있음 | 지난 계획의 **분류 머리만**(`● 설계`, `● 유지보수` 등) 적는다. 빈 `●` 하나만 둔 달도 있음 |
| 오른쪽 수행 계획 | 비어 있음(사용자가 Word 에서) | 항목까지 자세히 씀 |
| 기타 표 | 2열: `과제명 / 월간 실적: 기간` 머리 + `기타` / 본문 | 과제 표와 같은 3칸: 얇은 회색 빈 줄 + `수행 계획 / 수행 실적 / 수행 계획` + 본문 |
| 글머리(본문) | `▪` 분류, `1.` 묶음, `-` 항목, `;` 세부 | `●` 분류, `-` 항목, `:` 세부, `.` 그 아래(4단) |
| 날짜 표기(본문) | 회의 `(09.15, 장소)` | 일 `(9/23)`, 기한 `(~ 9/30)` |
| 같이 한 사람 | `(w. 이름 직급)` | 같음 `(w. 이름 직급)` |
| 파일 이름 | `월간보고_<이름>_<YYMMDD>.docx` | `<YY>년_<MM>월_월간보고_<팀 이름>_<이름>` (팀 이름은 제목의 `H/W팀` 이 아닌 소속 팀 이름) |
| 용지, 글꼴 | A4 가로, 맑은 고딕 10pt | 같음 |

공통점(바꿀 필요 없음): A4 가로, 맑은 고딕 10pt 본문, 칸 이름 굵게 10pt, 과제마다 표 하나와 표 뒤 빈 문단, 과제명 칸 세로 병합, 본문 칸 세 개(왼쪽 계획, 실적, 오른쪽 계획), 맨 끝 기타 표, 얇은 검정 실선 테두리, 회색 #F2F2F2.

## 3. HW 기본 템플릿(추출 결과)

### 3.1 쪽

- 용지 A4 가로(841.9 x 595.3 pt), 방향 landscape.
- 왼쪽 여백 약 2cm(56.7pt, 1134 twip). 05월 보고서만 약 1.8cm.
- 제목 가운데가 쪽 가운데와 거의 같아(420.4pt) 오른쪽 여백도 약 2cm 로 보인다. 그런데 표 폭(736.3pt)이 글 영역(약 728.5pt)보다 약 8pt 넓어 **표가 오른쪽 여백으로 조금 나간다**. 생성할 때는 오른쪽 여백을 960 twip 안팎으로 줄여 표가 안에 들어가게 하는 것을 권한다(제목 가운데가 4pt 옮겨지는 정도).
- 위 여백 약 2cm(추정, 쪽 맨 위 첫 줄 위치에서).
- **SW 여백(왼쪽 1800, 오른쪽 1440 twip, 글 영역 680pt)으로는 HW 표가 들어가지 않는다.** 여백은 양식마다 따로 둔다.

### 3.2 제목과 기간 줄

```
월간보고 [U+2013] H/W팀 (이름) [U+2013] 2026년 9월 8일      맑은 고딕 굵게 14pt, 가운데, 밑줄
[ 2026. 8. 17 ~ 2026. 10. 2 ]                                맑은 고딕 11pt, 가운데
(빈 문단, 굵게 12pt)
```

- 구분 기호는 SW 와 같은 U+2013 이다(문서 표기 규칙상 여기 글자로 적지 않는다).
- `H/W팀` 은 양식 고정 글자로 본다. 날짜는 **작성일**, 앞 0 없이.
- 기간 줄은 실적 기간이다. 형식 `[ YYYY. M. D ~ YYYY. M. D ]`(대괄호 안쪽 공백 하나, 점 뒤 공백 하나, 앞 0 없음).
- 세 보고서의 기간: 6주, 5주, 7주. 모두 월요일 시작 금요일 끝이고, 앞 보고서 끝 다음 월요일에 이어진다. 작성일은 실적 끝 다음 월요일이나 화요일. SW 와 같이 **달력의 한 달이 아니다.**

줄 구성:

| 줄 | 칸(격자 열) | 배경 | 높이 |

| 2 | (병합) / `개발` `일정`(2열, 두 줄 글, 2~3줄 세로 병합) / `개발 항목`(3열) / `시작`(4열) / `종료`(5열) / `상세 내용`(6~7열), 모두 굵게 가운데 | #F2F2F2 | 17.2pt |
| 3 | (병합) / (병합) / 빈칸 / 빈칸 / 빈칸 / 빈칸 | **#F2F2F2**(빈 줄도 회색) | 17.3pt |
| 4 | (병합) / `수행 계획`(2~3열) / `수행 실적`(4~6열) / `수행 계획`(7열), 굵게 가운데 | **흰색** | 19.0pt |

- 과제명 값 글자는 맑은 고딕 10.5pt(PDF 에 10.6 으로 찍힘), 가운데. 실제 보고서는 `발주처` `-` `과제명` 을 줄을 나눠 쓴 경우가 있다(앱은 SW 와 같이 공식 이름 그대로 넣으면 된다).
- 본문 칸 최소 높이가 커서 **사실상 과제마다 한 쪽**이다. 본문이 길면 다음 쪽으로 이어지고(09월 보고서 두 과제), 이어진 쪽에는 머리 줄이 되풀이되지 않는다.
- 개발 일정 표는 세 보고서 모두 비어 있다. 데이터 줄은 1개뿐이다.
- 표 사이는 빈 문단(굵게 12pt) 하나.

### 3.4 기타 표

| 줄 | 칸 | 배경 | 높이 |
|---|---|---|---|
| 1 | `기타`(1열, 끝까지 세로 병합, 가운데, 10pt) / 빈칸(2~3열) / 빈칸(4~7열) | 2열 이후 #F2F2F2. 글자 5pt 빈 문단이라 얇다 | 13.7pt |
| 2 | (병합) / `수행 계획` / `수행 실적` / `수행 계획`, 굵게 가운데 | 흰색 | 21.3pt |
| 3 | (병합) / 본문 세 칸 | 흰색 | 최소 약 156pt |

- 과제 표에서 과제 수행 기간 줄을 비우고 개발 일정 줄을 지운 모양이다. 1줄의 얇은 회색 빈 줄도 원본 그대로 둔다.
- 세 보고서 모두 실적 칸만 씀. 계획 두 칸은 한 번(08월) 왼쪽 계획에 쓴 적이 있다.

### 3.5 본문 글 모양(4단)

칸 안쪽 왼쪽 끝 기준(안쪽 여백 약 5.2pt 뒤) 위치:

```
● 분류                       ● 위치 +0,   글자 +11.4pt   (Word 글머리 기호, Wingdings 0x6C)
  - 항목                     - 위치 +8.5, 글자 +19.8pt, 줄 넘김도 +19.8
    : 세부                   : 위치 +19.8(항목 글자 줄과 같음), 줄 넘김도 +19.8
     . 그 아래               . 위치 +25.4
```

- 1단과 2단은 원본에서 Word 글머리 목록이다(`●` 뒤, `-` 뒤 간격이 Arial 탭). 3단 `:` 와 4단 `.` 는 손으로 친 글자다.
- 앱은 SW 와 같은 원칙으로 **글자를 그대로 두고 줄 앞 들여쓰기만 문단 들여쓰기로 바꾸면** 된다. Word 자동 목록은 쓰지 않는다. `●`(U+25CF)는 맑은 고딕에 있어 깨지지 않는다.
- 분류 묶음 사이는 빈 줄 하나.
- 자주 쓴 분류 머리(이름만): 유지보수, 정기점검, 예비 시재 점검, 기능 보완, 설계, 구현, 문의 대응, 교육 참석, 매뉴얼 작성.

빈 템플릿 예시(지어낸 값):

```

┌────────┬──────────────────────┬──────────────────────────────────────────┐
│        │    과제 수행 기간     │          2026년 3월 ~ 2026년 12월         │
│        ├──────┬───────────────┼────────┬──────┬──────────────────────────┤
│ (예시) │ 개발 │   개발 항목    │  시작  │ 종료 │         상세 내용         │
│  장비  │ 일정 ├───────────────┼────────┼──────┼──────────────────────────┤
│ 유지보수│      │               │        │      │                          │
│        ├──────┴───────────────┼────────┴──────┴─────────┬────────────────┤
```

(위 그림의 `-` 구분은 실제 문서에서 U+2013 이다.)

## 4. 앱 데이터와의 연결(HW 를 고를 때)

| HW 칸 | 채우는 곳 | SW 와 비교 |
|---|---|---|
| 제목 이름 | 로그인 이름 | 같음 |
| 제목 날짜 | 작성일(앞 0 없음) | 형식만 다름 |
| 기간 줄 | 실적 기간 | SW 는 표 머리에 찍음 |
| 계획 기간 | **쓰지 않음** | HW 를 고르면 계획 기간 고르기를 숨김(5장) |
| 과제명 | 공식 이름 | 같음 |
| 과제 수행 기간 | `project.dev_start_date ~ dev_end_date` 를 `YYYY년 M월` 로. 끝이 비면 `YYYY년 M월 ~` | 같은 DB 칸, 형식만 다름 |
| 개발 일정 | **빈 표**(머리 + 빈 줄 1개) | SW 의 그림 서랍은 HW 에서 쓰지 않음 |
| 일정 변경이력 | 없음 | payload `changes` 무시 |
| 왼쪽 수행 계획 | 빈칸 | 같음(앱이 지난 계획을 모르기 때문) |
| 수행 실적 | 기존 취합 글 그대로 | 같음 |
| 오른쪽 수행 계획 | 빈칸 | 같음 |
| 기타 표 | 실적 칸에 기존 기타 글, 계획 두 칸 빈칸 | 표 모양만 다름 |

- 웹 payload(`exportMonthlyDocx`)는 `template: 'sw' | 'hw'` 하나만 더하면 된다. 나머지 필드는 그대로, 호스트가 양식별로 무시할 것을 무시한다.
- 실적 글의 글머리 모양은 사용자의 보고 서식 설정(근태 가져오기 서식 포함)을 따르므로 양식과 따로 논다. HW 사람이 `●`, `-`, `:` 로 주간보고를 쓰면 그대로 나온다.

## 5. 결정(2026-11-10, 사용자)

시안: [prototypes/monthly-template-hw.html](prototypes/monthly-template-hw.html)(앱 코드는 바꾸지 않았다).

1. **양식은 기억하지 않는다.** 문서 설정 띠 첫 줄 맨 앞에 `양식 [SW | HW]` 세그를 두고, 열 때마다 SW 로 시작한다. 쓸 때마다 고른다(MONTHLY-REPORT-PLAN 5.4 의 "기억하는 값 없음"과 같다). 띠 머리 요약 맨 앞에 `SW 양식` 또는 `HW 양식`.
2. **파일 이름은 두 양식 모두 SW 규칙** `월간보고_<이름>_<작성일 YYMMDD>.docx`(초안). HW 실제 관례(`<YY>년_<MM>월_월간보고_<팀>_<이름>`)는 나중에 다시 본다.
3. **HW 를 고르면 계획 기간과 개발 일정 그림(과제 줄의 그림 단추, 서랍)을 숨긴다.** 계획 칸은 첫 줄의 맨 끝으로 옮겨, 숨겨도 앞 칸(양식, 작성일, 이름)이 움직이지 않는다. 열어 둔 그림 서랍은 HW 로 바꾸면 닫힌다. 그림은 DB 에 그대로 있고 SW 로 돌아오면 다시 보인다. 계획 기간 값도 그대로 남는다(SW 문서에만 쓰인다).
4. 미리 보기는 양식을 바꾸면 바로 다시 그린다. 상태 줄 문구(`과제 n개와 기타 표를 저장합니다`)는 양식과 상관없이 같다.

## 6. 남은 것(구현 때)

1. **제목의 팀 글자**: HW 는 `H/W팀` 고정으로 둔다. SW 양식 제목은 지금처럼 팀 글자 없이 둔다.
2. 여백: 3.1 대로 HW 오른쪽 여백을 줄여 표를 글 영역 안에 넣을지, 원본처럼 조금 넘치게 둘지.
3. 호스트: `exportMonthlyDocx` payload 에 `template` 하나를 더하고, `DocxWriter` 에 HW 그리기(제목, 기간 줄, 과제 표, 기타 표, 여백)를 더한다. HW 에서는 그림을 찾지 않는다.
