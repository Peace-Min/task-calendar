# 개인 캘린더: 일정·할 일 보기와 선택형 우측 패널

> 2026-10-22 보완. 관련: [이슈 #15](https://github.com/Peace-Min/task-calendar/issues/15), [이슈 #14](https://github.com/Peace-Min/task-calendar/issues/14).
> **현재 앱 기능·DB는 변경하지 않았다.** 이 문서는 후속 구현의 범위와 검증 기준이며, 첨부 화면은 가상 데이터를 사용하는 동작 시안이다.

## 1. 실제 검토 피드백과 문제

검토 대화는 다음 순서였다.

1. 일정과 할 일을 나눈 이유를 질문했다.
2. 할 일은 액션 아이템처럼 완료 체크를 하고 완료 상태를 화면에 표시하기 위한 것이라고 설명했다.
3. 검토자는 구분의 의미를 이해했지만, 달력에 두 종류가 섞여 복잡하므로 명시적인 탭 분리를 제안했다.
4. 사용자는 탭으로 분리하더라도 동시에 보고 싶은 경우가 있고, 현재 화면이 난잡하다는 느낌에도 동의했다.

따라서 우선 해결할 문제는 **입력 전에 종류를 고르는 부담으로 확정된 것이 아니라, 일정·할 일이 섞인 화면의 가시성과 동시 조회**다. 종류의 필요성을 인정하면서 표시 대상을 선택할 수 있게 한다.

이슈 최초안의 `완료 상태 관리` 체크박스 중심 입력 통합은 이번 보완안의 구현 선행조건이 아니다. 보기 방식과 입력 모델 변경을 별도 결정으로 다룬다.

## 2. 기존 앱 확인과 유지할 구조

`feat/db-app`의 앱 본체 `task-calendar-prototype.html`을 브라우저에서 가상 데이터로 실행하고, 일정 상세·할 일 패널을 확인했다. 이는 실제 WPF 호스트·사내 DB의 검증이 아니다.

- 상단: 제품명, 월 이동·오늘·연월 선택, 검색·내 과제·사용자·모양·보고서·새 기록 등 기존 진입점.
- 가로 과제 필터. 새 좌측 사이드바로 바꾸지 않는다.
- 본문: 일요일 시작 월 달력, 분할바, 우측 `일정 상세 / 할 일 / 커밋 내역`.
- 일정은 과제 색상·시각·카드, 할 일은 속 빈 칩·기간 연결·완료 체크·중요 표시를 유지한다.
- 날짜 선택은 패널의 기준 날짜를 바꾼다. 펼친 패널에서 칩을 누르면 해당 탭·항목을 확인한다.

앞선 시안의 좌측 과제 사이드바, 기본 주간 화면, 하단 목록·상세 배치는 기존 앱의 변경안으로 채택하지 않는다. 개인 주간 보기는 #14에서도 이번 범위 밖이다.

## 3. 달력 보기: 전체 / 일정 / 할 일

달력 영역 상단에 `달력 표시: 전체 / 일정 / 할 일`을 둔다. 서로 다른 저장소나 독립된 달력을 만들지 않고 **같은 데이터의 표시 대상만 바꾼다**.

| 보기 | 달력에 표시할 항목 |
|---|---|
| 전체 | 일정과 할 일을 함께 표시 |
| 일정 | 회의·약속 등 기존 일정만 표시 |
| 할 일 | 완료 체크 대상 업무만 표시 |

- 기존 사용자의 첫 기본값은 `전체`. 이후 선택은 계정별 PC UI 설정으로 기억한다.
- 보기 전환으로 선택 날짜·월·과제 필터·항목 데이터·미저장 입력을 초기화하지 않는다.
- 상단 과제 필터는 달력의 표시 범위를 정한다. 패널의 기존 별도 과제 필터 계약과 혼동하지 않는다.
- 달력 보기와 우측 기능 탭은 범위가 다르다. **달력 보기를 바꿨다는 이유만으로 우측 탭을 강제로 전환하거나 패널을 열지 않는다.** 사용자가 칩이나 패널 바로가기를 선택할 때 필요한 탭을 연다.
- 일정만 보는 동안에도 할 일·커밋 내역 진입점은 유지한다. `일정만 보기`는 할 일 기능을 끄는 동작이 아니다.
- 과제 색상, 시각·기간·중요도 등 기존 표현을 유지한다. 전체 보기의 복잡함이 탭 추가만으로 해결됐다고 가정하지 않는다.

## 4. 우측 패널: 기능 유지, 공간은 선택

#14의 범위를 그대로 따른다. **공용 화면은 상시 상세 패널 공간을 예약하지 않고, 개인 화면은 접기/펼치기를 제공한다.** 개인의 할 일·커밋 내역 기능까지 삭제하는 요구가 아니다.

### 펼친 상태

- 기존 `일정 상세 / 할 일 / 커밋 내역`과 날짜별 조회·편집 동작을 유지한다.
- `패널 접기`를 눈에 보이는 위치에 제공한다.
- 기존 사용자의 첫 기본 상태는 펼침. 이후 접힘 상태는 계정별 PC 설정으로 기억한다.
- 할 일을 연속 체크하거나 커밋을 검토할 때는 펼쳐 둔 채 작업할 수 있다.
- 기존 너비 조절과 포커스·키보드 접근을 보존한다. 시안의 고정 분할바는 제품에서 너비 조절을 없앤다는 결정이 아니다.

### 접힌 상태

- 패널과 분할바의 예약 폭을 제거해 달력이 실제로 넓어진다. 빈 패널 자리나 넓은 아이콘 전용 열을 남기지 않는다.
- 선택 날짜와 `일정 상세 / 할 일 / 커밋 내역` 바로가기, `패널 펼치기`를 항상 접근 가능한 위치에 둔다.
- 바로가기를 누르면 선택 날짜의 해당 탭을 연다. 날짜·월·달력 보기·과제 필터는 유지한다.
- 날짜를 선택하거나 달력 보기를 바꾸는 것만으로 패널이 다시 열리지 않는다.
- 칩을 누르면 패널을 강제로 펼치지 않고 해당 항목의 빠른 미리보기를 연다.
- 미리보기에는 제목·과제·날짜/기간·시각·장소·메모 최대 3줄을 표시한다. `상세 보기`와 `패널에서 보기`를 제공한다.
- `상세 보기`는 전체 메모와 항목 정보를 열고, 수정으로 연결한다. 패널은 접힌 상태를 유지한다.
- `패널에서 보기`를 명시적으로 선택하면 해당 날짜·탭·항목을 열고 강조한다.
- 할 일 미리보기에서 완료 체크와 취소가 가능하다. 체크 후 항목이 달력에서 숨겨져도 미리보기에서 취소할 수 있어야 한다.
- 바깥 클릭·닫기·Esc로 미리보기를 닫는다. 화면 경계를 벗어나지 않으며 호버에만 의존하지 않는다. 키보드로도 열고 닫을 수 있어야 한다.

### 좁은 화면

- 기존 하단 시트 동선을 유지한다. 시안을 근거로 상시 하단 목록을 새로 만들지 않는다.
- 패널 바로가기와 칩 미리보기에 계속 접근할 수 있고, 시트 닫기로 달력 공간을 되찾는다.
- 320/390/760/800/1024px에서 버튼·탭·미리보기·등록창의 잘림과 가로 넘침을 확인한다.

## 5. 완료 표시와 기존 기능 보존

- 달력의 `완료 표시`는 시안에서 기본 끔이다. 완료 상태나 데이터 자체를 삭제하지 않는다.
- 완료 항목은 패널의 완료 구역·상세·기존 보고서 경로에서 계속 확인한다. 완료 취소도 가능해야 한다.
- 반복·예외·알림·종일·장소·Git/SVN·날짜별 설명·중요도·공수·근태·검색·보고서·XML·다른 사람 일정 열람을 보존한다.
- 이번 보기 개선 때문에 `cal_entry`와 `cal_todo`를 합치거나 자동 재분류하지 않는다. 스키마 변경은 전제하지 않는다.
- 브라우저 시안의 배열 수정·전체 재렌더·삭제 처리를 제품의 저장·권한·동시성 설계로 복제하지 않는다.

## 6. 최초안에서 분리해 남길 검토

다음 문제의식은 유지하되 이번 보기·패널 개선의 필수 구현으로 섞지 않는다.

- `완료 상태 관리`로 일정/할 일 입력을 통합할지, 기존 종류 선택을 유지할지. 현재 시안은 기존 종류 선택을 유지한다.
- 작업 시작·종료, 별도 마감, 실제 완료일, 진행 기록 날짜의 의미와 저장 방식.
- `due`가 단일 할 일에서는 기한, 기간 할 일에서는 시작일인 현재 모델의 지남 판정.
- ‘이 날 완료’가 실제 완료일이 아니라 해당 날짜를 포함하는 완료 업무를 묶는 현재 라벨과 데이터의 관계.
- 계획 기간 밖 날짜별 기록 보존, 완료 시각이 없는 구파일, 완료 관리 해제 시 이관 정책.
- 날짜별 기록과 실제 완료일의 보고서 집계, 기간 막대·마감의 중복 집계 방지.
- `오늘의 약속 / 오늘·내일 마감` 요약, 별도 마감 필드, 작업 기간 표시 토글은 이번 화면의 확정 요소가 아니다.

예를 들어 작업 기간이 10/19–23, 별도 마감이 10/26인 업무를 10/22에 마감 지연으로 취급해서는 안 된다. 다만 현재 DB에 이 분리를 구현했다고 주장하지 않는다. 기존 종료일을 확정 마감으로 자동 해석하거나, 기간 변경 때문에 기록·완료일을 버려서는 안 된다.

## 7. 프로토타입과 검증 범위

- [브라우저 실행용 프로토타입](prototypes/personal-calendar-ux.html): 다운로드해 브라우저로 연다. 실제 앱에 삽입할 제품 코드가 아니다.
- [시안 동작 점검](prototypes/personal-calendar-ux.check.cjs): 기존 테스트 의존성이 있는 개발 환경에서 저장소 루트의 `node docs/prototypes/personal-calendar-ux.check.cjs`로 실행한다.
- 모든 과제·일정·할 일·커밋은 가상 데이터이며, 오늘은 **2026-10-22**로 고정되어 있다.
- 편집은 메모리에만 유지되고 새로고침하면 초기화된다. PC UI 선택 복원은 미리보기 환경의 지원 여부에 따라 다르다.
- 기존 앱 UI는 원본 브라우저 실행으로 확인했다. 새 시안은 원본 전체 기능의 복제물이 아니며, 관리·회사 보고 전송·권한·DB·반복·알림 등을 검증하지 않았다.
- 시안의 `보고서`는 가상 할 일의 최소 미리보기다. 실제 보고서의 항목·출처 선택·편집·형식·전송을 대체하지 않는다.
- 상단 도구줄을 유지하기 위한 일부 보조 버튼은 위치 확인용 안내만 연다. 실제 기능 구현 완료로 읽지 않는다.

확인한 동작:

- 전체/일정/할 일 전환, 선택 날짜 유지, 달력 보기와 우측 탭의 독립성.
- 패널 접기/펼치기와 바로가기 3종, 접힌 상태 날짜 선택, 칩 미리보기·상세·명시적 패널 열기.
- 완료 체크·취소, 날짜별 메모 편집 보존, 신규 입력 날짜 검증, 월 이동·오늘·과제 필터.
- Edge에서 1024px 화면의 달력 폭이 패널 펼침 **약 677px → 접힘 1006px**으로 증가하는 것을 측정했다. 이는 시안의 해당 창 크기에서의 값이며 제품의 고정 규격이 아니다.
- Edge에서 320/390/760/800/1024px의 문서 가로 넘침이 없고, 좁은 화면에서 하단 시트 열기/닫기가 동작함을 확인했다.

실앱 DB 저장·재시작 유지·보고 전송·레거시 회귀·사용성 개선 효과는 미검증이다. 동일 데이터의 탐색 시간·누락·반복 클릭 등을 비교한 뒤 효과를 판단한다.

## 8. 실앱 구현 수용 기준

- [ ] 기존 상단 도구줄·가로 과제 필터·월 달력·우측 기능 탭을 유지한다.
- [ ] 전체/일정/할 일이 동일 데이터의 표시만 바꾸고 선택 날짜·월·과제 필터·미저장 입력을 보존한다.
- [ ] 보기 전환이 우측 탭·패널 개방 상태를 임의로 바꾸지 않는다.
- [ ] 패널을 접으면 달력이 넓어지고 펼침 시 기존 기능과 너비 조절을 사용할 수 있다.
- [ ] 접힌 상태에서도 선택 날짜의 일정 상세·할 일·커밋 내역에 바로 접근한다.
- [ ] 접힌 상태의 날짜 선택은 패널을 강제로 열지 않는다. 칩 클릭은 빠른 미리보기로 연결된다.
- [ ] 미리보기·전체 상세는 접힌 상태를 유지하고, 명시적 패널 열기만 해당 탭·항목을 펼친다.
- [ ] 완료 숨김 후에도 상세·패널·보고서에서 데이터가 유지되고 완료 취소가 가능하다.
- [ ] 기한 없는 할 일은 달력 밖의 할 일 경로에서 계속 접근한다.
- [ ] 기존 사용자 기본 펼침·전체 보기와 계정별 설정 복원, 좁은 화면의 하단 시트 접근을 확인한다.
- [ ] 전 테마·키보드·모달 포커스·긴 한글 제목·기간 중첩·좁고 낮은 창을 확인한다.
- [ ] 실제 WPF/WebView2·DB·저장 토큰·권한·충돌·보고서·반복·알림 등 기존 기능 회귀를 확인한다.

제품 코드를 수정할 때는 `docs/HANDOFF.md`, `tests/README.md`, 현재 정본 DDL 및 #14의 선행 변경과 재대조한다. 운영 DB 실행·배포는 이 문서의 범위가 아니다.
