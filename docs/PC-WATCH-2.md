## 1. 이름: "보기만 과제" → "관심 과제"

- 화면 글자 전부: 왼쪽 묶음 이름, 주간 보기 과제 줄 이름표, 상세 창 머리 꼬리표, 고치기 막힘 안내(`pcRoMsg`: "관심 과제라 고칠 수 없습니다. 참여자만 고칩니다."), 목록 줄 aria.
- 고르는 창(#catAddModal 보기 모드): 제목 "관심 과제 추가", 줄 단추 [추가] / "✓ 관심 과제"(다시 누르면 뺌, title "누르면 관심 과제에서 뺍니다") / "내 과제"(흐림), 아래 줄 "이번에 n개를 관심 과제로 넣었습니다".
- 왼쪽 목록 끝 점선 단추 [＋ 관심 과제 추가].
- 호스트 문구 `MsgWatchFull`: "관심 과제는 50개까지 넣을 수 있습니다. 쓰지 않는 과제를 목록에서 빼세요." 코드 이름(watch, cal_project_watch, PCAL.watch)은 그대로.
- 사람 고르기의 "(보는 중)"(다른 사람 일정 보기)은 다른 기능이라 그대로.

## 2. 관심 과제 모양: 색 없음

- 관심 과제는 **과제별 색을 쓰지 않는다.** 지금 쓰는 구분 색(`sectionColor(sectionId)`)도 걷는다(개발 과제가 다 같은 색이라 구분이 안 되던 것).
- 달력 일정: 회색 점선 칸 하나(흰 바탕, 점선 테두리, 흐린 글자). 왼쪽 띠도 같은 회색. 색은 기존 토큰(밝게, 어둡게, 고대비 대응)에서 고른다. 하드코딩 금지.
- 왼쪽 목록, 주간 과제 줄, 날짜 팝업 과제 머리, 상세 창 머리의 색점 자리: **회색 빈 동그라미(○)**. 내 과제는 지금처럼 색점.
- 어느 과제인지는 날짜를 누르면 뜨는 과제별 묶음 팝업(`pcOpenDayList`)과 주간 보기 과제 줄로 본다. 마우스 툴팁을 더하지 않는다.

## 3. 과제 탭 왼쪽 목록: 두 탭(D안)

- 앱 탭(개인, 과제, 근태)은 그대로. 과제 탭 왼쪽 목록 위에 [내 과제 a/b | 관심 과제 c/d] 탭(a, c = 달력에 켠 수, b, d = 전체 수).
- 탭은 **목록만 바꾼다.** 달력은 두 탭에서 체크한 과제를 같이 보여 준다(내 과제는 칠한 칸, 관심 과제는 회색 점선).
- [전체 선택] [전체 해제]는 지금 탭의 과제에만. 관심 과제 탭에서 [전체 해제] 한 번이면 달력에 내 과제만 남는다.
- 지금 있는 묶음 머리 체크(내 과제, 보기만)는 탭과 겹치니 걷는다. 머리 "과제 n / m"은 "달력에 n개"로.
- 관심 과제 탭 목록 끝에 [＋ 관심 과제 추가]. 관심 과제가 0개면 그 탭은 빈 안내 한 줄과 이 단추.
- 고른 탭은 지금 과제 탭 설정(`pcPrefsSave`, PC 와 계정별)에 같이 기억한다. 처음은 내 과제.
- 서랍(좁은 폭 `pcSideHtml(inDrawer)`)도 같은 탭.

## 4. 참여자 필터: 개인 달력 보기 팝업 재사용

- 관심 과제 추가 창의 [참여자] 단추는 #peerPicker 여러 명 모드를 **쓰지 않고**, 개인 달력 보기 팝업의 과제 목록 부분(찾기 칸, [전체 선택] [전체 해제], `.fb-opts` 체크 목록, 키보드와 aria)을 **같은 함수로** 쓴다. 팝업 함수를 "목록 출처"를 받게 일반화하고, 개인 보기 팝업은 동작이 하나도 바뀌지 않아야 한다(기존 시험 그대로 통과).
- 규칙은 FILTER-MULTI 그대로: 상태 null = 전체, 빈 묶음 = 선택 없음, 다 켜면 전체로, 선택 없음은 [전체 해제]로만, 칩 없음, 단추 글자 "참여자 전체 / 김하늘 / 김하늘 외 N / 선택 없음", 바깥 클릭과 Esc 로 닫힘, 기억하지 않음(창 열 때마다 전체).
- 다른 점 하나: 목록을 **조직(팀)별 묶음**으로. 묶음 머리에 펼치기와 묶음 전체 체크(일부면 반쯤). 내 부서 묶음이 맨 위에 펼쳐져 있고 나머지는 접힘. 찾으면 맞는 묶음이 다 펼쳐짐. 오른쪽 수 = 참여 과제 수(개인 필터의 기록 수 자리), 0이면 흐리게(`.zero`).
- 거르기: 고른 사람 중 한 명이라도 참여한 과제가 남는다. 참여자 칸 "김하늘 외 1 포함", 명단 창 강조는 지금처럼.
- #peerPicker 여러 명 모드 코드(pkMulti*, pkAllEl, pkPickedUnits 등 여러 명 전용)는 걷는다. 한 명 고르기(다른 사람 일정 보기)는 바뀌지 않는다.

## 5. 날짜 패널: 묶음 접기(B안, PERSONAL-PANEL 2.1 의 연장)

- 일정, 할 일 두 묶음 고정은 그대로(탭으로 돌아가지 않는다. 2026-11-03 결정).
- 묶음 머리를 누르면 접힌다(▾/▸). 접은 상태는 계정별로 기억(개인 보기 설정과 같은 저장 방식).
- 묶음마다 **5개까지** 보이고 넘으면 "n개 더 보기", 펼친 뒤 "줄이기". 날짜를 바꾸면 다시 5개.
- 일정은 **한 줄 줄**(색 띠, 시간 또는 종일, 제목 말줄임). 누르면 그 자리에서 지금의 카드(분류, 시간과 장소, 기간, 반복, 메모, 수정 삭제)로 펼친다. 한 번에 하나만 펼친다. 달력 칩을 눌러 오는 강조(flash)는 그 줄을 펼치고 보이게 한다(5개 밖이면 더 보기를 연다).
- 할 일 줄은 지금 줄(체크, 제목, ★, ✕)을 그대로 쓰고 제목만 두 줄까지(전체는 title). 처음엔 한 줄 말줄임이었으나 240px 패널에서 "[과제] 날짜 ..." 앞머리만 남아 두 줄로 바꿈(2026-11-05 실제 위젯 점검).
- 열람 창(다른 사람 일정)과 나란히 보기의 두 묶음(상대 일정, 내 일정)도 같은 줄과 5개 제한.
- 보통 날(5개 이하)은 더 보기가 없다.

### 7.1 날짜 패널: 펼침은 상자 없이 들여쓴 상세
- **일정**: 줄을 누르면 카드 상자(cardHtml)를 붙이지 않고, 줄 아래에 들여쓴 몇 줄만: 시각 범위, 장소, 기간(n일째 / n일), 반복, 메모 중 **있는 것만**, 끝에 [수정] [삭제] 글자 단추. 분류 꼬리표와 줄에 이미 있는 시각(종일 등)은 다시 쓰지 않는다. 펼친 줄은 옅은 강조 바탕, 제목 여러 줄. 열람 창의 시간 겹침은 상세 줄 하나로.
- **할 일**: 줄(체크, 제목 두 줄까지, 과제 색점, ★, ✕)은 그대로. 제목을 누르면 패널 안 수정 폼(todoEditHtml) 대신 일정과 같은 들여쓴 상세(기한, 과제, 설명 중 있는 것)와 [수정] [삭제]. 일정과 할 일 펼침은 합쳐서 한 번에 하나.
- **할 일 [수정] = [+ 추가] 창(openQuickAdd)을 할 일 수정으로**. 지금 그 창은 일정만 수정한다(qaType 주석 "편집은 일정만"). 할 일 수정을 더하고(제목, 시작과 끝, 과제, 중요, 설명, 삭제), 패널 안 인라인 수정 폼과 그 상태(editingTodoId)는 걷는다. 다른 곳(밀린 할 일 팝업 등)에서 할 일을 고치던 길도 같은 창으로.
- 열람 창은 [수정] [삭제] 없음(읽기 전용 그대로).

### 7.2 밀린 할 일 팝업: 묶음 안을 과제별로
- 기한 지남, 기한 없음, 완료 세 묶음은 그대로(완료 접힘도 그대로).
- 각 묶음 안을 **과제별 소제목**(과제 색점, 과제 이름, 개수)으로. 순서는 과제 목록 순서, 과제 없는 할 일은 끝. 소제목을 누르면 그 과제만 접힘(기억하지 않음). 기한 지남 소제목 끝에 그 과제의 가장 오래된 기한.
- 소제목에 색점이 있으니 줄의 과제 색점은 뺀다. 과제 안 순서는 지금처럼 ★ 먼저, 날짜순.

### 7.3 관심 과제 추가 창
- **[참여자] 팝업 = 다른 사람 일정 보기 조직도를 그대로**(#peerPicker 의 조직도 탭 부분: 왼쪽 트리는 DB 순서와 계층, 펼치기, 사람 수, "내 소속", 오른쪽 경로와 "○○ 전원" 체크와 사람 목록, 좁으면 한 칸). 1차의 평평한 팀 목록(CAW_WHO_SRC 묶음)은 버린다. 내 부서를 맨 위로 끌어올리지 않는다(트리 순서 그대로, 처음 고른 노드만 내 소속).
  - 겉은 개인 필터 규칙: 위 찾기 칸, [전체 선택] [전체 해제], 칩 없음, 단추 글자 "참여자 전체 / 이름 / 이름 외 N / 선택 없음", 상태 null 전체, 빈 묶음 선택 없음, 다 켜면 전체, 기억 안 함, 바깥 클릭과 Esc 로 닫힘.
  - 더하는 것: 사람 줄마다 체크와 참여 과제 수(0이면 흐리게), "전원" 체크(일부면 반쯤), 고른 사람이 있는 트리 노드에 점. 사람 탭(즐겨찾기, 최근)과 ☆ 는 이 팝업에 없다.
  - **찾기는 이름만**(조직은 트리로). 안내 글자 "이름 찾기". 다른 사람 일정 보기의 찾기(이름, 직급, 조직)는 이번에 바꾸지 않는다.
  - 1차의 공용 목록 함수(fbFill 등)로 개인 보기 팝업을 일반화한 것은 그대로 둬도 된다(개인 보기 팝업 동작 불변). 참여자 팝업이 그 겉(찾기, 전체 선택/해제 단추, 단추 글자 규칙)을 쓰고 속은 peerPicker 조직도 함수(pkOrgIndex, pkTreeEl, pkUnitListEl 계열)를 체크 모드로 재사용한다. 한 명 고르기(다른 사람 일정 보기) 동작은 바뀌지 않는다.
- **"일정 있는 과제만" → "일정 없는 과제 숨김"**(뜻 같음, 처음 켬), 자리는 참여자 단추 옆이 아니라 **상태 체크 줄 끝**(세로 구분선 뒤, 개수 앞).
- **"상태 없음" → "상태 미지정"**. 같은 글자를 쓰는 과제 추가 창, 관리 창 상태 체크도 같이.
- **정렬 전환 [최근 활동순 | 이름순] 없앰.** 기본은 과제 추가 창과 같은 DB 순서(구분 묶음, No). 1차의 "이름순"은 실제로 DB 순서였다(이름 정렬 아님).
- **"최근 활동" 열 머리를 누르면 정렬**: 누를 때마다 최근 순(▼) → 오래된 순(▲) → 기본 순서. 정렬 중에는 구분 묶음을 풀고 한 줄 목록. 일정 없는 과제(숨김을 끈 때만 보임)는 어느 방향이든 맨 끝. 머리는 button, aria-sort. 기억하지 않음(창 열 때마다 기본 순서). 앱 첫 정렬 머리라 다른 표가 쓰게 될 때를 생각해 작은 공용 함수로.
- 표에 No 열(구분 안 번호, 과제 추가 창과 같은 값)을 보인다. 정렬 중에도 No 는 그대로.
