# 과제 탭 날짜 목록 팝업 결정 (2026-10-30)

대상: 과제 탭 달력에서 날짜(칸, 막대, +n)를 눌렀을 때 뜨는 그날 일정 목록. 점검과 조사는 `PROJECT-CAL-DETAIL-UX.md`, 비교 시안은 `prototypes/project-cal-detail.html`, 확정 시안은 `prototypes/project-cal-day-popup-final.html`.

**핵심: 과제를 묶음 머리(부모)로, 그 과제의 일정을 그 아래(자식)로 보이는 2단 계층.** 아래 규칙은 모두 이 구조를 깔끔하게 읽히게 하는 부속 규칙이다.

상태: 구현 완료(브랜치 feat/project-day-popup, 2026-10-30, 0d9ede2, feat/db-app 병합 4ef8f48), 0.25.0 판에 실림. 확인 기록은 맨 아래 "구현 결과".

## 확정: C안(과제별 묶음)

선택 이유(사용자 판단): 일정이 적은 과제는 시간을 잘 적지 않는다. 시각 열을 세우는 B안은 그 열이 대부분 빈다. 과제 이름으로 묶는 쪽이 "어느 과제 일정인가"를 글로 바로 답하고, 빈 자리도 생기지 않는다.

## 확정 규칙

| 항목 | 규칙 |
|---|---|
| 머리 | "10월 30일 (금)"(토, 일은 요일 색). "일정 n건" 없음. 오른쪽에 작은 "등록" 단추 |
| 묶음 | 과제 이름이 묶음 머리, 앞에 과제 색 네모 10px. 이름은 묶음마다 한 번 |
| 묶음 순서 | 왼쪽 과제 목록 순서(pcOrder) |
| 과제 안 정렬 | 종일과 여러 날 막대 먼저(시작일 순, 긴 것 먼저), 그 아래 시각 일정 시각 순 |
| 시각 표시 | 시각 열 없음. 시각이 있을 때만 제목 앞에 작게 "14:00~15:30"(끝 시각 포함). 빈 시각 자리 확보 금지 |
| 여러 날 | 제목 앞에 작은 회색 "10/28~10/31" |
| 읽기 전용 과제 | 묶음 머리 이름 뒤 작은 회색 글자 "읽기 전용" 하나. 줄 모양은 그대로. (구현 때 정정: 시안의 "종료"는 틀린 말이다. 앱에서 쓸 수 없는 과제는 상태 종료가 아니라 관리자가 숨긴 과제이고, 상태 종료 과제는 숨기지 않았으면 쓸 수 있다. 왼쪽 목록 표기 "숨긴 과제, 읽기 전용"과 맞춘다) |
| 등록 입구 | 머리 오른쪽 "등록"(btn sm). 큰 파란 하단 단추 없음. 보이는 과제가 모두 종료면 단추 없음 |
| 빈 날 | 머리와 등록 단추만. 안내 문구 없음 |
| 긴 제목 | 두 줄까지, 넘치면 말줄임(시각 앞말 포함 두 줄) |
| 메모 | 줄 오른쪽 작은 메모 아이콘 유지(PC_IC.memo) |
| 줄 누름 | 상세 창(pcOpenDetail), 지금과 같음 |
| 크기 | 폭 320px, 최대 높이 440px. 날짜 머리는 고정, 아래만 스크롤, 과제 머리는 스크롤 중 위에 붙음(sticky) |
| 좁은 폭(760px 이하) | 하단 시트(화면 높이 84%까지, 그립 막대), 같은 내용 |

## 폐기한 안

| 안 | 이유 |
|---|---|
| 0 현행 | 과제를 색으로만 구분, 시각 뒤섞임(과제 순서가 시각보다 앞섬), "일정 n건"과 빈 날 문구 |
| A 다듬은 칩 | 여전히 색만으로 과제 구분 |
| B 종일 위, 시간 아래 | 시간 없는 일정이 대부분이라 시각 열이 빈다 |
| D 오른쪽 패널 카드 | 달력 폭이 패널만큼 준다, 카드 정보가 많아 군더더기 위험 |
| E 줄 안에서 펼침 | 높이 고정으로 적은 날 빈 공간, 펼친 줄 단추가 가려짐 |
| F 표 | 460px 로 달력을 많이 가림, 표 머리가 군더더기 |

## 미결정과 이번에 정한 것

| 항목 | 상태 |
|---|---|

| 읽기 전용 표시 | 구현은 머리 옆 작은 "읽기 전용" 글자. 사용자가 실제 화면에서 더 줄일지(글자 없이 흐리게 등) 판단 남음 |
