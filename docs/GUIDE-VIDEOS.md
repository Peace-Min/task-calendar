# 사용 영상 안내 운용 규칙

정한 날: 2026-10-23(사용자). 상태: 규칙 확정, 구현됨(2026-10-23, feat/guide-videos, 아래 §7 계획과 §8 구현 메모).
이 문서는 앞으로의 구현과 배포에서 계속 쓰는 규칙이다. 바꿀 때는 사용자 확인 뒤 이 문서를 먼저 고친다.

## 1. 무엇을 어디에 두나

- 영상은 **Setup 에 넣지 않는다.** 업데이트 때마다 Setup 전체를 받으므로, 영상(4편 약 54MB)을 넣으면 매번 다시 받게 된다.
- 폐쇄망 공유 폴더(업데이트 폴더, `latest.json` 과 Setup 이 있는 곳) 아래 `guide\` 폴더에 사용자가 직접 올린다.

```
<업데이트 폴더>\guide\
  guide.json      판 번호와 영상 목록
  *.mp4           기능(주제)별 영상 파일
  *.srt           (선택) 같은 이름의 자막
```

- HTML 은 올리지 않는다. 목록, 재생, 장면 이동 화면은 앱 안에 있고 `guide.json` 을 읽어 그린다. 화면을 고치는 것은 앱 업데이트로 나간다.
- 공유 폴더 주소는 앱이 이미 아는 업데이트 폴더 주소에서 정한다. 따로 설정하지 않는다.

## 2. guide.json

```json
{
  "version": "2026-11",
  "videos": [
    { "id": "overview", "file": "overview.mp4", "title": "전체 소개" },
    { "id": "report", "file": "report.mp4", "title": "보고서",
      "chapters": [ { "t": 0, "title": "일간" }, { "t": 80, "title": "주간" }, { "t": 160, "title": "월간" } ] }
  ]
}
```

- `version`: 안내 판 번호. 크고 작음은 보지 않고 **같은가만** 본다. 날짜든 숫자든 바꾸기만 하면 된다.
- `videos`: 기능(주제)별 영상. 새 기능이 생기면 영상 파일과 줄을 더한다.
- `chapters`: (선택) 한 영상 안 장면의 시작 초. 사용설명서의 "영상으로 보기"가 그 장면부터 재생한다.
- 새 기능 표시나 알림 여부 같은 칸은 두지 않는다(버전마다 신규 기능을 기록하면 꼬인다).

## 3. 언제 묻나 (앱이 켜질 때 한 번)

로그인하고 첫 화면이 다 뜬 뒤, 실행 한 번에 한 번만 판단한다. 창을 다시 띄우거나 새로고침해도 다시 묻지 않는다.

1. 공유 폴더의 `guide\guide.json` 을 읽는다. 없거나 닿지 않으면 끝(묻지 않음).
2. 이 PC 에 계정별로 기억한 "본 판 번호"를 읽는다(localStorage, 키 `tc_guideSeen:<로그인>`). 접근은 try/catch.
3. 두 판 번호가 같으면 끝.
4. 다르면 문구를 고른다.
   - 내 일정과 할 일이 하나도 없는 계정(첫 사용자): "사용 영상을 보시겠습니까?"
   - 그 밖(기존 사용자): "새 기능 가이드가 추가되었습니다"
5. 단추: [보기] 는 영상 목록을 앱 안 창으로 열고 지금 판을 본 것으로 기록. [다시 묻지 않기] 는 지금 판을 기록만. [나중에] 는 기록하지 않음(다음 실행 때 다시 묻는다).

- 다른 계정으로 바꿔 로그인하면 그 계정 기준으로 다시 판단한다.
- 언제든 상단 "?" 메뉴의 "사용 영상"으로 목록을 연다(판 번호와 무관).

## 4. DB 를 쓰지 않는 이유

- "다시 묻지 않기" 하나 때문에 구조 번호를 올리지 않는다. PC 를 바꾸면 한 번 더 묻는 정도의 차이뿐이다.
- 첫 사용자 판단도 DB 칸 없이 "내 기록이 없는가"로 한다. 기록 없이 오래 안 쓰던 기존 계정이 한 번 받을 수 있지만 [다시 묻지 않기] 로 끝난다.

## 5. 사용자(운영자)가 하는 일

- 영상을 추가하거나 바꿈: mp4 를 올리고 `guide.json` 의 목록을 고친다. 판 번호를 그대로 두면 아무에게도 다시 묻지 않는다.
- 모두에게 알림(새 기능 영상을 올렸을 때): `guide.json` 의 `version` 을 바꾼다. 모든 계정이 다음 실행 때 한 번 받는다.
- 영상 다시 찍는 시점은 사용자가 정한다(2026-10-23: 지금 영상은 임시, 남은 작업이 끝난 뒤 한 번에 다시 찍는다).

## 6. 릴리스 체크리스트와의 관계

- 이 기능이 들어간 뒤의 릴리스 산출물은 지금과 같다(`latest.json`, Setup, `release-v<버전>.sql`). 영상과 `guide.json` 은 릴리스 산출물이 아니라 사용자가 따로 올리는 것이다.
- 화면을 바꾼 릴리스라면, 릴리스 안내에 "영상 다시 찍기 필요 여부"를 한 줄 적어 사용자가 판 번호를 올릴지 정하게 한다.

## 8. 구현 메모 (2026-10-23)

### 8.1 호스트(`widget/GuideHost.cs`, 메인 창 전용)

- guide 폴더 = 업데이트 폴더 주소(`widget.settings.json` 의 `UpdateSourceUrl`, 비면 `DeployConfig.UpdateSourceUrl`) + `guide`. 업데이트 코드(`Update.cs` 의 `KindOf`, `CombineUrl`)를 그대로 써서 형식이 같다. 따로 설정하지 않는다(§1).

| 업데이트 폴더 형식 | guide.json 읽기 | 영상을 캐시로 |
|---|---|---|
| 로컬 경로, UNC(`\\서버\공유`), `file://` | 업데이트 폴더가 있는지 먼저 본다(없으면 `unreachable`). 파일을 읽는다 | 복사한다 |
| `ftp://`(익명, 수동 모드), `http(s)://` | 받아서 읽는다(404, FTP 550 = `missing`) | 받는다 |

- 재생은 늘 캐시에서 한다. 가상 호스트 `guide.tcapp.local` 은 캐시 루트 `%LOCALAPPDATA%\TaskCalendar\guide-cache` 하나에, 웹뷰 초기화에서 `tcapp.local` 매핑 바로 다음, 첫 `Navigate` 전에 한 번 잇는다(`GuideMapInit`). 그 뒤로는 바꾸거나 지우지 않는다.
  - 왜(2026-10-23 PM 실측): 문서가 뜬 뒤에 건 `SetVirtualHostNameToFolderMapping` 은 그 문서의 요청에 적용되지 않았다. 다시 읽기 전에는 `fetch('https://guide.tcapp.local/guide.json')` 가 "Failed to fetch", `<video>` 는 오류 없이 readyState 0 에 머물렀고, `Page.reload` 뒤에는 200 이었다. 처음 구현은 명령 처리 중에 guide 폴더나 캐시 폴더로 매핑을 바꿨기 때문에, 실행마다 첫 보기 창에 영상이 나오지 않았다.
  - 매핑이 바뀌지 않으므로 실행 중에 업데이트 폴더를 바꿔도 다시 읽을 필요가 없다.
- `guideFetch(file)` 는 요청한 mp4 를 `guide-cache\<판 폴더>\` 로 복사하거나 받는다(`.part` 에 쓰고 끝나면 이름 바꿈, 진행 알림). 그 판 폴더에 같은 크기의 파일이 이미 있으면(원본 크기를 알 수 없을 때도) 건너뛴다. 원본 크기는 파일 공유는 파일 정보, HTTP 는 HEAD, FTP 는 SIZE 로 본다.
- 재생 주소는 `https://guide.tcapp.local/<판 폴더>/<file>`. 판 폴더 이름은 `GuideRules.SafeDirName`(파일 이름에 못 쓰는 글자는 `_`, 40자, 끝의 점과 공백 제거)이고 캐시 폴더와 같은 규칙이다. Windows 는 폴더 이름 끝의 점을 지우므로, 그대로 두면 지난 판 정리가 이 판을 지운다.
- 판 번호가 바뀌면 다른 판 폴더를 지운다(재생 중이라 잠겨 있으면 다음 기회에).

- 명령 둘. `guideManifest` 는 `{ ok, version, source:'file'|'net', videos }` 또는 `{ ok:false, reason }`(noSource, unreachable, missing, invalid, tooLarge, noVideos). `guideFetch { file }` 는 `{ ok, url, srt }` 또는 `{ ok:false, reason }`(badName, noGuide, unreachable, missing, download). 받는 동안 `window.__guideProgress({ file, got, total })` 를 0.3초에 한 번 민다.
- 시간 제한: guide.json 과 자막 읽기, 업데이트 폴더 확인은 6초(`BoundAsync`). 닿지 않는 공유 폴더가 부팅 뒤 화면을 붙잡지 않는다(웹은 부팅이 끝난 뒤에 묻는다). mp4 받기는 전체 15분.
- 검사(`GuideRules`): guide.json 은 256KB 까지. 모르는 칸은 무시. 판 번호는 글이나 숫자(64자까지). 영상 줄은 60개, 장면은 영상마다 60개까지. 규칙에 맞지 않는 영상 줄(이름, id 와 file 중복, 빈 제목)과 장면(음수, 숫자 아님, 하루 넘음)은 버리고 나머지를 쓴다. 쓸 영상이 없으면 `noVideos`.
- 이름 규칙(`GuideRules.NameOk`, 웹 `gvNameOk` 와 같다): 128자까지, `/ \ : * ? " < > |` 와 제어 문자 없음, `..` 없음, 점으로 시작하지 않음, 앞뒤 공백 없음, `.mp4` 나 `.srt`. `guideFetch` 는 여기에 더해 지금 목록에 있는 mp4 만 받는다. 자막 이름은 mp4 이름의 확장자만 `.srt` 로 바꾼 것이다.
- 자막은 주소가 아니라 글(1MB 까지)로 돌려준다. 페이지(`https://tcapp.local`)와 가상 호스트(`https://guide.tcapp.local`)는 출처가 달라 `<track>` 과 `fetch` 가 CORS 에 막히기 때문이다. 웹이 WebVTT 로 바꿔 blob 주소로 붙인다. `<video>` 는 출처가 달라도 재생된다.
- DB 를 쓰지 않는다(§4). 열람 창(`PeerWinCommands`)과 관리 창(`AdminWinCommands`) 허용 목록에 넣지 않았다. 그 창에는 "?" 메뉴가 없다. `MainWindow.xaml.cs` 에는 case 두 줄만 더했다.

### 8.2 웹(`task-calendar-prototype.html`)

- 묻기: `__applyState` 끝(첫 화면을 그린 뒤)과 세션 복원(`bootUserSession`)이 `gvOnBootApplied` 를 부른다. 둘 중 늦은 쪽에서 계정과 그 계정의 화면이 함께 선다. 열람 프레임, 열람 창, 관리 창, 브라우저는 거른다.
- 계정마다 실행 한 번: 판단을 마친 계정은 메모리와 sessionStorage `tc_guideAsked`(실행이 끝나면 사라진다)에 둔다. 목록이 없어도 그 실행에서는 다시 읽지 않는다. 오래 기억하는 것은 localStorage `tc_guideSeen:<로그인>` 하나다(try 안).
- 로그인 화면, 버전 관문 카드, 다른 창이 떠 있으면 3초마다 보고 닫힌 뒤 묻는다(20분 넘게 비지 않으면 그 실행에서는 묻지 않는다).
- 보기 창(`#gvModal`): 열 때마다 목록을 새로 읽는다(운영자가 그사이 올렸을 수 있다). 목록, `<video controls>`, 장면 단추(누르면 그 초로, 재생 중 지금 장면 표시), 자막 트랙(srclang ko). 늦게 온 회신은 버리고, 닫으면 재생을 멈추고 주소를 내려놓는다. 좁은 창(720px 이하)에서는 창을 채우고 목록이 위로 간다. 글은 전부 textContent 로 넣는다.
- "?" 도움말 창 아래에 [사용 영상] 단추.

### 8.3 시험

### 8.4 릴리스 체크리스트

§6 은 그대로다. 릴리스 산출물은 `latest.json`, Setup, `release-v<버전>.sql` 이고, 영상과 `guide.json` 은 넣지 않는다(설치 스크립트에 영상이 없음을 시험 S1 이 지킨다). 화면을 바꾼 릴리스는 릴리스 안내에 "영상 다시 찍기 필요 여부"를 한 줄 적는다.
