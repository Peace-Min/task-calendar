# 근태 화면 UI 지적과 원인 기록

> 2026-10-29 ~ 10-30, 근태 탭 일간(결정 9~12)과 주간(결정 13, 14) 작업 중 사용자가 실제 위젯을 써 보며 지적한 UI 문제와 원인, 조치를 모은다. 다음 화면 작업 전에 먼저 읽는다. 기획 정본은 [ATTENDANCE-PLAN.md](ATTENDANCE-PLAN.md), 결정은 [DECISIONS.md](DECISIONS.md).

## 1. 먼저 지킬 원칙 (지적에서 뽑은 것)

1. **설명 문구를 넣지 않는다.** 화면을 보면 아는 것을 글로 다시 말하면 사용자는 "AI 같다"고 느낀다. 상태를 알려 주는 것(보낸 시각, 임시 저장 시각, 오류, 결과)만 남긴다.
2. **안내 띠, 확인 창, 되돌리기를 기본으로 넣지 않는다.** 되돌릴 수 있거나 다시 하면 되는 동작은 묻지 않고 바로 한다.
3. **같은 일을 하는 단추를 두 개 두지 않는다.** 창의 X 와 머리의 ×, 하단 [복사]와 미리보기 [복사]처럼 겹치면 하나를 뺀다.
4. **장식 아이콘을 붙이지 않는다.** 잠금 표시(🔒) 없이도 글자로 된 과제명은 고칠 수 없다는 것이 보인다.
5. **화면은 정적이어야 한다.** 단추를 누를 때 반짝임, 자동 스크롤, 화면 전체 다시 그리기로 레이아웃이 출렁이면 안 된다. 바뀐 부분만 다시 그린다.
6. **떠 있는 패널은 자리를 고정한다.** 목록이 늘어도, 스크롤바가 생겨도 움직이지 않고, 부모가 잘라 내지 않게 한다.
7. **기존 사용자가 익숙한 모양을 따른다.** 회사 인트라넷과 같은 모양(목록부터, 표 구조, 미리보기)이 신뢰를 준다. 보고서 창에 이미 있는 조작(숫자 칸 안 화살표)과 다르게 만들지 않는다.
8. **제약은 기계가 읽어야 하는 칸에만 둔다.** 과제명과 시간은 정해진 칸으로 받고, 사람이 읽는 글은 완전히 자유롭게 둔다. 실수를 하나씩 규칙으로 막는 방식은 끝이 없다.
9. **단추 이름은 짧고 일반적으로.** "회사에 보고", "인트라넷에 채우기" 보다 "보고", 상태 "보고함" 보다 "완료".
10. **마우스 조작을 먼저 생각한다.** 키보드 단축키는 보조다. 사용자는 키보드 조작을 알지 못했다.

## 2. 지적 목록

### 2.1 문구와 이름

| 지적 | 원인 | 조치 |
|---|---|---|
| 날짜 머리 꼬리 ", 보고함" 이 AI 같다 | 상태를 굳이 글로 붙였다 | 뺐다(`35d6d02`) |
| 가져오기 출처 "근태관리"가 헷갈린다 | 회사 사이트 이름을 메뉴 이름으로 썼다 | "인트라넷"으로(이후 인트라넷 불러오기 자체를 없앰, 결정 12) |
| "회사에 보고" 가 이상하다 | 길고 설명조 | "보고" |
| 주간 "인트라넷에 채우기" 가 구리다 | 동작을 그대로 이름으로 썼다 | "보고"(일간과 같은 이름) |
| 목록 상태 "보고함" 이 이상하다 | 동사형 상태 | "완료" |
| "월요일이 든 달 기준", "진행사항 n개, 차주계획 n개" 가 AI 같다 | 규칙과 개수를 화면에 설명했다 | 모두 뺐다 |
| 그 밖의 설명 문구(정렬 안내, 자유 메모 설명, 가져오기 안내, 미리보기 "n줄, n자", "과제가 없습니다", "인트라넷에 이렇게 들어갑니다", 목록 안내 줄) | 같은 이유 | 모두 뺐다. 상태 줄은 "합계 n시간"만 남겼다 |
| 가져오기 단추 설명이 주저리주저리 | 단추마다 문장을 붙였다 | 채울 칸 이름만(예: "과제투입시간, 진행사항") |

지키는 시험: `attendance-web`(지운 안내가 없음), `attendance-weekly-web`(지운 글, 빈 과제투입시간에 문구 없음), `ui-copy-punct`.

### 2.2 확인 창, 안내 띠, 되돌리기

| 지적 | 원인 | 조치 |
|---|---|---|
| 불러오기 때 "덮어쓰기/그만두기" 확인이 불필요 | 덮어쓰기를 위험으로 보고 물었다 | 묻지 않고 바로 바꾼다 |
| 임시 저장 되살림 띠와 "버리고 처음 상태로"가 불필요 | 되살림을 알려야 한다고 봤다 | 안내 없이 이어서 연다. 처음부터는 [전체 초기화] |
| [전체 초기화] 뒤 "되돌리기"가 불필요 | 실수 대비로 넣었다 | 묻지도, 되돌리기도 두지 않는다 |
| Esc 가 막혀 있었다 | 긴 글을 지키려고 의도적으로 막았다 | Esc = 닫기 |
| 닫기, Esc, [목록]에서 "작성 중인 내용이 있습니다"를 왜 묻나. 창 X 는 바로 닫히는데(2026-10-30) | 글을 잃을까 봐 물었지만 닫기 전에 이미 임시 저장을 쓰므로 그 창의 [닫기]와 묻지 않는 닫기는 결과가 같았다. 창 X 만 달라 동작도 어긋났다 | 일간, 주간 모두 묻는 창을 없앴다. 닫을 때 임시 저장을 쓰고 바로 떠난다. 보내는 중에만 막는다 |

### 2.3 겹치는 단추와 장식

| 지적 | 원인 | 조치 |
|---|---|---|
| 창 X 와 머리 × 가 겹친다 | 브라우저 모드용 × 를 위젯에도 그대로 둠 | 머리 × 를 뺐다 |
| 하단과 미리보기의 [복사]가 필요 없다 | 브라우저용 대체 수단을 위젯에도 둠 | 둘 다 뺐다. 미리보기 글을 드래그해 복사 |
| 과제명 옆 🔒 가 번잡하다 | 고칠 수 없다는 것을 아이콘으로 강조 | 뺐다 |
| "글로 보기" 단추가 불필요 | 조립 결과를 토글로 보여 줌 | 오른쪽 [미리보기] 탭으로 |
| ▲ ▼ 순서 단추가 불필요 | 블록 순서를 손으로 바꾸게 함 | 캘린더 과제 순서로 자동 정렬 |
| [← 주간 목록] 화살표가 보기 싫고 잘 안 보인다 | 글자 화살표와 강조색 테두리 | 앱 아이콘(‹) + "목록", 차분한 테두리 |
| 보기 화면의 [수정]이 "내가 눌러야 하나" 로 읽힌다 | 보고한 날을 읽기 전용 화면으로 먼저 열었다 | 보기 화면을 없애고 바로 편집 화면(인트라넷과 같음) |

### 2.4 정적인 화면과 패널

| 지적 | 원인 | 조치 | 지키는 시험 |
|---|---|---|---|
| 과제 추가 때 UI 가 흔들린다 | (1) 추가, 빼기마다 편집 화면 전체를 다시 그려 글 칸 높이가 다시 계산됨 (2) 새 줄 반짝임 (3) 새 줄로 자동 스크롤 | 시간 목록만 다시 그린다. 반짝임과 스크롤 이동을 없앴다 | `attendance-weekly-web` (S) 반짝임 없음, `awAddPick` 이 `awRender()`, `scrollIntoView` 를 부르지 않음 |
| 과제투입시간이 정렬 안 된 것처럼 보인다 | 2열 자동 격자에 과제명 폭이 제각각 | 한 줄에 과제 하나, 점, 과제명, 시간, ✕ 칸 폭 고정 | `.aw-hr` 격자 칸 폭 확인 |
| 과제를 하나씩 고르고 다시 눌러야 한다 | 메뉴가 고르면 닫혔다 | 열어 둔 채 체크로 넣고 빼는 체크 목록 + [전체 선택] [전체 해제] + [닫기] | 체크 목록 시험 |
| 체크 패널이 과제가 늘 때마다 아래로 밀린다(설계 중 발견) | 패널을 [+ 과제 추가] 단추 아래에 붙였다 | 과제투입시간 칸 오른쪽 위에 고정 | 위치 측정(위젯) |
| 스크롤바가 생기면 패널이 왼쪽으로 밀린다 | 스크롤바가 생기며 영역 폭이 줄었다 | 스크롤 영역(`.at-list`, 일간과 주간 공용)에 `scrollbar-gutter:stable` | (S) `scrollbar-gutter:stable` |
| 패널 아래가 잘린다 | 표(`.aw-form`)가 둥근 모서리를 위해 `overflow:hidden` | 숨기지 않고, 둥근 모서리는 첫 칸과 끝 칸에 직접 | (S) `.aw-form` 에 `overflow:hidden` 없음 |

### 2.5 시간 칸

| 지적 | 원인 | 조치 |
|---|---|---|
| 시간 칸이 쓸데없이 넓다 | 기본 숫자 칸 76px | 52px(이후 62px, 칸 안 화살표 자리) |
| 위아래 조절을 왜 뺐나(UI 검토 권고로 스피너를 없애고 키보드만 남겼다) | 키보드 ↑ ↓ 를 사용자가 몰랐다. 마우스가 편하다 | 보고서 창처럼 기본 숫자 칸: 마우스를 올리면 칸 안 오른쪽에 화살표. 칸 밖 ▲ ▼ 단추안은 반려 |
| 숫자와 화살표가 붙어 보인다 | 기본 스피너 여백 없음 | 화살표에 왼쪽 여백 6px |
| 휠은 위험하다 | 숫자 칸은 포커스가 있을 때 휠로 값이 바뀐다 | 포커스가 있을 때만 휠을 막는다(목록 스크롤은 그대로) |

### 2.6 신뢰와 익숙함

| 지적 | 조치 |
|---|---|
| 미리보기는 인트라넷 모양 그대로여야 믿는다 | 주간은 인트라넷 주간보고 폼, 일간은 인트라넷 근태관리 입력 화면 모양. 테마와 상관없이 같은 색(`--nf-*` 토큰) |
| 주간 첫 화면은 인트라넷처럼 목록부터 | 목록(번호, 제목, 기간, 상태, 날짜) → 행이나 [작성] → 편집 |
| 주간 시안이 난잡하다 | 왼쪽 주 목록, 규칙 안내, 미사용 칸(미처리사항, 문제점 및 건의사항)을 걷어내고 네 칸만 |
| 미리보기 빨간 줄의 기준이 불명확 | 유효성 표시 기준을 사용자가 정할 때까지 색 표시를 뺐다(보내기를 막는 규칙은 유지) |

### 2.7 입력 제약 (휴먼 에러)

| 지적 | 원인 | 조치 |
|---|---|---|
| `[SONATA2 :10]` 처럼 쓰면 과제별 공수가 안 모인다 | 한 칸 글에서 과제 머리를 읽어 냈다 | 일간은 과제 블록(과제명은 캘린더에서, 시간은 숫자 칸), 결정 12 |
| `◈ 과제`, `[일정]` 소제목처럼 사람마다 쓰는 법이 달라 글로는 머리를 가릴 수 없다 | 같은 원인 | 과제명을 글에서 읽지 않고 칸으로 받는다 |
| 주간 진행사항은 PM 이 자유롭게 쓴다(담당자 배치표 등) | 주간에도 블록을 씌웠다 | 진행사항, 차주계획은 자유 글. 제약은 과제투입시간에만(결정 14) |

## 3. 다음 화면 작업 때 확인할 것

- 새 문구를 넣기 전에: 화면만 보고도 아는 내용인가? 그렇다면 넣지 않는다.
- 새 확인 창이나 안내 띠를 넣기 전에: 되돌릴 수 있는 동작인가? 그렇다면 묻지 않는다.
- 목록이나 패널을 바꿀 때: 바뀐 부분만 다시 그리는가? 반짝임, 자동 스크롤이 없는가? 스크롤바, 부모 `overflow` 에 밀리거나 잘리지 않는가?
- 숫자 입력: 보고서 창과 같은 기본 숫자 칸(칸 안 화살표)인가? 휠은 포커스 중에만 막는가?
- 실제 위젯에서 창 크기와 테마(밝게, 어둡게)를 바꿔 한 번 찍어 본다.
