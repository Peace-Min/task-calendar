# 내 과제 묶음: 공식, 일반, 기본

상태: 기획(2026-11-13, 사용자 결정). 시안 `docs/prototypes/category-groups.html` 의 A'.

## 1. 결정
1. **순서 규칙은 묶음 순서가 먼저다.** 공식 과제(DB 과제), 일반 과제, 기본 과제 순서이고 기본은 휴가, 기타 순으로 맨 아래 고정이다. 각 묶음 안의 순서는 사용자가 정한다.
2. **이 순서를 그대로 따르는 곳:** 근태 보고, 월간, 필터, 과제 선택 상자, 보고서, 다른 사람 일정 보기의 과제 순서(지금 `state.categories` 순서를 따르는 모든 곳).
3. **내 과제 창은 묶음 머리로 나눈다(A').**
   - 공식 과제 머리는 옅은 파랑(강조색 옅은 바탕과 글자)이다.
   - 일반 과제 머리는 지금 표 머리와 같은 회색 바탕이다.
   - 기본 머리는 바탕 없이 위쪽 굵은 경계선이다.
   - 머리에는 묶음 이름과 개수를 쓴다(예: "공식 과제 3").
   - 줄 모양은 묶음과 상관없이 지금과 같다(굵은 이름, 둘째 줄은 설명). 줄마다 붙던 "공식" 표는 없앤다. 머리가 대신한다.
4. **끌기는 같은 묶음 안에서만 된다.** 다른 묶음 위로 끌면 선이 생기지 않고 놓아도 그대로다. 끌기 공용 손 `ordDragInit` 을 그대로 쓴다. ⋯ 메뉴의 순서 단추(맨 위로, 위로, 아래로, 맨 아래로)도 묶음 안에서만 움직인다. 묶음 끝에서는 그 방향 단추를 막는다.
5. **휴가와 기타는 고정이다.** ⠿ 와 ⋯ 를 숨긴다. 줄을 누르면 지금처럼 수정 창이 열린다(기본 과제 수정 창은 이름을 바꾸지 못하는 지금 규칙 그대로).
6. **합치기를 양쪽 다 막는다.** 휴가나 기타를 다른 과제로 합치거나 옮길 수 없고, 다른 과제를 휴가나 기타로 합치거나 옮길 수도 없다. 합치기, 옮기기의 대상 고르기 목록에서 휴가와 기타를 뺀다. 공식 과제로 연결(재연결)할 때 휴가와 기타는 대상도 출발도 될 수 없다. 지금 코드에서 이런 경로를 모두 찾아 막는다(`isDefaultTask` 를 쓰는 곳과 옮기기, 합치기, 연결 흐름).
7. **새로 생기는 과제의 자리:** 일반 과제 추가는 일반 묶음 끝에, 공식 과제 추가와 공식 과제로 연결은 공식 묶음 끝에 들어간다. 휴가, 기타 아래로 가지 않는다.
8. **앱은 늘 규칙을 지킨다.** 부팅, 다시 읽기, 가져오기 뒤에 규칙과 다르면 묶음 순서로 고쳐(각 묶음 안 순서 유지) 저장한다. 같은 규칙이라 몇 번 돌아도 결과가 같다.

## 2. 기존 사용자: 배포 SQL 의 판 데이터 단계
- 0.28.0 에서 만든 장치(`db/deploy/data/`, `installer/release-sql.ps1` 의 판 데이터 단계, DB-RELEASE-OPS §5.4)를 그대로 쓴다. 판 번호는 배포 때 정하므로 파일 이름의 판은 배포 직전에 맞춘다.
- `cal_category.sort_order` 를 사람마다 다시 매긴다: 공식(DB 과제와 이어진 줄), 일반, 휴가, 기타 순서이고 묶음 안은 지금 sort_order, 그다음 uid 순이다.
- 안전장치는 0.28.0 과 같다.
  - `app_latest_version` 이 그 판보다 낮을 때만 돈다.
  - 순서가 바뀐 사람만 `cal_user_rev` 를 올린다.
  - 모든 바꾸는 문장에 키 칸 WHERE 를 붙인다. 한 표 UPDATE 이고 창 함수를 쓴다.
  - 저장 프로그램과 임시 표를 쓰지 않는다.
- 공식, 휴가, 기타를 가르는 DB 칸은 구현 때 schema-calendar.sql 과 앱의 `isOfficialCat`, `isDefaultTask` 판정에 맞춰 정하고 문서에 적는다.
  - 구현(2026-11-13): `db/deploy/data/0.29.0-category-groups.sql`(계획 판. 배포 판이 다르면 파일 이름과 머리를 바꾼다). 공식 = `source = 'db'`, 휴가 = `source <> 'db'` 이고 `TRIM(name) = '휴가'`, 기타 = 같은 꼴로 `'기타'`, 그 밖은 일반. 앱의 묶음 번호 `catGroupRank` 와 같다. 이름이 같은 개인 과제가 둘이면 둘 다 그 이름 묶음에 모이고 앞의 것(기본 과제)이 앞이다(그래야 몇 번 돌려도 같다). 리허설은 DB-RELEASE-OPS §5.4.

## 4. 시험
- 묶음 순서가 모든 순서 소비처(근태 보고, 월간, 필터, 선택 상자)에 반영된다.
- 끌기와 ⋯ 순서 단추는 묶음 밖으로 못 나간다.
- 휴가와 기타에는 ⠿ 와 ⋯ 가 없고, 누르면 수정 창이 열린다.
- 합치기, 옮기기, 연결에서 휴가와 기타가 양쪽 다 빠진다.
- 새 과제와 연결된 과제가 묶음 끝에 들어간다.
- 부팅 정리는 몇 번 돌아도 같다.
- 판 데이터 단계: release-sql 시험(그 판에만 들어감, 금지 문장, 키 WHERE, 판 문)과 실DB 사본 리허설(옛 순서 대비 묶음 순서, 묶음 안 순서 유지, 두 번째 실행 변화 없음, 안전 갱신 모드).
