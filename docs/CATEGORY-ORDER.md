# 과제 순서 설정 — 기획서

> 2026-10-01 · 대상 v0.19.x · 파이프라인 **기획 → 개발 → QA → 위키** 의 1단계 산출물. 개발·QA 의 정본.

## 0. 요구

사용자: "캘린더 내부의 과제 목록에서도 순서를 설정할 수 있어야 하고, 그 순서를 반영해서 **보고서 작성 위치**가 달라져야 한다."

## 1. 현재 동작(2026-10-01 조사)

| 영역 | 지금 | 근거 |
|---|---|---|
| 저장 | `state.categories` 배열 순서가 `cal_category.sort_order` 로 저장된다(저장마다 전 행 갱신) | `CalendarWriteDb.CategoryParams` `@so = i` |
| 읽기 | `ORDER BY c.sort_order, c.uid` | `CalendarDb.cs` 부팅 조회 |
| XML | 내보내기·가져오기가 배열 순서를 지킨다 | toXML/fromXML |
| 보고서 | 행 = `state.categories` 순서. 이름이 「기타」인 과제는 맨 뒤, 미분류(→「기타」)는 그 뒤 | `collectReportData` |
| 「과제 관리」 목록 | **실제 순서가 아니라 개인 과제 먼저 · 공식 과제 뒤**로 다시 묶어 보여 준다 | `renderCatModal` |
| 순서 바꾸기 | **수단이 없다**(추가한 순서 그대로) | — |

→ 저장·읽기·보고서는 이미 "배열 순서"를 따른다. 빠진 것은 **순서를 바꾸는 화면**과, 목록이 **실제 순서를 보여 주는 것**이다. 호스트·DB 변경 없음.

## 2. 목표 동작

| # | 상황 | 동작 |
|---|---|---|
| R1 | 「과제 관리」 목록 | 개인·공식 과제를 **한 줄로, 실제 순서대로** 보여 준다(공식 표시는 그대로) |
| R2 | 순서 바꾸기 | 각 행에 **▲ ▼** 버튼. 맨 위 ▲ · 맨 아래 ▼ 는 비활성. 누를 때마다 한 칸 이동 + **바로 저장**(저장 1회) |
| R3 | 접근성 | 진짜 버튼 · `aria-label`「위로 이동: 과제명」/「아래로 이동: 과제명」 · 옮긴 뒤 포커스가 **옮겨진 행의 같은 버튼**에 남고 목록 스크롤 자리 유지(「구성원 편집」 ▲▼ 와 같은 방식) |
| R4 | 반영 범위 | 같은 순서가 **보고서 행(일간·주간·기간 취합·복사·전송)**, 필터 막대, 새 기록·빠른 추가·할 일의 과제 선택, 내보내기에 그대로 쓰인다 |
| R5 | 예외(유지) | 보고서에서 「기타」 과제는 **늘 맨 뒤**, 미분류는 그 뒤. 「공식 과제(DB)」 **카탈로그** 화면(회사 목록 찾아보기)은 이 순서와 무관 |
| R6 | 새 과제 | 개인 과제 추가 · 공식 과제 편입은 **맨 뒤**에 붙는다 |
| R7 | 연결 끊김 | 오프라인 잠금(`guardEdit`) 중에는 이동하지 않는다 — 토스트, 상태·저장 변화 0 |
| R8 | 안내 | 목록 위에 흐린 한 줄 「순서는 보고서·필터에 그대로 반영됩니다」 |
| R9 | 다른 PC | 순서는 서버에 저장되므로 다른 PC 에서 로그인해도 같은 순서(다음 부팅 때 반영) |

## 3. 수용 기준(QA)

| ID | 기준 | 확인 |
|---|---|---|
| C1 | 목록이 `state.categories` 순서 그대로(개인·공식 섞임) | 계약 + 실 위젯 |
| C2 | ▲▼ 한 번 = 한 칸 이동 · 저장 1회 · 끝 버튼 비활성 | 계약 + jsdom |
| C3 | 옮긴 뒤 서버에서 다시 읽어도 같은 순서 | 실 위젯(reloadState) |
| C4 | 보고서 행 순서 = 목록 순서(「기타」·미분류 맨 뒤) | jsdom + 실 위젯(collectReportData) |
| C5 | 필터 막대·과제 선택 상자도 같은 순서 | 계약 + 실 위젯 |
| C6 | 오프라인 잠금 중 이동 불가(상태·저장 0) | jsdom |
| C7 | 포커스·스크롤 유지 | 실 위젯 |
| C8 | 기존 루프·스위트 무회귀 | run-loops · strict |

## 4. 범위 밖

- 끌어서 놓기(드래그) 정렬 — ▲▼ 로 먼저 낸다. 필요하면 다음에.
- 과제별로 보고서에서 숨기기 — 기존 「내용 없는 항목 제외」로 충분.
