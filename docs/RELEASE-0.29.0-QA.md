### 고친 것(점검 중)
1. 검토 P2-1: 근무시간 확인 창이 떠 있는 사이 날짜가 바뀌거나(창 복귀 새로고침, 다른 날짜 열기) 막는 블록이 생기면 [보내기]여도 보내지 않는다. 회귀 시험 attendance-web 에 하나.
2. 실위젯 루프 loop-attendance, loop-attendance-weekly 가 옛 설계(창 닫기, 보고서 창, `__rptSendArmed`, 0시간 막기, 주간 목록 기간)에 머물러 있었다. 지금 동작으로 고치고 run-loops 목록에 넣음(dist, 저장소 밖).

### 기록만(고치지 않음)
- 검토 P2-2: 배포 SQL 의 `TRIM(name) = '휴가'` 는 스페이스만 지우고 앱 `trim()` 은 탭, NBSP 도 지운다. 그런 이름이 있으면 부팅 때 한 번 더 다시 매겨 저장(rev +1)하고 끝난다. 순서 말고 바뀌는 것 없음.
- 루프 공백: 이 개발 계정에 어제 보낸 보고와 이번 달 앱으로 보낸 날이 없어 A3c(이전 보고 불러오기), A9 는 안내로 끝났다. 이전 보고 병합은 jsdom 시험(attendance-web 4-2 이전 보고 출처)이 잠근다.
- 주간 보낸 뒤 다시 열기는 실제 인트라넷 전송이 있어야 재현된다. jsdom 회귀와 루프 W6(보낸 뒤 `awSentKeep`)로 확인했고, 폐쇄망 실사용에서 한 번 본다.

### 폐쇄망 확인 목록
- 업데이트 뒤 내 과제가 공식, 일반, 휴가, 기타 순인지(배포 SQL 이 한 번 맞춤, 묶음 안 순서는 그대로).
- 일간 보고 [← 불러오기]가 체크한 과제만 바꾸는지.
- 주간 보고에 과제를 더해 보낸 뒤 바로 다시 열어 그 과제가 있는지.
