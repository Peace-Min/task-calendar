# 근태 창 다시 쓰기 (처음 연 뒤 숨겨 두기)

상태: 구현 완료(2026-11-02, 브랜치 feat/cal-common, eca9c69), 0.25.1 판에 실림. 설계 확정(2026-11-02 사용자). 파일 이름은 검토 과정의 흔적이다(처음엔 모든 화면을 메인 창 안으로 옮기는 안이었다, 5절).

## 1. 문제

- 사내 PC(폐쇄망)에서 근태 창(일간, 주간)을 열 때마다 1.5~2.5초 걸린다(사용자 체감). 근태는 날짜와 주를 넘겨 가며 하루에도 여러 번 여는 화면이다.
- 원인: 별도 창은 열 때마다 WebView2 를 새로 띄우고 앱 화면 파일 전체(약 2.4MB)를 다시 읽고 실행한다.
- 실측(외부망 개발 PC): 화면 준비까지 근태 0.28초, 창 하나에 renderer +42MB. 별도 창은 가볍게 만들어도 창당 20~30MB 가 브라우저 엔진 몫이다.

## 2. 결정

- **근태 창(일간, 주간 같이 씀) 하나를 처음 열 때 만들고, 닫으면 없애지 않고 숨긴다.** 다음부터는 그날 데이터만 새로 채워 바로 보여 준다.
- **처음 열 때는 창 틀과 로딩 표시를 바로 띄운다.** 웹 화면이 뜨기 전 구간이라 스켈레톤(웹으로 그림)은 의미가 없다. 호스트(WPF)가 그리는 "불러오는 중"과 가로로 흐르는 막대(메인 창 시작 표시 `loadingBar` 와 같은 모양)를 쓴다. 누르자마자 반응이 보여 여러 번 누르는 일도 막는다.
- **미리 만들어 두기(앱 시작 뒤)는 하지 않는다.** 시점 조정과 취소가 복잡하고, 첫 열기는 로딩 표시와 함께라 기다릴 만하다(사용자).
- 관리 창과 다른 사람 일정 창은 지금 그대로(자주 열지 않는다).

## 3. 동작

- 열기: 숨긴 근태 창이 있고 살아 있으면 그날 payload 를 넣고 보여 준다(지금 `attendOpen` 의 대상 바꾸기와 같다). 없으면 창을 만들고 로딩 표시를 보인 채 웹이 준비되면 payload 를 넣는다.
- 닫기(×, Esc, 닫기 단추): 지금의 닫기 확인 규칙(묻지 않고 닫기, 임시 저장 유지, 보고 중 막기)을 지난 뒤 **창을 숨긴다**. 숨길 때 웹 화면을 빈 상태(편집 내용, 열린 하위 팝업, 타이머 정리)로 돌려 다음에 다른 날짜가 깨끗이 열리게 한다.
- 다시 보일 때: 과제 목록, 테마, 그날 기록을 새 payload 로 채운다(오래된 내용이 남지 않게).
- 창 크기와 위치, 최대화 기억은 지금 그대로.

## 4. 실패와 정리 (앱이 뻗지 않게)

- 창 만들기와 다시 보이기를 예외를 잡는 길로 감싼다. 실패하면 로그를 남기고 그 창을 버린다. 다음 열기 때 새로 만든다. 메인 창은 영향이 없다.
- 숨긴 동안 화면 프로세스가 죽으면(`ProcessFailed`, 지금 처리 코드가 있다) 로그를 남기고 "준비 안 됨"으로 둔다. 다음 열기 때 새로 만든다.
- 로그아웃, 계정 바뀜, 앱 종료 때 숨긴 근태 창을 닫는다(다른 사람 정보가 남지 않게). 다음 로그인 뒤 처음 열 때 다시 만든다.
- 여는 시각(요청, 창 보임, 화면 준비)을 `widget.log` 에 남겨 배포 뒤 사내 PC 에서 첫 열기와 다시 열기를 비교한다.

## 5. 검토하고 버린 안

- 모든 화면을 메인 창 안 팝업으로(별도 창 제거): 구조는 가장 깔끔하지만 공수가 크고(별도 창 코드와 시험 걷어내기), 근태를 따로 띄워 페이지처럼 넘겨 보는 지금 습관을 잃는다.
- 근태 탭 안 화면 전환: 위와 같은 이유.
- 앱 시작 뒤 미리 만들기: 시점과 취소 처리가 복잡하다.
- 새 창으로 열기(팝업마다): 창당 메모리와 화면마다 데이터 넘기기가 필요하고, 동시에 띄워야 할 화면이 없다.

## 6. 따로 정할 것

- 메인 창 안 팝업 전체에 "앱 창 영역 최대화" 단추를 공용으로 넣을지(별도 작업). 넣는다면 넓은 작업 화면끼리만 마지막 크기를 같이 기억하고, 작은 입력 팝업은 늘 원래 크기로 연다.

## 7. 순서

1. 구현: 호스트(창 숨기기와 다시 쓰기, 로딩 표시, 실패 처리, 로그아웃 정리, 시간 기록), 웹(닫을 때 화면 비우기, 다시 보일 때 새로 채우기).
2. QA: 계약 시험, 실제 위젯(첫 열기와 다시 열기 시간, 날짜와 주 넘기기, 로그아웃 뒤, 화면 프로세스를 죽인 뒤 다시 열기), 근태 루프.
3. 위키(근태 보고), CHANGELOG.
