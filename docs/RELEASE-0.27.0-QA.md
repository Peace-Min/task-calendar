# 0.27.0 배포 전 점검(시니어 QA, 배포 담당 관점)

상태: 기획(2026-11-10, 사용자 지시 "QA, Wiki 진행 후에 버전 갱신 절차는 처음부터 다시"). 틀은 [0.26.0 점검](RELEASE-0.26.0-QA.md)과 같다. 결과는 이 문서 끝 "결과" 절과 `dist/qa-morning/release-0.27.0/`.

## 경위
- 첫 버전 갱신(커밋 `8b3b3a3`)은 strict, 인스톨러, 릴리스 SQL 리허설만 하고 실DB 루프(E)와 실위젯 탐색(D), 코드 리뷰(B, C)를 건너뛰었다. 그 산출물은 쓰지 않는다.
- 이 점검이 끝나고 위키를 고친 뒤, 버전 갱신은 CLAUDE.md 릴리스 체크리스트 1~6 을 처음부터 다시 한다(첫 갱신 커밋은 되돌리고 하나의 갱신 커밋으로).

## 범위
- 기준: 마지막 배포 0.26.0(`e0f72b7`, DB 구조 22). 앱 파일, `widget/CalendarWriteDb.cs`, `DocxWriter.cs`, `MonthlyReportExport.cs`, `ScheduleImageDb.cs` 가 바뀌었다.
- DB: 구조 22 그대로(이관 조각 없음). 릴리스 SQL 은 구조 확인과 최신 버전 정보만 쓴다.
- 기능 묶음:
  1. 근태 월간(예전 취합): 월간 보고 문서 하나, 보고서 양식 SW/HW, 읽기 전 빈 양식, 머리 체크 전체 선택, 미식별 넣을 곳 콤보.
  2. 주간보고 머리 읽기 넓힘(A안, docs/MONTHLY-HEAD-MAPPING.md).
  3. 개발 일정 그림 과제당 1장.
  4. 보고 프리셋 Ctrl+1~9, 가져오기 서식 수준, 머리기호 8개, 들여쓰기 28칸.
  5. 개인 캘린더 저장을 바뀐 행만(save-diff).
  6. 할 일 제목 전부 보임, 내 과제 ⋯ 메뉴 자리와 순서, 일간 패널 접기 삭제.

## 위험(높은 순)
1. **save-diff**: 저장 경로가 바뀌었다. 건너뛴 행, 지운 행, 충돌(rev) 처리에서 데이터를 잃으면 P0.
2. **월간 문서가 실제와 다름**: 미리 보기와 DOCX 가 다르거나, 읽은 글이 빠지거나 깨진다(보고가 잘못 나감).
3. **그림 1장 상한과 옛 데이터**: 0.26.0 에서 여러 장 넣은 과제.
4. **바뀐 화면**: 근태 월간, 날짜 패널 할 일, ⋯ 메뉴의 회귀와 출렁임.
5. **문서와 실제의 어긋남**: 위키, 패치노트.

### 고친 것
1. (P1) 월간 출처 [캘린더]가 주간보고 DB 글을 읽을 때 `atDecode` 로 `&nbsp;` 를 공백으로 되돌린다(주간 편집과 같음). 시험 MS12, 변이 MSM7.
2. (P2) 머리 꼬리 검사 `reHeadTail`: 꼬리가 기간, 시간, 쌍점, 대시와 숫자일 때만 머리, 그 밖(`[완료] 설계서 제출`)은 본문. 시험 netcus-weekly 에 본문 둘과 잰 꼬리 15가지, 변이⑩.
3. (P2) DOCX 내보내기도 과제당 첫 그림 1장(`ScheduleImageDb.ImagesForExportAsync`, DB 길과 사본 길).
4. (P2) 미리 보기 빈 줄 높이를 DOCX trHeight 값으로(17.3pt, 13.7pt).
5. (P2) 미리 보기 그림 폭을 DocxWriter.FitImage 와 같은 계산으로(`rptMImgFitStyle`). 시험 MS13, 변이 MSM8. 실위젯에서 1600x500 그림이 칸 폭의 99.9%(DOCX 와 같음).
6. (P2) 알림의 [폴더 열기] 뒤 "되돌렸습니다" 가 뜨지 않게(toast action `quiet`).

### 폐쇄망 확인 목록
- 들여쓰기(2수준 이상)를 쓴 주간보고를 보낸 주를 월간 출처 [캘린더]로 읽어 `&nbsp;` 가 없고 들여쓰기가 사는지.
- 0.26.0 에서 한 과제에 그림을 2장 이상 넣은 사람이 있는지(`project_schedule_image` 를 과제, 사람별로 셈). 있으면 첫 장만 문서에 들어간다고 알린다.
