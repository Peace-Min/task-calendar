# 기본 과제 휴가, 기타 (DEFAULT-TASKS)

> 작성 2026-10-07. 스키마 변경 없음(판번호 12 그대로). 주로 웹(HTML)과 시험. 호스트(C#)는 주석 정리 정도.
> 이 문서는 구현 전 설계다. 구현하며 달라지는 곳은 맨 아래 정정 이력에 적는다. 본문과 정정 이력이 다르면 정정 이력이 맞다.

## 1. 요구 (2026-10-07 사용자와 대화로 확정)

- 회사 주간보고 폼은 과제투입시간에 `[휴가]`, `[기타]` 가 늘 들어간다. 앱에서도 두 항목에 시간을 적고 주간 합계까지 맞아야 한다.
- 휴가, 기타는 **내 과제 목록의 진짜 과제**다. 일정을 넣을 때 고를 수 있어야 한다.
- 앱이 **이름으로** 알아본다. DB 는 기본 과제인지 모른다(스키마 변경 없음).
- **"과제 없음" 이라는 상태를 앱에서 없앤다.** 새 기록의 기본값은 기타다. 미분류를 기타로 모으던 보고서 로직, '기타' 를 맨 뒤로 보내던 규칙은 전부 지운다.
- 기본 과제는 이름 변경, 삭제를 막는다. 순서 변경(▲▼)과 색 변경은 허용한다.
- 과제를 지우면 **그 과제의 데이터(일정, 커밋 기록, 할 일, 과제별 시간)도 지운다.** 지우는 사람이 각오하는 동작이다. 확인창에 무엇이 몇 개 지워지는지 보여 준다.
- 새 기능 **"다른 과제로 옮기기"**: 한 과제의 데이터를 다른 과제로 통째로 옮긴다. 옮긴 뒤 지우는 안전한 길이고, '연차' 같은 비슷한 과제를 휴가로 합치는 길이다.
- 보고서 좌측의 근태(근무 형태, 초과근무)는 제출용이다. 휴가 시간과 연결하지 않는다(자동 채우기 없음).
- 일회성 이관 코드는 만들지 않는다. 예전 기타 시간(`__uncat__`) 옮기기, 비슷한 이름 정리는 하지 않는다.

## 2. 핵심 규칙 (불변식)

**"내 캘린더에는 이름이 정확히 '휴가' 인 개인 과제와 '기타' 인 개인 과제가 늘 있다. 모든 일정과 할 일은 실재하는 과제를 가리킨다."**

- 기본 과제 판별: `!isOfficialCat(c) && c.name === '휴가'`(또는 '기타'). 공식 과제(DB 연결)는 이름이 같아도 기본 과제가 아니다.
- 같은 이름의 개인 과제가 둘 이상이면 목록에서 앞에 있는 것이 기본 과제다. 나머지는 일반 과제다(옮기기로 합칠 수 있다).
- 보장 함수 `ensureDefaultTasks()` 하나가 이 불변식을 지킨다. 없으면 만들고(목록 맨 뒤에 붙인다), 있으면 아무것도 하지 않는다. 개인 과제에는 숨김 플래그가 없으므로 "숨김 해제" 는 필요 없다.
- 새로 만들 때 색: 휴가 `#2f9e6e`, 기타 `#7a8699`(구현자가 기존 팔레트에서 가까운 값으로 바꿔도 된다).

## 3. 보장 함수를 부르는 곳

| 시점 | 조건 | 메모 |
|---|---|---|
| DB 부팅 직후 | 내 창(!PEER), 편집 가능(bootOk, 연결 ok, 미저장 없음) | `__applyState` 본문에서 save() 를 부르면 안 된다(시험 data-source ⑤). `__applyProjects` 의 "바뀌었으면 잠금 아닐 때 save" 패턴처럼 부팅이 끝난 뒤 한 번. 없을 때만 저장이 생긴다 |
| XML 가져오기(교체) 뒤 | applyImport 안, state 를 만든 직후 saveFull 전 | 같은 이름 과제가 파일에 있으면 그것이 기본 과제가 된다 |
| 전체 초기화(clearAll) 뒤 | 같다 | 초기화 뒤에도 불변식 유지 |
| 브라우저(비 HOST) 첫 실행 기본 state, localStorage load() | 같다 | 데모 모드도 같은 규칙 |
| 열람 창(PEER) | **부르지 않는다** | 상대 데이터는 고치지 않는다 |
| 편집 잠금 중(연결 끊김 등) | 부르지 않는다 | 연결이 돌아와 다음 부팅/재적용 때 보장 |

## 4. 바뀌는 동작

### 4.1 빈 캘린더 판정 (`calendarIsEmpty`)

기본 과제만 있고 일정, 할 일, 과제별 시간이 하나도 없으면 빈 캘린더로 본다. 그래야 첫 실행 "이전 버전 기록" 가져오기 물음과 빈 캘린더 안내가 계속 뜬다.

### 4.2 과제 선택 상자

- 일정 기록 창(`#fCat`), 빠른 추가(`#qaCat`), 할 일 인라인 편집(`.te-cat`)에서 빈 선택지("미분류", "과제 없음")를 없앤다.
- 새 기록의 기본값: 필터로 고른 과제가 있으면 그 과제, 없으면 **기타**.
- 편집할 때 기록의 과제가 목록에 없으면(이론상 없어야 함) 기존 `ensureCatOption` 처럼 "(알 수 없는 과제)" 를 보여 주고, 사용자가 다른 과제를 고르게 한다. 조용히 첫 과제로 바뀌면 안 된다.
- 검색 창 과제별 탭(`#sCatSelect`)의 "과제를 선택하세요" 는 아직 안 고른 자리표시라 그대로 둔다.
- `refreshDbUi` 의 선택 상자 재채움(약 5690행)도 같은 규칙.
- 데이터 함수(`addEntry`, `updateEntry`, `addTodo`, `updateTodo`)는 categoryId 가 비면 기타 id 를 넣는다. 화면을 거치지 않는 경로의 마지막 방어선이다.

### 4.3 보고서

- `collectReportData` 에서 `gitaCat` 병합, `catKey` 의 `__uncat__` 분기, `uncat`, `uncatMeta`, 합성 '기타' 행, '기타' 맨 뒤 규칙을 지운다. 행은 내 과제 목록 순서 그대로다(0건 과제 포함, 기존 규칙).
- 일간 카드의 `__uncat__` 전용 안내("시간은 과제를 지정한 뒤")와 `.rcard-hnote` CSS 를 지운다. 기타 카드도 다른 카드처럼 시간 입력칸이 있다.
- 업무 없는 휴가, 기타 줄은 기존 "빈 항목 제외" 옵션으로 뺀다. 시간이 적혀 있으면 업무가 없어도 줄이 남는다(기존 `rowHasHours`).
- **netcus 회사 보고서를 읽어 합치는 기능의 '기타' 정렬과 `[미분류]` 묶음은 그대로 둔다.** 회사 보고 원문을 해석하는 다른 기능이다(parseNetcusWeek, buildNetcusSendText, renderNetcusPreview).

### 4.4 과제 보호

- 내 과제 창: 기본 과제 행에는 삭제 버튼이 없다(공식 과제의 del 무시 패턴과 같게). 수정은 열리되 이름 칸이 잠긴다. `catFormLocked` 와 `applyCatFormLock` 를 넓혀 쓰고 안내 문구는 기본 과제용으로 따로 둔다(예: "기본 과제라 이름을 바꿀 수 없습니다").
- 다른 과제의 이름을 '휴가' 나 '기타' 로 바꾸거나 그 이름으로 새로 만드는 것은 기존 중복 이름 검사가 막는다(확인할 것).
- 재연결(`runRelink`, 개인 과제를 공식 과제로 옮기기)의 대상 목록에서 기본 과제를 뺀다.
- `deleteCategory` 자체도 기본 과제면 아무것도 하지 않는다(화면 우회 방어).

### 4.5 과제 삭제 = 데이터 삭제

- `deleteCategory(id)`: 그 과제의 일정(커밋 기록 포함), 할 일, 과제별 시간을 state 에서 지우고 과제를 지운다. 한 번의 save 로 나간다. DB 쓰기는 이미 사라진 일정, 할 일, 시간, 과제를 FK 순서대로 지운다(CalendarWriteDb 단계 6, 10).
- 확인창: "'X' 과제를 삭제할까요? 이 과제의 일정 n개, 할 일 m개, 과제별 시간 k일이 함께 삭제되고 되돌릴 수 없습니다. 남기려면 먼저 '다른 과제로 옮기기' 를 쓰세요." 숫자가 0 인 항목은 생략해도 된다.
- 지운 뒤 필터가 그 과제였으면 해제(기존 동작).
- 실행 취소: 과제 삭제에는 실행 취소가 없다(지금도 없다). 일정이나 할 일 삭제의 실행 취소가 이미 지워진 과제를 가리키는 기록을 되살리면, 되살릴 때 기타로 붙인다(4.2 의 데이터 함수 방어선과 같은 규칙).

### 4.6 다른 과제로 옮기기 (신규)

- 진입: 내 과제 창의 각 과제 행에 "옮기기" 버튼. 개인, 공식, 기본 과제 모두 출발지가 될 수 있다.
- 대상 고르기: 작은 창에서 다른 과제 하나를 고른다(자기 자신 제외, 고를 수 있는 과제 `isPickableCat` 만).
- 확인: "'A' 의 일정 n개, 할 일 m개, 과제별 시간 k일을 'B' 로 옮깁니다." 확인 뒤 한 번의 save.
- 옮기는 것: 일정(커밋 기록 포함), 할 일의 categoryId, 과제별 시간.
- **시간이 같은 날짜에 겹치면 더한다(하루 24 상한, 기존 setTaskHours 와 같은 반올림).** 옮긴 쪽 시간 키는 지운다.
- 출발 과제는 남는다(빈 과제). 지울지는 사용자가 정한다. 기본 과제에서 옮겨도 기본 과제는 남는다.
- 편집 잠금(guardEdit)과 열람 창 금지. `tests/offline-web.test.mjs` 의 GATED_FUNCTIONS 에 추가한다.
- 재연결(runRelink)의 데이터 옮기는 부분과 겹치지만 이번에 재연결은 고치지 않는다(재연결은 시간을 안 옮기고 guardEdit 도 없다. 별도 과제로 남긴다).

### 4.7 XML 가져오기

applyImport 에서 state 를 만든 직후, saveFull 전에:

1. `ensureDefaultTasks()`
2. categoryId 가 비었거나 가져온 과제 목록에 없는 일정, 할 일 → 기타 id.
3. 가져온 과제 목록에 없는 과제 키의 과제별 시간은 버린다(지금도 DB 쓰기에서 버려진다. 이제 앱에서 명시적으로).

예전 데이터가 들어오는 입구는 둘이다. 앱의 XML 가져오기와 배포자의 대량 이관 도구(`db/deploy/xml-to-db`)다. 둘이 같은 정리 규칙을 따르므로(정정 이력 2차 1번) 이 정리가 일회성 이관 코드를 대신한다.

### 4.8 그 밖의 화면

- 검색 결과의 '미분류' 표시, 칩과 카드의 "과제 없음" 회색 처리 같은 표시 폴백은 **열람 창의 내 겹(buildMineOverlay, categoryId null 이 의도된 예외)** 때문에 남는 것은 남긴다. 내 데이터에서 null 을 전제로 한 문구('미분류')만 지운다.
- 도움말(약 3686행 "'기타'와 미분류는 보고서 맨 뒤"), 과제 삭제 문구(약 16179행), 관련 주석을 새 규칙에 맞춘다. 과거 패치노트 항목은 그대로.
- 사용 설명서 창(`#helpModal`)에 기본 과제, 옮기기, 삭제 시 데이터 삭제를 짧게 적는다.

## 5. DB 전제

- DB 는 아직 회사에 배포되지 않았다. 실제 사용자 데이터는 앱의 XML 가져오기(4.7)와 배포자의 이관 도구(`db/deploy/xml-to-db`, 정정 이력 2차 1번) 두 길로 들어온다. 둘 다 과제 없는 기록을 기타로 붙이므로 DB 에 categoryId 가 빈 행이 생기지 않는다. 그래서 부팅 때 null 을 고치는 처리는 두지 않는다.
- 개발 DB(taskcalendar)의 더미 데이터에는 과제 없는 일정이 있다(약 351건, 시험용 seed). 개발용이라 그대로 둔다. 이 행들은 화면에 과제 없이 보이고 보고서에는 나오지 않는다.
- `cal_entry.cat_no`, `cal_todo.cat_no` 는 NULL 허용 그대로(스키마 변경 없음).
- 호스트 주석 정리: CalendarWriteDb.cs 약 172행의 낡은 주석, schema-calendar.sql 의 "deleteCategory 가 null 로 푼다" 주석. 스키마 문서 주석만 고치고 DDL 은 바꾸지 않는다(판번호 12 유지, 바꾸면 schema-integrity 시험 확인).

## 6. 시험

- 기존 시험 중 `__uncat__`, gitaCat, '기타 맨 뒤', 빈 선택지 문자열, `calendarIsEmpty` 정규식, deleteCategory 의 null 처리, 부팅 저장 건수를 단정하는 것들을 새 규칙에 맞춘다(탐색 보고 9절 목록: app-context, category-order, loop-category-order, data-source, legacy-xml-prompt, offline-web 등).
- 새 시험(되살아나면 실패하는 형태로):
  - 부팅 뒤 휴가, 기타가 정확히 하나씩 있다. 이미 있으면 새로 만들지 않는다. PEER 에서는 만들지 않는다. 편집 잠금 중에는 저장하지 않는다.
  - 기본 과제는 삭제 버튼이 없고 이름이 잠기며 deleteCategory 가 거부한다. 재연결 대상에 없다.
  - 선택 상자에 빈 선택지가 없고 새 기록 기본값이 기타다.
  - 보고서에 `__uncat__`, gitaCat, '기타 맨 뒤' 가 없다. 기타 카드에 시간 입력칸이 있고 시간이 일간 본문, 주간 과제투입시간, 합계에 들어간다.
  - 과제 삭제가 그 과제의 일정, 할 일, 시간을 지운다. 확인창 숫자가 맞다.
  - 옮기기: 일정, 할 일, 시간이 옮겨지고 겹친 날짜의 시간은 더해지며 24 를 넘지 않는다. 출발 과제는 남는다.
  - XML 가져오기: 과제 없는 기록, 없는 과제를 가리키는 기록이 기타로 간다. 파일에 '기타' 가 있으면 그것을 쓴다(두 개 생기지 않는다).
  - 빈 캘린더 판정: 기본 과제만 있으면 비어 있다.
- 실 위젯 루프: 기존 loop-category-order C4('기타' 맨 뒤)를 새 규칙으로 바꾼다. 새 루프 `tests/loop-default-tasks.mjs` 로 부팅 보장, 삭제, 옮기기를 실제 DB 로 확인한다(zz 접두어 시험 과제, 끝나면 정리). run-loops.ps1 목록에 추가한다.

4. **커밋 가져오기(`runGitImport`)**: 시작 때 잡아 둔 과제 목록으로 비동기 반복을 돌아, 기다리는 사이 지워진 과제를 가리키는 일정을 만들 수 있었다. 각 과제의 커밋을 받아 온 뒤 그 과제가 아직 목록에 있는지 보고 없으면 건너뛴다. `catById` 는 카탈로그까지 보므로 `state.categories` 만 본다.
5. **두 PC 동시 첫 부팅**: 기본 과제가 없는 사용자가 두 PC 에서 거의 동시에 처음 부팅하면 각자 휴가, 기타를 새로 만들어 저장할 수 있다(새 행 INSERT 는 토큰 충돌이 아니고 이름 UNIQUE 도 없다). 그러면 같은 이름이 둘 생기고 목록에서 앞의 것이 기본 과제, 뒤의 것은 일반 과제가 된다(옮기기로 합친 뒤 지우면 된다). 드문 경우라 코드는 바꾸지 않았다.
6. **다시 주입될 때의 보장 플래그**: `__applyState` 가 `if(!PEER) __bootDefaultsDirty = ensureDefaultTasks(state);` 로 주입마다 플래그를 새로 정한다. 잠금으로 미뤄진 보장 저장이 남아 있어도, 서버가 이미 기본 과제를 갖고 돌려주면 쓸데없는 전체 저장을 보내지 않는다.
7. **이전 기록 가져오기와 저장 직렬화**: `dbSave` 는 저장 왕복 중에 온 전량 교체를 다음 통상(차분) 저장으로 보낸다. 그러면 원본 개명과 성공 토스트가 교체 회신에 달린 이전 기록 가져오기가 어긋난다. `awaitSaveIdle()`(저장 왕복이 끝날 때까지, 이어지는 저장 다섯 번까지 기다림)을 두고 `legacyPromptImport` 가 파일을 해석한 뒤, 빈 캘린더를 다시 보기 전에 기다린다.
8. **이름의 앞뒤 공백**: 기본 과제 판정(`defaultTaskOf`, `isDefaultTask`)은 이름의 앞뒤 공백을 빼고 비교한다(`catNameKey`). 공백이 붙은 기본 과제는 `ensureDefaultTasks` 가 **정확한 이름으로 바로잡는다**(돌려주는 값은 '바꿨나'). 보고서 머리 '[기타]' 가 회사 양식과 글자까지 같아야 해서 저장된 이름도 고친다. 부팅에서 바로잡으면 보장 저장이 한 번 나간다. 이관 도구도 같다.
