# 내 과제 창과 과제 추가 창 개선

> 상태: 구현 중 (2026-10-30, 브랜치 `feat/task-add`)
> 시안: [prototypes/task-add-proto.html](prototypes/task-add-proto.html) 의 「제안」 탭. 결정은 2026-10-30 사용자와의 대화에서 정했다.
> 먼저 읽을 원칙: [UI-FEEDBACK-ATTENDANCE.md](UI-FEEDBACK-ATTENDANCE.md) §1 (설명 문구 없음, 확인 창 최소, 장식 아이콘 없음, 정적인 화면, 마우스 먼저).

## 1. 왜

배포 뒤 사용자를 보니 대부분 과제를 추가할 때 공식 과제(DB)에서 고르지 않고 이름을 직접 입력했다. 원인은 화면 구조다.

- 「내 과제」 창 아래에 이름 입력칸과 큰 [과제 추가] 버튼이 늘 보여, 직접 입력이 주인공이었다.
- 공식 과제 입구는 위쪽의 작은 카드(「📁 공식 과제(DB) 찾아보기」) 하나였고, 그 창에서 담으려면 줄을 고른 뒤 오른쪽 상세의 버튼을 눌러야 했다(2단계).
- 공식 과제 목록에는 통상명칭만 보이고 사업명, 계약명은 상세를 열어야 보여, 이름이 비슷한 과제를 구분하기 어려웠다. 긴 통상명칭은 열 폭에서 잘렸다.
- 줄마다 ▲ ▼ 옮기기 수정 제거(삭제) 다섯 개가 늘어서 좁은 창에서 이름이 잘렸고, 「옮기기」가 순서 이동인지 데이터 이동인지 헷갈렸다.

## 2. 결정

| 번호 | 결정 |
|---|---|
| D1 | 「내 과제」 창은 **목록만** 보인다. 아래 입력 폼(이름, 색상, 설명)과 공식 과제 입구 카드를 없앤다. 머리에 **[＋ 과제 추가]** 버튼 하나. |
| D2 | 목록 줄 = ⠿ 손잡이, 색 점, 이름(그 아래 줄에 메모), **구분 열**(공식, 기본, 일반), 건수, **⋯ 하나**. 맨 위에 열 머리글(과제, 구분, 건수). 구분 표시는 이름 옆에 붙이지 않고 고정 열에 둔다. |
| D3 | 순서는 ⠿ 를 끌어서 바꾼다. 마우스 없이도 되도록 ⋯ 메뉴에 위로, 아래로, 맨 위로, 맨 아래로를 둔다. ▲ ▼ 버튼은 없앤다. 옮긴 뒤 반짝임과 자동 스크롤은 없다. |
| D4 | 줄을 누르면 **수정 창**이 열린다(⋯ 의 「수정」과 같다). 이름(일반 과제만, 길면 칸이 늘어나는 여러 줄 칸, 줄바꿈은 공백으로, 최대 60자), 색상, 메모. 공식과 기본 과제의 이름은 글자로만 보인다(입력칸 아님, 잠금 아이콘과 설명 없음). |
| D5 | ⋯ 메뉴: 수정 / 다른 과제와 합치기… (건수가 있을 때만) / 공식 과제로 연결… (일반 과제만) / 순서 묶음 / 내 캘린더에서 빼기 (공식) 또는 삭제… (일반, 빨간색). 기본 과제는 빼기와 삭제가 없다. |
| D6 | 「옮기기」는 **「다른 과제와 합치기」** 로 바꾼다. 합치기 창에 체크 하나: 일반은 「합친 뒤 이 과제 삭제」, 공식은 「합친 뒤 내 캘린더에서 빼기」, 기본은 체크 없음. 기본값은 꺼짐. 합치기 창 자체가 확인이므로 확인 창을 따로 띄우지 않는다. |
| D7 | 「내 캘린더에서 빼기」(공식): 일정, 할 일이 있으면 비활성이고 메뉴 항목 아래에 이유를 짧게 보인다. 되돌릴 수 있는 동작이라 묻지 않고 바로 뺀다. 단 과제별 시간이 지워지는 경우(시간 기록이 있을 때)만 확인한다. |
| D8 | 「기존 과제 재연결」은 **「공식 과제로 연결」** 로 바꾼다. 하단 버튼은 일반 과제가 하나라도 있을 때만 보인다. 일반 과제 줄 ⋯ 의 「공식 과제로 연결…」은 같은 연결 창을 열고 그 과제의 공식 과제 고르기 팝업을 바로 띄운다. 연결 뒤 일반 과제가 목록에 남는 것은 지금과 같다. |
| D9 | **과제 추가 창**은 상단 탭 **공식 과제 / 일반 과제**. 처음 열면 공식 과제 탭. 탭 아래에 부제나 안내 문구는 없다. 두 탭의 창 높이는 같다(탭을 바꿔도 출렁이지 않는다). |
| D10 | 공식 과제 탭 = 검색(통상명칭, 사업명, 계약명, 발주처), 발주처와 구분 고르기, 상태 체크박스(관리 화면, 재연결과 같은 기억), **표 한 장**. 열: 통상명칭, 계약명, 발주처, 상태, 계약기간, 동작. 구분은 열이 아니라 접히는 그룹 머리줄. 오른쪽 상세 패널은 없다. |
| D11 | 폭에 따라 열이 준다(목록 칸의 폭 기준). 760px 미만: 계약명과 계약기간을 숨기고 상태는 점만. 400px 미만: 발주처와 상태도 숨기고 발주처는 이름 아래 작은 줄, 머리글은 「통상명칭 / 발주처」. |
| D12 | 동작 칸: **[추가]** 한 번으로 내 캘린더에 들어간다. 이미 있으면 **「✓ 내 과제」**. 창은 닫히지 않아 여러 개를 연달아 추가한다. 추가할 때 색상과 메모를 정하지 않는다(필요하면 목록의 수정에서). 색은 지금처럼 구분 색이 초기값이다. |
| D13 | 줄을 누르면 그 줄 아래로 펼친다: 사업명, 개발시작, 개발종료(읽기 전용). 좁은 폭에서 숨겨진 열의 값(계약명, 발주처, 상태, 계약기간)도 펼침에 보인다. 표에 보이는 값은 펼침에서 다시 적지 않는다. 입력칸은 없다. |
| D14 | 긴 통상명칭과 긴 과제 이름: 두 줄까지 그대로, 넘치면 **앞부분 … 끝 8자**(연도, 차수처럼 끝에서 갈리는 이름을 구분하려고). 전체 이름은 title 로 보인다. 내 과제 목록과 추가 창 표에 같은 규칙. |
| D15 | 일반 과제 탭 = 과제 이름, 색상, 메모 (선택). 공식 과제 목록이나 안내 문구는 전혀 나오지 않는다. |
| D16 | 하단은 두 탭이 같다: 왼쪽 **[닫기]** 가 같은 자리. 공식 탭은 그 오른쪽에 이번에 추가한 개수(상태 표시), 일반 탭은 오른쪽에 **[추가]**. 일반 과제를 추가하면 창이 닫힌다. |
| D17 | 화면 말: 「일반 과제」(새 화면과 바꾼 화면만. 앱의 다른 곳의 「개인 과제」는 이번에 바꾸지 않는다). 「DB」 배지는 「공식」으로. |
| D18 | 바꾸지 않는 것: DB, 호스트 C#, 버전, 관리 화면의 공식 과제 편집(#officialModal 도킹), 관리자 지름길 「⚙ 공식 과제 편집은 관리에서 ›」(관리자만). |

## 3. 범위 밖 (다른 작업과 겹침)

개인 탭 필터 줄, 할 일 탭, `passFilter`, 주간 과제별 줄 `renderWeekRows`, 과제 탭 날짜 목록 팝업 `pcOpenDayList`, `deleteCategory` 와 `unsubscribeDbCat` 안의 필터 정리 줄(`filterCatId`, `noteFilterCat`)은 과제 필터 작업(`feat/filter-multi`)이 고치고 있어 건드리지 않는다.
