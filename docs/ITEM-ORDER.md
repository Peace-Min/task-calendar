# 일정과 할 일 순서 바꾸기 (0.28.0)

상태: 기획(2026-11-11, 사용자 결정). 시안 `docs/prototypes/day-panel-order.html`(A안 2판, 손잡이 자리 1번).

## 1. 결정
1. **규칙은 하나: 목록 순서.** 일정과 할 일 모두 추가한 순서로 보이고, 사용자가 끌어서 바꾼다. 시각 순, 중요 먼저, 완료는 아래 같은 다시 정렬은 없앤다.
2. **어디서나 같은 순서.** 오른쪽 날짜 패널, 왼쪽 월간 칸(넘치면 앞쪽부터 보이고 나머지는 +n개 더보기), 주간 줄, 검색 결과, 일간보고 [캘린더 가져오기]가 같은 순서를 쓴다. 여러 날 막대가 칸 위쪽에 깔리는 것은 그리기 배치라 그대로 둔다.
3. **순서는 날짜마다가 아니라 전체에 하나.** 여러 날, 반복 일정은 같이 나오는 모든 날짜에서 같은 앞뒤 관계다.
4. **손잡이는 ⠿(내 과제와 같은 모양).**
   - 일정 카드: 카드 안 맨 윗줄 왼쪽, 과제 표 앞(시안 1번).
   - 할 일 줄: 체크 상자 앞.
   - 눌리는 영역은 보이는 글자보다 넓게(약 24px).
   - 손잡이는 늘 보인다(마우스를 올릴 때만 나타나지 않는다).
5. **끌기 효과는 내 과제 순서 바꾸기와 같다**(`.cat-drag-ghost` 계열): 잡은 줄의 복제본이 그림자를 달고 따라오고, 원래 자리는 45%로 흐려지고, 놓을 자리에 선이 생기고, Esc 는 취소다. 5px 넘게 움직여야 끌기가 시작되어, 누르기(카드 열기, 할 일 펼치기)와 헷갈리지 않는다.
6. **일정은 5개만 보이고 접힌다.** 끌기를 시작하면 그날 일정을 전부 펼치고, 놓거나 취소하면 원래 접힘 상태로 돌린다.
7. **패널 위아래 끝 근처에서는 저절로 스크롤한다**(붙은 묶음 머리 높이만큼 위쪽 여유).
8. **키보드:** 카드나 할 일 줄에 포커스를 두고 Alt+↑ / Alt+↓ 로 한 칸씩. 접힌 자리까지 내리면 펼친다.
9. 다른 사람 일정 보기(열람)와 읽기 전용 화면에는 손잡이가 없다. 보이는 순서는 그 사람이 정한 순서다.

## 2. 저장
- DB 변경 없음. `cal_entry.sort_order`, `cal_todo.sort_order` 가 이미 `state.entries`, `state.todos` 배열 순서를 저장하고, 부팅은 `ORDER BY sort_order, uid` 로 읽는다(`widget/CalendarDb.cs`, `CalendarWriteDb.cs` 의 `@so`).
- 옮기기 = 배열에서 그 항목의 자리를 바꾸고 저장. 바뀐 행만 저장하므로 사이에 있던 행들의 sort_order 가 함께 다시 쓰인다(문제 아님).
- 패널은 그 날짜에 보이는 항목 사이의 앞뒤만 바꾼다. 배열 안에서는 "놓은 자리 바로 앞(또는 뒤) 항목"의 앞(뒤)으로 옮긴다. 그날 안 보이는 다른 항목들의 상대 순서는 그대로다.

## 6. 시험
- 정렬: 배열 순서대로 보이는지(패널, 월간 칸, 주간 줄, 검색), 시각과 중요와 완료로 다시 정렬하지 않는지.
- 옮기기: 끌기와 Alt+↑↓ 가 배열을 바꾸고 저장하는지, 접힌 일정 펼침과 원복, Esc 취소, 열람 화면에 손잡이 없음.
- 저장: 실DB 루프(loop-calendar-write 등)에서 순서가 저장되고 다시 읽어도 같은지.
- F2 는 실DB 그림 루프(`tests/db-schedule-image.mjs`)에 미리 보기 그림을 더한다. F3 은 회신 rev 로 맞춘 뒤 저장이 통과하는 시험.
