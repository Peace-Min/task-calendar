# 창 버튼, 맨 앞에 띄우기 단순화, 열람 창 독립 창 (WINDOW-UI)

작성 2026-10-16. 워크트리 `feat/window-ui`(8c7ef67 기준). **개발은 대기.** 다른 세션의 '맨 앞에 띄우기' 수정(ba5c535)이 QA 를 마치고 feat/db-app 에 들어온 뒤, 이 브랜치를 그 위로 맞추고 시작한다.

| 1 | WPF 프로그램처럼 오른쪽 위에 최소화, 최대화 버튼 | 시안(`dist/rehearsal/window-ui/proto-window-buttons.html`) 방향으로 간다. Windows 11 식 최소화, 최대화(이전 크기로), 닫기 |

## 1. 창 버튼(요구 1)

- 위쪽 막대(#hostbar) 오른쪽 끝: 맨 앞에 띄우기, 핀, ☰ 는 지금 자리 그대로. 그 오른쪽에 얇은 구분선과 창 버튼 셋(46x32): 최소화, 최대화/이전 크기로(글리프와 툴팁이 바뀜), 닫기.
- 닫기는 지금 ✕ 의 뜻 그대로다. 트레이를 쓰면 트레이로 숨기고, 안 쓰면 종료한다. 마우스를 올리면 빨간 바탕(#c42b1c), 흰 글리프.
- 막대 빈 곳을 두 번 누르면 최대화와 복원이 바뀐다.
- 최대화는 **작업 표시줄을 가리지 않는 크기**(그 창이 있는 모니터의 작업 영역)로 채운다. 모서리를 각지게, 바깥 그림자와 여백을 없앤다.
- 복원은 최대화 직전의 위치와 크기로 돌아간다. 최대화 상태와 직전 크기를 창 위치 설정에 함께 저장해, 다시 켤 때 최대화로 열리게 한다.
- 호스트: `WindowStyle="None"`, `AllowsTransparency="True"` 라 WPF 기본 최대화는 작업 표시줄을 덮고 투명 창 경계가 어긋날 수 있다. 그래서 `WindowState.Maximized` 를 쓰지 않고 작업 영역(모니터별 WorkArea)으로 크기를 직접 맞추는 방식을 우선 검토한다. 메시지: `winMinimize`, `winMaximizeToggle`, 웹으로 상태 알림 `__setWinState('max'|'normal')`.
- 키보드: Win+위/아래 화살표가 동작하는지 확인하고, 안 되면 범위 밖으로 적는다.

## 2. '맨 앞에 띄우기' 단순화(요구 4)

- 지금: 화면 가운데에 크게(1100x800) 띄우고 뒤를 어둡게 하며, 다시 누르거나 Esc 로 원래 자리와 크기로 돌아간다(`_focusMode`, `OpenBig`, `CloseBig`, 위키 '창 버튼과 트레이'). 켜져 있는 동안 저장된 크기가 평소 크기로 기록되던 결함이 있었다(ba5c535 에서 수정).
- 바꾼 뒤: **크기와 위치는 그대로 두고 다른 창들 위로만 올린다**(Topmost). 다시 누르거나 Esc 로 해제. 뒤를 어둡게 하는 막도 없앤다.
- 크기를 바꾸지 않으므로 크기 저장이 꼬일 여지가 없다. ba5c535 의 보정 코드 중 필요 없어지는 부분은 합칠 때 정리한다(그쪽 시험도 함께).
- 이름은 그대로 '맨 앞에 띄우기'.

## 3. 겹쳐 보기 펼침 스크롤(요구 2, 수정 완료, 커밋 전)

- 원인: 펼침의 줄 규칙이 `grid-auto-rows:minmax(74px,auto)` 였다. 격자 높이가 정해진 상태라 줄이 내용만큼 늘지 않았고, 칸은 `overflow:visible` 이라 넘친 칩이 다음 주 줄 밑으로 깔리고 스크롤도 생기지 않았다. 내 달력의 펼침도 같은 결함이 있었다.
- 수정: `minmax(min-content,auto)` 와 칸 `min-height:74px`. 넘칠 때만 격자가 스크롤된다. 나란히 보기 전용으로 따로 있던 같은 수정은 기본 규칙으로 합쳤다.
- 확인: 정적 서버와 headless Edge 에서 열람 창 흐름 그대로, 합성 데이터 200건. 넘친 칩 188개에서 0개. 고정, 촘촘히, 나란히 보기 회귀 없음. `tests/peer-expand-scroll.test.mjs` 10건. **실제 위젯 확인은 다른 세션 루프가 끝난 뒤.**

## 4. 열람 창 독립 창(요구 3)

지금 구조: 캘린더 화면 안의 `#peerModal` 이 `?peer=1` iframe 을 품는다. 일정은 부모 화면이 호스트에 `peerSchedule`(대상 loginId 만, 보는 사람은 호스트가 세션에서 읽음) 로 받아 iframe 에 넘긴다. 겹쳐 보기는 부모가 가진 **내** 일정을 함께 넘긴다.

바꾼 뒤:
- 호스트에 열람 전용 창 `PeerWindow`(WPF Window + WebView2, 메인과 같은 WebView2 환경 공유)를 둔다. 캘린더에서 '다른 사람 일정' 을 누르면 이 창이 열린다. 이미 열려 있으면 그 창을 앞으로 가져오고 대상을 바꾼다(창은 하나).
- 창은 일반 Windows 창 테두리와 버튼(최소화, 최대화, 닫기)을 쓴다. 메인 창과 독립(Owner 를 두지 않음)이라 따로 최소화하고, 다른 모니터로 옮길 수 있고, 작업 표시줄에 따로 뜬다. 앱을 종료하면 함께 닫힌다.
- 크기와 위치는 PC 에 하나 기억한다(widget.settings.json, 모니터 밖이면 주 모니터 안으로 끌어온다).
- 화면: 지금 `#peerModal` 의 머리줄(사람 이름, 사람 바꾸기, 즐겨찾기, 겹쳐 보기와 나란히 보기, 밀도)과 본문(iframe 의 열람 달력)을 창 전체에 맞춘다. 같은 HTML 을 `?peerwin=1` 로 띄워 그 모드에서는 열람 껍데기만 그린다.
- 데이터: PeerWindow 의 웹 메시지도 메인과 같은 처리기로 보낸다(`peerSchedule`, 사람 고르기 목록 `membersGet`). 겹쳐 보기에 필요한 **내** 일정은 메인 화면이 가진 상태를 호스트가 PeerWindow 로 넘기거나, 호스트가 DB 에서 읽어 준다. 어느 쪽이 단순한지는 개발 첫 단계에서 정한다(메인 상태가 정본이라 메인에서 넘기는 쪽을 우선).
- 권한: 지금과 같다. 보는 사람은 호스트 세션에서 읽고, 웹이 정하지 않는다. 열람 범위는 열 때마다 DB 에서 다시 판정한다.
- 앱 안 `#peerModal` 은 없앤다(독립 창으로 대체). 관련 시험과 루프(loop-peer-view, loop-peer-frame 등)는 새 창 기준으로 옮긴다.

## 5. 범위 밖

- 열람 창을 여러 개 동시에 띄우기(창은 하나).
- 메인 창 가장자리 끌어 크기 바꾸기 방식 변경(지금 방식 유지).

## 6. 시험과 QA

- 정적: 창 버튼 마크업과 메시지, 최대화가 작업 영역을 쓰는지, '맨 앞에 띄우기' 가 크기를 바꾸지 않는지, PeerWindow 메시지 경로와 권한(보는 사람을 웹이 정하지 않음), 펼침 스크롤 사슬.
- 실제 위젯 루프: 기존 33개 + 창 버튼(최소화, 최대화, 복원, 두 번 클릭), 맨 앞에 띄우기 전후 크기 불변, 열람 창 열기, 사람 바꾸기, 크기 기억, 겹쳐 보기 펼침 스크롤.
- 화면 캡처(라이트, 다크, 최대화, 좁은 창), 독립 리뷰 1회, strict 0 fail 0 skip.
- **다른 세션이 위젯 루프를 돌리는 동안에는 위젯을 띄우지 않는다**(단일 인스턴스라 상대 위젯이 꺼진다).

## 7. 위키

- '창 버튼과 트레이': 창 버튼 셋, 최대화와 복원, 바뀐 '맨 앞에 띄우기'.
- '다른 사람 일정 보기': 독립 창, 크기 기억, 겹쳐 보기 펼침 스크롤.
