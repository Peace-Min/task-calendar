# 주간 보고서 글 편집 (WEEKLY-EDIT)

> 작성 2026-10-08. 스키마 변경 없음(판번호 12 그대로). 호스트(C#) 변경 없음. 웹(HTML)과 시험, 문서만.

## 1. 요구 (2026-10-08 사용자와 대화로 확정)

- 주간 작성도 앱에서 자유롭게 고쳐서, 사람들이 실제로 쓰는 최종 내용이 캘린더 DB(`cal_report_weekly`)에 남게 한다.
- 앱에서 고치는 칸은 **넷**: 제목, 진행사항, 과제투입시간(읽기 전용), 차주계획. 회사 폼의 나머지 세 칸(미처리사항, 문제점 및 건의사항, 회의내용)은 **앱에서 쓰지 않는다**. 회사 화면에서 직접 쓴다. 그래서 DB 스키마는 그대로다(지금 표가 정확히 이 네 칸이다).
- "주간보고 작성"(전송 버튼)은 지금처럼 회사 주간보고 화면을 열어 네 칸을 채우고, 제출은 사용자가 그 화면에서 누른다. 그 창에서 더 고치는 것까지 막을 수는 없다(사용자 확인).
- 일간과 같은 원칙: 보고서와 캘린더는 따로 관리한다(보고서에서 고친 글이 캘린더 기록을 바꾸지 않는다). 머리 줄 `[과제]` 는 잠그고 그 아래 내용만 쓴 그대로 보낸다. 카드마다 X(이 보고서에서 빼기). 고친 글은 브라우저 저장소에 임시 저장.

## 2. 대상과 경계

- `reportMode === 'weekly'` 만. 기간 취합(custom)은 바꾸지 않는다(같은 `!daily` 렌더와 서식 저장값을 쓰므로 갈래를 `weekly` 로 따로 연다).
- 내용 출처 둘 다: 캘린더 기록(cal)과 netcus 일간보고(net). 상세 줄을 일간에서 쓰고 주간에서 모으는 길이 net 이라, net 에서도 고칠 수 있어야 한다.
- 고친 글과 X 는 **과제 이름(정규화)** 으로 기억한다. net 출처 과제에는 과제 id 가 없을 수 있기 때문이다. 출처를 바꿔도 같은 이름의 과제면 고친 글과 X 가 그대로 따라온다(초안 본문만 출처에 맞게 다시 만들어진다).

## 3. 화면

### 3.1 미리보기 머리

- 주간에도 일간과 같은 보기 전환 `[카드] [글 편집]`. 보기는 모드별로 따로 기억한다. 창을 열면 일간은 카드, 주간은 **글 편집(회사 폼 모양)** 으로 시작한다(2026-10-08 사용자 결정). 그 열기 동안 바꾼 보기는 모드별로 기억한다. 열람 창은 카드만.
- "고친 과제 n개"(진행사항이나 차주계획을 고친 과제 수), "이 PC에 임시 저장됨 HH:MM" 표시(일간과 같은 규칙, 저장소가 막히면 표시 없음).

### 3.2 카드 보기

- 카드 머리: 색 점, 과제명, (고쳤으면) "고침", 이번 주 시간 합계 "이번 주 n h"(읽기 전용, 시간 기록이 있는 과제만), X.
- 카드 본문: 진행사항 초안 또는 고친 글. **읽기 전용.** 주간의 기간 할 일 날짜 줄 ✎ 도 없앤다(보고서와 캘린더 분리 원칙. 날짜별 세부 내용은 할 일 편집에서 고친다). `commitDayNoteEdit` 등 처리기는 다른 쓰임이 없으면 함께 지우고, 있으면 남긴다(구현자가 확인해 정정 이력에 적는다).
- X: 일간과 같은 모양과 자리(흐리게, "이 보고서에서 뺌 되돌리기", 높이 변화 없음).
- 주간 X 에는 시간 안내 토스트가 없다(주간 X 는 진행사항, 차주계획, 과제투입시간, 합계에서 모두 뺀다).

### 3.3 글 편집 보기 (회사 주간보고 작성 폼 모양, 2026-10-08 사용자 결정)

회사 폼과 같은 두 칸 표(왼쪽 회색 칸에 항목 이름, 오른쪽에 값)이고 순서도 회사 폼 그대로다.

1. **기간**: 읽기 전용 `from ~ to`, 잠금 표시 "왼쪽 달력에서 고름".
2. **제목**: 읽기 전용, 자동 제목(`weekSubjectGuess(from)`, 예: "10월 첫째주"), 잠금 표시 "기간에 따라 자동". **고칠 수 없다**(회사 폼에서도 달력에서 날짜를 고르면 기간과 제목이 자동으로 채워진다).
3. **진행사항**: 과제마다 잠긴 머리 줄 `[과제명]` + 내용 칸. 초안은 지금 전송하는 endwork 의 그 과제 본문(빈 과제는 `-`).
4. **과제투입시간**(이름은 회사 폼처럼 파란 안내 색): 읽기 전용 블록. 지금 전송하는 content 와 같은 규칙(출처별)에서 X 한 과제를 빼고 합계를 다시 낸다. 아래 안내: "일간에 적은 시간의 합계라 여기서는 고치지 않습니다. 회사 안내: 기타와 휴가도 작성, 휴가 1일 8시간, 반차 4시간."
5. **미처리사항**: 자리만(점선, 입력 아님) "회사 화면에서 직접 씁니다".
6. **차주계획**: 과제마다 잠긴 머리 줄 `[과제명]` + 내용 칸. 초안은 빈 칸(지금 planwork 는 머리 줄만 있다).
7. **문제점 및 건의사항**, 8. **회의내용**: 미처리사항과 같은 자리만.

- 표는 스크롤하는 미리보기 안에서 줄어들지 않는다(flex:none). 440px 이하에서는 이름 칸을 84px 로 줄인다.
- 과제마다 "초안으로", 위쪽 "모두 초안으로"(이 기간의 고친 내용과 뺀 과제를 모두 되돌림, 확인 뒤).
- X 한 과제는 진행사항과 차주계획 모두에서 "[과제명] 이 보고서에서 뺌, 카드에서 되돌릴 수 있습니다" 한 줄.
- 대괄호 줄 안내(일간과 같은 문구)는 진행사항과 차주계획 내용 칸에 그대로 적용.
- 낡은 초안 안내(기준본과 지금 초안이 다를 때)는 진행사항에 적용(차주계획 초안은 늘 빈 칸이라 해당 없음).

## 4. 나가는 네 칸

- **고친 것도 뺀 것도 없으면** 전송 payload 의 네 칸은 지금 `buildWeeklyFields`(cal) 또는 net 출처 조립 결과와 **바이트까지 같다**. 주간 복사(`buildReportText` 주간 갈래)도 지금과 바이트까지 같다. 기존 시험(app-context 1311~1396, 1616~1643, 1900~1936, report-edit B2 등)이 그대로 통과해야 한다. `buildWeeklyFields` 의 시그니처와 반환 키는 바꾸지 않고, 초안 적용은 별도 함수로 감싼다.
- 진행사항(endwork): X 하지 않은 과제마다 `[과제명]` + `\n` + 본문(고친 글이면 `reportEditedBodyOut(글, '&nbsp;')`, 아니면 지금 규칙). 과제 사이 `\n\n`. 빈 본문 처리와 끝 줄바꿈은 지금 전송 규칙 그대로.
- 차주계획(planwork): 고친 칸이 하나도 없으면 지금처럼 머리 줄만(`[가]\n[나]`). 하나라도 있으면 과제마다 `[과제명]` + (본문 있으면 `\n` + 본문), 과제 사이 `\n\n`(머리 줄만 있는 과제도 자리 유지). X 한 과제는 뺀다.
- 과제투입시간(content): 지금 규칙에서 X 한 과제의 줄을 빼고 합계를 다시 낸다.
- 제목(subject): 늘 자동 제목(`weekSubjectGuess(from)`, net 도 같다). 고칠 수 없고, 예전 임시 저장에 제목이 있어도 쓰지 않는다(2026-10-08).
- 복사(주간): 지금처럼 진행사항을 복사하되 고친 글과 X 를 반영(단위 U+00A0).
- 호스트는 받은 글을 폼 textarea 에 그대로 넣고 `SaveWeeklyReport` 로 그대로 저장한다(C# 변경 없음). 그래서 DB 에는 앱에서 고친 네 칸이 남는다.

## 5. 임시 저장

- 키: `tc_rptDraftW:<who>:<from>_<to>`(일간 키 `tc_rptDraft:` 와 접두가 달라야 한다. 같은 접두면 일간 정리 규칙과 렌더 감시 시험에 걸리고 월요일 일간 키와 섞인다). `<who>` 는 일간과 같다.
- 값: `{ v:1, from, to, prog:{<이름키>: 글}, progBase:{<이름키>: 기준본}, progBaseSrc:{<이름키>: 출처}, plan:{<이름키>: 글}, out:[<이름키>…], savedAt }`. 제목은 저장하지 않는다(예전 저장본의 subject 는 읽을 때 버리고 다음 쓰기 때 사라진다).
- 쓰는 때, 읽는 때, 디바운스, 닫을 때와 pagehide 때 즉시 쓰기, 막힌 저장소의 메모리 대체, PEER 에서 0 접근은 일간과 같다. 렌더만으로는 쓰지 않는다.
- **주간 채우기 성공으로는 지우지 않는다.** 채우기는 제출이 아니고, 사용자가 고쳐서 다시 채울 수 있기 때문이다. 기간 끝(to)이 14일 넘게 지난 키는 보고서를 열 때 정리한다(이 계정 것만).
- 지금 있는 주간 회신 구분(`RPT_WEEKFILL_OK_RE`)과 일간 초안 보호는 그대로 둔다.

## 6. 바꾸지 않는 것

- 기간 취합(custom) 탭 전체.
- 호스트 C#(채우기, 성공 문구, `SaveWeeklyReport`, `ReportDb`), DB 스키마.
- 일간 글 편집의 동작과 키. 일간 X 의 시간 안내 문구.
- `closeOverlay` 의 reportModal 줄 글자, report-wiring 과 report-edit 의 변이 시험이 찾는 글자들(탐색 보고: S3 의 `rptDraftDisarmSend();   // 주간 채우기 회신`, `reportRowBodyText` 반환 줄 주석 등).
- 주간 전송에 확인창을 새로 넣지 않는다(지금도 없다).

2026-10-08 구현(§2~§7)에서 정한 것과 달라진 것:

- **나가는 네 칸(§4)**: `rptWOutFields(from, to)` 가 예전 조립(cal 은 `buildWeeklyFields`, net 은 `buildNetcusHoursText`, `buildNetcusSendText`, `buildNetcusPlanText`, `weekSubjectGuess`)을 먼저 만들고, 지금 행에 닿는 초안이 하나도 없으면 그 결과를 그대로 돌려준다. 초안이 닿으면 닿은 칸만 `rptWCompose` 결과로 바꾼다(X 는 content, endwork, planwork / 진행사항은 endwork / 차주계획은 planwork / 제목은 subject). `rptWCompose` 도 빈 초안이면 예전과 같은 글을 내는지 시험이 서식 여러 벌로 잠근다. `buildWeeklyFields` 의 시그니처와 반환 키는 그대로다.
- **주간 복사(§4)**: 고친 진행사항이나 뺀 과제가 있을 때만 `rptWCopyText` 로 다시 만들고(cal 은 끝 `\n`, net 은 끝 줄바꿈 없음, 예전 꼴 그대로), 아니면 예전 `buildReportText` 길을 그대로 탄다. 제목과 차주계획은 복사에 들어가지 않는다(예전처럼 진행사항만).
- **이름 키(§2)**: 키는 이름을 NFC 로 맞추고 공백을 모두 뺀 것(parseNetcusWeek 의 정규화와 같다). 같은 목록에 같은 키가 또 나오면 `#2`, `#3` 을 붙여 따로 기억한다(cal 의 동명 과제). net 출처는 같은 이름이 한 과제로 합쳐지므로 `#2` 행이 없고, cal 의 `#2` 행 글은 net 에서 쓰이지 않는다. net 의 `[미분류]` 블록은 키 `@미분류` 의 한 행이다(X, 진행사항 고치기 가능). 차주계획과 과제투입시간에는 지금 규칙대로 들어가지 않는다.
- **쓸 때 걷지 않음(§5)**: 일간과 달리 주간은 쓸 때 지금 행에 없는 이름의 흔적을 걷지 않는다. 행이 출처(cal, net)마다 달라서 걷으면 출처를 바꿨다 돌아올 때 고친 글이 사라진다. 대신 "고친 칸 n개", "임시 저장됨", "모두 초안으로" 켜짐은 지금 행 기준으로만 센다. 흔적은 "모두 초안으로" 나 14일 정리로 지워진다.
- **제목(§4)**: 내용 칸 값이 초안(`weekSubjectGuess`)과 같아지면 고치지 않음으로 돌아간다. 비우거나 공백뿐이면 나갈 때는 초안 제목을 쓴다(빈 제목으로 채우지 않는다). 제목 칸에도 "초안으로" 가 있다.
- **차주계획(§4)**: 공백뿐인 글은 고친 칸으로 치지 않는다(지운다). 고친 칸이 하나라도 있으면 X 하지 않은 과제마다 머리 줄을 자리 유지로 남긴다(§4 그대로).
- **전부 뺐을 때**: X 로 모든 과제를 빼면 `rptWOutFields` 가 null 을 돌려 "보낼 내용이 없습니다" 로 막는다(예전 0 행일 때와 같은 안내). net 은 endwork 가 비면 같은 안내다.
- **"고친 칸" 표시(§3.1)**: 고친 제목, 진행사항, 차주계획 칸 수다. 뺀 과제는 세지 않지만 "임시 저장됨" 은 뺀 과제만 있어도 보인다(일간과 같다).
- **요약줄**: 주간 cal 요약줄 끝에 일간과 같은 ", n개 뺌. 내용은 글 편집에서 고칩니다. 캘린더 기록은 바뀌지 않습니다" 를 붙인다(열람 창 제외). net 요약줄에는 ", n개 뺌" 만 붙인다.
- **14일 정리(§5)**: 키의 기간 끝(to)이 오늘에서 14일을 뺀 날짜보다 이를 때만 지운다(14일째는 남는다). 이 계정 키만, 꼴이 맞지 않는 키는 건드리지 않는다. 그래서 끝난 지 15일 넘은 지난 주를 다시 열면 그 주의 초안은 없다.
- **net 미리보기(§3.2)**: net 카드는 예전 표시(대괄호 과제명, 미등록 표시, 미분류 사유)를 그대로 두고 X 와 "이번 주 n h" 칸을 더했다. 주간에서는 예전 "과제투입시간 n h" 힌트 대신 "이번 주 n h" 를 쓴다(기간 취합은 예전 힌트 그대로). net 은 병합 캐시를 읽은 뒤에만 보기 전환과 글 편집이 보인다(읽는 중에는 숨김).
- **시험(§7)**: 새 시험은 `tests/weekly-edit.test.mjs`(정적 7, 브라우저 cal 10, 위젯 net 6, 열람 창 1, 변이 포함). 깨진 기존 시험은 새 규칙을 잠그는 꼴로 바꿨다: report-edit S1, B1(주간 X 와 보기 전환 있음, 기간 취합만 날짜 줄 ✎, X 와 보기 전환 없음), app-context 의 주간 날짜 줄 시험 셋(주간은 읽기 전용, 편집 앵커와 저장 왕복 시험은 기간 취합으로 옮김)과 commitDayNoteEdit 대조군 문구. 실 위젯 루프는 `tests/loop-weekly-edit.mjs` 로 새로 두었다(netcus 읽기도 하지 않고 병합 캐시를 페이지에 넣는다).
