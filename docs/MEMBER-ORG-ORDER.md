# 구성원 편집 조직 트리와 단일 순서

상태: 구현 완료(2026-10-26, f06f86f)

## 배경

구성원 편집은 전체 명부만 표시하고 순서 편집을 시작하면 검색을 비웠다. 소속별로 구성원을 찾아 수정하거나 순서를 정하기 어려웠다.

## 결정

- 사용자 결정(2026-10-26): A/B 시안 중 B안 조직 트리형을 선택한다. 타인 일정 보기와 같은 탐색 방식으로 구성한다.
- 사용자 승인(2026-10-26): 조직별 독립 순서를 만들지 않고 기존 전체 순서를 필터링한다. 기획, 개발, QA, 위키 진행을 승인했다.
- 구현 결정: 전체, 조직(하위 포함), 소속 없음으로 탐색한다. 처음 열 때는 전체다. 조직을 바꾸면 검색을 비운다.
- 구현 결정: 선택한 목록에서 이웃한 두 사람의 전체 명부 자리를 맞바꾼다. 다른 구성원의 자리는 그대로다. 전체에서 해당 조직을 다시 걸러도 동일한 순서가 된다.

## 바꾸는 것

1. 왼쪽 조직 트리, 오른쪽 검색과 명부를 표시한다. 조직 정렬과 부모 관계는 기존 명부의 도우미를 재사용한다.
2. 선택한 조직 안에서 이름, 직급, 소속, ID를 검색하고 기존 편집 폼을 연다.
3. 순서 편집을 켜면 검색을 비우고 조직 선택과 검색을 잠근다. ▲▼는 표시된 목록의 양 끝에서 잠긴다.
4. 저장은 기존 saveUserOrder에 전체 명부를 전송한다. 활성 구성원 누락 거부, 관리자 검증, 퇴사자 포함, 늦은 갱신 처리, 취소 복원은 유지한다.
5. 선택한 조직이 갱신 후 사라지면 전체로 돌아간다. 비관리자에게 조직 버튼을 만들지 않는다.
6. 단독 창과 관리 화면에 들어간 상태 모두 목록 높이를 유지한다.

## 하지 않는 것

DB 구조, C# 저장 경로, 버전, 배포 파일, 타인 일정 보기, 조직별 순서 컬럼은 바꾸지 않는다. 실제 사용자나 공용 DB에 시험 쓰기를 하지 않는다.

## 순서와 검증

시안 확인과 사용자 승인, 웹 변경, 조직별 이동 및 취소와 전체 저장 시험, 기존 구성원 시험, 전체 strict, 위젯 빌드, 화면 확인, 위키 및 인계 보고 순으로 진행한다.
