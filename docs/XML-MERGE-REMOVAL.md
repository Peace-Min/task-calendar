# XML 가져오기 병합 제거 (XML-MERGE-REMOVAL)

> 작성 2026-10-07. 스키마 변경 없음(판번호 12 그대로). 웹(HTML)과 시험, 문서만 바뀐다. 호스트(C#) 변경 없음.
> 이 문서는 구현 전 설계다. 구현하며 달라지는 곳은 맨 아래 정정 이력에 적는다. 본문과 정정 이력이 다르면 정정 이력이 맞다.

## 1. 요구

사용자 결정(2026-10-07): "XML 병합 기능 자체를 전량 제거."

배경:

- 처음 켤 때 뜨는 "이전 버전 기록" 가져오기는 2026-10-01 결정으로 이미 **바로 교체**다(병합 없음).
- 그런데 ⋯ 메뉴와 빈 캘린더 안내의 "XML 가져오기"가 여는 미리보기 창(`#importModal`)에는 아직 **병합 버튼**이 있다. 물음 창이 떠 있는 사이 무언가를 적었을 때 넘어가는 곳도 이 창이다.
- 병합은 과제와 기록을 **ID 로만** 합친다. 다음 작업(기본 과제 휴가, 기타)에서 이름이 같은 과제가 두 개 생기는 원인이 되고, 이를 막으려면 이름 기준 재매핑 같은 지저분한 로직이 필요하다. 병합을 없애면 가져오기는 언제나 교체이고, 그 뒤처리 한 곳만 보면 된다.

요구를 한 줄로: **XML 가져오기는 어느 문으로 들어와도 교체 하나다. 병합 버튼, 병합 코드, 병합 전용 보조 함수, 병합을 말하는 문구와 문서를 모두 없앤다.**

## 3. 결정

| 항목 | 결정 |
|---|---|
| 미리보기 창 | 남긴다. 파일 내용과 현재 데이터 개수를 보여 주는 확인 창 역할. 버튼은 [취소] [교체] 둘 |
| 설명문 | 병합 줄을 없애고 교체 한 줄만: "교체: 현재 데이터를 모두 지우고 파일 내용으로 대체합니다." 문구 규칙(엠 대시, 띄어 쓴 가운데 점, 낫표 금지)을 지킨다 |
| [교체] 뒤 확인창 | 지금처럼 둔다(`confirmBox('전체 교체', …)`). 캘린더가 비어 있지 않을 때 지워지는 것을 한 번 더 알리는 유일한 장치다 |
| `applyImport` | 교체만 한다. `mode` 인자를 없애고 `applyImport(opt)` 로 바꾸거나, 인자를 받되 `'replace'` 외의 값이면 아무것도 하지 않는다. 어느 쪽이든 **병합 갈래 코드와 병합 토스트는 남지 않는다**. 구현자가 고르되 호출처를 모두 맞춘다 |
| `mergeLegacyStores` | 함수째 지운다. 다른 호출처가 없음을 확인하고 지운다 |
| `importXml` 시험용 창구 | 교체만 한다(병합 기본값 제거) |
| 첫 실행 "이전 버전 기록" 경로 | 동작 변화 없음. 누른 순간 비어 있지 않으면 미리보기로 넘기는 것도 그대로(이제 그 미리보기가 교체만 고른다) |
| 원본 파일 개명 | 그대로. 교체가 성공하면 `.migrated-<날짜>` 로 바뀐다. "병합은 이름을 그대로 둔다" 는 문장은 문서에서 지운다 |
| 호스트(C#) | 바꾸지 않는다. 호스트에는 병합 개념이 없다(웹이 결과를 만들어 전량 교체로 보낸다) |

## 4. 바꿀 것

### 4.1 앱 (`task-calendar-prototype.html`)

1. `#importModal`: 설명문의 병합 줄 삭제, `#btnImpMerge` 버튼 삭제.
2. `applyImport`: 병합 갈래와 병합 토스트 삭제. 교체 갈래와 그 뒤 공통 처리(`saveFull`, 모달 닫기, 다시 그리기)는 그대로.
3. `mergeLegacyStores` 삭제.
4. `#btnImpMerge` 이벤트 연결 삭제.
5. `importXml` 창구를 교체 전용으로.
6. 병합을 말하는 주석 정리(2절 표의 주석들). 역사 설명이 필요한 곳은 "2026-10-07 병합 제거(XML-MERGE-REMOVAL)" 한 줄로 남긴다.
7. 패치노트 모달(`#patchModal`)의 과거 버전 문구는 **건드리지 않는다**(과거 기록이다). 새 버전 항목은 릴리스 때 쓴다.

### 4.2 시험 (`tests/`)

병합을 전제로 한 시험은 "병합이 없다" 를 잠그는 시험으로 바꾼다. 지우기만 하지 말고 되살아나면 실패하게 한다.

- `app-context.test.mjs` 약 2600~2635행 "가져오기 병합: 기존 값은 절대 덮지 않는다" 시험: 병합 규칙 시험을 없애고, 대신 `#btnImpMerge` 부재, `mergeLegacyStores` 부재, `applyImport` 에 병합 갈래 없음(교체 뒤 state 가 파일 내용과 같음)을 확인한다.
- `legacy-xml-prompt.test.mjs`: 371행 근처의 "교체와 병합 토스트가 둘 다 있다" 단언을 교체 토스트만 있고 병합 토스트는 없다로 바꾼다. "미리보기(병합/교체)" 문구가 든 단언 메시지와 주석을 "미리보기(교체)" 로 맞춘다. 병합을 부르면 실패하는 기존 변이 시험(⑩b)은 유지하거나, 병합 자체가 없어져 의미가 없으면 "병합 갈래를 되살리면 실패" 하는 변이로 바꾼다.
- `data-source.test.mjs` 500행 근처: `applyImport('merge')` 를 쓰는 변이 문자열을 교체 전용 계약에 맞게 고친다.
- `loop-import-ui.mjs` 5단계 "병합(merge): 같은 내용이면 증가 0". 실제 위젯 루프다. 병합 단계를 없애고, 미리보기 창에 병합 버튼이 없음을 확인하는 단계로 바꾼다. 단계 번호가 뒤에서 참조되면 함께 맞춘다.
- 그 밖에 `grep -rn "merge\|병합" tests/` 로 XML 가져오기 병합을 가리키는 곳을 모두 찾는다. **netcus 일간/주간 병합, 커밋 병합(mergeGitSvnCommits), 기간 할 일 병합은 다른 기능이므로 건드리지 않는다.**
- 새 시험: (가) `#importModal` 버튼이 [취소] [교체] 뿐이다. (나) 미리보기에서 [교체] 를 누르면 확인창을 지나 교체된다(기존 시험이 있으면 그것으로 충분). (다) 앱 소스에 `btnImpMerge`, `mergeLegacyStores`, "데이터를 병합했습니다" 가 없다.
