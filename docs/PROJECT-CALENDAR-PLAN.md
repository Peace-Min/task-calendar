## 1. 이슈가 요구하는 것 (요약)

1. **공식 과제마다 공용 캘린더.** 참여자는 작성자와 관계없이 공용 일정을 등록, 수정, 삭제한다.
2. **공용과 개인은 별도 데이터.** 자동 합치기와 자동 공유가 없다. 공용 일정을 내 개인 일정으로 **명시적으로 1회 복사**할 수 있다(출처 보존, 중복 방지, 원본과 독립).
3. **화면:** 상단 **개인 / 과제** 탭. 과제 탭은 왼쪽 과제 목록(전체 선택, 전체 해제, 개별 체크는 표시와 숨김, 이름 클릭은 단독 보기), **월간**(연속 기간 막대)과 **주간**(과제별 행), 간결한 등록 폼(날짜가 기본, 시간 지정은 스위치, 메모와 장소는 펼침), "메모 첫 줄 표시" 켜기와 끄기 하나, 클릭 미리보기와 상세, **최근 변경**(과제별, 날짜순, 일정별, 변경 전후 값).
4. **동시성과 이력:** 행 단위 낙관적 잠금(`row_version`), 응답 유실 뒤 재시도에도 중복 없음(`mutation_uid`), 변경 이력은 지우지 않는 기록.
5. **개인 캘린더 개선**(월간 가시성, 입력 간소화, 오른쪽 패널 접기).
6. **제외:** 기간 축 보기, 별도 일정 목록, 시간 유무 필터, "기간 작업 / 시간 일정" 종류 선택, 메모 표시 3종, 같은 색 강제, 상시 상세 패널, 공용 반복, 공용 할 일과 커밋과 보고, 공용 알림, 복구 UI, 공용 XML.

이 중 **5번(개인 캘린더 개선)은 이번 작업에서 뺀다**(사용자 결정 Q3). 이번 작업은 과제 캘린더만 한다.

## 3. 범위

### 3.1 이번 작업

- 과제 탭 전부: 탭 줄, 왼쪽 과제 목록, 월간, 주간, 등록과 수정과 삭제, 미리보기와 상세, 최근 변경, 개인 일정에 등록(복사), 새로고침.
- DB 구조 16(새 표 넷), 호스트 클래스 하나와 명령 여섯, 휴지통 과제 영구 삭제 판정 한 곳.

### 3.2 과제 탭에 보이는 과제 (Q6)

- **과제 탭에 보이는 과제 = 내 과제(`cal_category`, `source='db'`)에 넣은 공식 과제.** 과제 캘린더에 들어가려면 지금 있는 "공식 과제 찾아보기" 로 그 과제를 내 과제에 넣는다.
- **판정은 서버 함수 하나에서만 한다**(`ProjectCalendarDb` 의 "내 과제 탭 과제 목록", "이 과제를 쓸 수 있나"). 지금은 그 함수가 `cal_category` 를 본다. 읽기, 쓰기, 이력, 복사 명령은 모두 이 함수만 부른다.
- **화면은 과제 탭 목록을 스스로 계산하지 않는다.** 서버의 부트스트랩 회신을 쓴다(`state.categories` 에서 걸러 만들지 않는다).
- **공용 표는 `cal_category` 를 가리키지 않는다.** 과제 번호와 일정 번호만 가리킨다.
- 그만 보기: 과제 탭에서 체크를 해제한다(표시와 숨김). 내 과제에서 빼면 지금 동작대로 그 과제의 개인 일정, 할 일, 공수가 함께 지워지므로 그만 보는 수단으로 안내하지 않는다.
- 숨긴(비활성) 공식 과제는 과제 탭에서 읽기 전용이다.
- 참여자 수(시안의 "6명")는 그 과제를 내 과제에 넣은 사람 수다.
- 이 결정으로 이슈의 "참여와 편입은 별개, 처음 참여자 0명" 은 적용하지 않는다. 지금 내 과제에 공식 과제를 넣어 둔 사람은 배포 순간 그 과제 캘린더를 쓴다(서버에 아직 사용자가 없어 실제 영향은 작다).

### 3.3 이번에 하지 않는 것

- 이슈 §12 의 제외 전부.
- **개인 캘린더 개선**(개인 월간, 개인 입력 폼, 오른쪽 패널 접기). 나중에 따로 정한다(Q3).
- **관리자나 PM 의 과제별 참여인력 배정**(검토자 의견). 3.4 의 원칙으로 나중에 따로 한다.
- 관리 허브와 그 안 화면.
- 브라우저 단독 모드(위젯 없이 `.html`)의 과제 탭: "서버에 연결된 위젯에서만 쓸 수 있습니다" 안내만 보인다. localStorage 로 흉내 내지 않는다.

### 3.4 나중 작업: 관리자 배정의 원칙

- 참여인력은 `project` 의 열이 아니라 별도 표(과제 번호와 사람 번호의 짝)로 둔다.
- **관리자는 남의 내 과제에 쓰지 않는다.** 개인 데이터는 본인 앱만 쓴다는 전제(저장 충돌 감지, 번호 발급, 색과 순서 규칙)를 지키고, 배정 해제가 남의 개인 기록 삭제로 이어지지 않게 한다.
- 공식 과제 찾아보기는 나에게 배정된 과제만 보이고, 내 과제에 넣는 것은 본인이 한다.
- 과제 탭 판정은 "내 과제에 있고 + 지금 배정되어 있음" 으로 바꾼다. 3.2 의 판정 함수만 고치면 된다. 배정이 풀리면 과제 탭에서만 사라지고 내 과제와 개인 기록은 남는다.
- 처음 명단은 그 시점의 내 과제 편입으로 채우는 것을 권한다. 배정 화면은 관리 창 안의 새 항목이다. PM 에게도 맡기려면 과제별 PM 정책이 먼저 필요하다.

## 4. DB 설계 (구조 번호 16)

### 4.1 원칙

- 공용 트랙은 **새 표 넷**이다. 개인 `cal_entry`, `cal_category` 에 가짜 소유자나 `user_id=0` 을 넣지 않는다.
- **외래키가 가리키는 기본키는 번호**(Q2). 밖으로 나가는 정체성은 `uid`(UNIQUE)로 따로 둔다. `project(id, uid)` 와 같은 모양이다.
- 시각은 모두 UTC `DATETIME(3)`.
- 표 기본 문자셋 `utf8mb4`, `utf8mb4_0900_ai_ci`. 정확 비교하는 값 집합 열(`action`)과 클라이언트 id(`uid`, `mutation_uid`)는 `_bin`(기존 `cal_*` 선례).
- 사람은 **이름 글자로만** 남긴다(Q5). 사용자 FK 가 없다.
- **글자 상한 정책: 과제 일정 메모만 8,000자, 나머지 글자 칸은 200자.**
  - 같은 숫자를 세 곳이 쓴다: 화면(입력 칸 `maxlength` 와 저장 전 검사), 서버(저장 전 검사, 넘으면 자르지 않고 거절), DB(칸 폭). 웹과 호스트에 상수를 하나씩 두고, DDL 과 어긋나면 시험이 실패한다.
  - 근거: 상용 캘린더도 설명은 넉넉하게 받는다(구글 캘린더 약 8,000자, Asana 약 65,000자). 달력은 제목을 말줄임으로 자르고 메모는 첫 줄이나 미리보기 3줄만 보여 주므로 상한이 달력 모양을 바꾸지 않는다. 변경 이력의 긴 메모는 앞부분만 보이고 펼쳐서 전체를 본다.
  - 기존 칸은 바꾸지 않는다: 코드표 이름(구분과 상태 50, 발주처 100, 회의실 40, 직급 30)은 목록에서 고르는 짧은 라벨이다. 장소(자유 글자 200)가 회의실 이름(40)보다 긴 것은 외부 주소와 회의 링크를 담기 때문이다. 개인 일정 제목과 메모의 DB 형식(MEDIUMTEXT)도 그대로다. 맞출지는 별도 작업 후보다.
- 표 이름은 **가칭**이다(Q10, 구현 때 정한다).

### 4.2 표

**① `cal_project_rev`: 과제별 동시성 감시점**

| 열 | 형 | 뜻 |
|---|---|---|
| `project_id` | `INT UNSIGNED` PK | `project.id` FK, `ON DELETE CASCADE`(공용 일정이 있는 과제는 영구 삭제가 막히므로 안전) |
| `rev` | `BIGINT UNSIGNED NOT NULL DEFAULT 0` | 그 과제의 공용 쓰기마다 +1 |
| `updated_at` | `DATETIME(3) NOT NULL` | UTC |

- 그 과제의 첫 쓰기 때 `INSERT … ON DUPLICATE KEY UPDATE rev = rev + 1` 로 생긴다. 쓰기 트랜잭션의 **첫 문장**이 이 ODKU 다(개인의 `cal_user_rev` 규칙과 같다).

**② `cal_project_event`: 과제 일정**

| 열 | 형 | 뜻 |
|---|---|---|
| `event_id` | `INT UNSIGNED AUTO_INCREMENT` PK | 내부 번호. 이력과 복사 대응표가 가리킨다 |
| `uid` | `CHAR(36) _bin NOT NULL` UNIQUE | 클라이언트가 만든 안정 id. 생성 재시도의 멱등 키, 웹과의 정체성 |
| `project_id` | `INT UNSIGNED NOT NULL` | `project.id` FK **RESTRICT**(공용 일정이 있는 과제는 영구 삭제 불가) |
| `title` | `VARCHAR(200) NOT NULL` | CHECK `title <> ''` |
| `start_date` | `DATE NOT NULL` | |
| `end_date` | `DATE NULL` | 단일일 NULL, 종료 포함. CHECK `end_date IS NULL OR end_date > start_date`(개인 `cal_entry` 와 같은 규칙) |
| `start_time`, `end_time` | `TIME NULL` | CHECK: 둘 다 NULL, 또는 `end_date IS NULL` 이고 둘 다 있고 `end_time > start_time` |
| `location` | `VARCHAR(200) NOT NULL DEFAULT ''` | |
| `memo` | `TEXT NOT NULL` | 앱 상한 8,000자 |
| `row_version` | `BIGINT UNSIGNED NOT NULL DEFAULT 1` | 낙관적 잠금 |
| `is_deleted` | `TINYINT(1) NOT NULL DEFAULT 0` | CHECK `IN (0,1)`. 소프트 삭제, 행을 지우지 않는다 |
| `created_by_name`, `updated_by_name` | `VARCHAR(200) NOT NULL` | 글쓴이와 마지막 수정자 이름 |
| `created_at`, `updated_at`, `deleted_at` | `DATETIME(3)` | UTC, `deleted_at NULL` |

- 인덱스: `(project_id, is_deleted, start_date, end_date)`, `(project_id, updated_at, event_id)`.
- 범위 조회 조건: `start_date <= @to AND COALESCE(end_date, start_date) >= @from`.

**③ `cal_project_change`: 변경 이력(지우지 않는 기록)**

| 열 | 형 | 뜻 |
|---|---|---|
| `change_no` | `BIGINT UNSIGNED AUTO_INCREMENT` PK | 안정 정렬과 커서 |
| `project_id` | `INT UNSIGNED NOT NULL` | `project.id` FK RESTRICT |
| `event_id` | `INT UNSIGNED NOT NULL` | `cal_project_event` FK RESTRICT |
| `mutation_uid` | `CHAR(36) _bin NOT NULL` | 재시도 멱등 키. UNIQUE `(project_id, mutation_uid)` |
| `action` | `VARCHAR(8) _bin NOT NULL` | CHECK `IN ('create','update','delete')` |
| `actor_name` | `VARCHAR(200) NOT NULL` | 변경한 사람 이름 |
| `title_snapshot` | `VARCHAR(200) NOT NULL` | 삭제 뒤에도 당시 제목 |
| `before_json`, `after_json` | `JSON NULL` | 바뀐 필드만(create 는 after 만, delete 는 before 만) |
| `changed_at` | `DATETIME(3) NOT NULL` | UTC |

- 인덱스: `(project_id, changed_at, change_no)`, `(event_id, changed_at, change_no)`.
- 한 저장의 여러 필드 변경은 한 행이다. 바뀐 것이 없는 저장은 행을 만들지 않는다.

**④ `cal_project_copy`: 개인 복사 대응표**

| 열 | 형 | 뜻 |
|---|---|---|
| `user_id` | `SMALLINT UNSIGNED` | 복사한 사람 |
| `event_id` | `INT UNSIGNED` | 원본. `cal_project_event` FK RESTRICT |
| `entry_no` | `INT UNSIGNED NOT NULL` | `(user_id, entry_no)` 가 `cal_entry` FK **ON DELETE CASCADE** |
| `project_name_snapshot` | `VARCHAR(200) NOT NULL` | 출처 표시 |
| `source_row_version` | `BIGINT UNSIGNED NOT NULL` | 복사한 판 |
| `copied_at` | `DATETIME(3) NOT NULL` | UTC |

- PK `(user_id, event_id)`(같은 원본은 한 번만), UNIQUE `(user_id, entry_no)`.
- 개인 복사본을 지우거나 XML 전량 교체로 `cal_entry` 가 지워지면 대응표 행이 CASCADE 로 사라져 **다시 복사할 수 있다.** 원본과 이력은 그대로다.
- 사람은 `cal_entry` 를 거쳐 묶인다(`cal_entry.user_id` 가 RESTRICT). 개인 일정이 있는 사람은 지금도 영구 삭제가 안 되므로 휴지통의 인력 판정(`UserRecordTables`)을 고칠 필요가 없다.
- `cal_entry.entry_no` 는 삭제 뒤 재사용된다(계약 H-1). CASCADE 로 대응표가 먼저 사라지므로 재사용된 번호가 옛 대응을 물려받지 않는다.

### 4.3 기존 표와의 관계

- `cal_category` 는 바꾸지 않는다. 과제 탭 판정(3.2)이 읽기만 한다: `user_id`, `source='db'`, `project_uid`. 같은 사용자의 공식 과제 분류색도 과제 탭 표시에 쓴다.
- 휴지통 과제 영구 삭제: 공용 일정 수를 세어 1건 이상이면 거부(2 절 7번). 공용 일정이 없으면 `cal_project_rev` 행은 CASCADE 로 함께 지워진다.
- 개인 저장(`CalendarWriteDb.SaveAsync`)은 공용 표를 읽거나 쓰지 않는다. `cal_entry` 삭제가 대응표를 CASCADE 로 지우는 것만 새로 생긴다(FK 동작은 권한 검사를 받지 않는다).

### 4.4 정본 DDL

- 새 표 넷은 `db/deploy/schema-calendar.sql` 에 넣는다. DROP 목록과 CREATE 목록, 표 수 주석, `cal_schema_meta` 시드 16, 표 주석을 함께 고친다. `project` FK 때문에 `schema-structure.sql` 다음에 만들어진다(지금 순서 그대로).
- `setup-taskcalendar.ps1` 의 기대 표 수와 구조 시그니처, `tools/schema-report`, `docs/DB-SCHEMA.html`, `db/table-design-report.html`, `db/CALENDAR-TABLE-DESIGN.md`(새 절: 공용 트랙), `db/TABLE-DESIGN.md` 를 같은 라운드에 맞춘다.

### 4.5 이관 조각 `db/deploy/migrations/v16-<이름>.sql`

DB-RELEASE-OPS §5 규칙 그대로:

1. 첫 줄 `-- @migration from=15 to=16`.
2. 자기 확인: `db_structure_version` 이 `'15'` 면 `@go`, 16 이상이면 `@skip`, 그 밖은 `중단: v16 조각 - …` 로 1146. `@go` 일 때 `db_updating = '1'` 이 아니면 멈춤. 변수는 `@go`, `@skip`, `@g`, `@s`, `@m_` 만.
3. 바꾸기: 네 표를 `CREATE TABLE IF NOT EXISTS …` 로, 정본과 **글자까지 같은 정의**로, 모두 `PREPARE` 로 `@go` 일 때만. 순서는 FK 순서(rev, event, change, copy). 옮길 데이터는 없다.
4. 검증: 네 표가 있고 표마다 열 수와 FK 수가 기대와 같음(information_schema). 틀리면 `db_updating = 1` 인 채로 멈춤.
5. 끝 한 줄: `UPDATE cal_schema_meta SET v = '16', updated_at = UTC_TIMESTAMP(3)` 다음 줄 `WHERE k = 'db_structure_version' AND v = '15';`.
6. 쓰지 않는 것: `db_updating`, `@r_`, GRANT, 저장 프로그램, DELIMITER, `lock_wait_timeout`.
7. 다시 돌리기: 앞선 실행이 중간에 멈췄어도 IF NOT EXISTS 로 이어서 끝난다.

앱 쪽 짝(같은 커밋): `DbGate.AppStructureVersion = 16`, 정본 시드 16, `tests/schema-guards`, `tests/release-sql.test.mjs` 의 사슬 기대(13 에서 16)와 흉내 실행(13, 14, 15 에서 16).

첫 사내 배포에 함께 실으므로(Q1) 그 배포의 `release-v<버전>.sql` 하나가 서버를 13 에서 16 까지 올린다.

### 4.6 권한

| 표 | 앱 계정 권한 | 이유 |
|---|---|---|
| `cal_project_rev` | SELECT, INSERT, UPDATE | ODKU. DELETE 없음 |
| `cal_project_event` | SELECT, INSERT, UPDATE | 소프트 삭제라 DELETE 없음 |
| `cal_project_change` | SELECT, INSERT | 지우지 않는 기록 |
| `cal_project_copy` | SELECT, INSERT | 정리는 CASCADE |

- 정본 `db/deploy/grants-calendar.sql` 에 이 줄들을 더한다("cal_* 전부에 GRANT 한 줄" 규칙).
- **배포 SQL 은 GRANT 하지 않는다.** 폐쇄망 서버 앱 계정은 `taskcalendar.*` 전체 권한이라 운영자에게 따로 할 일이 없다.
- 개발 PC 의 최소 권한 앱 계정은 root 로 따로 GRANT 한다(안 하면 1142). root 비밀번호는 사용자가 채팅으로 주고 파일이나 명령줄에 남기지 않는다.

### 5.1 클래스

| `widget/CalendarWriteDb.cs` | 고침(작게) | 개인 일정 한 건을 **이미 열린 트랜잭션 안에서** 넣는 내부 함수(발번 MAX+1, 행 투영 재사용)를 꺼낸다. 복사가 부른다. `SaveAsync` 동작은 바꾸지 않는다 |

- 회신의 `error.kind` 는 호스트가 `forbidden`, `conflict`, `invalid` 로 채운다. 연결 오류는 기존 분류(network, auth, gate 등)를 쓴다.
- C# 러너를 직접 링크하는 루프와 도구(loop-calendar-write, loop-peer-view, loop-report-wiring, dryrun-xml-to-db)의 .cs 목록에 새 파일이 필요한지 확인한다(HANDOFF §5).

### 5.2 연결과 권한

- **모든 연결은 `DbGate.OpenAsync`.** 그다음 프리앰블: 읽기는 `REPEATABLE-READ`(여러 과제를 한 스냅샷으로), 쓰기는 `READ-COMMITTED`, 둘 다 `time_zone='+00:00'`, `innodb_lock_wait_timeout=5`(기존 상수 재사용).
- 신원: `UserSession.Load` 의 `login_id` 로 `app_user` 에서 `user_id`, `is_active`, 이름. 세션이 없거나 비활성이면 `forbidden`. **`edit_role` 은 보지 않는다.** 웹이 보낸 사용자 값은 받지 않는다.
- 읽기: 그 과제가 내 과제에 있음(3.2 판정 함수). 쓰기: 읽기 조건 + 과제 `is_active = 1` + 사용자 활성.
- 판정은 모든 명령에서 다시 한다(버튼 상태와 무관, 오래 열어 둔 폼, 위조 요청).
- 보안 경계가 아니다. 공유 앱 계정이 직접 DB 에 붙는 지금 구조와 같은 수준의 난간이다(DB-RELEASE-OPS §0).

### 5.3 쓰기 순서 (저장, 삭제)

1. `DbGate.OpenAsync`, 쓰기 프리앰블, 트랜잭션 시작.
2. **첫 문장:** `INSERT INTO cal_project_rev(project_id, rev, updated_at) VALUES(@p, 1, @now) ON DUPLICATE KEY UPDATE rev = rev + 1, updated_at = @now`. 과제 단위 직렬화.
3. 신원, 과제 탭 판정, 과제 상태 확인. 거부면 롤백.
4. 멱등: 같은 `(project_id, mutation_uid)` 이력이 있으면 그 결과를 돌려주고 롤백(응답 유실 뒤 재시도).
5. 생성: 같은 `uid` 가 이미 있으면 4번과 같게. 수정과 삭제: `UPDATE … WHERE event_id=@e AND row_version=@expected AND is_deleted=0`. 0행이면 `conflict`(최신 행을 함께 회신). 자동 덮어쓰기 없음.
6. 글자 상한과 날짜, 시각 검사(4.1). 넘으면 `invalid`, 자르지 않는다.
7. 바뀐 필드 계산. 없으면 이력 없이 끝낸다.
8. `cal_project_change` INSERT(같은 트랜잭션). 실패하면 전체 롤백.
9. **커밋 직전 관문 재확인:** `cal_schema_meta` 를 잠금 없이 한 번 더 읽어 `Ok` 가 아니면 롤백(`CalendarWriteDb` 와 같은 규칙).
10. 커밋, 새 `rowVersion` 과 `projectRev` 회신.

### 5.4 명령 (메인 창 전용)

응답은 `{ ok, data?, error?: { kind, message } }`.

| 명령 | 요청 | 회신 |
|---|---|---|
| `projectCalendarBootstrap` | 없음 | 과제 탭 과제 목록(내 과제에 있는 공식 과제, 쓰기 가능과 읽기 전용 구분), 과제별 rev, 표시 메타(`common_name \|\| project_name`, 발주처, 구분 번호), 과제별 참여자 수, 내 복사 대응(`eventUid` 와 개인 `entryUid`) |
| `projectCalendarLoad` | `{ projectUids, from, to }` | 쓸 수 있는 과제의 범위 일정과 rev. 판정에서 빠진 과제는 제외하고 그 사실을 알림 |
| `projectCalendarSave` | `{ projectUid, eventUid, expectedVersion?, mutationUid, event }` | 저장된 일정, 새 rowVersion, projectRev |
| `projectCalendarDelete` | `{ projectUid, eventUid, expectedVersion, mutationUid }` | 소프트 삭제, projectRev |
| `projectCalendarChanges` | `{ projectUids, changedFrom, changedTo, fieldFilter, cursor, limit }` | 이력 행(기본 50), 다음 커서 `(changedAt, changeNo)`, 더 있음 여부. 묶기(과제별, 날짜순, 일정별)는 웹이 한다 |
| `projectCalendarCopy` | `{ projectUid, eventUid, expectedVersion, mutationUid }` | 새 개인 일정 uid 또는 기존 복사본, 그리고 개인 스냅샷 재적재 결과 |

- 관리 창(`?win=admin`)과 열람 창(`?peerwin=1`)의 명령 허용 목록에는 넣지 않는다. 병합 때 "허용 목록 밖 명령 거절" 시험이 새 명령을 거르는지 확인한다.
- 날짜 DTO: `YYYY-MM-DD`, 시각 `HH:mm` 또는 null, UI 종료일은 포함(DB 단일일 `end_date=NULL` 은 시작일과 같은 종료로 회신), `rowVersion` 정수.

### 5.5 개인 일정에 등록 (복사)

1. 웹: 개인 화면에 저장 안 된 변경이 있으면 먼저 저장을 끝낸다(저장 큐가 빌 때까지 기다림, 실패면 복사하지 않음).
2. 호스트 `projectCalendarCopy` 한 트랜잭션: **잠금 순서 `cal_project_rev` 다음 `cal_user_rev`**(개인 저장은 `cal_user_rev` 만 잡으므로 순환이 없다).
   - 과제 탭 판정과 원본 `row_version` 확인.
   - 기존 대응이 있고 그 개인 일정이 살아 있으면 그것을 회신한다.
   - 없으면 그 사람의 해당 공식 과제 `cal_category`(과제 탭에 보인다는 것이 이미 내 과제에 있다는 뜻)를 분류로 `cal_entry` 한 건(제목, 날짜, 시각, 장소, 메모, `remind = 0`, 반복 없음, 커밋 없음)과 대응표를 넣는다. 개인 행 투영은 `CalendarWriteDb` 의 같은 함수를 쓴다.
   - 커밋 직전 관문 재확인.
3. 커밋 뒤 호스트가 개인 스냅샷을 다시 읽어(`reloadState` 와 같은 경로) 웹에 적용한다. 1번에서 미저장 변경이 없음을 보장했으므로 덮을 것이 없다.
4. 공용 이력에는 남기지 않는다.

- 시각이 없으면 `all_day = 0` 에 시각 NULL(시각 없는 하루 일정. "하루 종일 바쁨" 을 붙이지 않는다).
- 원본이 바뀌거나 지워지거나 내 과제에서 그 과제를 빼도 복사본은 그대로다(단 내 과제에서 빼면 지금 동작대로 그 과제의 개인 일정이 지워지므로 복사본도 함께 지워진다). 출처 표시는 대응표의 `project_name_snapshot`.

### 5.6 다른 사람의 변경 받기 (Q4)

- **주기 확인은 없다.** 확인 시점은 셋: 과제 탭에 들어갈 때, 위젯 창으로 돌아올 때(활성화), 내가 저장한 직후. 그리고 **새로고침 버튼.**
- 확인은 지금 보이는 범위를 `projectCalendarLoad` 로 다시 읽는 것이다. 과제 목록이 바뀌었을 수 있으면(탭 진입, 새로고침) `projectCalendarBootstrap` 도 다시 읽는다.
- 화면이 잠깐 낡아도 안전하다. 남이 먼저 고친 일정을 내가 저장하면 `row_version` 충돌로 막히고 안내가 뜬다.
- OFFLINE-RESILIENCE A11(정상일 때 주기 DB 접속 0)을 그대로 지킨다. 써 보고 필요하면 주기 확인을 나중에 더한다.
- 연결 실패는 기존 장애 분류와 재연결 꼬리(15/30/60초 뒤 300초)를 그대로 쓴다. 과제 탭 실패로 개인 화면을 비우지 않는다.
- 세대 번호(사용자, 탭, 범위)로 늦게 온 옛 회신을 버린다.

### 6.1 지금 화면에서 확인한 사실

- 월간은 `renderGrid()`(10491)에서 `renderMonthGrid()`(10510~10669). 여러 날 일정은 날마다 칩이고 `seg` start/mid/end 와 음수 여백으로 이어 보인다(CSS 339~344). **주간 보기는 없다.**
- 메모는 달력 칸에 나오지 않고 오른쪽 패널 카드에만 나온다(`cardHtml` 10781).
- **클릭 미리보기 팝오버는 없다.** 기준이 될 위치 보정 팝업은 열람 상대 고르기(`pkPlace` 7679)다.
- 장소 콤보 A안(11964~12092)은 접두사로 재사용된다: 마크업 `.loc-combo[data-pfx]` + `#{pfx}Loc` + `#{pfx}LocPop` 뒤 `locBind(pfx)`. 목록은 `__applyCodes` 셋째 인자로 채워지는 `sharedRooms`.
- UI 설정은 모두 localStorage 다. 대부분 전역 키이고 사람별 키는 `tc_peer<kind>:<loginId>` 같은 몇 개뿐이다. 보던 날짜와 보기는 저장하지 않는다(부팅 때 오늘).
- 전역 Esc 처리(18986~19020)는 닫을 팝업 목록을 글자로 박아 둔다(19005). 새 팝오버는 여기에 넣어야 한다.
- `__applyProjects`(6421)와 `mapDbRows`(6398)가 공식 과제를 `db-<uid>` 로 바꾼다. 공식 과제 찾아보기는 `#officialModal`(2945, `openOfficialModal` 12641).

### 6.2 상태와 설정 (Q7)

- 과제 탭 상태는 새 모듈 객체 하나에 담는다: 과제 목록, 표시 선택, 보기, 기준 날짜, 범위의 일정, 세대 번호. **`state.entries` 에 섞지 않는다.** 개인 저장, XML, 전량 교체 경로는 과제 탭 상태를 모른다.
- 모듈 상태 변수를 늘리지 않는다는 기존 규칙(HANDOFF §4)을 지킨다. 객체 하나로 묶는다.
- **기억하는 것(localStorage, 로그인 계정별 키):** 마지막 탭, 월간과 주간, 체크한 과제(설정 없음과 빈 선택을 구분), 메모 첫 줄 표시(기본 끄기). 위젯과 브라우저 모두 같은 코드로 동작하고 저장 위치만 다르다. 계정별 키라 같은 PC 에서 다른 계정으로 로그인하면 그 사람의 설정을 쓴다.
- **기억하지 않는 것:** 날짜. 다시 켜면 오늘로 간다(개인 캘린더와 같게).
- 처음 들어오면 전체 선택. 새로 내 과제에 넣은 과제는 표시 선택에 더한다. 내 과제에서 빠진 과제는 설정에서 정리한다.

### 6.3 탭과 배치

- 상단 `header.topbar` 와 `#filterbar` 사이에 **개인 / 과제** 탭 줄. `insertBelowTitleBar()`(5449)가 같은 자리 뒤에 장애 띠를 끼우므로 띠가 탭 줄 아래에 오도록 삽입 기준을 탭 줄로 바꾼다(한 곳).
- 과제 탭에서는 `#filterbar`, `section.cal`, `#dayPanel` 대신 과제 화면 컨테이너 하나를 보인다. 개인 화면 DOM 은 지우지 않고 숨긴다(개인 미저장 상태, 저장 큐, 장애 띠가 그대로 산다).
- 상단 버튼 중 과제 탭에서 뜻이 없는 것(검색, 열람, 보고서, 새 일정)은 숨긴다. 새 일정 자리는 과제 탭의 "일정 등록" 이 맡는다.
- 열람 창과 관리 창에는 탭이 없다.
- 브라우저 단독 모드: 과제 탭은 안내 한 장(3.3).

### 6.4 과제 탭 화면

- **왼쪽:** "과제 n / m", 전체 선택, 전체 해제(이슈 §3.3 의 켜짐과 꺼짐 규칙), 과제 줄(체크 = 표시와 숨김, 이름 = 단독 보기, 비활성 과제는 "종료/숨김, 읽기 전용" 표시). 목록 아래에 **"공식 과제 추가"** 링크가 기존 공식 과제 찾아보기 창을 연다.
- **과제가 하나도 없을 때:** "내 과제에 공식 과제를 추가하면 그 과제의 공용 캘린더가 여기에 보입니다" 와 "공식 과제 추가" 단추.
- **상단:** 과제 제목(전체 또는 단독), 최근 변경, 일정 등록, 날짜 이동, 오늘, **월간 / 주간**, 메모 첫 줄 표시 체크, **새로고침.**
- **월간:** 공용 일정은 반복이 없으므로 **연속 막대**(주 단위로 잘린 한 요소)로 그린다. 배치는 순수 함수(입력: 일정, 주 범위. 출력: 차선과 조각)로 만들어 시험한다. 정렬은 이슈 §3.4(시작일, 종료일 내림차순, 과제 표시 순서, uid). 시각 있는 하루 일정은 과제색 점 + 시각 + 제목. 칸 클릭은 그 날짜 선택, 막대 클릭은 **누른 날짜** 선택과 미리보기.
- **주간:** 월요일~일요일 7열, 과제마다 고정 행(과제명 열 고정), 행 안에 막대 차선과 시각 일정. 좁은 창은 날짜 영역만 가로 스크롤.
- **미리보기 팝오버:** 앵커 근처, 화면 밖이면 위치 보정, 바깥 클릭과 Esc 와 닫기. 내용은 제목, 과제, 기간과 시각, 메모 3줄, "상세와 전체 메모 보기". Enter 와 터치로도 열린다. 전역 Esc 목록에 등록.
- **상세 창:** 전체 메모, 과제명, 날짜, 시간, 장소, 글쓴이, 수정, 삭제, **개인 일정에 등록**(이미 했으면 "개인 일정에 등록됨" 으로 끔).
- **등록과 수정 폼:** 저장할 과제(전체 보기에서는 "과제를 선택하세요" 로 시작, 단독 보기는 그 과제), 제목(200자), 시작일, 종료일, 시간 지정 스위치(켜면 같은 날짜의 시작과 종료 시각), 접힌 "메모와 장소"(값이 있으면 펼쳐서 엶. 메모 8,000자, 장소 200자). 장소는 **콤보 A안**(새 접두사로 `locBind`). 저장 중 중복 제출 막기, 실패와 충돌이면 입력 유지, 충돌이면 "최신 내용 확인 / 입력 유지".
  - 시안(final.html)은 전체 보기에서도 첫 과제가 미리 골라져 있다. **이슈 문장("과제를 선택하세요")을 따른다.**
- **최근 변경 창:** 넓은 모달. 묶기(과제별 기본, 날짜순, 일정별), 과제 필터(현재 표시 선택 안으로만), 기간(7일 기본, 30일, 전체. 기준은 수정 시각, KST 날짜), 항목(모두, 날짜와 시간, 메모, 삭제), 변경 전후 값(긴 메모는 앞부분만, 펼치기), 50건씩 "더 보기", 불러온 수와 더 있음 표시.
- 0개 표시 상태: 목록과 버튼은 남고 달력에 "표시할 과제를 선택하세요".
- 모든 사용자 입력은 `textContent` 또는 기존 이스케이프 함수로만 그린다.
- 색: 내 과제의 그 공식 과제 분류색. 이름도 함께 보여 색만으로 구분하지 않는다.
- 편집 잠금: 연결 끊김과 관문 차단 때 기존 `guardEdit()`, `body.db-locked` 를 과제 탭 쓰기 버튼에도 건다. 과제 일정 쓰기는 개인 저장 큐와 따로 돈다(단건 즉시 저장).

### 6.5 손대지 않는 것

- 개인 월간 렌더, 개인 입력 폼, 빠른 추가, 오른쪽 패널(이번 범위 밖).
- 관리 허브(`#adminHub` 2798~2846, JS 10964~11373)와 그 안 화면. 휴지통의 새 거부 문구는 호스트가 고정 문구로 돌려주므로 화면 수정이 필요 없다.
- 공식 과제 찾아보기 창은 그대로 재사용한다(여는 진입점만 하나 더).

### 6.6 2차 시안과 사용자 결정 (2026-10-22 오후)

시안: [prototypes/project-calendar.html](prototypes/project-calendar.html). 실제 앱 화면(제목줄, 상단바, 월 격자, 입력 폼, 장소 콤보)을 옮기고 과제 탭을 얹은 모양이다. 아래는 이 절이 6.3, 6.4 보다 우선한다.

- **과제 추가 진입 없음.** 과제 탭에 "공식 과제 추가" 링크를 두지 않는다. 과제 탭 목록은 내 과제에 넣은 공식 과제(DB 과제)뿐이고 넣고 빼기는 내 과제 창에서만 한다. 빈 상태 안내도 내 과제 창으로 안내한다.
- **짧은 과제 이름 없음.** 막대 앞 약칭(데이터에 없는 값)을 쓰지 않는다. 과제 구분은 과제 색 점과 전체 과제명(목록, 미리보기, 상세)으로 한다.
- **메모 첫 줄 표시.** 켜도 칸 높이와 보이는 일정 수는 바뀌지 않는다. 월간은 제목 뒤에 메모 첫 줄을 흐리게, 주간은 제목 아래 줄에. 들어가지 않으면 메모 줄만 생략하고 제목은 지킨다.
- **등록과 수정 폼은 한 화면.** 펼치고 접는 칸과 시간 스위치가 없다. 순서: 제목 / 시작일, 종료일 / 과제 / 시작 시각, 종료 시각(선택) / 장소(회의실 콤보 A안) / 메모(8,000자) / 취소, 저장. 시각을 적으면 시간 일정, 비우면 날짜만 있는 일정. 시각은 하루 일정에서만, 시작과 종료 시각은 둘 다 적거나 둘 다 비운다. 좁은 창에서는 한 줄에 한 칸.
- **최근 변경 필터는 종류: 전체, 추가, 수정, 삭제.** 바뀐 칸(날짜, 시간, 장소, 메모 등)은 필터가 아니라 줄마다 변경 전과 후로 보인다.
- **오른쪽 패널 없음(과제 탭).** 개인 탭 패널은 그대로.
- **같은 날 여러 일정 중 하나를 고치기 쉽게(사용자 지적, 세부는 개발 뒤 화면을 보며 다듬음):**
  - 날짜 칸의 빈 곳이나 날짜 숫자를 누르면 **그날 일정 목록** 팝업(지금 "+n" 목록과 같은 모양). 줄마다 과제 색 점, 과제명, 시각 또는 기간, 제목, **[수정]** 글자 단추. 맨 아래 "이 날짜에 일정 등록".
  - 막대 미리보기에도 **[수정]** 을 바로 둔다. 상세 창은 전체 메모가 필요할 때만 연다.
- **시안대로 둔 기본값(써 보고 바꿀 수 있음):** 달 이동(◀ 오늘 ▶)은 과제 탭에서 과제 화면 위쪽 줄에 둔다. 요일 시작은 월간 일요일, 주간 월요일. 개인 탭의 복사본에는 "과제 캘린더에서 복사" 배지. "+n" 은 그날 일정 목록 팝업. 단독 보기는 체크를 바꾸지 않고, 체크를 건드리면 전체 보기로 돌아간다. 충돌 안내의 "최신 내용 확인" 은 최신 값으로 다시 채우고, "내 입력 유지" 는 다음 저장 때 최신 판 위에 저장한다. 수정 때 과제는 바꿀 수 없다. 종료된 과제는 읽기 전용이지만 개인 등록은 된다. 상세 창에 마지막 수정(사람, 시각).
- **표 이름(Q10):** `cal_project_rev`, `cal_project_event`, `cal_project_change`, `cal_project_copy` 로 정한다(가칭을 그대로 확정).

- 충돌 회신은 `{ ok:false, error:{kind:'conflict'}, data:{ latest } }`(지워졌으면 `latest.deleted = true`, 없으면 null).
- **개인 복사의 첫 잠금은 `cal_project_rev` 공유 잠금(`FOR SHARE OF r`)이다.** 공용 쓰기가 아니라 rev 를 올리지 않는다(남의 화면을 공연히 다시 읽게 하지 않는다). 그다음 `cal_user_rev` ODKU(`CalendarWriteDb.BumpUserRevInTxAsync`). `mutationUid` 는 형식만 보고, 멱등은 대응표 PK 가 맡는다. 새 개인 일정은 uid `e-<uuid>`, 그 사람 일정의 맨 뒤 순서, `all_day 0`, `remind 0`, 분류는 내 과제의 그 공식 과제다. 개인 행은 `CalendarWriteDb.InsertEntryInTxAsync`(`EntryParams` 와 `SaveAsync` 와 같은 INSERT 문 `EntryInsertSql`)로 넣는다. 새로 만들었을 때만 호스트가 `BootFromDbAsync`(reloadState 와 같은 길)로 개인 스냅샷을 다시 싣는다.
- 최근 변경 필터는 6.6 대로 종류(`kind`: all, create, update, delete)다. 옛 이름 `fieldFilter` 도 같은 뜻으로 받는다. 새것부터, 커서는 `(changedAt, changeNo)`, 한 번에 1~200(기본 50).

- 호스트로 가는 문은 `pcReq` 하나다. 여섯 명령 밖의 이름과 브라우저, 열람 창(PEER), 따로 뜬 창(SUBWIN)에서는 보내지 않는다. 열람 창과 관리 창에는 탭 줄이 없다(`pcInit` 이 노드를 지운다). 관문 실패(`gate`)는 호스트가 차단 카드를 밀어 주므로 화면은 말하지 않는다. 연결 실패는 호스트가 `__dbConnLost` 를 밀어 기존 재연결 꼬리가 맡는다.
- 세대 번호: 범위 읽기(`PCAL.gen`), 목록 읽기(`PCAL.bootGen`), 최근 변경(`PCAL.rc.gen`). 계정이 바뀌면(`pcOnBootApplied` 가 `pkMe()` 를 본다) 셋 다 올리고 상태를 비운 뒤 그 계정의 설정을 읽는다.
- 설정 키는 `tc_pcal:<login_id>`(브라우저는 `tc_pcal:local`). 값은 `{ tab, view, sel, known, memo }`. `sel` 이 배열이면 그 선택(빈 배열이면 아무것도 안 봄), 없으면 전체. `known` 은 지난번 목록이라, 새로 내 과제에 넣은 과제를 켜고 빠진 과제를 정리하는 데 쓴다(`pcSelReconcile`).
- 부팅: 계정이 처음 정해지면 마지막 탭을 되살린다. 개인 탭이면 복사 배지를 위해 `projectCalendarBootstrap` 을 **한 번** 읽는다(주기 확인이 아니다).
- 창 복귀: 호스트가 메인 창 활성화를 웹에 알리지 않으므로 `window` 의 `focus` 와 `visibilitychange` 를 쓴다. 과제 탭이 보일 때만, 5초 안의 반복은 한 번으로 `projectCalendarLoad` 만 다시 읽는다. 탭 진입과 새로고침은 목록과 범위 둘 다다.

**화면(6.6 대로, 시안과 다르게 정한 것)**
- 날짜 칸의 빈 곳이나 숫자를 누르면 **그날 일정 목록**(줄마다 과제 색 점, 과제명과 시각 또는 기간, 제목, [수정], 맨 아래 "이 날짜에 일정 등록"). 시안의 칸 더블클릭 등록은 넣지 않았다(한 번 누름이 목록을 열어 두 동작이 겹친다). 주간의 칸을 누르면 그 과제 행의 목록이고, 등록 폼에 그 과제가 골라져 있다.
- 미리보기에 [수정](쓸 수 있는 과제만)과 "상세와 전체 메모 보기". 장소가 있으면 한 줄 더.
- 메모 첫 줄: 월간은 제목 뒤 흐린 글, 주간은 둘째 줄. 주간 막대는 메모 줄 자리를 늘 두어(높이 38px 고정) 켜고 꺼도 행 높이가 같다. 월간 보이는 차선 수(`pcMonthCap`)는 칸 높이와 차선 수만 본다.
- 월간 "+n" 줄: 다 들어가면 "+n" 줄을 두지 않고, 넘칠 때만 14px 줄을 남긴다(시안은 차선이 하나 넘칠 때도 다 그려 칸 밖으로 8px 넘쳤다).
- 시간 일정의 메모 표시 글리프는 시안의 줄 아이콘을 `PC_IC.memo` 로 옮겼다. 약칭은 쓰지 않는다(과제 색 점과 전체 과제명).
- 폼: 저장 중에는 창이 닫히지 않는다(`dataset.busy`). 연결 실패와 시간 초과면 같은 `eventUid`, `mutationUid` 를 남겨 다시 누르면 호스트 멱등이 한 번만 남긴다. 충돌, 잘못된 값, 거부면 변경 id 를 새로 만든다. 충돌인데 최신 행이 지워졌으면 "이미 지워졌습니다" 로 저장을 막는다. 기간은 366일까지(시안 규칙, 서버는 범위 읽기만 731일로 막는다). Esc 나 배경 누름은 바뀐 입력이 있으면 묻는다(기존 폼과 같은 `isGuardedModal`).
- 최근 변경: 기간은 이 PC 시각 자정 기준으로 `changedFrom` 을 보낸다(서버는 UTC 로 받는다). 종류 필터는 서버가 건다. 줄의 일정 제목은 지금 읽은 범위에 있으면 지금 제목 단추(상세 열기), 없으면 그때 제목. 같은 묶음 안에 삭제 줄이 있으면 "(삭제됨)". 추가와 삭제는 날짜, 시간, 장소, 메모를 요약하고, 수정은 바뀐 칸마다(시작과 종료 시각이 함께 바뀌면 "시간" 한 줄).
- 개인 일정에 등록: 편집 잠금(`guardEdit`)과 확인 뒤 `awaitSaveIdle()` 로 개인 저장 왕복을 기다리고, 그래도 미저장, 저장 중, 충돌 상자가 있으면 보내지 않는다. 성공하면 대응을 `PCAL.copies` 에 넣고 상세를 "등록됨" 으로 바꾼다. 개인 화면은 호스트가 다시 싣는 스냅샷(`__applyState`)이 바꾼다.
- 개인 탭 배지: `cardHtml` 의 카드 머리에 "과제 캘린더에서 복사". 달력 칸 칩에는 달지 않았다(시안과 같음).
- 색 토큰: 충돌 상자는 앰버 경고 토큰(`--ovl-*`), 최근 변경의 "추가" 표시는 `--ok` 로 했다(시안의 고정 색은 디자인 토큰 래칫에 걸린다).
