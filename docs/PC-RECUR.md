# 과제 일정 반복

상태: 구현 완료(2026-11-02, 브랜치 `feat/pc-form`). 실제 DB 확인은 개발 DB 에 `dist/rehearsal/apply-v20c-dev.sql` 을 돌린 뒤. DB 구조 20 에 합친다(20 은 운용 배포 전, 2026-11-02 사용자 결정 A).

## 1. 배경

- 개인 일정에는 반복이 있고 과제 탭 공용 일정에는 없다. 정기 회의, 주간 점검 같은 공용 일정을 매번 새로 등록해야 한다.
- 같은 판(2026-11-02)에 과제 일정 폼에 종일과 종료 자동 채움을 넣었다(DB 그대로). 반복은 DB 칸이 없어 스키마를 바꾼다.

## 2. 결정 (2026-11-02 사용자, 개인 일정과 같게)

1. **폼은 개인과 같다**: 반복 [안 함 | 매주 | 매월]. 끝 날짜, 횟수 칸은 폼에 두지 않는다(개인 폼과 같다). 끝 없이 반복한다.
2. **수정은 반복 전체**에 걸린다. 회차 하나만 고치기는 없다(개인과 같다).
3. **삭제는 "이 날짜만 삭제 / 반복 전체 삭제"**(개인 `recurExcept` 와 같은 확인 창). 이 날짜만 삭제는 예외일을 더한다.
4. **"개인 일정에 등록"** 은 누른 그 회차 하루를 반복 없이 복사한다.
5. **변경 이력**에는 반복 전체 수정, 이 날짜만 삭제가 한 줄씩 남는다.
6. 달력(월간 막대, 주간 과제별 줄), 날짜 목록 팝업, 상세 창은 회차를 펼쳐 보인다. 회차 막대와 줄에는 개인처럼 반복 표시를 단다.
7. **DB 구조 20 에 합친다.** 이 PC 의 개발 DB 는 이미 20 이라 늘어난 칸과 표만 만드는 일회용 SQL 을 사용자가 Workbench 에서 실행한다(비밀번호는 사용자만).

## 3. DB (구조 20 에 합침)

- `cal_project_event` 에 칸 추가:
  - `recur_freq` ENUM('weekly','monthly') NULL. NULL 이면 반복 아님.
  - `recur_interval`, `recur_until`, `recur_count` 는 두지 않는다(폼이 쓰지 않는다. 필요해지면 그때 더한다).
- 새 표 `cal_project_event_except`: `event_id`(FK cal_project_event, ON DELETE CASCADE), `except_date` DATE, PK(event_id, except_date). 개인 `cal_entry_except` 와 같은 결.
- 규칙: 반복 일정의 예외일은 실제 회차 날짜만(호스트가 거른다). 소프트 삭제된 일정의 예외일은 그대로 둔다.
- v20 조각(`db/deploy/migrations/v20-weekly-meeting.sql`)에 칸 추가와 표 만들기, 검증을 더한다(없을 때만). 정본 `schema-calendar.sql`, 앱 계정 권한(`grants-calendar.sql`, `server-app-account.sql`), 설치 스크립트 표 수, 데모 DB, 스키마 보고서와 시험을 함께 맞춘다.
- 개발 DB 용 일회용 SQL: `dist/rehearsal/apply-v20c-dev.sql`(칸과 표가 없을 때만 만들고, 앱 계정 권한).

## 4. 호스트(C#)

- `ProjectCalendarDb` 읽기(`LoadAsync`)는 `recurFreq` 와 `recurExcept`(날짜 배열)를 싣는다.
- 저장(`SaveAsync`)은 `recurFreq` 를 저장한다(허용 값만). 동시 수정 판(row_version) 규칙은 그대로.
- 회차 삭제: 새 명령(또는 삭제 명령의 갈래) `occDate` 가 있으면 예외일을 더하고 이력에 "이 날짜만 삭제" 를 남긴다. 판 올림.
- 복사(`CopyAsync`)는 회차 날짜를 받아 그날 하루로 복사한다.
- 웹과 호스트 명령 목록, 계약 시험을 갱신한다.

## 5. 화면

- 등록과 수정 폼에 반복 선택(개인 폼 `#qaRecur` 와 같은 모양과 문구).
- 회차 펼치기: 개인 `expandOccurrences` 와 같은 규칙(매주, 매월, 예외일 제외). 월간, 주간, 날짜 목록 팝업, 상세가 같은 함수를 쓴다.
- 삭제: 반복 일정이면 "이 날짜만 삭제 / 반복 전체 삭제" 확인(개인과 같은 문구).
- 상세 창에 반복 표시(예: "매주").

## 5-1. 구현에서 정한 것

- 이 날짜만 삭제는 변경 이력에 update(예외일)로 남는다. delete 로 남기면 최근 변경이 그 일정 전체를 삭제됨으로 칠해서다.
- 반복 종류를 바꾸거나 끄면 그 일정의 예외일을 지운다(권한에 DELETE).
- 이미 지운 날짜를 다시 지우거나 복사하면 "이미 지운 날짜입니다.".
- 여러 날 반복 일정의 복사는 누른 회차와 같은 길이.
- 폼에는 반복 안내 글을 두지 않는다(선택 상자만).

## 6. 하지 않는 것

- 회차 하나만 고치기, 끝 날짜, 횟수, 간격, 매일, 매년.
- 개인 일정 반복 동작 변경.
- 버전 번호.
