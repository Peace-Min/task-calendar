Excel 장표
DB에서 뽑는 리포트. 양방향 동기화 없음.
  • DB가 원본(authoritative) — Admin이 앱에서 과제를 관리하고, 목록·제약·이력은 DB가 강제한다.
  • Excel은 추출 리포트 — 기존 사업부 Excel은 최초 1회만 이관하고, 이후엔 DB가 마스터. Excel을 고쳐도 DB로 돌아오지 않는다.
  • 드롭다운 강제 — section/status는 ENUM으로 값 목록을 고정(오타 변종 차단).
  • 소프트삭제 + 감사 — 삭제는 is_active=0(복구가능), created_at/updated_at로 변경 시각 자동 기록.

설계 근거

  • 모델 B(DB 원본) — 원본을 DB 하나로 못박아 "앱↔Excel 양방향 동기화 지옥"을 원천 차단. Excel은 DB에서 뽑는 리포트.
  • source_no·customer.no 제거 — 원본 No는 Excel 행 순번 아티팩트. DB가 원본이면 무의미 → Excel 추출 시 ROW_NUMBER로 생성.
  • section/status = ENUM — Admin이 드롭다운에서 고르게 해 "진행중"/"진행 중"/"진행중 " 오타 변종 차단. 별도 룩업 테이블 없이 컬럼에 값 고정(값 추가 시 ALTER — 드물어서 OK).
  • is_active 소프트삭제 — 앱 "삭제"=is_active=0(숨김·복구가능·이력보존). 영구삭제는 DB에서 직접 DELETE. 조회는 보통 WHERE is_active=1.
  • 감사 컬럼 — created_at/updated_at로 언제 바뀌었는지 자동 기록(updated_at은 ON UPDATE 자동).
  • FK ON UPDATE CASCADE — 발주처 개명 시 project.customer 자동 전파. 삭제는 RESTRICT(발주처 지운다고 과제 안 날아감).
