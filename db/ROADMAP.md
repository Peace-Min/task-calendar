## P1. 인증 스텁 (권한 테이블은 지연) — **[XS]** ✅ **완료** *(localhost)*
> 실제 직원/권한 테이블(`app_user`)은 **배포 직전(P6.5)로 지연**. 코어 스키마(project/customer)와 독립이라 지연해도 되돌릴 게 없음. 지금은 스텁으로 충분.

- [x] 인증/권한 체크를 **한 지점으로 격리** — 호스트(C#) `ProjectDb.VerifyAdmin` 한 함수. UI는 **JIT 프롬프트(UAC 패턴, `requireAdmin`)** — 편집 순간에만 비번을 묻고 통과 시 액션 이어실행(설정창에 상시 로그인칸 없음). 비번은 JS에 노출하지 않고 호스트로만 넘김. 나중에 이 한 곳만 교체.
- [x] 자격 = **코드 베이크 디폴트(`admin`/`1234`, `ProjectDb.cs`)** + 설정에서 변경 시 `db-config.json`에 **관리자 자격만** 평문 저장. ⚠️ **베이크 디폴트는 배포 빌드에 포함된다**(개발/임시용) — 추출·우회 가능하므로 **실사용자 배포 전 P6.5(netcus 위임)로 반드시 대체.**
- (지연 → P6.5) `app_user` 테이블 · 앱용 최소권한 DB 계정 · netcus 인증 위임
- **게이트**: 스텁으로 admin/viewer 분기 동작(나중에 구현만 교체) ✅

## P2. 실데이터 스키마 검증(조기) — **[S]**  *(실 Excel 필요)*
> 앱을 다 만들기 **전에** 실데이터로 스키마 구멍을 미리 잡는 단계.

- [ ] 실제 사업부 Excel을 **테스트 임포트**해 더미에 없던 컬럼/케이스 확인
- [ ] 있으면 스키마 보완(반복)
- **게이트**: 실데이터 건수·왕복 대조 이상 없음
- **왜 조기?**: 뒤늦게 스키마가 틀리면 앱·이관 작업을 되돌려야 하므로 먼저 검증

## P3. 앱 ↔ DB 연동 (핵심 구현) — **[L]** ✅ **완료** *(localhost)*
> WPF+WebView2 위젯 작업. 이 프로젝트의 본체. (하위 항목이 확정 결정의 P3.1~P3.5에 대응)

- [x] **3s = 스키마 선행** `project`에 안정 `uid`(UUID, assign-once) 추가 → 일정은 `db-<uid>`로 참조. schema.sql 반영 완료(로컬 13행 UUID). (→ `ARCHITECTURE.md` §4.7.3, ADR #13)
- [x] **3a = P3.1** MySQL 커넥터 연결. **접속 정보 = 배포 베이크(★배포 구성 상수, `ProjectDb.cs`)** — 사용자 설정 UI 없음. `db-config.json`은 **관리자 자격만** 저장(연결정보 아님). *(초기안 "config 외부화"는 §4.6에서 베이크로 정정)*
- [x] **3b = P3.1** 과제 목록 **읽기 + 로컬 캐시**(오프라인 조회)
- [x] **3c** **온라인 상태 감지** → 마스터 CRUD는 온라인일 때만(오프라인=읽기전용, 조회는 캐시로 지속)
- [x] **3d = P3.2** 과제 **관리자 CRUD**(등록/수정/소프트삭제, UPSERT), `section`/`status` **ENUM 드롭다운** + 발주처 드롭다운. **P3.3** 공식 과제 **카탈로그 화면**(넓은 조회 UI).
- [x] **3d-1 = P3.4/P3.5** 공존(불변식 강제): 참조 네임스페이스(`db-<uid>` vs 개인) · 피커=공식+개인 둘 다 · 개인↔공식 재선택 자유 · **재연결 도구**(로컬 일괄 재태그, 오프라인 가능) · **단일 카테고리 스토어**(개인+구독 공식 한 목록, 출처 5구역 격리) · 해석 항상 성공(편입분 이름·색 유지 + `dbGone` 마크 + 플레이스홀더). 상세 → `ARCHITECTURE.md` §4.7.1·§4.7.4
- [x] **3e** **권한 반영**: 관리자만 편집 — 인증은 **JIT 프롬프트 스텁(UAC 패턴)** 한 지점(`ProjectDb.VerifyAdmin`), 나중 P6.5에서 app_user/netcus 위임으로 교체
- [ ] **3f** (옵션·미구현) **낙관적 잠금**: 저장 직전 `updated_at` 비교
- **게이트**: 로컬에서 전체 CRUD + 캐시 조회 + 권한 구분 + 오프라인 조회 + 재연결 동작 검증(메인이 실증 — 피커 공식 13건 실증)
- **방식**: dev-delegate(실질 구현)

## P4. Excel 추출기 (리포트) + 재연결 도우미 — **[M]**  *(지금 가능, P3와 병행 가능)*

- [ ] DB → Excel 장표 생성: **No=ROW_NUMBER**(추출 시 생성), `section`별 그룹/헤더 렌더, 기존 장표 레이아웃 재현
- [ ] **보고서 정책**(입력 관대/출력 엄격): **참조 기준 판정**(①) — `db-<uid>` 있으면 공식 집계, 그 외 **`기타`로 묶음**(②). 이름 매칭 금지. (→ `ARCHITECTURE.md` §4.7.2)
- [ ] **재연결 도우미 v1(순수 수동)**: 미연결 로컬 과제 → 사용자가 DB 목록에서 **직접 선택**/개인 유지. 자동매치 없음. 배치=설정/도구 상시 버튼+업데이트 후 1회 넛지, 개별=일정 편집. 카테고리 단위 매핑. (→ `ARCHITECTURE.md` §4.7.3)
- **게이트**: 원본 장표 형식 대조 + 공식/기타 분리 정확 + 수동 재연결 동작
- **방식**: dev-delegate

## P5. 실데이터 정식 이관 (1회성) — **[S~M]**  *(P2 후, 실 Excel 필요)*

- [ ] 실 Excel(2시트) → **`customer` 먼저**(발주처 FK 타겟) → `project`
- [ ] 이관기 규칙: 발주처 표기 정규화 · '미정'/공백→NULL · 선진행 상태 NULL · 섹션 헤더행→`section` 승격
- **게이트**: 이관 후 건수·왕복 대조. **이후 DB가 마스터**(재임포트 없음)
- **방식**: dev-delegate

## P6.5. 권한·보안 확정 (배포 직전) — **[S~M]**  *(실사용자 배포 전)*
> P1에서 지연한 것들. 실사용자에게 앱을 뿌리기 전 반드시 스텁을 실제 권한으로 대체.
> **★ 인증 방식 확정(2026-07-21): 회사 사이트(netcus) 인증 위임.** 우리 DB는 비밀번호를 **저장하지 않는다.**

- [ ] **인증 위임 흐름**: 위젯 → 회사 사이트(netcus) 로그인 시도(기존 NetcusService 자산 재사용) → 성공한 회사 ID로 → `app_user`에 존재 검사 → 있으면 그 role로 로그인, 없으면 viewer(읽기). 검증은 호스트(C#) 한 지점(현 `VerifyAdmin` 자리 교체).
- [ ] `app_user` 테이블 추가: `username`(=회사 ID), `role`('admin'|'editor'|'viewer'), `is_active`, 감사. **비밀번호 컬럼 없음**(인증은 회사 사이트 몫). 전 직원 아님 — 편집 권한자만 등록하면 충분(미등록=viewer).
- [ ] 코드 베이크 관리자(admin/1234)·db-config.json 관리자 자격 **제거**(위 흐름으로 대체)
- [ ] 앱용 **최소 권한 공용 DB 계정** 생성(전 사용자 공통, 해당 테이블 SELECT/INSERT/UPDATE만; DROP·계정변경 금지) → `ProjectDb.cs` 배포 구성 블록의 root 개발값 교체
- **게이트**: netcus 로그인 성공/실패/미등록 각 케이스 role 실동작, 스텁 흔적 제거 확인
- 인지된 트레이드오프: 편집 권한이 netcus 가용성에 의존(사이트 다운 시 편집 불가) — 편집 월 2~3회 + "편집=온라인만" 정책과 일관이라 수용

## P6. 폐쇄망 임시 서버 구축 — **[M]**  *(폐쇄망 필요)*

- [ ] 폐쇄망 PC에 MySQL **반입·설치**(반입 절차 확인)
- [ ] `schema.sql` 적용 + P5 실데이터 이관
- [ ] **서버화**: `bind-address=0.0.0.0` · 방화벽 3306 · 원격 최소권한 계정
- [ ] 고정 IP 확인(이미 설정됨) → `ProjectDb.cs` **★배포 구성 상수를 폐쇄망 IP로 교체 후 재빌드·자동업데이트 배포**
- **게이트**: **다른 PC에서** 앱으로 접속·조회·편집 성공
- **주의**: 배포 전 서버 MySQL **8.0+ / 콜레이션** 확인

## P7. 배포 · 운영 — **[M]**  *(폐쇄망)*

- [ ] 앱 배포(기존 자동업데이트/공유폴더 경로 재사용)
- [ ] 사용자 온보딩: `app_user` 승인(확인된 유저만 편집)
- [ ] 백업 정책(정기 덤프), 간단 운영 점검
- **게이트**: 실사용자 시나리오(조회·편집·오프라인) 정상

## P8. (나중) 전용 서버 이관 — **[S]**

- [ ] 상시가동 박스/회사 서버로 DB 이관 → `ProjectDb.cs` **★배포 구성 상수만 교체 후 재빌드·자동업데이트**(같은 엔진, 저비용)

## 권장 진행 순서

1. ✅ **완료**: **P1 인증 스텁(JIT 프롬프트)** + **P3 앱↔DB 연동(P3.1~P3.5)** — 읽기·캐시·CRUD·카탈로그·재연결·단일 스토어까지 localhost에서 구현·실증.
2. **다음(지금 바로)**: **P4 Excel 추출기 + 보고서 정책**(입력 관대/출력 엄격, 참조 기준 집계).
3. **실 Excel 확보되면**: **P2**(스키마 검증) 먼저 → 이상 없으면 P5(정식 이관).
4. **실사용자 배포 전**: **P6.5**(스텁 → app_user·netcus 인증 위임 + 최소권한 계정).
5. **폐쇄망 준비되면**: **P6**(임시 서버) → **P7**(배포). 이후 필요 시 **P8**(전용 서버).

가장 먼저 손댈 조각: **P4 Excel 추출기**(보고서 참조 기준 집계). 권한 테이블은 배포 직전 P6.5로 미룸.
