## P1. 인증 스텁 (권한 테이블은 지연) — **[XS]**  *(지금 가능)*
> 실제 직원/권한 테이블(`app_user`)은 **배포 직전(P6.5)로 지연**. 코어 스키마(project/customer)와 독립이라 지연해도 되돌릴 게 없음. 지금은 스텁으로 충분.

- [ ] 인증/권한 체크를 **한 지점(인터페이스/함수)으로 격리** — 예: `IPermissionProvider`. 지금 구현은 **코드레벨 admin 스텁**(config 플래그 등). 나중에 이 한 곳만 DB 조회로 교체.
- [ ] ⚠️ 코드레벨 인증은 **개발/임시용만** — 배포앱에 하드코딩하면 추출·우회 가능. **실사용자 배포 전 P6.5로 반드시 대체.**
- (지연 → P6.5) `app_user` 테이블 · 앱용 최소권한 DB 계정
- **게이트**: 스텁으로 editor/viewer 분기 동작(나중에 구현만 교체)

## P2. 실데이터 스키마 검증(조기) — **[S]**  *(실 Excel 필요)*
> 앱을 다 만들기 **전에** 실데이터로 스키마 구멍을 미리 잡는 단계.

- [ ] 실제 사업부 Excel을 **테스트 임포트**해 더미에 없던 컬럼/케이스 확인
- [ ] 있으면 스키마 보완(반복)
- **게이트**: 실데이터 건수·왕복 대조 이상 없음
- **왜 조기?**: 뒤늦게 스키마가 틀리면 앱·이관 작업을 되돌려야 하므로 먼저 검증

## P3. 앱 ↔ DB 연동 (핵심 구현) — **[L]**  *(지금 가능)*
> WPF+WebView2 위젯 작업. 이 프로젝트의 본체.

- [ ] **3s (스키마 선행)** `project`에 안정 `uid`(UUID, assign-once) 추가 → 일정은 `db-<uid>`로 참조. schema.sql 갱신·재적용·게이트(작음). (→ `ARCHITECTURE.md` §4.7.3, ADR #13)
- [ ] **3a** MySQL 커넥터 연결 + **접속 설정 외부화**(config, 지금은 localhost)
- [ ] **3b** 과제 목록 **읽기 + 로컬 캐시**(오프라인 조회)
- [ ] **3c** **온라인 상태 감지** → 편집은 온라인일 때만(오프라인=읽기전용)
- [ ] **3d** 과제 **CRUD UI**(등록/수정/소프트삭제), `section`/`status` **ENUM 드롭다운**
- [ ] **3d-1** 기존 데이터 공존(불변식 강제): 참조 네임스페이스(`db-<id>` vs 로컬) · 로컬 태그 편집=로컬→DB 단방향 · 해석 항상 성공(캐시 삭제분 보관+이름 스냅샷 폴백). 상세 스펙 → `ARCHITECTURE.md` §4.7.1
  - [ ] (스카우트 선행) 위젯의 **로컬 카테고리 참조 형식** 확인 → `db-` 네임스페이스 비충돌 확정
- [ ] **3e** **권한 반영**: editor/admin만 편집 UI 노출 — *P1의 인증 인터페이스 사용(지금은 스텁, 나중 P6.5에서 app_user로 교체)*
- [ ] **3f** (옵션) **낙관적 잠금**: 저장 직전 `updated_at` 비교
- **게이트**: 로컬에서 전체 CRUD + 캐시 조회 + 권한 구분 + 오프라인 조회 동작 검증(메인이 실증)
- **방식**: dev-delegate(실질 구현)

## P4. Excel 추출기 (리포트) + 재연결 도우미 — **[M]**  *(지금 가능, P3와 병행 가능)*

- [ ] DB → Excel 장표 생성: **No=ROW_NUMBER**(추출 시 생성), `section`별 그룹/헤더 렌더, 기존 장표 레이아웃 재현
- [ ] **보고서 정책**(입력 관대/출력 엄격): **참조 기준 판정**(①) — `db-<uid>` 있으면 공식 집계, 그 외 **`기타`로 묶음**(②). 이름 매칭 금지. (→ `ARCHITECTURE.md` §4.7.2)
- [ ] **재연결 도우미 v1(순수 수동)**: 미연결 로컬 과제 → 사용자가 DB 목록에서 **직접 선택**/개인 유지. 자동매치 없음. 배치=설정/도구 상시 버튼+업데이트 후 1회 넛지, 개별=일정 편집. 카테고리 단위 매핑. (→ `ARCHITECTURE.md` §4.7.3)
- **게이트**: 원본 장표 형식 대조 + 공식/기타 분리 정확 + 수동 재연결 동작
- **방식**: dev-delegate

## P5. 실데이터 정식 이관 (1회성) — **[S~M]**  *(P2 후, 실 Excel 필요)*

- [ ] 실 Excel(2시트) → **`customer` 먼저**(발주처 FK 타겟) → `project`
- [ ] 이관기 규칙: 발주처 표기 정규화 · '미정'/공백→NULL · 선진행 상태 NULL · 섹션 헤더행→`section` 승격
- **게이트**: 이관 후 건수·왕복 대조. **이후 DB가 마스터**(재임포트 없음)
- **방식**: dev-delegate

## P6.5. 권한·보안 확정 (배포 직전) — **[S~M]**  *(실사용자 배포 전)*
> P1에서 지연한 것들. 실사용자에게 앱을 뿌리기 전 반드시 스텁을 실제 권한으로 대체.
> **★ 인증 방식 확정(2026-07-21): 회사 사이트(netcus) 인증 위임.** 우리 DB는 비밀번호를 **저장하지 않는다.**

- [ ] **인증 위임 흐름**: 위젯 → 회사 사이트(netcus) 로그인 시도(기존 NetcusService 자산 재사용) → 성공한 회사 ID로 → `app_user`에 존재 검사 → 있으면 그 role로 로그인, 없으면 viewer(읽기). 검증은 호스트(C#) 한 지점(현 `VerifyAdmin` 자리 교체).
- [ ] `app_user` 테이블 추가: `username`(=회사 ID), `role`('admin'|'editor'|'viewer'), `is_active`, 감사. **비밀번호 컬럼 없음**(인증은 회사 사이트 몫). 전 직원 아님 — 편집 권한자만 등록하면 충분(미등록=viewer).
- [ ] 코드 베이크 관리자(admin/1234)·db-config.json 관리자 자격 **제거**(위 흐름으로 대체)
- [ ] 앱용 **최소 권한 공용 DB 계정** 생성(전 사용자 공통, 해당 테이블 SELECT/INSERT/UPDATE만; DROP·계정변경 금지) → `ProjectDb.cs` 배포 구성 블록의 root 개발값 교체
- **게이트**: netcus 로그인 성공/실패/미등록 각 케이스 role 실동작, 스텁 흔적 제거 확인
- 인지된 트레이드오프: 편집 권한이 netcus 가용성에 의존(사이트 다운 시 편집 불가) — 편집 월 2~3회 + "편집=온라인만" 정책과 일관이라 수용

## P6. 폐쇄망 임시 서버 구축 — **[M]**  *(폐쇄망 필요)*

- [ ] 폐쇄망 PC에 MySQL **반입·설치**(반입 절차 확인)
- [ ] `schema.sql` 적용 + P5 실데이터 이관
- [ ] **서버화**: `bind-address=0.0.0.0` · 방화벽 3306 · 원격 최소권한 계정
- [ ] 고정 IP 확인(이미 설정됨) → 앱 config의 DB 주소를 **폐쇄망 IP로 교체**
- **게이트**: **다른 PC에서** 앱으로 접속·조회·편집 성공
- **주의**: 배포 전 서버 MySQL **8.0+ / 콜레이션** 확인

## P7. 배포 · 운영 — **[M]**  *(폐쇄망)*

- [ ] 앱 배포(기존 자동업데이트/공유폴더 경로 재사용)
- [ ] 사용자 온보딩: `app_user` 승인(확인된 유저만 편집)
- [ ] 백업 정책(정기 덤프), 간단 운영 점검
- **게이트**: 실사용자 시나리오(조회·편집·오프라인) 정상

## P8. (나중) 전용 서버 이관 — **[S]**

- [ ] 상시가동 박스/회사 서버로 DB 이관 → 앱 config **접속 주소만 교체**(같은 엔진, 저비용)
- [ ] 백업/모니터링 이관

## 권장 진행 순서

1. **지금 바로**: **P1 인증 스텁**(인터페이스 격리만) → **P3 앱 연동** 착수. P4(Excel 추출)는 여력 되면 병행.
2. **실 Excel 확보되면**: **P2**(스키마 검증) 먼저 → 이상 없으면 P5(정식 이관).
3. **실사용자 배포 전**: **P6.5**(app_user로 인증 스텁 대체 + 최소권한 계정).
4. **폐쇄망 준비되면**: **P6**(임시 서버) → **P7**(배포). 이후 필요 시 **P8**(전용 서버).

가장 먼저 손댈 조각: **P3 앱↔DB 연동**(인증은 P1 스텁으로). 권한 테이블은 배포 직전 P6.5로 미룸.
