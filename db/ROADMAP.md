## P1. 인증 스텁 (권한 테이블은 지연) — **[XS]** ✅ **완료** *(localhost)*
> 실제 직원/권한 테이블(`app_user`)은 **배포 직전(P6.5)로 지연**. 코어 스키마(project/customer)와 독립이라 지연해도 되돌릴 게 없음. 지금은 스텁으로 충분.

- [x] 인증/권한 체크를 **한 지점으로 격리** — 호스트(C#) `ProjectDb.VerifyAdmin` 한 함수. UI는 **JIT 프롬프트(UAC 패턴, `requireAdmin`)** — 편집 순간에만 비번을 묻고 통과 시 액션 이어실행(설정창에 상시 로그인칸 없음). 비번은 JS에 노출하지 않고 호스트로만 넘김. 나중에 이 한 곳만 교체.
- [x] 자격 = **코드 베이크 디폴트(`admin`/`1234`, `ProjectDb.cs`)** + 설정에서 변경 시 `db-config.json`에 **관리자 자격만** 평문 저장. ⚠️ **베이크 디폴트는 배포 빌드에 포함된다**(개발/임시용) — 과제 DB 우선 배포(P6.4) 시엔 관리자 암호를 실제 값으로 교체(1234 금지)하고 최소권한 계정으로 blast-radius를 제한하며, 실 per-user 강제는 사용자 DB 구축 시 P6.5(netcus 위임)로 대체.
- (지연 → P6.5) `app_user` 테이블 · 앱용 최소권한 DB 계정 · netcus 인증 위임
- **게이트**: 스텁으로 admin/viewer 분기 동작(나중에 구현만 교체) ✅

## C3.6. 이관 방식 확정 — 자동이관 폐기, 명시적 가져오기 — **[M]** ✅ **완료**(2026-09-01)

> **사용자 판단**: 「DB 트리거로 첫 실행이면 로컬 xml 을 자동으로 불러온다」 같은 것은 **안티패턴**이다.
> 명시적 읽기/내보내기 패턴이 맞다.

**왜 맞았나 — 이 저장소가 이미 그 비용을 치르고 있었다.** `migrateLocalStores()`(localStorage → XML
자동 1회 이관)가 부팅 경로 3곳에서 돌고 있었고, 스스로 `TODO(제거예정)` 을 달고도 지울 조건을 아무도
판정하지 않아 계속 살아 있었다. 게다가 **다른 계층에 방어 부채**를 만들었다 — `CalendarDb` 가
`lsMigrated` 를 하드코딩 `true` 로 막고 있었고, 안 그러면 localStorage 좀비가 **DB 로** 들어가고
무효 근태 코드가 '정근' 으로 정규화됐다. 같은 판단의 선례가 둘 더 있다 — 감사 트리거 폐기(설계 §7.5),

- [x] `migrateLocalStores()` + 호출부 3곳 + `lsMigrated` 마커 제거 (계약 G-0 최상위 키 **15 → 14**)
