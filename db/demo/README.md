# 데모 DB 키트 (사용 설명 영상 녹화용, 이슈 #13)

사용 설명 영상을 찍을 때 화면에 실제 직원 이름, 실제 과제와 발주처, 실제 일정이 나오면 안 됩니다.
이 키트는 로컬 DB(`taskcalendar`)를 **늘 같은 모양의 데모 데이터**로 바꾸고, 녹화가 끝나면 **원래 DB 로 되돌립니다**.
일정 날짜는 실행하는 날 기준으로 계산하므로 언제 찍어도 "이번 달" 화면이 채워져 보입니다.

## 파일

| 파일 | 역할 |
|---|---|
| `demo-data.mjs` | 손으로 고치는 정의: 가상 이름 명단, 발주처, 공식 과제, 개인 과제, 장소, 일정과 할 일 문구, 데이터를 받는 사람 |
| `build-demo-sql.mjs` | 정의와 기준 날짜로 `demo-load.sql` 을 만든다. 같은 입력이면 바이트까지 같은 SQL 이 나온다 |
| `demo-db.ps1` / `demo-db.cmd` | 실행 도구: `-Load`(백업 뒤 넣기), `-Restore`(되돌리기), `-Status`(상태 보기). 종료코드 0~5 |

생성된 `demo-load.sql` 은 저장소에 넣지 않습니다. 기준 날짜와 녹화 계정 login_id 에 따라 내용이 달라지고, `-Load` 가 실행할 때마다
`dist\demo-db\` 에 새로 만들어 함께 남기기 때문입니다(무엇을 부었는지는 그 파일이 증거입니다).

## 무엇이 바뀌고 무엇이 그대로인가

바뀌는 것(`-Load`)

- **사람(app_user)**: 녹화 계정은 이름만 `홍길동` 으로 바뀌고 login_id 는 그대로입니다(위젯이 그 login_id 로 로그인돼 있어야 하므로).
  나머지 사람은 이름과 login_id 가 가상 명단 순서대로 바뀝니다. 재직 중이고 녹화 계정과 같은 조직인 사람이 먼저 이름을 받으므로
  `김철수`(kimcs), `이영희`(leeyh), `박민수`(parkms) 는 보통 같은 팀 동료가 됩니다. 그다음 `최지은`(choije), 그 뒤는 성과 이름을 엮은 가상 이름입니다.
- **발주처(customer)와 공식 과제(project)**: 전부 지우고 `(예시) 가나테크` 같은 발주처 5개, `(예시) 장비 개발` 같은 공식 과제 8개로 바꿉니다.
  구분은 일반계약, 선진행, 사업부관리가 섞여 있고 상태에는 종료와 1차 납품완료, 미정도 있습니다.
- **캘린더(cal_\*)**: 모든 사람의 일정, 할 일, 과제별 시간, 근태, 보낸 보고, 설정, 장소 목록을 지웁니다.
  그리고 녹화 계정과 동료 셋에게 지난달 1일부터 이번 달 말일까지의 데이터를 만듭니다.
  - 내 과제: 공식 과제 3개, 개인 과제(주간 회의, 자료 정리, 교육 수강 중 일부), 기본 과제 휴가와 기타
  - 일정: 평일마다 1~3개, 매주 반복하는 주간 팀 회의, 이틀짜리 휴가와 오후 반차, 사흘짜리 고객사 현장 지원, 오후 교육.
    장소는 `(예시) 3층 회의실` 처럼 모두 `(예시)` 로 시작합니다. 알림은 꺼 두었습니다(녹화 중에 알림 창이 뜨지 않게).
  - 할 일: 사람마다 8개(끝낸 것, 기한이 지난 것, 곧 기한인 것, 기간 할 일과 날짜별 메모, 기한 없는 것)
  - 과제별 시간: 기준 날짜까지의 평일 대부분
  - 동료 셋의 공식 과제가 녹화 계정과 일부 겹쳐 겹쳐 보기, 나란히 보기, 펼침 화면이 자연스럽게 보입니다.
  - 그 밖의 사람에게는 캘린더 데이터가 없습니다.
- **cal_user_rev**: 지우지 않고 모든 사람의 값을 하나씩 올립니다(없던 사람은 1).

그대로인 것

- 조직(org_unit)과 직급(title_code), 구분과 상태 코드, `cal_schema_meta`(판번호 13)
- 사람의 user_id, 소속, 직급, 열람 범위, 편집 권한, 재직 여부, 순서
- **MySQL 계정과 권한**. 이 키트는 GRANT, CREATE USER, DROP USER 를 내지 않습니다.

## 쓰는 법

`demo-db.cmd` 를 `db\demo` 폴더에서 실행합니다. 관리자(root) 비밀번호는 물어볼 때 입력합니다(인자로 받지 않습니다).

1. 이 PC 에서 다른 세션이 위젯 루프를 돌리고 있지 않은지 확인하고, 이 DB 에 붙은 위젯을 모두 닫습니다.
2. 상태 보기: `demo-db.cmd -Status`
3. 넣기: `demo-db.cmd -Load`
   - 녹화 계정은 이 PC 위젯의 세션 파일(`%APPDATA%\TaskCalendar\user.session`)에서 읽습니다. 못 읽으면 `-MyLoginId <로그인 ID>` 를 주세요.
   - 기준 날짜를 바꾸려면 `-BaseDate 2026-10-19` 처럼 줍니다(기본은 오늘).
   - 먼저 DB 전체를 `dist\demo-db\taskcalendar-before-demo-<시각>.sql` 로 백업하고 끝의 `-- Dump completed` 를 확인합니다.
     표별 행 수는 같은 이름 뒤 `.counts.json` 에, 어느 백업으로 되돌릴지는 `dist\demo-db\taskcalendar-demo-marker.json` 에 적습니다.
   - 데모 SQL 은 트랜잭션 하나로 들어가고, 안의 검증(사람 수, 소속과 권한 지문, 조직과 직급 지문, 행 수 등)이 하나라도 틀리면 COMMIT 전에 멈춥니다.
4. 위젯을 띄웁니다. 설정의 계정 이름은 세션 파일에 남은 옛 이름이라, **로그아웃했다가 다시 로그인하면** `홍길동` 으로 바뀝니다.
   녹화 계정의 열람 범위가 `self` 이면 다른 사람 일정이 보이지 않습니다(`-Load` 가 경고합니다). `db\deploy\scope-all.cmd` 나 관리 화면으로 넓히세요.
5. 녹화합니다.
6. 되돌리기: 위젯을 닫고 `demo-db.cmd -Restore`
   - 지금 상태(데모)를 `before-restore` 덤프로 먼저 남긴 뒤, DB 를 지우고 백업 때의 문자셋과 정렬 규칙(기본 `utf8mb4_0900_ai_ci`)으로 다시 만들어 백업을 붓습니다.
   - 판번호 13 과 표 이름 집합, 표별 행 수가 `-Load` 때 센 값과 같아야 통과입니다. 통과하면 표지 파일은 `-restored-` 이름으로 옮겨집니다.
   - 앱 계정(taskmgr_app)의 표 단위 권한은 DB 를 지워도 남으므로 위젯은 그대로 붙습니다.
   - 지금 DB 에 데모 데이터가 없고 표지 파일도 없으면 되돌리지 않습니다(실데이터를 옛 백업으로 덮는 사고를 막기 위해서입니다).
7. 위젯을 다시 띄우고, 계정 이름이 `홍길동` 으로 남아 있으면 로그아웃했다가 다시 로그인합니다.

무인 실행은 다른 운영 도구와 같습니다. `TASKMGR_ADMIN_PW` 환경변수를 두거나 stdin 첫 줄로 비밀번호를 넘기고 `-Yes` 를 함께 줍니다.

## 주의

- **데모 데이터가 들어 있는 동안 이 PC 의 로컬 DB 는 모든 세션과 모든 루프에게 데모 데이터입니다.** 이 PC 가 서버 노릇을 하므로
  같은 DB 에 붙는 다른 위젯도 데모 데이터를 봅니다. 녹화가 끝나면 바로 되돌리세요.
- **다른 세션이 위젯 루프(`tests/loop-*.mjs`, run-loops)를 돌리는 동안에는 녹화하지 마세요.** 루프가 만든 시험 과제가 화면에 섞이고,
  루프는 데모 데이터를 실데이터로 알고 판정합니다. `-Load` 와 `-Restore` 는 앱 계정 세션이 열려 있으면 멈춥니다(종료코드 4, `-Force` 로만 건너뜀).
- 두 번 넣지 않습니다. 표지 파일이 있거나 DB 에 `(예시)` 과제가 이미 있으면 `-Load` 는 멈춥니다. 데모 상태를 백업하면 되돌릴 실데이터가 없어지기 때문입니다.
- 백업 파일(`dist\demo-db\`)에는 실데이터가 들어 있습니다. `dist/` 는 저장소에 들어가지 않습니다. 다른 곳으로 옮기지 마세요.

## 종료코드

| 코드 | 뜻 |
|---|---|
| 0 | 넣고 확인까지 통과, 되살리고 확인까지 통과, 또는 상태를 보여 줌 |
| 1 | 데모 SQL 이나 되살리기가 멈췄거나 끝난 뒤 확인이 실패함. 화면의 상태와 명령을 따른다 |
| 2 | 확인(Y)을 받지 못해 취소함. 바뀐 것 없음 |
| 3 | 사전 점검 실패(도구, 비밀번호, 접속, DB, 판번호가 13 이 아님, 녹화 계정, 데모 상태, 백업 파일). 바뀐 것 없음 |
| 4 | 앱 계정 세션이 열려 있음. 위젯을 모두 닫는다. 바뀐 것 없음 |
| 5 | 백업 실패(mysqldump 실패나 덤프가 온전하지 않음). DB 는 건드리지 않음 |

## 정의 고치기

`demo-data.mjs` 만 고칩니다. 공식 과제, 발주처, 장소는 `(예시)` 로 시작해야 하고, 사람 이름은 실존 인물이나 유명인과 겹치지 않게 둡니다.
고친 뒤 `node tests/run-tests.mjs` 의 `demo-db.test.mjs` 가 결정성, 이름 규칙, 가드, 백업 순서를 확인합니다.
SQL 만 미리 보려면 `node db/demo/build-demo-sql.mjs --my-login <로그인 ID> --base-date 2026-10-19 --out <파일>` 을 실행합니다(DB 에 붙지 않습니다).
