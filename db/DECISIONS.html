SQLite 기각(편집자 여럿·중앙권한). 사용자 PC에 MySQL 설치 불필요.

수정됨 07-21접속 정보 = 배포 구성(베이크) · 조회 = 캐시(오프라인 OK)
"설정값"→정정: 연결정보는 배포 전 호스트 코드 디폴트(ProjectDb.cs ★배포 구성 블록)로 설정하고 빌드·배포. 사용자 연결설정 UI 없음 — 설정창엔 관리자 상태·해제·DB 상태줄·새로고침만(상시 로그인칸 없음 — 인증은 JIT 프롬프트). 조회는 캐시로 오프라인 지속.
확정편집 = 두 종류로 분리
일정 편집=로컬 쓰기(오프라인도 가능). 과제 마스터 CRUD=DB 쓰기(온라인만).

권한 / 인증

수정됨 07-21지금 코드 베이크 스텁 → 배포 직전 app_user
인증을 "역할 반환" 한 지점(ProjectDb.VerifyAdmin)으로 격리. 자격은 코드 베이크 디폴트(admin/1234) — "배포엔 안 나감"은 오해였고 배포 빌드에 포함된다(개발/임시용). 설정에서 변경 시 db-config.json에 관리자 자격만 평문 저장. P6.5에서 app_user(편집 권한자만) + netcus 인증 위임 + 최소권한 DB 계정으로 교체.
수정됨 07-21관리자 인증 = JIT 프롬프트(UAC 패턴)
"설정창에서 미리 로그인"→정정: 설정창엔 상태 배지·해제·DB 상태줄·새로고침만. 편집/추가/삭제를 누른 그 순간에만 비번을 묻고(requireAdmin) 통과 시 액션을 이어 실행. 비번은 JS에 남기지 않고 호스트로만 전달.

과제 입력 · 공존 · 보고서 정책

확정타입 있는 참조 (충돌 방지 핵심)
일정의 과제 = 공식(db-uid) / 개인(local) / freetext 타입 유니언. 타입이 참조에 박혀 절대 안 섞임.
수정됨 07-21단일 카테고리 스토어 (P3.5) + 출처 격리
개인 과제와 구독한 공식 과제(source:'db')를 한 목록(state.categories)에 담고 XML에 영속(오프라인 캐시 겸함). dbCatalog는 카탈로그·재연결 전용. 이중 목록(state.categories vs dbCatalog)은 기각 — 소비 지점마다 병합이 필요해 필터바에 DB 과제가 안 뜨는 실버그를 냈다. 출처 인지는 5구역(카테고리 모듈·관리UI·카탈로그·재연결·XML)에서만, 전시·보고서는 균일 소비, 접두검사는 isOfficialId 한 곳.
확정입력 제약 없음
DB 과제 선택 또는 자유입력 — 뭐든 허용. 통제는 보고서에서.
확정 ①보고서 판정 = 참조 기준
db-uid 참조가 있으면 공식(집계), 그 외 전부 비공식. 이름 매칭(자동/상시) 금지 — 오타·동명 fuzzy 회피.
확정 ②비공식 = 기타로 묶음
보고서에서 비공식은 기타 버킷(총량·투명성 유지). 완전 제거는 옵션.
확정기존 데이터 무변경 · "필드 없음 = 비공식"
옛 일정 손 안 댐. 타입 표시 없으면 비공식(사용자/레거시)으로 기본 해석. 일괄 마이그레이션 없음. 새 필드 vs 인코딩은 P3 스카우트에서 확정.
확정 D3DB 과제 하드삭제 금지 · 해석 항상 성공
소프트삭제만(일정 참조가 DB 밖이라 FK 보호 불가). 구현: 단일 목록에 편입된 과제가 마지막 이름·색을 유지하고 카탈로그에서 사라지면 dbGone 마크(피커엔 숨김, 라벨은 해석), 어디에도 없으면 (공식 과제) 플레이스홀더 → 빈칸·크래시 없음. 일정 단위 {이름,색} 스냅폴백은 미구현(향후 옵션).
수정됨로컬(개인) tier 동결 해제
"로컬 동결"→ 개인 라벨(freetext) 요구로 변경. 개인 tier는 계속 생성 가능.
수정됨피커 = 공식(DB) + 개인 둘 다
"피커 DB 전용"→ 변경. "새 건 DB만"은 공식 과제 한정이었음.

재연결 도우미 (v1)

확정순수 수동 (자동매치 없음)
미연결 로컬 과제를 사용자가 DB 목록에서 직접 선택 또는 개인 유지. 이름 자동매칭 없음(오타·변종도 수동으로 해결). 자동 pre-fill은 나중 옵션.
확정배치 = 설정 상시 버튼 · 개별 = 일정 편집 (구현)
설정의 "🔗 기존 과제 재연결" 상시 버튼으로 카테고리 단위 일괄 매핑(개인 과제→공식, 일정·할일 categoryId 로컬 교체·오프라인 가능), 개별은 일정 편집에서 재선택. 업데이트 후 1회 넛지 + 이후 뱃지는 미구현(향후) — 상시 버튼만 제공.
확정위젯 표시 보존 / 보고서 승격은 재연결로
기존 정리는 위젯에서 100% 그대로. 보고서에서 공식 인정받으려면 재연결. 삭제·재입력 불필요.
