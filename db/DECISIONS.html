핵심 원칙 — 입력은 관대하게, 출력(보고서)은 엄격하게
입력 시엔 뭐든 허용(DB 과제 선택 또는 자유입력) — 입력 제약을 걸지 않는다. 제약은 보고서 생성 한 곳에만: DB에 정의된 공식 과제만 집계, 나머지는 기타.

데이터 모델

확정모델 B — DB가 원본
Admin이 앱으로 과제 CRUD, Excel은 DB에서 단방향 추출 리포트. 기존 Excel은 최초 1회만 이관.
확정2테이블 — customer + project
뷰 0. 컴팩트. Excel 흔적(source_no·no) 제거.
확정section·status = ENUM
드롭다운 소스. 별도 룩업테이블 없이 컬럼에 값 고정.
확정소프트삭제 + 감사
is_active=0(복구가능), created_at/updated_at 자동.
확정FK ON UPDATE CASCADE
발주처 개명 자동 전파. 삭제는 RESTRICT.
확정과제명 중복 미처리
현재도 안 막음(회귀 아님).
확정 D1안정 uid 추가 (외부 참조키)
project에 UUID(assign-once) 추가. 일정은 db:<uid>로 참조 → rename·덤프복원·이관에도 불변. 내부 PK(autoinc id)는 유지. 전시명을 키로 쓰지 않음. ✅ schema.sql 반영 완료(로컬 13행 UUID)

배포 · 운영

확정MySQL 유지 · 사용자는 앱만
SQLite 기각(편집자 여럿·중앙권한). 사용자 PC에 MySQL 설치 불필요.
확정중앙 DB 위치 단계
localhost → 폐쇄망 PC(고정 IP) → 전용 박스/회사 서버. 접속 주소만 교체.
확정접속 주소 = 설정값 · 조회 = 캐시(오프라인 OK)
FTP 경로처럼 config 1줄. 조회는 서버 꺼져도 지속.
확정편집 = 두 종류로 분리
일정 편집=로컬 쓰기(오프라인도 가능). 과제 마스터 CRUD=DB 쓰기(온라인만).

권한 / 인증

확정지금 코드레벨 스텁 → 배포 직전 app_user
인증을 "역할 반환" 인터페이스 한 지점으로 격리. 지금 admin/1234 스텁(개발용, 배포엔 안 나감) → P6.5에서 app_user(편집 권한자만) + 최소권한 DB 계정으로 교체.

과제 입력 · 공존 · 보고서 정책

확정타입 있는 참조 (충돌 방지 핵심)
일정의 과제 = 공식(db:uid) / 개인(local) / freetext 타입 유니언. 타입이 참조에 박혀 절대 안 섞임.
확정입력 제약 없음
DB 과제 선택 또는 자유입력 — 뭐든 허용. 통제는 보고서에서.
확정 ①보고서 판정 = 참조 기준
db:uid 참조가 있으면 공식(집계), 그 외 전부 비공식. 이름 매칭(자동/상시) 금지 — 오타·동명 fuzzy 회피.
확정 ②비공식 = 기타로 묶음
보고서에서 비공식은 기타 버킷(총량·투명성 유지). 완전 제거는 옵션.
확정기존 데이터 무변경 · "필드 없음 = 비공식"
옛 일정 손 안 댐. 타입 표시 없으면 비공식(사용자/레거시)으로 기본 해석. 일괄 마이그레이션 없음. 새 필드 vs 인코딩은 P3 스카우트에서 확정.
확정 D3DB 과제 하드삭제 금지 · 해석 항상 성공
소프트삭제만(일정 참조가 DB 밖이라 FK 보호 불가). 캐시가 삭제분 보관 + 일정에 {이름,색} 스냅샷 폴백 → 빈칸·크래시 없음.
수정됨로컬(개인) tier 동결 해제
"로컬 동결"→ 개인 라벨(freetext) 요구로 변경. 개인 tier는 계속 생성 가능.
수정됨피커 = 공식(DB) + 개인 둘 다
"피커 DB 전용"→ 변경. "새 건 DB만"은 공식 과제 한정이었음.

재연결 도우미 (v1)

확정순수 수동 (자동매치 없음)
미연결 로컬 과제를 사용자가 DB 목록에서 직접 선택 또는 개인 유지. 이름 자동매칭 없음(오타·변종도 수동으로 해결). 자동 pre-fill은 나중 옵션.
확정배치 = 설정/도구 상시 버튼 · 개별 = 일정 편집
업데이트 후 1회 비강제 넛지 + 이후 뱃지(강제·주기 팝업 없음). 카테고리 단위 매핑(아래 일정 일괄 재연결).
확정위젯 표시 보존 / 보고서 승격은 재연결로
기존 정리는 위젯에서 100% 그대로. 보고서에서 공식 인정받으려면 재연결. 삭제·재입력 불필요.
