# 수행과제 캘린더 — 데스크톱 위젯 (WPF + WebView2)

검증 완료된 HTML 프로토타입(`../task-calendar-prototype.html`)을 **본체로 그대로 임베드**한 Windows 11 데스크톱 위젯입니다. 실행형 앱처럼 매번 켜는 게 아니라, **로그인 시 자동 상주**하며 **다른 창 뒤(바탕화면 레이어)에 깔려** 바탕화면 아이콘처럼 늘 그 자리에 있습니다. 단 캘린더 조작이 핵심이라 **클릭·입력은 정상 동작**합니다.

## 동작 방식
- **UI/로직**: 임베드된 단일 HTML(검증 완료) — 월 그리드, 과제 카테고리, 기록 작성, 키워드/과제별 검색, 드래그 이동, 공휴일 등 동일.
- **데이터**: 브라우저 localStorage가 아니라 **`%APPDATA%\TaskCalendar\data.xml`** (기계가독 `taskCalendar` XML v1). 다른 SW에서 그대로 읽어 확장 가능. 변경 시마다 원자적(atomic) 저장.
- **창 구성**: WPF 창은 **WebView2가 100% 채웁니다.** 상단의 파란 **호스트바**(`⠿ 수행과제 캘린더` + 📌 ⚙ ✕)는 HTML 안에서 그려집니다 — WPF가 직접 그리는 영역을 두면 바탕화면 부착 시 그 부분이 검게 렌더되기 때문(원인은 아래 "알려진 한계" 참고).
- **바탕화면 부착(기본 ON)**: 창을 **바탕화면(Progman)의 자식 창**으로, **아이콘 레이어보다 위에** 붙입니다.
  - 바탕화면 보기(Win+D)를 해도 **아이콘처럼 그대로 남음** (앱처럼 최소화되지 않음)
  - 아이콘 *위*라서 **클릭·일정 입력·검색·한글 입력 정상 동작**
  - 일반 앱 창 뒤로 깔림(앱 위로 안 떠오름) → 데스크톱처럼 행동
  - **부착 중에는 이동(드래그) 잠금** — 제자리에 고정됩니다. 옮기려면 📌를 눌러 부착 해제 후 `⠿ 수행과제 캘린더` 영역을 드래그하고, 다시 📌로 부착.
  - **크기 조절(우하단 그립)은 부착/해제 모두 가능** — 좌상단을 고정한 채 크기만 바뀌므로 위치 고정과 충돌하지 않음.
  - (📌는 바탕화면 부착 ↔ 일반 플로팅 창 전환)
- **좌/우 너비 조절**: 좌측 캘린더와 우측 기록 패널 사이의 **세로 분할바를 드래그**해 비율 조절(폭 ≥ ~760px 일 때 좌우 배치, 그 미만은 세로 스택). 조절한 너비는 저장됨.
- **자동 시작**: 최초 실행 시 `HKCU\...\Run`에 자동 등록(로그인 시 자동 상주). ⚙ 메뉴에서 켜고/끌 수 있음. 작업표시줄·Alt+Tab에는 안 나타남.

## 실행
이미 빌드돼 있습니다:
```
bin\Release\net9.0-windows\TaskCalendarWidget.exe
```
더블클릭하면 됩니다. (단일 인스턴스 — 중복 실행해도 하나만 뜸)

## 빌드 (폐쇄망 오프라인)
```
dotnet build -c Release
```
- `nuget.config`가 원격 소스를 비워 nuget.org 접속을 시도하지 않습니다(타임아웃 방지).
- WebView2 패키지(1.0.3179.45)는 로컬 NuGet 캐시에서, .NET 런타임/apphost는 설치된 9.0.17 팩에서 해결됩니다.
- `RuntimeFrameworkVersion=9.0.17`로 고정 — 설치된 런타임에 맞춤(미설치 패치를 NuGet에서 받지 않도록).

## 상단 호스트바 / ⚙ 설정 메뉴
호스트바 버튼: **📌 바탕화면 부착/해제**, **⚙ 설정**, **✕ 종료**.
- **이동**: 부착 해제(플로팅) 상태에서 `⠿ 수행과제 캘린더` 영역 드래그 (부착 중에는 이동 잠금)
- **크기 조절**: 우하단 그립 드래그 (부착/해제 모두, 모든 크기에서 동작)

⚙ 설정 메뉴:
- **바탕화면에 부착** (체크 토글) — 📌 버튼과 동일
- **크기 프리셋** — 작게(360×470) / 보통(440×560) / 크게(560×680) / 와이드(900×640)
- **Windows 시작 시 자동 실행** (체크 토글)
- **위치·크기 초기화** (우하단 기본 위치로)
- **위젯 종료**

> 이동·리사이즈는 HTML 포인터 이벤트 → 호스트가 `SetWindowPos`로 실시간 적용하는 방식이라 부착/플로팅 모두 동작합니다. ⚙ 크기 프리셋은 빠른 조절용 보너스입니다.

## 데이터 위치
| 파일 | 용도 |
|---|---|
| `%APPDATA%\TaskCalendar\data.xml` | 캘린더 데이터(교환용 XML). HTML 프로토타입의 내보내기/가져오기와 100% 호환 |
| `%APPDATA%\TaskCalendar\widget.settings.json` | 창 위치·크기·자동시작 상태 |
| `%APPDATA%\TaskCalendar\WebView2\` | WebView2 사용자 데이터(자기완결) |

## 다른 PC로 옮기기 (런타임 없는 PC 포함)
설치된 .NET 9 런타임이 없는 PC로 옮기려면 자체 포함(self-contained) 단일 exe로 게시:
```
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```
→ `bin\Release\net9.0-windows\win-x64\publish\TaskCalendarWidget.exe` 하나만 복사하면 됨(.NET 설치 불필요). WebView2 런타임은 Windows 11에 기본 내장.

## 알려진 한계 / 참고
- **부착 방식**: 아이콘 뒤 벽지 레이어(WorkerW)가 아니라 **바탕화면(Progman) 자식 + 아이콘 위**로 부착합니다(클릭·입력 가능 + Win+D 잔존).
- **검은 띠 이슈(해결됨)**: 초기 버전은 WPF가 그리는 타이틀바·테두리가 있었는데, **WPF 창을 Progman 자식으로 `SetParent`하면 WPF 자체 렌더링(DWM 합성)이 깨져 그 영역이 검게 남았습니다**(WebView2는 독립 HWND라 정상). → WPF 그릴 영역을 0으로 만들고 **WebView2가 창 전체를 채우게** + 컨트롤을 HTML 호스트바로 이동해 해결. 고정·기본/큰 창 모두 화면 캡처로 검은 띠 소멸 확인.
- **다중 모니터**: 부착 위치는 **주 모니터** 기준으로 계산됩니다. 보조 모니터에 두려면 잠금 해제(플로팅)로 옮긴 뒤 사용하거나, 주 모니터에서 위치를 잡고 고정하세요.
- **자동시작 경로**: 현재 빌드 출력 경로(`bin\Release\...`)가 등록돼 있습니다. exe를 다른 폴더로 옮기면 ⚙ 메뉴에서 자동시작을 껐다 켜 경로를 갱신하세요(또는 안정적인 폴더에 publish 후 그 exe로 자동시작 재설정 권장).
- 알림·반복 일정·주간/일간 뷰·음력 명절은 다음 단계 백로그입니다.
